## 1. 产品骨架与图例

### 1.1 核心对象

- **推进**：主对象。有目标 / 内容、上下文列表、产物列表、子任务。生命周期：创建 → 移入「我的推进」（同时**默建定时任务**）→ 反复开门 / 关门 → 移入归档区。
- **门**：推进上的待办面。三种：**决策门**（AI 扫到新东西，给决策建议）、**验收门**（AI 判定目标是否达成，图上标注"特殊的决策门"）、**任务门**（AI 推荐开会 / 拆子任务派人）。门由「接下来做什么」打开，可定时自动触发也可手动触发；门有明确的关闭条件。
- **上下文 / 产物**：推进的两类附着物。上下文 = 输入侧（聊天、纪要、文件），产物 = 输出侧（灵基任务的结果、会议纪要、子推进回传）。
- **灵基任务**：Agent 执行面。"让灵基做"把推进的上下文 / 产物带入，多轮修改后验收，产物再关联回推进。
- **子推进**：任务门拆出的子任务被认领后，在接活儿方那里成为一个完整的推进，拥有全部三门。递归。

### 1.2 图例（画板右下角原文）

## 3. 逐节点定义

每个节点按同一模板：原图位置 → 触发 → 输入 → 输出 → 人工干预与输入 → 终态 → 评测要点 → 风险 → 待确认。

### N-01 AI 发现 · 任务拆解推荐

- **原图**：进入 AI 推荐主页 → 浏览新手引导 / 数据授权 → 点击启动按钮 → 跳转 AI 发现，浏览拆解的任务 → 创建推进 / 忽略
- **触发**：自动。数据授权后由后台扫描生成；"点击启动"只是进入查看。
- **输入**：用户授权的数据源全集（图上只写"数据授权"，具体是 IM 会话、会议纪要、文件、日程中的哪些，需确认）；用户身份与组织关系。
- **输出**：若干"拆解的任务"卡片。每张卡应能一键成为推进，因此隐含字段至少有：标题、目标、来源上下文引用、建议的第一步。
- **人工干预**：逐卡「创建推进」或「忽略」。忽略不是删除，卡片掉入归档区。
- **终态**：创建 → 移入我的推进（N-02 的定时任务同时建立）；忽略 → 归档区。
- **评测要点**：与人工标注"值得推进的事"对比的召回 / 精确；卡片间去重；来源可追溯（每张卡能指回原始消息 / 文件）；冷启动无数据时不硬凑；线上采纳率与忽略率。
- **风险**：中。只读无副作用，但它是首屏，决定激活。

### N-02 接下来做什么 · 门路由

- **原图**：「接下来做什么（可手动触发）」→ 决策门 | 验收门 | 任务门。接活儿方的子推进侧是同一个节点（「决策门 | 验收门 | 任务门」绿色循环）。
- **触发**：双触发。默建的定时任务周期性自动跑；用户也可手动点。
- **输入**：推进的全量当前态：目标 / 内容、上下文列表、产物列表、子任务及认领状态、历史开门关门记录、时间信号（距上次开门、是否临近截止）。
- **输出**：开哪些门（0 到 3 扇）以及每扇门的载荷，分别交给 N-03、N-06、N-07 / N-08。"不开门"是合法输出。
- **人工干预**：无直接干预。门是粉色被动选项，用户只能决定"现在评估一次"，不能决定开哪扇。
- **终态**：不落终态，是循环的起点。
- **评测要点**：多标签路由准确率（对比人工判断"此刻该开哪扇门"）；空开门率（打扰）；漏开门率（该验收没提、该拆任务没拆）；定时触发的幂等性（同一状态反复评估不应反复开同一扇门）；触发频率与推进活跃度的匹配。
- **风险**：高。这是打扰的总闸。
- **待确认**：是一次调用统一路由，还是三扇门各自独立评估后合并。这决定评测粒度和数据集切法。

### N-03 决策门 · 上下文 / 产物扫描

- **原图**：决策门 → 「查看 AI 扫到的上下文 / 产物」→ 采纳 / 忽略。忽略 → 「无需处理，门关闭」。
- **触发**：自动，随决策门打开。
- **输入**：推进 + 可达数据源（IM、会议、文件、子推进回传的新上下文 / 产物）+ 已关联上下文作为去重基线。
- **输出**：新扫到的候选列表。每条含：来源、摘要、与本推进的关联理由。
- **人工干预**：采纳 / 忽略。图上是整体二选一，是否支持逐条勾选需确认。
- **终态**：忽略 → 门关闭；采纳 → 进 N-04。
- **评测要点**：相关性精确 / 召回；新颖性（不重复推已关联的东西）；来源正确；**权限边界**（只扫用户本人可见的会话与文件）。
- **风险**：高。隐私与权限。

### N-04 决策门 · 决策建议生成

- **原图**：采纳 → 「查看 AI 给出的决策建议」→ 确认 | 补充
- **触发**：自动，用户采纳上下文后。
- **输入**：推进目标 / 内容 + 刚采纳的上下文 / 产物。
- **输出**：一条或多条决策建议（做什么、改什么、谁来做），每条带依据引用。
- **人工干预**：确认，或**补充**。补充是自由文本：加条件、给偏好、纠正事实。
- **终态**：进 N-05。
- **评测要点**：建议可执行性；依据忠实度（引用的上下文真实存在且支持结论，不编造）；与目标一致性；人工补充是否被下游 N-05 吸收。
- **风险**：中。

### N-05 推进目标 / 内容刷新（两个触发口）

- **原图**：① 决策门确认 | 补充 → 「AI 刷新推进的目标 / 内容」→ 多轮修改 | 确认 → 「确认后门关闭」；② 验收门不通过 → 「输入理由，AI 刷新推进的目标 / 内容」→ 多轮修改 | 确认 → 同一个「确认后门关闭」。
- **触发**：自动，承接人工的确认 / 补充或不通过理由。
- **输入**：旧版目标 / 内容 + 决策建议 + 人工补充文本（口 ①），或 + 不通过理由（口 ②）+ 相关上下文。
- **输出**：新版目标 / 内容。本质是 diff，未涉及的部分应原样保留。
- **人工干预**：多轮修改（自然语言改稿意见）| 确认。
- **终态**：确认后门关闭。
- **评测要点**：编辑局部性（只改该改的段落）；理由 / 补充吸收率；多轮收敛轮数；不丢原目标（回归检查）；版本可回溯。两个口要分别建集，口 ② 的输入是否定性反馈，更难。
- **风险**：中。改的是推进的"宪法"，但有人工确认兜底。

### N-06 验收门 · 达成判定 + 证据展示

- **原图**：验收门（特殊的决策门）→ 「AI 判定达成，展示各项目标及证据」→ 通过 → 推进移入归档区；不通过 → 输入理由 → N-05 口 ②。
- **触发**：自动，门路由认为可能达成时。
- **输入**：推进目标清单 + 产物列表 + 上下文 + 子任务完成状态。
- **输出**：逐目标的达成 / 未达成 + 每条的证据引用 + 总体判定。
- **人工干预**：通过 / 不通过。不通过必须**输入理由**。
- **终态**：通过 → 归档；不通过 → 刷新目标后门关闭（推进继续）。
- **评测要点**：逐目标判定准确率（对比人工标注）；证据忠实度（引用真实存在且确实支持）；**过早宣告达成率**（假阳性，单列指标）；遗漏目标；线上不通过率与理由聚类。
- **风险**：高。终态判断。
- **待确认**："特殊的决策门"是否复用 N-03 的扫描能力来找证据。

### N-07 任务门 · 会议推荐 + 字段自动填充

- **原图**：任务门 → 「推荐预定会议、关联上下文 / 产物」→ 确认 → 「生成会议，发出会邀通知，门自动隐藏」→ 「开完会，纪要拉入推进产物列表，门关闭」；修改 → 「跳转会议页面 & 自动填好字段内容，用户修改后确认」→ 同上；忽略 → 「无需处理，门关闭」。
- **触发**：自动。
- **输入**：推进状态 + 参与人 / 组织关系 + 日历可用性（隐含）+ 待关联的上下文 / 产物。
- **输出**：会议草案，结构化到会议表单字段：主题、参会人、时间、议程 / 背景、关联的上下文 / 产物。
- **人工干预**：确认；修改（表单级编辑后确认）；忽略。
- **副作用**：确认后发出会邀通知，参会人可见。门先"自动隐藏"（等会开完），会后才"关闭"。
- **终态**：会后纪要自动进产物列表（N-16）→ 门关闭。
- **评测要点**：该不该开会（必要性判断，对比人工）；参会人准确率；各字段填充正确率；线上修改率与修改了哪些字段；会邀发出前确认步骤必达（不可跳过）。
- **风险**：高。对外发通知。

### N-08 任务门 · 子任务拆解 + 指派推送

- **原图**：任务门 → 「拆解子任务，推送给他人 / 自己」→ 对方认领 / 对方忽略；同时连到接活儿泳道的「接到 AI 推荐通知」。认领 → 「收到认领通知」→ 「收到产物通知（子任务卡片位）」→ 审阅产物 → 多轮修改 | 验收 → 子任务完成 → 所有子任务完成，主任务完成 → 推进移入归档区。忽略 → 「收到忽略通知」→ 转派 | 拒绝 | 自己做 | 撤销。「全部认领 / 自己做 / 撤销后，门关闭」。
- **触发**：自动。**图上任务门直接连到推送，中间没有黄色（人工选择）节点。**
- **输入**：推进目标 / 内容 + 上下文 / 产物 + 候选人信息（组织、历史协作、当前负载，均为隐含）。
- **输出**：子任务列表。每条：任务描述、建议执行人（他人或自己）、带入的上下文 / 产物包、接活儿方看到的协作卡片。
- **人工干预**：
  - 派活儿方：事后控制。收到认领 / 忽略通知后可 转派 / 拒绝 / 自己做 / 撤销。
  - 接活儿方：认领 / 忽略，且「动作 & 理由回传给主推进」，理由是自由文本。
- **副作用**：跨人推送任务，最重。
- **终态**：全部认领 / 自己做 / 撤销后门关闭；所有子任务完成后主任务完成 → 归档。
- **评测要点**：拆解完备性与独立性（MECE）；粒度合适度；指派准确率（对比最终实际认领人）；接活儿方忽略率与忽略理由分布；派活儿方撤销率（误推的直接代价）；上下文包充分性（接活儿方能否不追问就开工，可用"认领后首个动作是否是提问"做代理指标）。
- **风险**：最高。
- **待确认**：推送前是否有派活儿方确认。若没有，评测必须精确率优先，并把撤销率设为上线门槛。

### N-09 灵基任务执行（Agent，多轮）

- **原图**：让灵基做 → 「跳转灵基任务，带入上下文 / 产物」→ 多轮修改 | 验收 → N-10。接活儿方侧是「新建灵基任务，带入上下文 / 产物」，同构。
- **触发**：人工。
- **输入**：推进目标 / 内容 + 带入的上下文 / 产物 + 用户在任务对话框里的指令 + 每一轮的修改意见。
- **输出**：产物（文档、方案、数据等），多版本。
- **人工干预**：多轮修改（自然语言）| 验收。
- **终态**：验收 → N-10。
- **评测要点**：产物质量（按产物类型分 rubric）；上下文利用率（是否真的用了带入的东西，可用引用覆盖率量）；多轮修改的指令遵循；收敛轮数；验收率。这是唯一的开放式 Agent 节点，需要用户模拟器做多轮评测。
- **风险**：中。产物在验收前不外泄。

### N-10 灵基主动建议 · 把产物关联回推进

- **原图**：多轮修改 | 验收 → 「灵基主动建议把产物关联回推进」。派活儿侧到此为止；接活儿侧继续 → 「通知主推进有新产物 / 上下文」。
- **触发**：自动，灵基任务验收后。
- **输入**：灵基任务产物 + 用户的推进列表（来源推进应优先）。
- **输出**：建议卡：关联到哪个推进、作为产物还是上下文。
- **人工干预**：采纳 / 忽略，图上未画但必然存在。
- **评测要点**：目标推进命中率；误关联率。
- **风险**：低。

### N-11 @灵基 创建推进

- **原图**：进入某个单聊 / 群聊 或 新建 / 进入某个灵基任务 → 「@灵基 创建推进」→（连线标注：拉取指定范围上下文 / 产物）→ 移入我的推进。
- **触发**：人工，@ 指令。
- **输入**：指定范围的会话消息或灵基任务内容 + @ 后的自然语言指令。
- **输出**：新推进（标题、目标、内容、关联上下文）+ 默建定时任务。
- **人工干预**：选范围、写指令；创建前是否有预览修改，图上未画。
- **评测要点**：从聊天中抽取目标的准确性；范围遵循（不越界拉消息）；群聊多人多话题下的抗噪；与已有推进的重复检测。要按来源分集：单聊 / 群聊 / 灵基任务。
- **风险**：中。群聊数据进入推进，涉及可见域。

### N-12 @灵基 带入 xx 推进

- **原图**：「@灵基 带入 xx 推进」→（拉取指定范围上下文 / 产物）→ 移入我的推进。
- **触发**：人工。
- **输入**：指定范围会话 + 目标推进。
- **输出**：增量上下文 / 产物挂到该推进。是否顺带触发 N-05 刷新目标，图上未画。
- **人工干预**：选范围、选目标推进。
- **评测要点**：目标推进解析（"xx"的消歧，尤其名字相近时）；增量去重；是否应触发目标刷新的判断。
- **风险**：低。

### N-13 @灵基 引用 xx 推进

- **原图**：「@灵基 引用 xx 推进」，无出边，终点在会话里。
- **触发**：人工。
- **输入**：目标推进的当前态。
- **输出**：推进摘要 / 卡片发回会话。
- **人工干预**：选目标推进。
- **评测要点**：摘要忠实度；**脱敏与可见域**（把私有推进引用到群里时，哪些字段可以露出）。
- **风险**：中。信息进群。

### N-14 会议 → 生成推进建议

- **原图**：查看某个会议 / 会议记录 → 点击开始 AI 推进 → 「拉起任务对话框，上下文 / 可修改」→ 「点击发送指令，生成推进建议」→ 「选择想创建的推进任务」→ 移入我的推进。
- **触发**：人工。
- **输入**：会议记录 / 纪要（用户可先编辑再作为上下文）+ 指令。
- **输出**：多个候选推进任务，可多选创建。
- **人工干预**：改上下文、写指令、勾选要建的。
- **评测要点**：从纪要抽取行动项 / 目标的召回与精确；候选间去重；与用户已有推进的重合提示；用户编辑过上下文后是否尊重编辑。
- **风险**：中。

### N-15 L2 灵基主动关联推进 · 提示卡片

- **原图**：注释「L1 手动唤起关联到推进 / L2 灵基主动关联推进，提示卡片」，位于 IM、灵基任务、会议三条入口之间。图上没有独立框，但它是 N-11 到 N-14 的自动版。
- **触发**：自动后台，监听新消息 / 新纪要 / 新灵基任务产物。
- **输入**：新内容流 + 用户的推进列表。
- **输出**：提示卡片："这条内容疑似与推进 X 相关，是否带入"。
- **人工干预**：采纳 / 忽略。
- **评测要点**：精确率优先（每张误卡都是打扰）；召回；延迟；权限（只看用户本人可见的内容）；与 N-03 的关系（同一能力的推式 vs 拉式）。
- **风险**：高。打扰加隐私。

### N-16 会后纪要自动拉入产物

- **原图**：「开完会，纪要拉入推进产物列表，门关闭」。
- **触发**：自动，会议结束事件。
- **输入**：会议与推进的关联关系 + AI 速记生成的纪要。
- **输出**：纪要作为产物挂到推进；门关闭。
- **人工干预**：无。
- **评测要点**：端到端时延与成功率（会议结束 → 产物出现）；纪要本身的质量属于 AI 速记的评测范围，作为上游依赖单独管。
- **风险**：低。

## 5. 横切维度（流水线的坐标轴）

### 5.1 触发方式

| 方式 | 节点 |
|---|---|
| 自动后台 | N-01、N-03、N-04、N-05、N-06、N-07、N-08、N-15、N-16 |
| 人工触发 | N-09、N-11、N-12、N-13、N-14 |
| 双触发 | N-02（定时 + 手动）、N-10（自动出卡，人决定采纳） |

自动节点的评测重心是**精确率与打扰**，人工节点的评测重心是**指令遵循与质量**。

### 5.2 上下文来源类型

授权数据全集（N-01）/ IM 指定范围（N-11、N-12）/ 会议纪要（N-14、N-16）/ 灵基任务内容（N-11 到 N-13 的第二入口）/ 上传文件（I-3）/ 子推进回传（N-03 的一部分）。每种来源的噪声结构不同，数据集要按来源分层。

### 5.3 输出形态

| 形态 | 节点 | 评测方法 |
|---|---|---|
| 候选列表（排序） | N-01、N-03、N-14、N-15 | 精确 / 召回 / 去重 / 来源可追溯 |
| 结构化对象 | N-07（会议表单）、N-08（子任务 + 指派）、N-11（推进） | 字段级准确率 + 整体可用性 |
| 局部改写 | N-05 | diff 局部性 + 反馈吸收 + 回归 |
| 判定 + 证据 | N-06 | 逐项准确率 + 证据忠实度 + 假阳性单列 |
| 路由决策 | N-02 | 多标签分类 + 空开 / 漏开 |
| 开放式产物 | N-09 | 分类型 rubric + 多轮模拟 |
| 摘要 | N-13 | 忠实度 + 脱敏 |

### 5.4 副作用等级

0 只读（N-01、N-02、N-03、N-04、N-09、N-15）→ 1 改自己的推进（N-05、N-06、N-10、N-11、N-12、N-14、N-16）→ 2 对外通知（N-07、N-13）→ 3 跨人推送（N-08）。等级越高，上线门槛越应偏向精确率，并要求确认步骤不可跳过。

### 5.5 循环与递归

- 多轮循环：N-05、N-09、I-2。要评收敛轮数和每轮的指令遵循，不能只评首轮。
- 递归：子推进拥有全部三门，即 N-02 到 N-10 在接活儿方那里再跑一遍。要评"深度 2 时上下文是否正确隔离"（子推进的门不该扫到主推进无关的东西，主推进的验收也不该把子推进的产物当成自己的）。

### 5.6 门关闭正确性

每扇门都有明确终态，是可以精确验收的规则层：

| 门 | 关闭条件（原图） |
|---|---|
| 决策门 | 忽略 → 无需处理，门关闭；采纳 → 刷新 → 确认后门关闭 |
| 验收门 | 通过 → 推进归档；不通过 → 理由 → 刷新 → 确认后门关闭 |
| 任务门（会议） | 忽略 → 门关闭；确认 → 发会邀 → 门自动隐藏 → 开完会纪要入产物 → 门关闭 |
| 任务门（子任务） | 全部认领 / 自己做 / 撤销后门关闭；所有子任务完成 → 主任务完成 → 归档 |

## 7. 评测流水线分层建议

### L0 离线单节点

每个节点一个 golden set + 一套判分。优先级按风险：N-08 → N-02 → N-06 → N-07 → N-03 / N-15 → N-05 → N-01 / N-14 / N-11 → 其余。

- 候选列表类：人工标注相关性，算 P / R / nDCG，另加去重率与来源可追溯率。
- 结构化对象类：字段级对比 + 整体可用性 rubric。N-08 的指派准确率以真实认领人为标签。
- 判定类（N-06）：逐目标标注，假阳性单独设阈值。证据忠实度用"引用是否存在 + 是否支持"两步判。
- 改写类（N-05）：构造（旧稿，反馈，期望改动范围）三元组，评局部性与吸收率。
- 路由类（N-02）：构造推进状态快照 → 应开门集合，评多标签 F1，空开率单列。

### L1 链路级

三条门链各自端到端：

- 决策门链：N-03 → N-04 → N-05 → 门关闭
- 验收门链：N-06 → （不通过）N-05 → 门关闭 / （通过）归档
- 任务门链：N-07 → 会邀 → N-16 → 门关闭；N-08 → 认领 → 子推进 → 回传 → 主任务完成

链路级看的是上游错误在下游的放大，以及门关闭的正确性。

### L2 多轮与 Agent 仿真

N-05、N-09 用用户模拟器给修改意见，评收敛轮数与每轮遵循。N-08 → 接活儿方 → 子推进 → 回传 这一条用双角色仿真，重点评递归下的上下文隔离。

### L3 线上指标

按第 6 节的隐式标签直接采：采纳率 / 忽略率（N-01、N-03、N-10、N-15）、空开门率（N-02）、不通过率与理由聚类（N-06）、修改率与字段分布（N-07）、忽略率 / 撤销率 / 转派率（N-08）、验收轮数（N-09）。这些指标反过来给 L0 补标注。
