## 0. 一句话与总判据

**只存发生过的话和事，其余全部重算。**

人说的话、agent 做的事、世界发生的事，写进一条只追加、带签名、带出处、成链的日志。钱账、承诺账、判断账、责任图、判断队列，以及旧系统看见的样子，都是这条日志的纯函数。人的回程律不是一份月报，而是写入时的一条外键。

**总判据**：一年后，一个当时不在场的人，不问任何人，能不能从日志复原这几件事：谁、凭什么信息、做了什么决定、结果如何、钱花在哪。

## 1. 第一性：一条账值什么

账的价值是**当证据用**：用来对质一个更愿意忘掉的人，读的人当时不在场。所以每条记录必须有三样东西：

| 要素 | 含义 | 缺了会怎样 |
|---|---|---|
| 谁说的 | 签名，能对应到一个身份 | 「我没答应过」无法反驳 |
| 凭什么 | 出处，指回原始的消息、文档、调用，并带内容摘要 | 记录与事实对不上时，不知道该信哪个 |
| 什么时候知道的 | 记录时刻和发生时刻分开 | 无法公平评价当时的判断 |

再加一条：**只追加**。改错不是修改，而是追加一行冲销，就像会计用了五百年的红字。

**旧 ERP 的病不在表结构，在入口。** 记录是事后由人补录的描述，是第二份工作，而第二份工作一定滞后、一定失真。沙盘里旧系统那一侧的「要等」和「没记下」，都是这么来的。

**后 AGI 的反转。** 生成信息的成本趋近于零，稀缺的东西变成了**有人签了字**。所以设计重心要从「录入」转到「签收」：模型可以起草一切，只有人的签收才产生事实。

由此推出三条：

1. **记账不是第二份工作。** 入口必须在行动路径上（会话和 agent 守门人），不在路径上的入口一定滞后。
2. **能重算的不存。** 状态、余额、队列、比值都是投影；只存重新得不到的东西：话、动作、观测。
3. **改错是追加。** 改错本身也是证据。

## 2. 原子：日志里只有四种行

| 行 | 谁写 | 必带 | 例子 |
|---|---|---|---|
| **人说的** `said` | 人 | 签名（云之家身份 + 卡片或消息 id + 摘要） | 受领一条承诺、拍板、验收、签收移交、签发租约、签发规则 |
| **agent 做的** `did` | agent | 租约号；租约链在写入时解析到一个人 | 编码 agent 合入代码、实验 agent 出读数、采购 agent 下单、守门人拦下一次越权 |
| **世界的** `seen` / `peer` | 外部系统、外部的人、对方账本 | 出处（系统 + 单据号 + 摘要）；对方账本要对方签名 | 客户的微信、供应商到料回执、银行流水、模型账单 |
| **规则推出** `ruled` | 系统 | 规则版本号 + `causedBy`（由哪几行引出） | 展开判断需求、排进判断带宽、发出改期提议、到检验点结账、月结 |

`ruled` 其实是 `did` 的特例：规则版本就是系统的租约，签发这版规则的人（记在法账里）就是回程终点。所以回程律对系统本身同样成立。

### 2.1 什么写入，什么不写

一件事要写进日志，必须满足以下三条之一：

- (a) 有人说了；
- (b) agent 或系统**对外界或对人**做了动作，比如下单、发卡、通知、合并、排进某人的日程；
- (c) 外界告诉了我们。

其余一律是投影。沙盘里的对照：

| 沙盘里的事 | 写不写 | 理由 |
|---|---|---|
| 「J1 已判」 | 不写 | 由 `judgment/decided` 算出 |
| 「P2 悬空：到 3,000 / 4,500」 | 不写 | 由回执数量对承诺数量算出 |
| 「J3 排今天 16:00」 | 写 | 系统把半小时放进了老陈的日程，并给他发了卡 |
| 「PB 改期提议已发 B 客户，等签收」 | 写 | 系统对外发出了一个提议 |
| 「J2 → 推翻」 | 写 | 这是一个裁决：会通知当事人，可以被申诉 |

## 3. 记录怎么产生：四个入口

### 3.1 agent 行动：守门人就是记账员

agent 碰外部世界的每一次调用，都要过守门人（`next/tools/src/guard.ts`）。检查顺序是：逃逸封禁 → 撤销实时读 → 合同硬项 → 身份复验 → **租约命中** → 写级 → 问人。

守门人的每个出口都必须留一行：

| 出口 | 写下 |
|---|---|
| 租约命中，放行 | `did`，带租约号 |
| 由触发它的那条消息授权，放行 | `did`，`authority` 指向那条 `said` |
| 超出租约或不可逆，转人 | `did: guard/held`，加一条 `ruled: judgment/demanded` |
| 拒绝 | `did: guard/denied`，带理由 |

agent 通往外部世界没有别的路，所以 agent 这一侧的账**由构造保证完整**，不靠纪律。

**先记后做（写前日志）。** 如果动作已经发生、日志却没写上，就出现了一个无人担责的动作。所以顺序必须是：

1. 写 `did/intent`，带幂等键；
2. 执行外部动作；
3. 写 `did/result`，带对方回执号。

进程崩溃后，重放所有「有 intent 没 result」的行，去对方系统按幂等键对账，再补写 result 或冲销。这就是 outbox 模式，用来保证不存在没记账的动作。

### 3.2 人的承诺：起草—受领

群里有人说「周五前给你」：

1. agent 起草一条 `commitment/proposed`。这是 `did`，**还不是承诺**。
2. 承诺人点受领，写下 `commitment/opened`（`said`，带承诺人签名）；或者婉拒；或者超时，留在「待受领」投影里。

**铁律：没受领的不进承诺账。** 承诺账一旦混进一条没人认过的承诺，等到第一次有人说「我从没答应过」，整本账的信用就没了。

跨组织时，对方的受领由对方账本签名（`peer`），见 §11。

### 3.3 判断：发现—拍板—结账

一条判断有三个时刻，各写一行：

1. **出生** `ruled: judgment/demanded`。有三种触发：
   - 守门人拦下超出租约或不可逆的动作；
   - 一个外部事实和某条承诺矛盾，比如到料 3,000 颗、承诺 4,500 颗；
   - 会话里出现了相互竞争的方案，比如拍照记账和模板。

   **归谁不由模型猜。** 模型只做分类（「这是选做什么」「这是金额代码怎么审」）；归属由图上的职责边查出来。职责本身也是一条签过字的承诺，例如 P0「老秦 → 公司：研发规范」。先后关系存成 `blockedBy` 边。排期对着**被测量的判断带宽**：私账层已经在测每个人的停留与等待中位数（`next/pledger/src/judg.ts`）。

2. **拍板** `said: judgment/decided`。带上：
   - 选项；
   - 押了什么、检验信号、检验点、代价；
   - **当时所见**：把当事人眼前的证据冻结成一份内容寻址快照，日志里只存摘要。

   不存当时所见，事后评价判断就只能靠后见之明，对人不公平。

3. **结账** `ruled: judgment/settled`。检验点到期时，系统读信号，给出「没被推翻」或「推翻」。信号模糊时由人结账（`said`）。当事人可以申诉（`said: judgment/contested`），申诉是追加的一行，不改原行。

### 3.4 钱：引用与归属

银行流水、发票、工资、云账单留在原系统，那里本来就有法律效力。新账只存两样：

- **引用**：`seen: money/referenced {system, docId, amount, currency, digest}`。
- **归属**：`money/attributed {ref → commitment | judgment | bet}`。由规则推出，或由人指定。

没有归属的钱进入「未归属」投影，是可见的一行。月结时必须清零，或者由人签字留存。

**agent 的算力成本是唯一已经握在我们手里的钱**：模型账单按租约记，而租约知道 agent 当时在为哪条承诺干活，所以成本能自动归到承诺和赌注上。「每一个点花了多少」因此成了一个查询，不再是月底的分摊。

## 4. 信封

现有信封见 `next/graph/src/types.ts` 的 `GraphEvent`（`v / sv / seq / time / type / data / actor`，外加 `audience / idemKey` 标注）。账本级信封在它上面加七个字段：

```ts
interface LedgerEvent<D = JsonValue> {
  readonly v: 2                      // 信封版本（现为 1）
  readonly sv: number                // 族 schema 版本
  readonly seq: number               // 分区内单调递增，无空洞
  readonly recordedAt: number        // 系统得知的时刻（现 `time`）
  readonly effectiveAt?: number      // 事情发生的时刻；缺省 = recordedAt          ← 新
  readonly type: string              // family/verb
  readonly atom: 'said' | 'did' | 'seen' | 'peer' | 'ruled'                         ← 新
  readonly actor: {
    readonly kind: 'person' | 'agent' | 'system' | 'world' | 'peer'
    readonly openId?: string         // person
    readonly agentId?: string        // agent
    readonly ledgerId?: string       // peer：对方账本
  }
  readonly lease?: string            // did 必填；ruled 填规则版本 id               ← 新
  readonly authority?: number        // 由哪一行 said 授权（守门人放行时）           ← 新
  readonly sig?: { via: 'card' | 'msg' | 'peer'; ref: string; digest: string }  // said/peer 必填 ← 新
  readonly anchor?: { system: string; ref: string; digest: string }            // seen 必填      ← 新
  readonly causedBy: readonly (number | string)[]   // ruled 必非空；字符串用于「月末时钟」「检验点到期」 ← 新
  readonly audience: readonly string[]  // 继承自产生它的那句话
  readonly idemKey: string
  readonly data: D
  readonly prev: string              // 上一行的 hash
  readonly hash: string              // H(prev ‖ 本行规范化序列化，不含 hash)
}
```

- **规范化序列化**：键排序、数字定点、不带空白。否则哈希验不过跨实现。
- **大字段不进日志**：agent 的完整推理过程、当时所见的证据快照、附件，都放内容寻址存储，日志只存摘要。会话日志存回合级事实、图存产品级事实，这个分工不变（`next/README.md` 表）。

## 5. 恒等式 = 写入约束

回程律落到存储层就是一组外键。写入路径上用确定性代码校验，**不调用模型**。

| # | 约束 | 违反时 |
|---|---|---|
| I1 | `did` 必须引用一张在 `recordedAt` 有效、范围覆盖本动作的租约；租约必须由一行 `said: lease/granted` 产生 → 链的终点是人 | 拒写，动作不执行 |
| I2 | `ruled` 必须引用一个已签发的规则版本，`causedBy` 非空；规则版本由 `said` 签发（法账） | 拒写 |
| I3 | 每条进行中的承诺，任一 `seq` 恰有一个持有人。移交 = 新边出生 + 接手人签收，之后旧边转入 `transferred`；签收之前持有人不变 | 拒写第二个持有人 |
| I4 | 每条判断需求必有归属人；归属人缺席时，必须生成移交需求，不得进入「无人」状态 | 标记并转给职责链上的下一位 |
| I5 | `said` 必须有签名，签名者 = `actor`；模型工具面上**没有** `said` 的写口 | 拒写 |
| I6 | `seen` 必须有出处摘要；`peer` 必须有对方账本签名 | 拒写 |
| I7 | 钱的引用要么有归属边，要么进入「未归属」投影 | 标记；月结闸门 |
| I8 | 只追加：存储层没有 UPDATE/DELETE；更正 = 冲销行，引用原 `seq` | 权限层面拒绝 |
| I9 | `judgment/decided` 必须带当时所见的摘要；结账只对照当时所见与检验点 | 拒写 |

I1、I2、I5、I6、I8、I9 关乎「这一行能不能成立」，在写入时拒绝。I3、I4、I7 关乎「时间流逝后出现的空洞」，由反应器标记并路由。

**为什么不能分三个库存。** 恒等式要靠构造成立，不能靠对账成立。复式记账的发明就在于一笔交易同时写两边，不平就立刻看得见。三本账放三个库，就要月底对账，而对账正是旧 ERP 的病。

## 6. 投影

| 投影 | 折叠自 | 回答 |
|---|---|---|
| 承诺账 | `commitment/*` + 回执 | 谁欠谁什么，到哪一步了 |
| 判断账 | `judgment/*` | 谁押了什么，押对没有 |
| 钱账 | `money/*` | 钱花在哪条承诺、哪一注上 |
| 责任图 | 三本账 + 租约 | 出了事，此刻找谁 |
| 判断队列（计划对象） | `judgment/demanded/scheduled/decided` + 带宽测量 | 现在有什么在等人拍板，排在谁那里 |
| 判断档案 | 本人的 `decided` + `settled` | 我哪类判断准（私账，只有本人可见） |
| 旧系统视图 | 全部，按旧规则有损投影 | 旧 ERP 此刻会怎么答。沙盘的 `oldOf()` 就是这个函数，它证明旧 ERP 是同一条日志的有损投影 |

**规矩**：

- **投影 = f(日志前缀, 折叠版本, 规则版本)**，必须是纯函数。快照只是缓存，要记自己由哪一版折叠逻辑算出（`GRAPH_FOLD_VERSION`）。仓库付过一次学费：快照没记版本，16 个对象和全量重放对不上。
- **反应器替代 MRP 夜批。** 每追加一行，就跑一遍规则，把产生的新行（`ruled`，带 `causedBy`）写进同一条追加链。旧 MRP 每晚把订单展开成物料需求；这里每来一个事件，就把它展开成判断需求。
- **没有排名投影。** 不存在任何返回「人名 × 分数」的投影（§9）。

## 7. 时间

- **双时间**：`recordedAt` 是系统得知的时刻，`effectiveAt` 是事情发生的时刻。二者之差按类型统计，就是账的健康度：滞后越大，入口越不在路径上。
- **回看**：「9 月 1 日那天我们知道什么」= 对 `recordedAt ≤ 9/1` 的前缀重新折叠。沙盘里的 `viewAt(k)` 就是这个操作。旧系统只有一个时间，而且会覆盖，所以永远答不了。
- **法账影子重放**：新规则版本先在全部历史上重放，和旧版本的投影做差，对表通过后才签发。改规则因此变成一个可证伪的提案，不再是一次拍脑袋的变更。这是组织级 RSI（法账：提案 → 签发 → 影子 → 对表）的工程底座。

## 8. 更正、申诉、遗忘

- **冲销**：`*/reversed {of: seq, reason}`，由更正者签名。冲销本身也是证据：谁、何时、为何改了什么。现有内核已经是带墓碑的折叠（`next/graph/src/store.ts`）。
- **申诉**：`judgment/contested`，等于再开一条判断需求，归申诉的裁决人。
- **遗忘与只追加的冲突**：个人信息删除权靠**加密粉碎**解决。敏感字段用每个主体一把密钥加密，删除 = 销毁密钥。哈希链里存的是密文摘要，所以链仍然完整，内容却已不可读。场所合同 `memoryPolicy: 'never'` 的场所，只记结构（谁对谁、何时、哪一类），不记内容。

## 9. 可见域：这是能记下来的前提，不是合规项

承诺和判断的账，等于每个人的诺言和失误的全记录。一旦它变成监控工具，人们就会把话挪到私聊里说，入口一枯，账就空了。所以：

- 一条记录的**听众继承自产生它的那句话**：你在场听到的，你才能看（`audience`，设计 v4.4）。
- **每次读取都过读取域钩子**（`GraphReadHook`），派生导出也不例外。观看者由编排层绑定，永远不是模型可传的参数。
- **判断档案归本人**（私账层，pgraph 第二存储域：观看者单一、审计不挂源、本人可取走销毁）。组织只看聚合。
- **不给人打分**：任何投影的返回类型都不出现「人名 × 分数」；比值由人自己得出。

## 10. 物理存储

| 层级 | 形态 | 适用 |
|---|---|---|
| L0（现在） | 每账户分区一份 `graph.jsonl` + `snapshot.json`，单进程单写者（`next/graph/src/log.ts`） | 单团队试运行 |
| L1 | Postgres 一张事件表，按租户列表分区、按月子分区；每分区一个写序列器 | 单企业 |
| L2 | 每个法人主体一个分区；跨主体的边 = 双边事件；清算服务（§11） | 集团、跨组织 |

L1 的表结构：

```sql
create table ledger_event (
  tenant_id     uuid        not null,
  seq           bigint      not null,
  recorded_at   timestamptz not null,
  effective_at  timestamptz,
  type          text        not null,
  atom          text        not null check (atom in ('said','did','seen','peer','ruled')),
  actor         jsonb       not null,
  lease_id      text,
  authority     bigint,
  sig           jsonb,
  anchor        jsonb,
  caused_by     jsonb       not null default '[]',
  audience      text[]      not null,
  idem_key      text        not null,
  data          jsonb       not null,       -- 敏感字段为主体密钥下的密文
  prev_hash     bytea       not null,
  hash          bytea       not null,
  primary key (tenant_id, seq),
  unique (tenant_id, idem_key),
  check (atom <> 'did'  or lease_id is not null),
  check (atom <> 'said' or sig is not null),
  check (atom <> 'seen' or anchor is not null),
  check (atom <> 'ruled' or jsonb_array_length(caused_by) > 0)
) partition by list (tenant_id);

revoke update, delete, truncate on ledger_event from app_writer;   -- I8 由权限保证，不靠代码自觉
```

- **写序列器**：哈希链要求每个分区内全序。每个租户一个序列器（advisory lock 或单分区单消费者队列）；外键约束（I1–I9）在序列器里同步校验，通过才落盘。
- **投影表**：由投影工作者拥有，可以随时删掉重建；检查点表记 `(projector, foldVersion, ruleVersion, upToSeq)`。
- **大对象**：内容寻址存储（对象存储），键 = 摘要。
- **规模粗算**：一千人的企业，每天约五万次 agent 动作、两千条承诺事件、几百个判断，每行约 1 KB，一年二三十 GB。**字节不值钱**，值钱的是 §3 的入口、§5 的约束和 §9 的可见域。

**刻意不选的**：

- **区块链**：信任模型是「组织 + 中立托管方」，用哈希链加外部存证就能做到防篡改，不必付共识的代价。
- **图数据库**：责任图的规模是人数乘以承诺数，递归 CTE 就够；需要时再加一个图投影。
- **专用事件库产品**：任何「分区内有序 + 只追加」的存储都行。选无聊的技术，把复杂度留给约束本身。

## 11. 防篡改、存证与清算所

- **哈希链**：每行带上一行的哈希（沙盘日志原文里每行的 `⛓`）。改动任何一行，后面每一行都对不上。
- **每日根存证**：每个分区每天的链尾哈希（或当日 Merkle 根）交给外部：客户、审计方或可信时间戳服务。之后想私下重写历史，就必须同时篡改外部那份。
- **部分验证**：读取域会过滤，读者只看得到一部分行，所以按日构建 Merkle 树，给可见的每一行附上包含证明。这样读者不必看见全部，也能验证自己看到的那部分没被改过。
- **跨组织承诺边**：恒测和供应商之间那条「4,500 颗 MCU，9 月 28 日」，是两本账里的同一个条目（沙盘里的 `peer/commitment`）。协议分三步：一方提出 → 另一方对方账本签名 → 交付、验收、核销逐步双签。成对的事件由中立方保管，争议对着它解决。
- **这就是清算所**。按结算事件收费，指的就是这一层：一次「交付—验收—核销」完整闭合。卖点不在存储，而在证据效力和双边网络。

## 13. 分期落地（每期一扇证据门）

| 期 | 内容 | 证据门（dogfood 指标） |
|---|---|---|
| E0 | 信封加 `atom / lease / authority / causedBy`；守门人每个出口留一行（命中、消息授权、拦下、拒绝）；I1/I5/I8 写入校验 | 一周内 agent 写操作 100% 能回程到人；`guard/held` 每条都对应一个判断需求 |
| E1 | 判断需求成为组织级对象：出生（三种触发）→ 排期（带宽）→ 拍板（冻结当时所见）→ 结账；接通 pledger 的押 | 「现在有什么在等人拍板」能在 1 秒内答出，且和人的自报一致 |
| E2 | 钱：模型账单按租约归属到承诺和赌注；「未归属」投影 + 月结闸门 | 「每个点 / 每张单的 agent 成本」不再需要手工分摊 |
| E3 | 双时间、哈希链、每日根存证、加密粉碎 | 任意一天可以复算出同一个根；滞后统计上线 |
| E4 | Postgres 分区 + 序列器；投影工作者 | 触发条件：单分区写入或回放时间到达阈值。不提前做 |
| E5 | 跨组织承诺边与清算服务 | 第一对真实的双签「交付—验收—核销」 |

比例尺律照样适用：每期先写删了什么，再写加了什么；新层在拿到使用证据之前，规格不超过脊柱级。

## 14. 断言（合并门槛）

1. 没有任何代码路径能在不写 `did` 行的情况下执行外部写操作（对守门人每个出口做测试）。
2. `did` 行的租约链在写入时必须解析到一个 `person`；解析失败则拒写，并且外部动作不发生。
3. 模型可调用的工具面上，不存在写 `said` 的接口。
4. 删除全部投影表和快照后，从日志全量重放，投影逐字节一致。
5. 任意前缀 k 的回看，等于只用前 k 行折叠的结果。
6. 改动日志任意一行，哈希校验在该行及其后全部失败。
7. 任何投影的返回类型都不含「人名 × 分数」。
8. 状态类字段（悬空、已判、核销……）在日志里出现即测试失败：它们只能出现在投影里。
9. `judgment/decided` 行必须带当时所见的摘要，且该摘要指向的快照可以取回。
10. 每一笔进入钱账的引用，要么有归属边，要么出现在「未归属」投影里。

## 15. 不做什么

- **不做第二个总账。** GL 留在原系统，新账只引用和归属。
- **不存状态。** 状态是投影。
- **不让模型写事实。** 模型只能起草（`did`），事实由人签（`said`）。
- **不在写入路径上调用模型。** 约束校验是确定性代码。
- **不给人打分。** 判断档案归本人。
- **不上区块链，不提前上图数据库**，不为假想的规模提前分布式化。
