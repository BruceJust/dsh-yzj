## v4.9/v4.10 目标执行动线 + 磨目标与完成度评估（2026-08-20 下午）

设计侧新增决策 #41（v4.9 目标执行动线）与 #42（v4.10 磨目标与完成度评估），技术侧 §5.3 / §7.4 / §7.6 同步。本段是按它们做的完整开发。

### 新增一个 cordis 插件：`obj-goal`

和 `obj-commitment` 分开，**恰恰是为了证明目标不是新对象**：这个插件里所有写入都是普通的 `commitment/*` 事件。它加的只有三件人必须出现的事（提案、裁决、验收），以及一个不许静默的机械后果（代发登记话语）。

新族三个，全部零新节点类型意义上的"附属"：

| 族 | 干什么 | 为什么不是承诺的字段 |
| --- | --- | --- |
| `proposal` | 立目标提案 / 拆解提案，逐条裁决 | 提案在被确认前**不该在图上成为承诺**——它是等待签发的稿子 |
| `assessment` | 差距简报 | 它是**材料**，生命周期与被评估的目标正交（一个目标可以被评估很多次） |
| `goal-context` | 一个话题正为哪个目标干活 | 挂接引用是**语境**的属性，不是某一条承诺的属性 |

### 入口 A① 传送门：板上不做分配表单

目标行两个 CTA：**委派 ↗** 与 **评估**。两个都只问一件事——**在哪个会话里说**——然后跳进去。

- **场所人选不推导**：选择器列的是话题（承诺是在话题里呼吸的：登记卡落在那里、回执在那里读、板上「打开」跳回那里）。一个还没有话题的群会**带理由**显示，而不是从列表里消失——不说原因的空列表和坏掉的列表长得一样。
- 跳过去之后 composer 带 **目标 chip**，锚定条照常显示落点；语态预置为「公」（听不见的委派不算委派），但**可见可改，且什么都不会自动发出去**。
- **句子由人说**。chip 在的时候，如果句子里没有触发词，chip 下面会多一行：「句子里带上 @next，这次委派才会被登记成可跟踪的承诺」——**提示，不是代写**。改写别人要发出去的话是越权。

### 语境装载：说出口才算数

`goal-context/armed` 在**发送成功之后**才写，不在跳进来的时候写。跳进一个会话看了一眼就关掉，图上不该留下「这个房间在为某目标干活」这种断言。

chip 因此有两态，画法不同（虚线/实线），因为它们是两个不同的事实：

- **待装载**（虚线，「带着目标来的」）：传送门递过来的，还没成为事实；
- **已装载**（实线，「本话题的目标」）：**从图上读回来的**，此后这个话题里登记的每条承诺都继承它。

第二态必须从图上读，否则刷新一次、离开再回来 chip 就消失，而下一次登记照样继承——一个会对挂接撒谎的 chip 比没有 chip 更坏。

`commitment_register` 的语境继承判定序随之改成：**装载的引用 > 话题内单一目标启发式**。后者原本是前者的替身。

### 入口 A② 拆解提案：确认即签发，落库即代发

- 每条**单独**裁决：确认 / 驳回 / **挂起**（「不是现在」和「不」是两个事实）。桌面上是逐条按钮，云之家文本通道走「确认 1,3」——**同一套 action id，同一个仲裁者**。
- **不弹第二张确认卡**。一次主权时刻一次确认；代发是它的机械后果，不是另一件要批的事。
- **落库即代发**：确认一条 → 铸出承诺 → 以裁决人名义把登记卡投到执行者所在的会话，**听众集合由这条消息确立**。所以 `mint()` 在有待发场所时**不预置 audience**——那会变成「看过提案的人都知道这条承诺」，而在代发失败时这句话是假的。
- **失败必须响**：投不出去 → `notified: 'failed'` → 板上红字「未通知 · 请亲发」。幽灵承诺禁令的失败模式恰恰是"落库了但没呼吸"，静默失败等于把同一个鬼放到下一层。
- **出口**：「收起」把半裁决的提案退休掉。只挂起不收尾的卡就是这个族要防的僵尸。

### 目标三看

- **状态**：子承诺计数（已有）。
- **产出**：目标 → 承诺 → 工件**两跳派生归集**，折叠。一次扫完 lineage 后按话题分桶，不是每个目标扫一遍全表——这个视图每 6 秒刷新一次。
- **过程**：**一跳可达，绝不搬运**。行上一个链接跳回会话，外加**一行**过程摘要（最近回执）。不做摘要聚合——那就是 §7.4 禁的第二时间线。

**顺带修掉一个真实缺陷**：板上的行原先只读 `executor.topicKey`（只有 agent 执行者才有），所以**别人欠的那些承诺根本没有「打开」按钮**——恰恰是承诺板存在的理由那一类。改成 `state.topicKey ?? executor.topicKey`。

### 磨目标（v4.10）

- 立目标表单新增**「怎么算完成」**（成功标准）。表单上明说：**也请写进云之家目标正文，那里才是真身**；这里留的是你签发时的原话，日后差距简报拿它逐条比对。
- 立目标的 `sourceAnchor` 指向**磨稿会话**（原来是 `desktop:board`——真实但无用）。
- `goal_propose` 工具：agent 只有提案权。**必须带 successCriteria**。真身链接可以在确认时贴——最常见的真实顺序就是"边看提案边把文档建出来"。没有链接就**不铸**，卡留在开着的状态。

### 完成度评估（v4.10）

- `goal_evidence`（只读）：成功标准 × 子承诺终态 × 工件归集，全是派生查询。
- `goal_report`：写差距简报卡，逐条 已达成/部分/缺失 + **证据锚点**。出口两个在卡上（**验收** / 继续），第三个在板上。
- **简报默认落私语域**。子承诺跨场所，放到群里会被可见域悄悄削掉一半证据，然后把剩下的当成全貌——这比拒绝生成更坏。
- **差距一键变委派**在**板上**：板上有传送门，评估喂回执行才成得了闭环。一个环两头得在同一个地方。
- **验收关闭的是目标承诺本身**，`cause: 'accepted'`，且只有带 openId 的人能按。

### 顺带补的一条数据律：承诺的墓碑

`commitmentFamily` 原来没有吸收态。加上：**作废与合并是吸收的**，只有 `commitment/reopened` 能回来。

不加就有一条真实路径：目标被作废之后，一张早先生成的简报卡上按「验收」，那条 `commitment/closed` 会把它从 `voided` 翻成 `closed`——僵尸复活，而作废本来就是为了终结僵尸。（已单测锁住。）

### 重启补账：把「落库即代发」的实现自己造出来的鬼堵掉

铸承诺与盖章是**两次 append**，崩在中间就留下一条既没通知、也没标「未通知」的承诺——幽灵承诺禁令的实现自己长出了同一个鬼。而 `hydrate` 不发 `yzj-graph/appended`（重放直接折进 store），所以**永远不会有人重试它**。

启动扫一遍：`notifyPlaceKey` 有、`notified` 空的开着的承诺。**投影登记表让这次补账是精确的而不是猜的**——卡真的被投出去过就会有 `card/projected`：

- 有投影 = 说过了，只是没盖章 → 补个章，**绝不重发**；
- 没投影 = 真没出去 → 现在发。

盲目重试会重复刷屏，一律标 failed 又会冤枉已经说过的那条。两条单测锁住这两支。

### 对抗审查：11 条发现，全部处理

本轮结束后跑了一次对抗审查（**跑真代码，不是读代码**：审查者自己搭了一份临时 spec 逐条验证，验完删掉）。11 条里 9 条是真缺陷，2 条是我把话说满了。全部已修，各配单测。

**一等（会写坏数据 / 会发错消息 / 会越权）**

1. **确认两次会二次铸造、二次投递、还能复活已完成的承诺。** 重叠选择（先「确认 1」再「确认 1,2」）是人真实的答法，而条目的承诺 id 由 提案+序号 派生——第二次确认在同一个对象上再 append 一次 `commitment/opened`：登记消息**再进群一次**，且该事件带 `status:'open'`，把对方已经报完成的那条**翻回进行中**，回执还挂在上面。修：`apply` 跳过已确认的条目。
2. **确认目标提案时贴一个已有目标的链接，会覆盖那个目标。** 目标 id 由真身 URI 派生，于是名字/owner/成功标准/血缘全被改写，已验收的会重新打开——而它的子承诺还指着同一个 URI，整棵子树被静默改嫁。板上的 `declare-goal` 从第一天就挡这个，卡这条路没挡，**因为纯 `apply` 看不见图**。修：提案卡改成**绑 ctx 的工厂**（`createProposalCard(ctx)`），签发时能问图两件事——这条承诺是不是已经存在、这个 URI 上是不是已经有目标。
3. **`goal_evidence` / `goal_report` 用 `rawObject` 读目标，绕过了可见域。** 群里任何人贴一个文档链接，就能让 agent 把**私语域立的目标**的名字、owner、成功标准在群里念出来。修：**结构与措辞分开读**——存在与状态走 raw（提问者手里本来就有这个 URI，这两样不泄露什么），而**每一个人写的字符串只从 viewer-scoped 那次读里来**。
4. **签发是屋里任何人都能按的。** `allowedActors: openId !== undefined` 不是检查，是「有身份就行」。而确认之后的登记消息是**以操作者的名义**发进一个按按钮的人可能都不在的群。修：提案与简报都记 `decider`，只有它能按（审批家族一直是这么做的）。
5. **前缀关键词把闲聊读成签发。** 实测「同意归同意，但先别登记」「就这样下去可不行」「ok 我先看看再说」全都解析成 `confirmed`；目标提案分支还把 input 整个丢掉、恒选第 0 条。修：关键词收窄到**只剩祈使动词**（确认/驳回/挂起/收起），松散同义词全删。残留敞口（「确认一下真要做吗」）是文本通道与「完成」「验收」共有的老性质，现在至少被限制在**一个人**身上。
6. **哪儿都没有场所的条目会静默变成幽灵承诺。** 桌面语境 + 条目没写场所 → 铸出来的承诺没有 `notifyPlaceKey`、没有 `notified`、没有 audience，板上看起来一切正常，而本人永远不知道。修：**出生即标记** `notified:'failed'`，板上红字「未通知 · 请亲发」。

**二等（会误导人）**

7. **什么都没决定的裁决回执说「已记录」。** 「确认 1-2」被 `parseInt` 读成 1、第 2 条悄悄丢掉；「确认 第2条」读成 NaN、一条都没决定。修：编号解析支持**区间**与**带修饰的数字**。（真身链接缺失那一支仍会给出「已记录」——那是卡总线生成的回执，`apply` 影响不到，如实记在这里。）
8. **同一会话里的第二次评估会改写已验收的简报。** 简报 id 由 turn 锚派生，而桌面的锚是**整个会话**。修：assessment 家族加吸收态（答过的不再打开）+ 已结算的锚自动换号；并补上「目标已结束就不写简报」。
9. **挂起在桌面是单向门。** 挂起之后按钮全消失，而纯桌面提案没有文本投影可以回「确认 2」——第三个答案退化成一个慢一点的驳回。修：挂起的条目保留确认/驳回。
10. **桌面卡上不显示登记会落到哪儿。** 只读了 `item.placeName`，于是没写场所的条目**一片空白**，而确认之后它真的会发进一个群。修：显示**有效落点**（条目 → 提案所在会话 → 「没有可投递的会话」三态）。空白是三态里最坏的一种。
11. **重启补账的注释把话说满了。** `deliverToPlace` 是先发消息、后登记投影两步，崩在**那个**窗口里看起来就是「从没发过」，补账会再发一次。修：注释改成如实描述这个窗口，并说明为什么接受——重复看得见，幽灵看不见。

**审查确认无问题的（不再重复论证）**：重放不会重发（`hydrate` 不发 `appended`，只有 `append` 发）；监听器不成环；proposal 的自定义 reduce 正确；没有「TS 接口里有、zod schema 里没有」的字段；`goal_report` 的幻影目标护栏有效；`goalOfTopic` 无跨场所泄漏。

**一个连带的产品后果，如实记**：可见域收紧之后，**在群话题里拆一个私语域立的目标，卡上只显示链接而不是名字**——在那个场所里它的正文本就不可见（桌面私语在群话题内仍按 place 读，是 `deskBinding` 既有规则）。工具返回里会说明并给出办法：去本地会话里拆。这不是 bug，是 §1.6 在这条动线上的代价。

**修复后回归实测**：拆解两条 → 确认第 1 条（只 1 条被铸、只 1 次投递）→ 挂起第 2 条（**按钮仍在**）→ 再确认它 → 板上 2 在跟、两条都「已通知」；卡上每条显示「登记发到「…」」；console 零错。

**修掉的三条**

1. **判定序反了：模型的「推断」压过了人的「语境继承」。** 代码是 `args.parentGoalRef ?? inherited`——只要模型给了引用就赢，**包括它只是猜的**。于是「跳进来说了一句」这个人做出的确定性动作，被一次相似度联想覆盖。设计的次序恰恰相反（继承是确定性，推断是像不像），而**错挂即汇报污染**。已把「明说」与「猜的」分开，推断降到继承之下；ack 的措辞也改成按**实际发生的挂接方式**说，而不是按模型要什么说。
2. **出生血缘是个死参数。** `declare-goal` 收 `sessionId`，但板上根本没人传——`sourceAnchor` 一直是 `desktop:board`。我上一轮在这份文档里写的「血缘指向磨稿会话」**当时是假的**。已把当前会话从中栏透到板、再透到立目标表单。实测：`sourceAnchor: session:session-yzj-next-ecdb…`。
3. **评估触发只做了「拉」，没做「推」。** 设计写明两半。已补：子承诺**全部到终态**且目标仍开着 → 侧栏承诺板按钮显示「N 该评估」（逾期仍然压过它，逾期更响；刚立还没有活的目标**不算**——那是「还没开始」不是「做完了」）。三条单测锁住。

**没做成的两条，如实说**

- **传送门只选场所，不选执行者。** 不是省事：`yzj-cli` 里 `im group` 只有 `recent`，**没有群成员列表**，`contact user get` 也只能按 openId 反查、不能按名字搜。所以「选执行者」在 P1 无法构造。降级形态是现成且不差的：人在自己的句子里点名，agent 读群消息本就能把名字解析成 openId。补 API 之前只能这样。
- **回写真身（两个听众的第二个）完全没有。** 这一条要老实讲透：**对操作者，零维护成立**——挂接零操作、状态自动、产出自动。**对全组不成立**：云之家目标文档永远停在被创建的那一刻，谁想让全组看到进展，仍然得手动去改文档。这正是验收句点名的那种失败。原因是 CLI 只有 `send`，没有文档写入。在拿到文档 API 之前，**「目标活着不需要人维护」这句话只对看得见承诺板的人为真**。

### 第二轮对抗审查：浏览器半边（上一轮只审了 objects）

**9 条真缺陷 + 2 条小的，全部已修。**审查同样是跑代码：一次性 spec 验了卡片总线那几条，草稿丢失那条是**在真实实例里复现的**。

**一等**

### 使用中提出的三处（2026-08-20 傍晚）

**文件消息把文件名说了两遍。** 云之家的文件报文是 `content: "[文件]:r29-summary.md"` **加上** `param.name: "r29-summary.md"`——占位符是给渲染不了附件的客户端看的描述，我们渲染得了，所以它不是标题，是重复。加了 `isPlaceholderOnly`：拿**真实文件名**比对，而不是按模式匹配，否则有人正经写一句「[文件]:计划 你看下」会被吃掉。文件名也不再用省略号：`r29-summary.md` 和 `r29-summary-v2.md` 差在末尾，省略号恰好切掉信息量最大的那头。改成**两行**、任意字符断词。**实测**：卡上一个名字、正文里零个占位符、`line-clamp: 2`、`overflow-wrap: anywhere`。

**引用行的门。** 群视图早就有「跳到被回复的那条」，话题列里却只画了一行死文本——同一件事两个 surface 一个能点一个不能，本身就是缺陷。补上，并且是**两个**门，因为它们回答两个不同的问题：**跳过去**＝「那句话在哪」（同话题内滚动定位 + 落点闪一下），**看整串**＝「这段对话到底在聊什么」（回群时间线，被引用的那句常常来自主楼）。群视图那侧另加了「打开话题」。

**但这一条只做到「代码在、类型过、测试绿」，没能在真实数据上演示。** 原因值得记：群视图里，引用链一旦点火就整条收进话题卡（热链收纳 v4.7），所以**能显示的引用行恰恰是那些没有话题可开的**——「打开话题」按构造就很少有目标；而这套数据里话题内部几乎没有引用消息（引用都发生在群时间线）。功能是按设计做的，**演示不了 ≠ 跑通了**，所以按这个措辞记。

**表情/表态：现在拿不到。** 查证两处：`yzj-cli im` 只有 `message`(send/list) 与 `group`(recent) 两支，**没有任何表态/表情接口**；把原始报文打出来看，字段只有 `content / msgType / param / extFields`，`extFields` 为 `null`，**没有任何 reaction 结构**。所以对某条消息的「收到」「666」这类表态，**当前通道读不到，也发不出**。表情作为**消息**发出来则是普通文本，照常显示。要做需要开放平台补接口——记在这里，不是本轮能绕过去的。

### 附件一直在显示占位图（2026-08-20 傍晚，实测推翻旧结论）

操作者问「文件能不能点开预览」「图片直接显示个缩小版」。查下来问题比这大得多：**附件从来就没真正显示过**。

`attachmentUrl()` 建的是 `https://static.yunzhijia.com/image/<groupId>/<id>`。它**答 200**，所以一直没人怀疑。实测：

- 39 字节的 `r29-summary.md` → 回来一张 **18KB 的 96×96 PNG**（文件类型图标）。所以文件卡上那个 `download` 链接，一直在把一枚图标按文件名存下来。
- 两张**完全不同**的图片（2025×1247 与 925×303）→ 回来的字节 **MD5 完全相同**，都是同一张 108×108 占位图。

早先几轮记的「附件 CDN 同时服务图片与文件正文，免鉴权」是**错的**。它经得起「`<img>` 加载成功」这种检查——占位图当然能加载。

**真身只有一条路**：`yzj-cli file download --id <file_id>`（39 字节的 md 拿回来是真的正文，635KB 的图拿回来是真的 2025×1247）。这条路在**宿主**上，浏览器过不去（CDN 也没有 CORS 头）。

于是这一轮把附件整条改成：**线上传 id，字节走宿主，按 id 缓存到工作区**（附件 id 不可变，取过一次不必再取；否则一屋子截图等于一张图一个 CLI 进程）。

- **图片**：`IntersectionObserver` 懒加载，进视野才取；槽位按平台给的真实宽高**预留比例**，图到位时屋子不跳。
- **文件**：点击 = **就地预览**。文本类（md/txt/json/csv/日志/代码…）直接显示正文（20 万字符封顶，超了说清楚）；图片类直接显示；其余明说「这个类型没法在这里预览」并给出**它真实落在哪个路径**——附件没有公开链接，能给的最诚实的东西就是那个路径。
- **6MB 以上不内联**，只报大小与路径：RPC 通道走 JSON，一个 40MB 的视频不该变成 base64 塞进 DOM。

**顺带修掉一个更早的错**：图片**不是**以 `richText` 的 `desc[]` 段发来的。粘一张图进聊天，来的是 `msgType:'file'` + `ftype:1` + `ext:'png'` + `picWidth/picHeight`。只读 `desc[]` 的结果是**每一张贴进来的截图都被画成一张灰色文件卡**——这正是操作者说的「图片消息直接显示一个缩小版本」。三个标记任取其一即判为图片（单靠哪一个都会漏掉某个客户端的形状），单测锁住。

**一条真的拿不到的**：`richText` 里**内嵌**的图片段是另一个 id 空间——CDN 给占位图，`file download` 直接回 `code=2005, Get download info failed`。**没有路**。UI 因此明说是哪一堵墙（「这张图嵌在富文本里，云之家没开下载口」），而不是转一圈给一句「取不到」——后者会让人以为是网络抖了一下。

**实测**：自聊里 4 个图片槽 → **2 张取到真身**（2025×1247、1575×904，与报文标注一致），2 张给出富文本那条具体理由；dsh-2 的 `r29-summary.md` 点开 → 正文 `# R29 / 话题 job-done 产物验收。` 就地显示。404 测试全绿、8 包构建干净、console 零错。

### 预览要渲染，文件要能拿走（2026-08-20 傍晚）

**md / html 现在是渲染出来的，而且渲在 `<iframe sandbox="">` 里。**

沙箱不是顺手加的：预览的输入是**同事上传进群的文件**。把它 `dangerouslySetInnerHTML` 进这一页，等于把任意标记塞进那个持有回环 RPC 通道的文档里。空 `sandbox` 属性关掉脚本、同源、表单与导航——**安全性来自结构，而不是来自「但愿我的转换器堵住了每一种写法」**。md 与 html 走同一个框，一个机制。

Markdown 转换器是自己写的（shell 的 primitives 里没有渲染器，也不想为预览拖一个依赖进 client bundle）。规矩只有一条硬的：**先转义，再变形**。转义放在后面会把自己产出的标签也打烂；不转义则会让 `.md` 悄悄按 HTML 渲染——那是对「这个文件是什么」撒谎。链接**只保留文字和可见的目标，不产出 href**：框里本来就导航不了，活的 href 只是个假控件。10 条单测锁住转义与人真的会写的那些构造。

**下载补上了，而且是宿主做的。** 附件没有公开地址，走 RPC 把 40MB 变成 base64 只为触发浏览器保存，是绕远路去够一个宿主本来就能写的目录。所以「↓ 下载」= 宿主把缓存里的那份**复制到 `~/Downloads`**，并**回真实路径**——「下载好了」而不说落在哪，是没法拿去用的回执。**同名不覆盖**（`方案 (2).docx`）：下两版的人要的是两份，不是把已经批注过的那份悄悄换掉。

**实测**：`r29-summary.md` 点开 → 沙箱框（`sandbox=""`、框内 `document.scripts.length === 0`）里渲出 `<h1>R29</h1>` 与正文段落，不再是裸文本；按「↓ 下载」→ 「已下载到：/Users/Apple/Downloads/r29-summary.md」，文件真的在那儿、内容正确。414 单测全绿、console 零错。

### 触发词的边界假设了拉丁文打字习惯（2026-08-20 傍晚，第二次「没响应」）

现场：830 项目群 **17:38:25「@next他发的是什么东西」——没有回应**，日志里也没有任何解释。同一个群里 agent 17:06 还在正常干活，所以不是接入问题。

```
(^|\s)@next(?=\s|[，。！？,:;]|$)
```

它要求触发词后面是**空格、六个标点之一、或行尾**。**中文里没人在 @ 之后打空格。**「@next他发的是什么东西」是最自然的写法，而它一个字都不匹配——agent 从头到尾不知道有人在叫它。（更巧的是，它二十分钟前刚在这个群里记下一条记忆：「没叫我，我就不说话」。于是它非常忠实地执行了一个错误的判定。）

那个前瞻真正要防的只有一件事：**`@next` 不该被 `@nextgen` 触发**。而这种风险只存在于「下一个字符可能继续这个词」的地方——对一个 ASCII 触发词来说就是另一个 ASCII 单词字符。**汉字不可能继续 `@next`，所以汉字就是边界**，任何语言的标点也是，不该是某人随手列的那六个。

改成两侧对称的 `(?<![A-Za-z0-9_-])@next(?![A-Za-z0-9_-])`——左边同理，「问一下@next他发的什么」前面也不会有空格。桌面发送与轮询共用这一个谓词（`deskSendPlan` 调的就是 `isAgentTrigger`），所以一处修好两条路都好。六条单测锁住，包括仍然拒绝 `@nextgen` 与 `mail@next`。

**残留一处不一致，如实记**：浏览器里的提示（「⚡叫上」按钮的选中态、锚定条的点火预告）用的是 `draft.includes(alias)`，比服务端松。以前是服务端更严（UI 说会点火、实际不会），现在方向反过来且只差 `@nextgen` 这类写法——当前两个触发词下不会发生，没有去动它。

**已发出去的那条不会被补跑**：游标已经越过它，重放旧消息的风险比让人再发一遍大得多。

### 「执行完了但群里没回复」——两个缺陷，第二个更坏（2026-08-20 傍晚）

现场时间线（830 项目群）：

- 17:46:44 重发「@next他发的是什么东西」→ 触发词修复生效，`topic/registered` + `task/opened`，群里收到「已接收」。
- 17:49:06 **模型侧 502**（`Upstream service temporarily unavailable`）→ `task/voided`，群里收到「【Agent失败】…」。**到此为止 `runTrigger` 已经 return，这一轮的交付路径结束了。**
- 17:50:51 操作者在桌面**私语**里说「继续完成」→ 走的是 `prompt()`，不经过 `runTrigger`。
- 17:58:18 agent 把活干完了：下载了 zip、拆开、逐项数清 749 个接口、还查出 `export_yapi.py` 里写死了 YApi 登录 cookie。**答案很好，一个字也没发出去。**

**缺陷一：私语域的回答没有一扇通往群里的门。** 私语的答案**不该**自动进群（那是把社交决策代做了，§1.6），但它必须**有一个动作**能送过去，否则唯一出路是复制粘贴。已补：agent 的私语回答上一枚「↗ 发到群里」，以操作者名义发出，发不发由人决定。

**缺陷二（更坏）：这一列声称那条答案已经发出去了。** `buildStream` 里 `const heard = inPlace ? 'public' : 'private'`——只要会话是个云之家话题，**每一条** agent 文本都被标成 public，脚注写「已发到 X · 群内所有人可见」。于是屏幕上言之凿凿地说它发了，而群里什么都没有。这正是本产品一路在拒绝的那类谎，结果长在自己身上，也正是「执行完了怎么没回复」之所以令人困惑而不是一目了然。

改成**看证据**：agent 的回复是以操作者账号投进群的，所以它会以一条 `own` 消息回到同一个窗口（投递文本以答案正文开头）。窗口里找得到开头 = 发过；窗口覆盖得到却找不到 = 没发过。**窗口之外的历史确实不知道**——那一段维持旧假定，也不给「发到群里」，免得把早就发过的答案再发一遍。谎被限制在看不见的那一段，当下这一段是准的。四条单测锁住四种情形。

**没做的（有意）**：不做「502 之后自动续跑并交付到群」。任务已经诚实地作废了，而把一次**私语**指令的产物自动投进群，正是可见域要防的方向。人按一下，就够了。

**实测**：那条真实答案的行上现在有「↗ 发到群里 / ⧉ 复制」，修复前是 0 个。423 单测全绿。

### 归错类的修正：这不是私语/群的问题，是「中断该怎么恢复」（2026-08-20 晚）

上一条我把 502 那件事归成了「私语的答案没有门通往群里」，补了一枚「发到群里」按钮。**Bruce 纠正：不是那个问题——是 agent 执行失败了，需要触发它继续，而原来该发哪里，继续之后的结果就该发哪里。** 这个归类是对的，我的是错的。

**502 杀掉的是载体，不是意图。** 而代码把两者一起埋了：

```
if (summary.reason?.kind === 'error') { voidTask(...); deliver('【Agent失败】…'); return }
finally { this.state.completeTask(trigger.msgId) }
```

`completeTask` 把待办记录清掉了——那条记录**正是为了让意图活过载体**而存在的（`replayPending` 靠它做重启恢复）。于是触发消息被忘掉，任务进了终态，唯一的出路是私下推一把，**而那时落点已经随着上一轮一起消失了**。一份 452KB 的 zip 被完整拆解、逐项数清、还查出脚本里写死了 YApi 登录 cookie——一个字没发出去。

**改法：`task/interrupted`——可应答、可继续，且继续之后回原落点。**

- 失败不再是 `voided`（终态），而是 **`interrupted`**：可应答状态，卡上一个「继续」动作，群里的失败消息也改成「回复「继续」我接着做，**结果仍然发在这里**」。这是审批家族早就写过的那条道理的复用：**重启杀死的是载体，不是意图**。
- **恢复地址单独存**（`resumable`，与运行队列 `pending`分开）。分开是必须的：`pending` 会在重启后**自动重放**，而中断的任务不该自己重试——**重试是人发起的、一次**。这样地址跨重启存活，工作却不会自己进循环。
- 「继续」走的是 `task/resumed` → 通道监听 → **重新进 `runTrigger`**。为什么绕回原路而不是直接推 agent：**`runTrigger` 才是拥有交付的那一段**，跳过它的恢复会像那次私语一样把答案搁浅。群里回「继续」和桌面按「继续」是同一条路，因为都落在同一个动作总线上。
- 「作废」在中断态**仍然可用**——否则「继续」就成了另一个死胡同。
- 中断的任务**进注意力列**（`需要我` 一档，行上写「中断待继续：…」）。不出现在列里，等于把「这件事没做完」藏起来，而那正是那天晚上发生的事。

**已经发生的那一条不会追溯**：830 那个任务已经是 `voided`，而作废是吸收态。它的答案仍然可以用上一轮补的「↗ 发到群里」送出去；这次的修复管的是**之后**的每一次中断。

**四条单测**锁住：中断可应答、「继续」只在中断态出现、中断态仍可作废、继续之后回到 open。427 单测全绿、8 包构建干净。

### 明标的降级形态（§5.5 规则②）

- **`goal/written-back` 未实现**。回写云之家真身需要文档写入能力，**yzj CLI 只有 `send`**——`YzjChannelClient` 全部方法读完确认过。可选的降级形态是"提示操作者去粘贴"，但那正是检验⑤禁止的**把人变回程泵**，所以宁可空着并写在这里。挂接诞生与终态两个时刻的回写，押文档 API。

## 同步 v3.1（设计 v4.6/v4.7）+ 完整轨迹入口（2026-08-19 下午）

### 受话判定取代含-@ 判定（v4.7 · 分诊 ④）

分诊从「消息里有没有 @」改成「**受话者里有没有 agent**」：alias/@ **或回复任何 agent 消息**。判定不能用发送者身份——agent 正是以操作者账号发言——所以问的是出站登记表：`isOwnOutboundId(replyMsgId)`。

连带三件事：

- **v2.5 F13 作废**。它把「仅操作者可 steering」当成防注入护栏，前提是"回复是一条特权通道"。v4.7 否掉这个前提：**回复某人的消息就是向他受话**，群成员回复 agent 与 @agent 完全同权，把关的是准入白名单而不是回复机制本身。
- **`card-steering` 分支删除**。卡片就是 agent 消息，回复它当然是受话；关键词匹配仍在前（「验收」是应答不是闲聊），不匹配就按普通一句话进对话。上一轮我为修「agent 听不见对自己问题的回答」加的补丁，被这条规则整个吸收掉了。
- **自聊也适用**：回复检查排在自聊规则**之前**。自聊那条规则管的是"裸消息不该触发"，而**特意回复 agent 自己的卡片**从来不是裸消息。

**实测**（dsh-2，2026-08-19 13:57）：对一条 agent 消息回复「那这条就先这样吧，李婷那边我自己去说。」——**全文没有一个 @**——照样开出 `task/opened`，agent 认出话题上下文、给两条承诺都记了 `receipt/recorded`、并回帖。

### 回复 = 挂链（v4.7）

`resolveTopicRootId` 本来就走到链根，所以"落点=链根所在边界"是既有行为；v4.7 要的是把它**正名**并补上投影侧：

- **冷链平铺**：人-人引用链平铺主楼、带引用线（与云之家/微信两端一致）。一句「收到」不该重构主楼，纯人-人链**连卡都不配出**。
- **热链收纳**：链上消息受话 agent 的那一刻，整条链收进**根消息原位**的热卡。实现上给每条消息带上 `chainRootId`（挂链是数据事实），群视图里凡是链根已成话题的消息**不再平铺**——两处都画就等于说链和话题是两个东西，而收纳的全部主张是它们是一个。

### 锚定条（D13④）+ hover 双动词

一次发送同时回答四个正交问题（落点/受话/指涉/可见域）却共享一个发送键，所以**落点在按下之前常显**：「发到本话题」/「↩ 挂到 X 的这句」，点 × 回默认锚。**点火预告**已实现：已挂链状态下输入 `@`，锚定条当场变成「**整条链将收纳为话题**」。

时间线上每条公域消息 hover 出两个动词：**↩ 回复**（挂链）与 **⚡@agent**（挂链+受话的复合动词）。⚡ 的实现是**预填一个 @next**——零隐藏状态，删掉 @ 就自动降级成普通回复。

### Back 与 Up 分立（D13②）

导航栈进 store：进话题 = push（连同**离开时的滚动位置**），「‹ 返回」= pop 并把那个像素还回去；面包屑群名是 **Up**，去群视图。两个问题两个控件——一个控件兼职正是那条 bug 本身。三条单测锁住栈语义。

**实测**：群视图滚到 1433px → 进话题 → ‹返回 → **回到 1433px**。（第一次测出来是 0，原因是 Playwright 点击前会把元素滚进视口，等于把被测的前提自己清掉了；改成不触发自动滚动的点击后通过。）

### 话题卡就地展开（D13③）

群视图话题卡下面一个「展开看最后几条」——**手势，不是默认渲染**。数据按需取（新 `topic-tail` 端点）：一个有十几个话题的场所，默认预览要付十几次消息读，去渲染一屏没人要求展开的东西。

### 完整轨迹入口（Bruce 直接指出的缺口）

§7.1 写着「trace-link 进 harness 轨迹」，而整列替换把宿主轨迹视图带走了——入口通向的地方没了，入口也就一直没做。现在由我们自渲染：会话头「≡ 完整轨迹」+ **工作块展开后里面也有一个**（门要从它通向的房间里看得见）。

面板把中栏折叠掉的东西全部摊开：云之家入站原文（含我们注入的完整前言——"模型到底被告知了什么"只有这里答得了）、思考、回答、每次调用的完整参数、每个结果、重试、耗时，按发生顺序，可逐条展开，带「只看工具」筛选。实测一个真实回合 **36 个节点**。

它仍然不是第二份存储——读的是宿主自己的 conversation 快照，和融合列折叠的是同一个数组。

## v4.8：左栏是完整的 IM 面（2026-08-19 傍晚）

设计 v4.8 只改了一件事，但它是第一性的那一件：**dsh + 云之家是唯一工作界面 ⇒ 工作台必须是完整的 IM 面**。左栏只列 agent 话题，等于把非 agent 的会话推回原生客户端——入口割裂当场复活，违检验①与第七动词。

「谁在找我」（消息维度）和「什么需要我」（任务维度）是**两个正交问题、两个段**；v3.4 的注意力租约只辖任务段，不辖消息基座。

### 动手之前先把平台摸清楚了（两路并行勘察）

结论比设计里的假设更好，也更硬：

| 设计假设 | 实测事实 |
|---|---|
| 「`group recent` 是最近活动窗口」 | **它是全量名册**：本账号 525 条会话，翻到底 `more=false`，含从未有过消息的会话 |
| —— | 每行**已经带齐**了 groupId / groupName / groupType / **unreadCount** / **headerUrl（真头像）** / lastMsg{内容,类型,发送人,时间} / joinTime |
| —— | **不按 lastMsgSendTime 排序**：499 行里 91 处逆序。服务端按一个不外露的 updateTime 排，所以**排序必须我们自己做** |
| —— | `--limit` 硬上限 20（文档写的 1-100 是错的）；**偏移 502/503 两条服务端记录坏了**，任何跨过它们的页 `code=1110201` 永久失败；连发翻页会 `code=503` 限流 |
| 「无群搜索 API」 | 属实，各级 `--help` 全无。**本地名字过滤是唯一的搜索** |
| 「未读只读」 | 属实：`im` 只有 `message send/list` 和 `group recent`，没有任何 mark-read。**手机红点我们清不掉** |

顺带查出 `parseGroup` 一直在**丢 unreadCount 与 headerUrl**，并且**要求 lastMsgId 非空**——于是「有未读但还没有消息」的会话被整批静默丢弃。这在这份列表只喂分诊时看不见（那种会话本来也没东西可分诊），但它一旦要**成为**会话列表，就是个洞。

### 做了什么

**① 会话名录（底账）。** 每轮轮询在**任何门之前**把见到的每一条会话记进 `channel-state.json`。这一步零新增成本——轮询本来就要拉会话列表才能找到工作——买到的是：重启后列表还在，以及本地名字过滤有东西可过滤。名册按 `lastMsgTime` 倒序，上限 1000 条按陈旧度裁剪，`readAt` 跟着裁。

**② 未读 = `min(服务端, 本地)`。** 服务端的数只读、只信它往下掉；这边唯一比它清楚的是「我已经看到这条了」。所以本地只有一个动作：把计数**归零**。在桌面打开某会话即记 `readAt = 当时的 lastMsgId`，新消息一来徽标自己回来。**手机侧红点清不掉，这是已接受缺陷，写在这里而不是省略。**

**③ 左栏基座。** ☁ 分栏内三段：**群 / 私聊 / 助手与通知**，每段内**在岗场所行在前、其余按最近活动**（设计原文「在岗场所行之下补轻量会话行」）。行的形状是**推导**出来的，不是配置的：有话题且在岗 → 场所行（主楼 + 话题子行 + 聚合徽标）；其余 → 轻量会话行（真头像 + 名称 + 末条预览 + 右列时间在上未读在下）。这就是「接单开关切换 = 轻量行 ↔ 场所行升降级」的兑现——一个会跟 guard 说法不一致的左栏，等于承诺一个不会应答的 agent。

**特殊行**：助手号/系统号（groupType 3/8，本账号 24 条）自成一段、**默认收起、不计总徽标**——它们是订阅源不是有人找你，让机器人主导那个数字，那个数字就没用了；自聊行显示「审批与私语通道」、**未读豁免**（它的可应答流量已经在上面的分诊 chips 里，数两遍就是同一个要求要两次）。分栏头显示总未读（排除助手与自聊）。

**过滤框**：会话超过 12 条时出现，本地按名字过滤——这是平台没有群搜索时唯一的搜索，也是名录必须持久化的原因。

**D10 隐身钩子**：`stealth` 落在 surface 的**部署配置**上而不是列里的开关（一旦成为开关，就得有人记得在投屏前按它，而那正是没人记得任何事的时刻），随 inbox 载荷下发：整段折叠、徽标归零、预览隐藏。

**④ 未接单的会话可进可发，@ 有出生故事。** 打开任意会话都能读（`placeView` 不再因为「话题树里没有」就空手而归，名字改从名录取）。发送这件事拆成两问，靠 `deskSendPlan` 一条规则回答：**没受话 agent → 照发**（人看人发不受任何限制，这是产品的全部意义）；**受话且在岗 → 发并点火**；**受话但未接单 → 一个字都不发**。理由很实在：在同事面前留一个永远不会有人应答的 @，比在这里说清楚糟得多。锚定条在按下之前就预告「这个场所没接单 · @ 不会被应答」，发送键也不再自称「交给 agent」；被拒时给三个门——看场所合同 / 去掉 @ 再发 / 知道了。

顺带修掉一个真缺陷：`sendFromDesktop` **此前完全没有 allow-list 检查**，能在未接单的群里直接 `runTrigger`。

**⑤ `recentGroups` 不再一页失败全盘皆输。** 第 1 页失败仍然是真故障（健康度该看见），第 2 页起失败就带着已拿到的返回。这不是防御性习惯：限流是实测存在的，坏记录是实测存在的，而此前一次 503 就让整轮轮询作废。

### 有意的收窄（写下来，可审计）

- **不做 525 条的深度遍历。** 名录跟着 `groupPages`（默认 3 页 = 60 条）随轮询累积，活跃过的会话都会进来。要一次性抓满 525 条，得 26+ 次翻页 + 限流退避，还要绕开两条服务端自己都序列化不了的记录——对一个脆弱 API 上的**雕花**。名录的形状已经能承接它，等有真实需要再说。
- **不做「接单开关」的 UI。** 设计那句「接单开关切换 = 轻量行 ↔ 场所行升降级」描述的是**后果**，而后果已经兑现（行形是 allow-list 的函数）。开关本身是部署的爆炸半径，不该是列里一个可以随手点的东西；场所合同面板说明它的现状与改动位置。

### 实测

侧栏：分栏头 `云之家 · 95 条未读`；`群 20 / 私聊 16 / 助手与通知 24`（= 3 页 × 20，正是 `groupPages`）；36 行拿到真头像；在岗的 dsh-2 是场所行带 `待验收` + 未读 12 + 话题子行；过滤 `ds` → 49 行；助手段默认收起。零 console 错误。

未接单会话闭环（全程没往任何群发出一个字）：从轻量行进入「830 项目【登顶计划】」→ **读到 40 条真实消息、真人头像、可输入** → 输入 `@next` → 锚定条当场「这个场所没接单 · @ 不会被应答」→ 按发送 → **什么都没发**，出生故事 + 三个门 → 「去掉 @ 再发」把草稿改成普通消息。

### 自审：三轮对抗性评审的结果（2026-08-20）

交付前把 v4.8 侧栏、承诺板、以及最近全部改动逐条对着规格与代码审了一遍。**结论：功能上有真缺口，代码里有真缺陷，而且有几条是我自己文档里写了、代码里没有的。** 下面是全部。

#### 我自己写错的三条（最该记住的）

1. **语境继承在生产里根本不可能触发。** `goalOfTopic` 按 `executor.topicKey` 找，而那个字段**只有 agent 执行者才有**；`commitment_register` 造的全是人类执行者。也就是说：这个工具写出来的承诺，对它自己喂的那套继承机制**结构性不可见**。**而我的测试是绿的**——因为测试 seed 的是「agent 执行者 + parentGoalRef」，一个生产里没有任何写入方会产生的形状。这正是我在别处反复指出的那类错误，我自己又犯了一次。修法：承诺记下**它是在哪个话题里被许下的**（`topicKey`，与执行者无关），继承与 `/link` 都走它；测试改用工具真正写出的形状，并加一条专门证明「工具确实写了 topicKey」的用例（已变异验证：抽掉那一行，它红）。
2. **文档里声称的补偿不存在。** 我写「不做接单开关的 UI，场所合同面板说明它的现状与改动位置」——**合同面板里根本没有这一行**。已补：合同面板第一段就是「接单/未接单」，说清后果和它改在哪儿（`allowedGroupIds`）。
3. **批量补挂造了个单向门**（上一轮已自查并补了移出/作废），但**移出把来路留成了「事后补挂」**——一条已经躺在无归属里的行，标签写着"刚补挂过"。已加 `detached` 这个来路值：挂接引用和它的来路一起走。

#### 对抗性评审抓到的真缺陷（已修）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| **`/link <任意文本>` → 承诺板的 `href`** | 群里任何成员发一句 `/link javascript:…`，操作者打开承诺板就有一个可点的、跑在**持有 loopback RPC 通道的那个文档里**的链接 | 只有 http/https 才渲染成链接，其余显示为「这个引用不是一个链接」；`safeHref` 单测覆盖 8 种恶意 scheme |
| 立目标**不幂等** | id 由真身 URI 派生，同一个链接第二次立会**覆盖**已有目标的名字/owner/锚点（子承诺被静默改嫁），作废过的还会**复活**成 open | 先查对象：已有活目标就拒绝并说清；已作废/已结束的不许用同一链接重开 |
| 四个写端点**不校验目标存在** | 一个错 id 不会报错，会**凭空造出**一条 `what: ''` 的 open 承诺，且没有任何端点能删掉它 | 批量写之前先整批校验；一条不存在就整批拒绝（回执也因此不再说谎） |
| `void-commitment` **绕过卡片仲裁总线** | 对一条**已完成**的承诺按作废会成功，已完成静默变已作废，且没有 `answer/recorded` 留痕 | 只允许作废 open 的；其余拒绝并说明 |
| 移出写 `parentGoalRef: ''`，而卡片的**文本投影**直接判 `undefined` | 移出后按「催一下」，会往同事群里发一句光秃秃的 **`承 `** | 卡片同时判空串；加单测（这是会发进真实群的投影） |
| 墓碑关了正门，**旁边那扇还开着** | 作废的任务晚到的 `terminal` 被 reduce 丢弃了，但 `append` 仍然成功返回，**执行继续往下走并铸出一条承诺**——操作者被告知任务已取消，板子上却长出一条 open 承诺，还能被催办 | 铸承诺前读一次任务状态，voided/accepted 直接返回 |
| `Attachments` 用 `replaceWith` **改 React 拥有的 DOM** | 房间每 6 秒重拉，React 把 `src` 写到一个已经脱离文档的节点上——图片**永远不再重试**，CDN 恢复了也不行 | 坏图是 state 不是 DOM 编辑；顺带修了同一张图出现两次时的 key 冲突，和大图没有 onError 的空遮罩 |
| 日期分隔在消息前就推入 | 某一天的消息若全被收进已有话题卡，那天的分隔线**下面什么都没有**——房间宣称这天没动静，而这天的动静在一张归在更早日期的卡里 | 分隔线延迟到那天第一条**真的会渲染**的行 |
| 写端点的**拒绝理由被客户端丢掉** | 服务端说「这个真身已经立过目标了：「X」」，用户看到的是「通道无响应」——一个不说理由的拒绝，就是在教人这个产品会随机不干活 | 写路径改走保留 error 的通道；实测拒绝语已一路到达 toast |
| 助手号/系统号**可以发言** | 订阅面开着完整 composer，桌面可以往通知号里发消息 | UI 关掉输入框并说明为什么；`deskSendPlan` 服务端也拒（UI 是第一道门，这是真正拦住的那道） |
| 隐身档没有**整段折叠** | 三件事只做了两件，而没做的那件正是投屏上唯一要紧的——会话**名字**还在屏幕上 | 隐身时基座整界收起（仍可手动展开：一个不能取消的演示档是没人敢开的档） |
| 自聊标签在**在岗分支**丢失 | 实际部署里自聊就在 allow-list 里、且长出了话题，所以它走场所行分支，「审批与私语通道」这个标签**永远不显示** | 场所行分支也读它 |

### 承诺板 v4.8：目标出生三入口 + 挂接三时刻（变更记录 #49）

**第一性没变，所以没有新节点类型。** 目标是**复合承诺**，那么「立目标」就不是新动词——登记一条 `{executor: owner 本人, 验收: 人工, goalRef: 云之家真身 URI}` 的承诺，登记机制原样复用。图上仍然没有目标节点：目标行和它下面的工作**靠 URI 相认**（一边 `goalRef` 声明、一边 `parentGoalRef` 服务），没有边要维护，也没有第二套账要对齐。

| 做了什么 | 为什么是这个形状 |
|---|---|
| 承诺板增 **GOALS** 缩放级别（全部 / 按目标） | 「项目视角」是承诺板的一个缩放级别，不是新 surface |
| 目标行 = 虚线 + owner + 子承诺状态计数 + **「终态：人工验收」**药丸 + 「看真身 ↗」 | 虚线是**主张**：真身在云之家不在图上，画成实心就是宣称一份我们没有的副本。**聚合是信号不是状态**——计数只报信号，父承诺终态永远走人工验收（Asana 的 connected work 保留人工 check-in 是同一条教训） |
| **无归属组**：未挂目标的承诺全部可见，可多选 → 一次挂到同一目标 | **未挂是合法状态，不是错误**（OKR 工具十年教训：什么都挂 = 什么都没挂）。这一组买到的不是「强制对齐」，是**对齐债务从看不见变成拉一下就看见**——周会一次补挂的动线 |
| **立目标**入口：表单即确认卡 | 铁律**人签发**——按下就是签发；agent 没有任何工具能写目标，它只有提案权 |
| 挂接来路逐条显示（**从语境继承** / 挂接为推断 / 事后补挂） | **继承不是推断**，两件事不共用一个词；亮出来才可能被纠正 |

**出生时刻 · 语境继承**（多数挂接应零操作发生在这里）：在一个已经服务于某目标的话题里开出的新承诺，**自动继承**那个引用，ack 里亮出可纠。语境里有两个不同目标就什么都不继承（**宁空勿错**）；语境里什么都没有就不挂，那是合法结局，不是要用猜测填的洞。

#### 自己抓到的一个单向门

批量补挂做完就发现：**它没有出口**。§5.5 环路完整性检验要求每个动作都有出口，而「挂上去」之后没有任何手势能把它挪回无归属；同理，在这里立的目标**在任何场所的流里都没有卡**，关键词那条退役路径够不到它。两个都是我刚造的单向门，都补了：子承诺行有「移出」，目标行有「作废」。顺带一条：**被作废且底下空了的目标不再占一个组**（板子是「在滑的东西」不是完整档案），但**底下还有活的**照旧保留——那些活没有停止存在，藏起来比留一行空的更糟。

**实测闭环**（全程未发任何群消息）：按目标视图 → 1 个目标 / 5 条无归属 / 人工验收药丸在 → 立目标「实测目标-59124」→ 2 个目标 → 勾 2 条批量补挂 → 无归属 5→3、来路显示「事后补挂」→ 逐条「移出」→ 回到 5 条 → 「作废」目标 → 该组消失、真实的那个目标still在。图里零实测残留（目标只剩墓碑，两条真实承诺的 `parentGoalRef` 已还原为空）。

### 右栏三个 tab 在哪都一样（变更记录 #45）

Bruce：「我在不同话题、本地对话下，右边的资源怎么都是一样的呢」。属实，而且这一问底下压着两个真缺陷。

**表层：三个 tab 里有两个根本不看你站在哪。** `资源` 是整个账号产出过的一切、`记忆` 是账号记过的一切——面板自称「跟会话走」，实际不走。同一份列表出现在每个话题和每个本地会话里，读起来跟坏了没有区别。

改成**同一个点上的三个半径**：

| tab | 话题里 | 本地会话里 |
|---|---|---|
| 当前 | 这个话题产出的 | 这个会话产出的 |
| 资源 | **这个场所**里所有话题产出的 | 本机会话产出的（不属于任何群） |
| 记忆 | 在这个场所里成立的（place 轴过滤到本场所 + entity/org） | 不限场所的（本机没有场所，place 轴一条不给） |

记忆的过滤与写入侧 `scopeFor` **同一推导**——两边不一致就会出现写得进、读不出。半径本身常显在 tab 下面一行：一个内容取决于你站在哪的面板，必须说出它认为你站在哪，否则两份一样的列表分不出是设计还是 bug。

#### 底层：桌面发起的回合根本不在场所里（真缺陷）

写实测用例时抓到的：在 dsh-2 的话题里用「对 Agent 说 · 私」让它 `memory_note`，结果落库是 `scope: "desktop"`。

根因——**orchestrator 只认得它自己开的回合**。IM 触发的回合有 binding；操作者在桌面敲进话题会话的那句话，是宿主直接 `session.prompt` 跑的，`activeTurns` 里没有它，于是 `bindingFor` 落到「桌面默认 binding」——那个 binding 没有场所。后果不止记忆：

- 场所惯例被记到 `desktop` 这个**谁也不会去读的坐标**，在它被学到的那个群里永远看不见；
- `audience` 缺失，写入侧那句「Filed where it was learned」根本没生效；
- 血缘同理：`topicKey` 退化成 `session:<id>`，桌面在话题里建的文档会掉进「本机会话」池子。

修法：`bindingFor` 认不出的会话，去话题索引里问一次——**桌面发起的回合如果发生在话题会话里，它就发生在那个话题的场所里**。谁敲的键盘不决定读取域，听众集合才决定（§1.6），所以 viewer 同走准入回合那条保守单域规则：群话题读该场所，DM 读作操作者。

**闭环实测**（私语态，全程没往群里发任何东西）：在 dsh-2 话题里记一条 → 该话题 `记忆` 里出现（出处、× 忘掉都在）→ 切到本地会话**看不到** → 在话题里点 × 忘掉 → 收尾干净。上一轮 bug 留下的那条 `scope=desktop` 的孤儿记忆也一并让 agent 按 id 忘掉了，图里现在零残留。

### 工作块里是精简，不是原始（变更记录 #44）

Bruce：「agent 执行过程卡片内显示的应该是精简的信息，不是原始的信息，如『Bash Finalize patch and Compose validation』，而不是把 bash 命令展示出来，详细内容是在完整轨迹中查看」。

工作块是**入口**。往对话中间贴一段 `{"command":"…","timeoutMs":15000}` 不是「这一步干了什么」的摘要——那是日志，放错了地方。而「干了什么」这个问题，**只有工具自己答得了**：知道 `yzj_doc_block_update --id X` 意味着「改文档正文」的不是 UI。

`dsh-tools` 恰好有一条现成的契约：工具声明 `presentCall` / `presentResult`，宿主把 render intent 挂到 tool/call 与 tool/result 帧上（`ToolResultNode.callView` / `.resultView`、`RunningToolCall.callView`）。中栏改成读它：

| 卡种 | 取哪一句 |
|---|---|
| `terminal`（bash） | **`description`**——它的 `title` 就是命令本身，而人要看的是那句话 |
| 任意卡 | 完成态的 `resultView.title` 优先——它知道这次调用最后怎么样了 |
| `generic` / `diff` | `title` |
| 工具什么都没声明 | **只留工具名**，一个字都不编 |

最后一行是有意的：从 `argsRaw` 里推标题，等于这一列去猜它不拥有的包在说什么——和当初凭空发明节点类型是同一类错误。参数留在完整轨迹里（实测仍在：`调用 bash {"command":"pwd && ls -1",…}`，可展开看完整 JSON）。

顺手把 `context` 步骤也收了：它的正文是写给模型的 system reminder，成页地长，工作块里只说产出者的名字 + 「上下文注入」。

#### 另一半：我们自己的 41 个工具原本什么也没声明

只改 UI 是半个修法——内置工具（bash/read/grep）本来就有 render intent，而 `yzj_*` 一个都没有，会退化成光秃秃的工具名。所以每个工具补一行 `presentCall`，写在 `description` 下面一行：**上一句是给模型看的，下一句是给人看的**，正好对照。

`yzj_whoami → 确认自己是谁`、`yzj_doc_workspace_list → 知识库列表`、`yzj_doc_create → 新建文档《价格页》`、`graph_query → 查承诺`、`memory_note → 记下一条本场所的惯例`。

加了一条**族级守卫**：每个工具都必须能用自己 schema 的最小合法入参产出一句非空、且不含 `undefined` 的标题。第一版守卫用一袋共享的样例参数，结果只测到了碰巧满足的那些工具——`defineTool` 会先校验再调 presenter，参数不合就直接返回 undefined。改成**按每个工具自己的 JSON Schema 生成最小合法入参**后才真的覆盖全族；删掉任意一个 presenter，守卫会点名那个工具（已变异验证）。

**实测**（本地会话，一次让它调三个只读 yzj 工具）：

```
✓ context               上下文注入
✓ bash                  List all files including hidden          36ms
✓ read                  Read …/CONVENTIONS.md                     8ms
✓ skill                 Load skill yzj-cli                       14ms
✓ yzj_whoami            确认自己是谁                              379ms
✓ yzj_doc_workspace_list 知识库列表                               785ms
✓ graph_query           查承诺                                    784ms
```

进行中的块头同形：`▶ 进行中 3 步 graph_query · 查承诺 345ms`。块里**零原始 JSON**，零 console 错误。

### 侧栏第三轮：顶层大分栏 + 收起即全收 + chrome 收敛（D13⑤ 续 · 变更记录 #43）

设计稿又改了左栏排版，三条，都跟着做了。

**① 顶层大分栏 = 通道轴的一级投影。** 侧栏最外层先分两界：**云之家**（有 IM 通道的场所：群 / 私聊）与 **本地**（工作夹场所）。这个区别比任何一界内部的分组都大，所以它拿一档比组内灰标签更响的排版——8px 上边线 + 800 字重 + `.08em` 字距，右端一句轻提示（`群 · 私聊` / `工作文件夹`），Finder 的 FAVORITES/LOCATIONS 同族。上一版把「本地」做成和「私聊」同级的灰标签，是**把一层层级压平了**；层级税从视觉词汇上一次付清。分栏头同走披露列语法，可整界收起。

**② 收起即全收。** 上一轮我实现的是 Slack 式「折叠组里仍露出当前会话那一行」——设计推翻了它，理由很硬：**按下折叠却有一行留着，读起来是控件失灵**；折叠是注意力的用户主权，就得彻底。位置不丢是**另一件事**，用另一个记号：收起且含当前会话的场所行，左缘一道细示位线（`inset 2.5px`）。

这条我往上补了一级：**规则递归**。整界收起时场所行本身也没了，示位线得由分栏头来说——否则「位置不丢」在一层成立、在上一层失效。设计里「分栏头…规则递归」这句就是这个意思。

**③ chrome 收敛（「箭头不高级」）。** 三处：披露箭头从字符 `⌄` 换成 **1.5px 描边 SVG**（字符的基线随字体走、粗细也随字体走、跨平台还换形状）；场所行/标签行的箭头**hover 才现身、收起态常显**（状态不能藏——Notion 同族），分栏头的常显（分栏头除了披露什么都不是）；分栏头**不带图标**（☁ / ⌂ 在一部分平台上渲染成彩色 emoji），纯排版表达——顺手把 `☺ 私聊`、`▢ 无文件夹` 的字形也去了，同一条规则不该只在一处执行。

#### 顺带修掉：嵌套 button

改的时候发现上一轮留了个真缺陷——**折叠三角是 `<button>`，而它被放进了另一个 `<button>` 里**（私聊标签行、工作夹行）。HTML 不允许，React 用 DOM API 建树所以浏览器没报错，测试也过了，但两个控件其实是一个手势，事件同时冒泡到两处（靠 `stopPropagation` 兜着），辅助技术读出来是两个可聚焦控件。

修法正是设计那句话的直译：**行体本职是折叠的行**（分栏头 / 纯分组标签 / 工作夹），箭头只是**装饰性 `<span>`**，整行是唯一的控件；**行体另有本职的行**（群行 → 开主楼），箭头才是真按钮，两个控件各司其职。

**实测**：两个分栏头带提示渲染 · SVG 箭头 5 个、字符箭头 0 个 · 场所行箭头 opacity 0→1（hover）、收起态锁定 1、分栏头恒 1 · 收起 dsh-2 后子行 8→0 且场所行示位线 `true` · 收起云之家整界后 dsh-2 行消失、示位线升到分栏头（`云之家 holds:true` / `本地 holds:false`）· 零 console 错误。

### 工作块说不出自己在跑还是跑完了（变更记录 #40）

Bruce：「agent 工作过程卡片看不出来 agent 是在进行中还是已完成」。属实，而且根因比措辞深一层。

**中栏只读了 `nodes`，而 `nodes` 是终态日志。** 宿主把「回合正在发生」拆成三个字段，一个都不在 `nodes` 里：`runningCalls`（发出去还没回来的调用）、`partial`（正在流式吐出的回答）、`running`（回合是否还开着）。只读 `nodes` 的后果是：**整个生成期间这一列一动不动**，然后"啪"地出现一个已经完成的工作块——它看起来跟已完成没有区别，因为它渲染出来的时候本来就已经完成了。措辞层面的补丁救不了：「Agent 正在工作」和「Agent 工作过程」是同一号字同一个颜色的两个近似短语。

三处都补齐：

| 事实 | 之前 | 现在 |
|---|---|---|
| 在飞的工具调用 | 完全不渲染 | 折进**当前那个块**（同一段机器动作，只是有一步还没答），◐ 脉冲 + **每秒走字的计时** |
| 流式回答 | 完全不渲染 | 活动行：`正在回答`（正文）/ `正在思考`（只有 reasoning 时取尾行）/ `等待模型`（请求已发、第一个字没回来） |
| 工具报错 | 和成功一样打 ✓ 绿勾 | ✕ 红叉，块头变 `⚠ N 步失败`，块体转红 |

块头现在三条通道同时说状态——**颜色、脉冲、边框**：`● 进行中`（蓝底脉冲 + 蓝边 + 蓝晕）/ `✓ 已完成 · 用时 6.0秒`（绿）/ `⚠ N 步失败`（红）。跑的时候块头显示**当前工具名**（在干什么比干了多久有用），跑完显示**用时**（`tool-result.callTime → time`，不是猜的）。

活动行故意是**私**：回答在发出去之前没到过群里，回合收尾定稿时才翻成公——这个翻转本身就是规则的教具。

**实测**（本地会话，`sleep 6 && echo done`）：`进行中 1 步 bash` → `bash · 2.0秒` → `3.0秒` → `4.0秒` → `5.0秒` → `✓ 已完成 1 步 用时 6.0秒`。零 console 错误。

一个只有跑起来才看得见的边界：**调用比 tick 年轻时时长算出来是 0，而 `durationOf` 不肯印 0**，于是块头出现悬挂的 `bash ·`。第一次实测就抓到了；分隔号改成跟着数字走，不跟着步骤走。

### 目录选择回到 dsh 的原方案（变更记录 #41）

Bruce：「选择本地工作目录的弹窗直接，按照 dsh 的原始方案，直接选择本地目录」。

dsh 自己的形态查清楚了：ui-workspace **只拥有触发器和登记语义**（`createWorkspace({path})` + 可重试错误框），"从 open 到拿到路径"之间的全部交互属于一个**槽位占位者**——`sidebar.workspaces.directoryFlow`。本机装的是 native 占位者，它**无渲染**，收到 `open` 就调 `host.pickDirectory()` 开操作系统自己的文件夹对话框（宿主侧是 `osascript choose folder`）。也就是说：**dsh 原方案里，点一下就是系统对话框，中间没有任何自建界面。**

那个洞我们挂不上——`sidebar.workspaces.directoryFlow` 由我们所遮蔽的那个条目声明，而**声明即认领**（slots 注册表对重复声明直接 throw）。但占位者干的事只有一件，我们可以原样干：**点击直接 `pickDirectory()`**，回来 `create` + 落到新会话。我自建的三路弹窗降级为**没有 native 能力时的兜底**（宿主若配的是 browse 占位者，就没有系统对话框可开；一个会死的功能比一个会降级的功能糟）。

按钮期间显示 `⌛ 系统对话框已弹出…` 并说明**对话框开在跑 dsh 的那台机器上，不在浏览器里**——这是一个可能永远不返回的调用，不能只画成"有点慢"。失败给可重试错误条（`重新选择` / `手填路径`）。

**实测**：点击后我们自己的弹窗**没有出现**（`ownDialog: false`），按钮进入 ⌛ 态；关掉系统对话框后按钮干净复位。

### 会话行补齐：时间 + 重命名 / 分叉对话 / 归档对话（变更记录 #42）

替换 `sidebar.workspaces` 时，宿主会话行上的**相对时间**和**行内菜单**一起被拿走了。三个动词按 dsh 自己接线的地方原样接回：`sessions.binding(id).session.rename` / `sessions.fork({increaseTitle:true})` + `open(child)` / `workspaces.archiveSession`。相对时间沿用 dsh 的桶（刚刚 / N分钟 / N小时 / N天 / N个月 / N年），这样这边的行和那边的行读起来是同一种行。

**只有本地会话有这个菜单，话题行没有**，理由不是省事：话题行的标题来自图对象的 topic label 而非会话标题（**重命名什么都不会变**）；话题的分叉不绑任何场所（**发不出去**）；归档和注意力租约打架（租约已经把办完的话题移进群视图，那里还走得回去）。三个动词有两个是死路，一个啥都不做的菜单比没有菜单更糟。

**两处偏离 dsh，都是有意的**：

1. **归档先问一句。** dsh 直接归档，但归档在这一面**没有回头路**——archived 会话从所有分组面和搜索里消失，客户端契约里没有反向动作。§5.5 环路完整性检验说每个动作都要有出口；这个动作没有，那就至少在进门前说清楚（「归档后这里就找不到它了（日志还在盘上）」）。
2. **过滤 `archivedSessionIds`。** 我们的本地列表是减法定义的，不减掉归档集的话，归档完那一行还在——动作看起来像没生效。

**实测**：重命名 → 标题真的换了并持久化；分叉 → 多出 `xxx (1)`；归档 → 确认条出现、点「归档」后行消失。分叉出来的那个会话跑完就归档掉了，重命名过的那个改回了原名——探针不留垃圾。

### 侧栏第二轮：折叠 + 披露列 + 本地=工作夹场所（D13⑤ 续 · 变更记录 #39）

三条裁决，都跟着做了：

**① 折叠回来了，且和租约正交。** 上一轮我判「折叠 YAGNI」是错的：**租约是系统代理**（只修剪终态子行），**折叠是注意力的用户主权**（收起"活跃但当下不关心"的整组）——租约管不了整组注意力。两条自我约束照做：折叠组的**聚合徽标常显**（注意力不因整理而丢失）；折叠组里**含当前会话时仍露出那一行**（Slack 同族）。

**② 披露列固定在行首左缘，全树垂直对齐一列**（Finder/VS Code/Notion 同位）。设计明确否掉了行尾方案：右侧 `›` 在 iOS 语法里是「进入」不是「折叠」，且会挤进徽标的注意力信号区。交互语法就此统一——**披露列永远管折叠，行体做行的本职**：群行开主楼，工作夹/纯分组是纯容器、行体即折叠。子行的从属竖线正对披露列下方延伸。

**③ 本地 = 工作夹场所。** 工作文件夹是**无 IM 通道的场所**（合同/工具/记忆随文件夹走，本就是 dsh 的原生语义），所以每个文件夹是一条场所行（⌂ + 名字 + 路径 · N 个会话），本地会话是它的子行——dsh 原生「workspace > sessions」结构直接投影。孤儿「本地」标签没了，侧栏语法完全统一为：**场所行（群/工作夹）+ 子行（话题/本地会话）+ 纯分组标签**。

#### 顺带查出：当前会话根本没传进侧栏

做「折叠组仍露出当前会话」这条时才发现 `currentSessionId` **从来没被传给过侧栏**——注册处压根没给。后果不只是这条新规则失效：**高亮当前行这件事从第一天起就没工作过**，只是没人盯着它看。

根因是我把它当成了 prop，而 `sidebar.workspaces` 是 root 作用域的槽位，**根本没有 `props.sessionId` 可给**。正解是它本来就在侧栏已经在读的那份快照里（`list.current` 与 `ids`/`byId` 同源），改成 `useSessions(state => state.current)` 即可。

### 侧栏节点词汇（D13⑤ · v4.7）：节点是行，标签是字

设计稿改了左栏，成因是 Bruce 那句「看不出群名可点」。诊断写得很准：**场所穿了排版标签的衣服**——灰字 + 分隔线是全行业的「分节符」语法，肌肉记忆读出来就是"不可点"；而话题行比场所行视觉更一等，**层级画反了**。Slack/Discord/Teams 是同一个答案：频道是行，分区是字。

侧栏里三种东西，各穿各的衣服：

| 东西 | 衣服 | 为什么 |
|---|---|---|
| **场所**（在岗群） | **一等行**：群头像 + 群名（750）+「主楼 · N 个话题」+ 聚合徽标，点击入主楼 | 它是图的一等居民——有自己的视图、有状态、走得进去 |
| **话题** | **缩进子行 + 从属竖线** | 注意力租约修剪的正是子行；父常驻、子退租的从属关系必须看得见，否则修剪读起来像丢失 |
| **纯分组**（私聊/本地） | **灰字 + 分隔线** | 它是排版，不是节点 |

顺带去掉了我自己加的折叠三角：设计稿没有它，而租约已经在替你修剪子行了；场所行现在是明确的点击目标，一个控件不再兼两职。头部也按设计稿改回**同一基线**（收件箱 + 副标题一行）。

### 我的错，且是设计专门为之修订的那一条

Bruce 报「点进 # dsh-2 好像不能在群里发消息」。属实——**群视图我压根没给 composer**，还写了段注释论证「场所不是跟 agent 的对话，没有可 steer 的东西」。

这个论证是错的，而且错在设计已经点名的地方：**场所就是一场对话，只不过是人和人的**。v4.6 变更记录第 36 条一字不差地记着触发它的那句指正——「群里发不了普通消息/回复不了别人」，成因写的是「§1.3 只搬了 IM 习语的渲染半边，书写半边被 agent 中心视角丢掉」。我把这个 bug 原样重建了一遍：把房间画出来，却不让人在里面说话。

修法即 D13①：群视图有完整 composer——**发到主楼**默认落点、**↩ 回复**挂链、**⚡@agent**一步挂链+受话，锚定条常显落点、输入 @ 当场预告（未挂链→「将长出一个新话题」；已挂链→「整条链将收纳为话题」）。

## 段 5 续：群视图看得见房间、本地会话有目录（2026-08-19 上午）

Bruce 报了两件事：「dsh-2 群里还有其他人发言，3090 好像看不到」「本地会话应该还需要打开本地工作目录来进行」。两条都成立，且各自暴露一个真缺陷。

### ① 群视图把房间埋了

其他人（单国鑫）确实在发言，消息也确实读到了——但**被 13 张话题卡压在下面**。根因是我给「起点已滚出窗口」的话题写的兜底：`unshift` 到顶部。一个有十三个话题的场所于是渲染出十三张卡片压着一句可见的话，**群视图不再是房间，成了一排离开房间的门**。

两处修：
- 起点不在窗口内的话题收进**默认折叠**的「更早的话题 · N」条——归档仍然点得进去（冷卡是归档话题的永久住址），但不霸占房间；
- `messagesInPlace` 按页回翻（上限 4 页），因为一个热闹场所一下午就烧穿一页 20 条。

### ② 本地会话没有目录入口

遮蔽 `sidebar.workspaces` 时一并拿走的还有**宿主唯一的「打开目录」入口**。本地会话必须跑在某个目录里，所以在此之前**根本无法新建一个**：＋ 按钮落到一个 New Session 视图，而它的工作区选择器随那一列消失了。**占了一个座位不等于判定没人需要它。**

补法：「本地」组按工作目录分组（成员关系读 `WorkspaceView.sessionIds`——宿主把归属记在**工作区**上，会话摘要里根本没有目录字段），加「＋ 目录」入口。

**目录选择器踩到的宿主事实**：这台宿主组合的是 **native** 能力不是 **browse**——`host.listDirectory` 直接回 `directory-picker-unavailable: ... the composed picker serves "native"`。而 native 的 `pickDirectory()` **从浏览器里看不见**：对话框弹在跑 dsh 的那台机器上，promise 在有人过去点之前不会 settle。我第一版把它当成唯一路径，按钮就永远停在「打开中…」——**一个可能永不返回的控件绝不能长得像"有点慢"**。

最终形态三条路并存，且都说清自己是什么：系统对话框（并写明"对话框开在跑 dsh 的那台机器上，不是这个浏览器里"）· 目录浏览（宿主有 browse 时才出现）· **绝对路径输入框**（两个能力都没有时仍然能用——这是"降级"和"死掉"的区别）。实测用路径框登记了 `/Users/Apple/Documents/project/dsh-yzj`，侧栏当场长出这个目录。

### 侧栏对齐设计稿的最后一处

设计稿的 `GROUPS` 把**所有私聊收在一个「私聊」组**下，最后一组是「本地」。我们此前一个场所一个组头。已改：群一组一个头（可点进群视图），**私聊合并成一组**（人不是一个能走进去的场所，DM 背后没有群视图，一人一个组头等于一列去不了任何地方的标题），本地垫底。

Bruce 指出「左侧栏和设计稿还是不一样，尤其是下面的群」。对照 `ultimate-form-demo-v4.html` 的 `renderSidebar()` 逐行核，**我做错的是结构不是样式**：

## 段 5 起步：环路完整性断言 + 群视图 + 场所合同（2026-08-18 夜）

### 动词×投影矩阵与环路完整性断言（段 5 具名交付）

设计 §5.5 的规则有两半，此前只断言了一半：

> 每押后一个视图/通道，必须给留在 P1 的对象配一个最小 IM 习语的**进/出口**。

`answer-path.spec.ts` 管的是**出口**。**进口从来没人断言**——而这正是本系统烂过的地方：`memory` 有内核词汇、有 schema、有桌面 tab、**零生产者**，于是那个面板永远空着，没有任何测试反对。「没人用」和「根本没有入口」从外面看一模一样，这恰是这条规则要防的失效。

`next/channel/tests/loop-matrix.spec.ts` 补齐整张矩阵，四段 18 条：

| 段 | 断言 | 变异测试证明它会红 |
|---|---|---|
| **进口** | 每个被渲染的家族都有活的生产者；记忆既有 `memory_note` 也有 `memory_forget`；每张卡都渲染得出 IM 文本 | 摘掉 `memory_note` 注册 → 红，且指名 `memory（声明的工具一个都没注册）` |
| **出口** | **每个动作**（不是每张卡一个词）都够得到；关键词解析回它自己；同卡内无词冲突；可应答态至少一个动作可用；`replyHints` 只承诺此刻做得到的 | 拿掉 `void` 的 keywords → 红，指名 `task:void`；让「验收」同时被两个动作认领 → 红，指名冲突双方 |

**中栏分叉：Bruce 裁 (a) —— 整列替换，已执行。** 代价如实记：宿主的对话/轨迹视图、composer、模型选择、访问模式、附件入口随 `conversation` 一起消失（子槽由占位者声明，遮蔽即全失）。「工作块→轨迹」的入口因此由我们自渲染——仍读宿主 session 快照，不另建存储（§2 本意），但渲染归我们。另补：本地会话（非话题）会随工作区列表一起失踪，已在场所树下加「本地会话」分组兜住。

### 段 4 首日 spike 结果：`conversation.view` 替换（已定形）

指南要求段 4 首日先做这个 spike，因为它决定整段形态。**结论：设计里"chain 替换"这个说法不成立，但目标形态（交错）可达，不需要走"同窗 rail 降级"。** 三条证据：

1. `conversation.view` 是 **list 槽**（`kind:'list'`, `scope:'session'`），投影成 **tab**（`ViewTab{id,label}`），活动视图存在 `ChatStoreState.view`。它是**增补**不是**替换**——注册一个条目得到一个并列的视图页，不会顶掉 Chat。
2. **往内置 Chat 视图里交错 IM 消息是堵死的**：Chat 节点由 `ConversationNodeDefinition.match(event: SessionEvent)` 从 **session 事件**派生，而 IM 消息不是 session 事件，把它们变成 session 事件需要写自定义耐久事件——**铁律 2 / F4 明令禁止**（冷读白名单会让整条日志不可读）。`ChatNodeDataMap` 虽是 merge-extensible 接口，但没有生产者就没有节点。
3. **我们自己的视图页里交错是可达的**：`ctx.conversationViews.register()` 允许插件注册自有 view target 与 builder（同一条 session 事件流），`ConversationViewSnapshotStore.get('chat')` 可读 chat target 的快照。也就是说，我们的 pane 里能同时拿到轨迹节点与（经 RPC 取的）本话题 IM 消息，按时间交错。

**定形**：段 4 = 注册一个自有 `conversation.view` 条目「融合」，pane 内自渲染融合时间线（轨迹节点 × 本话题 IM 消息），而不是改内置 Chat 视图。设计原文"chain 替换"改为"注册自有视图页"——形态不变（交错），实现路径变。

### 收窄：宽度的三条里只兑现了两条

设计说「可拖分隔线 + 两端护栏 + **全局记一个值**下次如旧」，并要求打开预览时右栏「接管**并加宽**」。

- **可拖 + 双护栏：宿主已有，直接用。** `DETAILS_MIN/MAX = 300/520`、`CENTER_MIN = 640` 硬底线，拖拽把手是 AppFrame 自己渲染的。设计说的「中栏可回复最小宽」比我们能自定的更严。
- **自动加宽：做不到。** `ctx.layout` 对外只有 `toggleSidebar / openDetails / closeDetails`；`setDetails(px)` 是 root entry 的 store action，跨插件拿不到。所以只能开，不能定宽——打开即 360。
- **上限 520：宿主的钳位。** 设计自己那句「**更宽的需求走沉浸态，分隔线不必覆盖全区间**」正好落在这道边界上，所以阶梯是 卡 → 并排(300–520) → 沉浸(全屏)。
- **跨开合的宽度记忆：没有。** 宿主的 layout store 明写「关闭面板即忘记拖拽宽度，重开回到契约默认值」。要兑现得改宿主。

不自建第三栏来绕开：那会覆盖中栏、挡住 composer——正是设计拒绝 modal 的那条理由。

### 实测发现并已修的洞（都不是「看起来不好」，是「什么都没发生」）

| 症状 | 成因 | 修法 |
|---|---|---|
| 群主楼点「预览」毫无反应 | 右栏是**会话作用域**槽：当前会话是空会话时宿主根本不给它东西渲染，槽照样挂载、列宽是 0。预览渲染进了一个 0 宽的格子 | 并排没地方落就跳级去沉浸。三态的阶梯可以跳级，不能断在半空 |
| 从沉浸按 Esc「返回」，文档消失 | 上一条的另一半：退回的那个格子本来就打不开 | `leaveImmersive()`：有地方落才回并排，否则关掉——退进看不见的地方等于弄丢 |
| 第一次预览莫名跳全屏 | 判「有没有地方落」靠量像素，而列宽是 0.3s 动画过来的：样式已写 360，计算值仍是 0px | 改读宿主写在框上的 `data-details-collapsed`（与 `cols.details` 同一次提交落下，同步、不受动画影响），像素判断保留为第二条——属性哪天改名，它仍兜得住真的关着的情形 |
| `css.aside` 拼进 className 成了字面量 `undefined` | 空 CSS 规则被打包器丢掉 | 给它一条真声明 |

### 没做，及为什么

- **云之家在线文档的正文投影**：`yzj_doc_download_url` 明写不支持 otl/dbt/md 节点，而 agent 建的文档正是这几类；它们的正文只能走 `doc block list`（另一条数据通路，不是 4e 的 file-data 代理模式）。所以在线文档在卡上是**一扇门**——而且门比投影更对：那是活的对象，此刻可能已被人改，一份复制品会过期（数据律 1）。
- **多维表格的 schema + 记录窗口**：§7.5 原文是「表格**走资源投影**」，即交给资源 tab 那条既有线，不在本次预览族内。附件里的 csv/tsv 属 file-data，已画成表。
- **窗口缩到 CENTER_MIN 以下时右栏被宿主自动关掉**，预览随之不可见（再拉宽即恢复，宿主不改写宽度偏好）。这是 concession chain 的既有行为，对象面此前同样如此，未特殊处理。

## 真身之变：`truth/changed` 终于有了生产者（2026-08-21）

### 先把上一轮那句话说准

我此前写「`truth/changed` 没有生产者」，说得太含糊。准确的情况是：**这一族的定义、schema、读的路一直都在，但没有任何一行代码去看过那份文档**，所以永远没有东西可生产。而后果比「少一个提醒」严重得多——整个系统对一个目标的判断，来自**立目标那一刻抄下的一份成功标准副本**（`criteria`），而设计说真身在云之家、改成功标准就是去改那份文档。两句话合起来是：**只要有人在云之家改了正文，agent 与页面都永远不会知道**。段 4f 里做的 `criteriaDrifted` 只抓得住「我们自己那份副本变了」，而副本只在有人经我们改它时才变——恰恰是真身不作为源头的那种情况。

### 做法：消费时刻的一次比对，不是轮询

设计原文是「Recorded at the **consumption-time check**」。所以不养定时器：`goal_evidence` 与 `goal_report` 在被调用的那一刻顺手看一眼真身。这同时兑现了「随时可对账，不是持续对账」——没人问的时候，系统不该替谁盯着一份文档；而**有人问的这一刻，恰恰是那份副本会被当真的一刻**。

三种结果分开，合并任意两个都是撒谎：**没变** / **变了**（写 `truth/changed`）/ **看不了**（通道不在、不是知识库链接、文档被删）。把「看不了」说成「没变」，是用一次失败的观察冒充一次成功的观察——这套系统里最贵的谎，因为它让人以为对过账了。

### 实测撞出来的关键一条：指纹取错了会得到一个永远说「没变」的检查器

第一版用 `doc get` 的 `version`。**实测：往正文里插一段话，它纹丝不动**（那是节点元数据的版本——改标题、移动、改权限才动），`updateTime` 也不动。正文的版本在 `doc block list` 的顶层。

取错的后果是最坏的一种：一个永远答「没有改动」的检查器，比没有检查器更危险。改成先问正文版本、失败再退回节点更新时间；指纹是**一个带来源的字符串**（`blocks:3` / `node:1@…`）而不是数字——两条路的数字不在一个量纲上，混着比会凭空报出一次并不存在的改动。

### 端到端实测（一次性探针，全程零真实对象）

在「我的知识」里建了一份可弃文档 `真身之变探针-v412`，走完整条路：

1. 对 agent 说「立个目标…」→ **它只提了案**（铁律：人签发），确认后目标落库；
2. `goal_evidence` 第一次读 → 图上落下 `truthFingerprint: blocks:2`，**没有**误报变更，agent 原话：「真身：第一次记下它现在的样子（正文版本 2）——从现在起它被改动会被发现」；
3. 用 CLI 往那份文档正文里插一段（模拟有人去云之家改了成功标准），正文版本 2 → 3；
4. `goal_evidence` 再读一次 → **图上第一次出现 `truth/changed`**，agent 原话：

   > 真身已被改动（blocks:2 → blocks:3）。**下面这份成功标准是我们上次抄下来的副本，可能已经过时**——要对着当前正文判断，先用 yzj_doc_block_list 读一遍真身正文。

5. 目标页横幅同步显形，而且带的是 **agent 的原话**，不是页面自己猜的一句。

事后：目标已作废、探针文档已删除。

### 仍然收窄的部分

- **人的感知形态待体验后再定**（Bruce 裁决）。现在只是把 agent 写下的那句话接到既有横幅上，没有新增任何 UI；要不要主动推给人、推到哪儿，等用起来再说。
- **只有目标的真身被盯着**。工件引用（`lineage/produced` 的 URI）走同一个家族，但还没有接消费时刻的检查——它们的消费点在预览与归集里，形状不同，等有真实的「引用失效」样本再设计。
- **`kind: 'missing'` 与 `'stale'` 仍无生产者**：现在只产 `'changed'`。文档被删时我们答的是「看不了」而不是「没了」——因为一次读失败分不清是删了还是权限没了，而把两者说成同一件事，正是这个文件反复在拒绝的那类事。

## v4.14/v4.15 审批对象交互模式：验收卡 + 可应答分类学 + 会话决断条（2026-08-21）

设计侧 #46（信号即门）与 #47（可应答分类学与决断条空间规则），技术侧 §4/§5.2/§7.1 与附录 4g 同步。本段是按它们做的完整开发。

### 一句话：把「需要你」从一份名册改成一个接口

此前每一处「需要你」的投影，都是一份**手写的类型名单**——收件箱一族一段 `query({kind, status})` 自己拼一句中文，群视图另写一份四族名单，目标页决断层再写一份音调白名单。名单不会报错，只会**安静地少一种**：`assessment` 就这样在收件箱里缺席过一整段时间，一份写好的差距简报静静躺着，没有任何一处提它。

Bruce 问「确认是其中一种状态，还有其他状态吗」——**任何以枚举场景作答的名册，都会在下一个场景出现时被再问一次**。所以答案不是把名单补全，是让名单不再存在。

### 分类学落在哪：家族自己说话

`CardDefinition` 多了一个 `demand(state)`，家族用它回答两个问题——**我属于六种交互模式的哪一种**（单答确认／逐条裁决／双动词验收／签发／多出口评估／待答询问），以及**我属于三层定律的哪一层**（阻塞待答／默认生效可纠／信号）。字面也由它自己写。

服务侧一个抽象查询 `ctx.yzjCards.demands(viewer)`：遍历 `pendingAnswerables`，挨个问家族「你在等什么」。**决断条、收件箱的「需要你」、群视图话题卡徽标、目标页决断层，四处读的都是它，一处都不认识 approval 或 task。**

这条不是靠自觉维持的——`decision.spec.ts` 里有一条用例，当场注册一个这套代码从没见过的家族（转办认领，设计里押在采纳门后的那一员），**一行视图代码不改**，它必须自己出现在条上、出现在收件箱里、带着自己的徽标。做不到就说明「抽象查询」名不副实，而下一次增员会重演差距简报缺席那一次。

**缺省是「进决断面」**。漏声明会发生，漏显示不可以——一个在等人答却哪儿都不出现的对象，正是幽灵承诺禁令要禁的那种东西；没声明的家族按阻塞待答收编，字面退回它自己文本投影的第一行。反过来，`signal` 与 `default-effective` 必须**显式**说出来。`loop-matrix.spec.ts` 另有一条守住主路：每一张注册在案的卡都得自己声明，兜底只是安全网。

### 什么不进条，和什么进条一样重要

`commitment`（进行中／逾期）与 `waiting`（等着别人）现在显式声明自己是 **`signal`**。它们要的是被看见，不是被裁决——把一条逾期承诺塞进决断条，人就得为每一件还没做完的活按一次「我知道了」，那正是「宁默认勿阻塞」拦下的东西，也是零维护死掉的样子。它们仍然出现在收件箱的留意层（运行中／等待中），动词就近长在板上那一行。

### 验收卡：家族第六员

「找不到验收项」的病根不是它滚走了，是**它长得不像一个等你的东西**。可应答检验当年点名了确认、裁决、租约、询问，唯独漏了验收。现在 `task` 的终态自己声明 **③双动词验收**，中断自己声明 **⑥待答询问**——把两者说成同一种，等于请人去验收一份不存在的产出。

三条收紧的落点：

- **只有「有交付的完成终态」出卡**——失败／超时／空回合走既有作废路径，作废的任务连 `demand` 都没有。这一条在数据层是**结构性成立**的，不靠 UI 把关。
- **终态回帖 = 过程摘要 = 验收卡是同一条消息**——`finalReply` 本来就是一体三面（正文 + 过程摘要 + 验收动词提示 + 卡句柄），未改，加了用例锁住不双发。
- **`allowedActors` = 委派者 ∪ 操作者**——此前是「有 openId」，那不是一道检验，它放行了房间里的每一个人。`task/opened` 现在记下 `delegatedBy`（触发那条消息的发送者）与 `operator`（这条会话的账号），验收／打回／作废／继续四个动词走同一道门。记在对象上而不是事后从 `sourceAnchor` 反查那条消息：消息会滚出窗口、会被撤回，而验收权的依据不能取决于一次还读不读得到的历史查询。老任务（两个字段都没有）退回旧行为——**一张没人能答的卡本身就是一种失败**，而它会发生在那些正等着被验收的历史任务上。

### 会话决断条

时间线**顶上、滚动容器外面**的一条细线。数据是 `window_.cards` 的一次过滤投影——和流内那些卡是**同一个数组**，所以「同源、先答先赢」不是纪律，是想让两边说不同的话都做不到。

- **指针投影非复制落座**：条上只有名字和一个跳转，点下去是 `scrollIntoView` + 高亮闪一下。卡留在它出生的位置，前后语境强制在场——因为语境就是决断的证据。顺手防住「批量清账不看上下文」。
- **答完即溶**：`demand` 没了 chip 就没了，一件不剩时整条不占位。
- **一行封顶**：并排的是**真的放得下的那几个**，其余折成 `+N`（点它跳到第一个被折起的那件，**不展开成清单**）。设计原话就是「放得下的前几个」，而固定三个不是那个意思——实测过：右栏一开中栏被压窄，三枚 chip 挤成「待验收 农佳捷…」「待验收 抱歉，」「待验收 代」，第三枚只剩一个字，占着位置什么也没说，而它挤掉的恰是能让前两枚说清楚的空间。条自己量自己（回调 ref + `ResizeObserver`，因为它会整条消失又整条回来），窄了就少并排一个、多折进 `+N`。另有两道兜底：`.chips { overflow: hidden }` 与每枚 chip `max-width: 34%`——一条四百字的交付摘要即使被压缩后仍会是最宽的那个。
- **本语境直属**：`cardsFor` 本来就只装本话题的对象，所以「绝不上卷」在数据层就成立了。
- **条长即治理信号**：五件起，条尾长出「经常在确认这类操作？设为租约 ›」。

### 逐级兑付：每一跳都是门

链上四跳，全部在真实数据上点过：侧栏 chip「✓ 8 待验收」→ 落到一个真的会话且那一行确实是待验收；侧栏场所行徽标 → 它下面第一行说的那句（**徽标不再自己拼一遍**，否则头上写「待确认」、点进去第一件事是「冲突待裁」）；群视图话题卡徽标「待验收」+ 卡上那句它欠的话 → 话题；决断条 chip → 滚动定位 + 高亮到那张卡。

`decision.spec.ts` 把它写成断言：收件箱每一个非零计数都得有一个落脚会话，且**那个会话此刻确实显示着那个音调**；条上每一枚 chip 都指得到一个真的对象。

### 顺带修掉的两个

- **冲突从来不进任何一个 chip 计数**。它此前自成一档音调（rank 2），而计数只统计 confirm/review/running——于是一件已经把工作停在半路的事，在三个 chip 里一个都不算，没有任何入口能到它。归进「单答确认」之后它有门了。
- **`cardsFor` 那份手写名单**里没有 `assessment` 的那段时间，差距简报连流里都不出现。现在遍历的是卡注册表。

### 本段的收窄（如实）

- **`default-effective` 这一层有定义、无生产者**。挂接推断 ack、回执状态提议、蒸馏公示三样行为都存在，但都不是「带这个层的可应答对象」——枚举值先立在那里，是为了让下一个写家族的人知道这一层存在、以及塞错层的代价。
- **主楼没有决断条，这是对的，不是漏的**。今天没有任何对象直接出生在主楼（都挂在某个 topicKey 上），而按「绝不上卷」，话题里的待答**必须**只改话题卡的徽标。`loop-matrix.spec.ts` 加了一条对偶断言：每一个阻塞待答都得归属一段语境——否则它在决断条、收件箱、群视图三处都不出现，谁也不吵，只是永远没人答。
- **冲突丢了那抹红**。分类学把冲突确认归进单答确认，颜色就和确认同档；「冲突待裁」四个字由家族自己写在徽标上（`demand.badge`），一屏上仍分得开。少一种颜色，少一份要维护的名册。
- **租约仍然没有签发者**。条尾那个入口点下去落到场所合同面板，那里如实写着「授权租约还没有开门…它押在『审批疲劳真实发生』这道疼痛门后面」。**信号即门要的是能兑付，不是能兑现**——指向一个说实话的地方，比指向一个假装能签发的表单诚实。
- **群视图「更早的话题」折叠行只显示徽标，不显示它欠的那句话**。那是一行紧凑的索引，徽标已经付得出这一跳。
- **答完即溶只在单元测试里验过**。要在真实数据上验，就得对一件真实的交付按下「验收」，那会往一个真实的群里发一条回声——造得起的实验才做。

|---|---|---|
| **`placeView` 的「还在办」被我悄悄扩宽了** | 我把那份四族名单换成「遍历卡注册表」，顺手把 `commitment` 也算进了「还在办」——而**承诺比话题活得久**：一条人家欠着的活可以挂三个星期，它所在的对话早就办完归档了。后果是收件箱（那里承诺根本不定音调）说这个话题空闲、群视图说它进行中，**同一件事两个屏幕两种说法**。拆枚举不是目的，拆掉的那个枚举当时正拿着一条语义 | 留意层只问 `task`/`waiting` 两族（任务未终态、还在等人），等人答的那几种走抽象查询——**从四族减到两族**，比原来还少，语义一字未动 |
| **`conflict/flagged` 不带听众集合** | 冲突卡是**明确投到活正在干的那个场所**的（「冲突要被造成它的人看见」），可对象自己说「我没被说进任何场所」。两句话对不上的后果不抽象：群视图问「这个话题欠着什么」，隔离函数如实答「什么都没有」——一件已经把活停在半路的事，在它停下来的那间屋子里没有任何徽标，而那张卡就躺在群里。这一条**先于本轮就在**，是新做的群视图徽标把它照了出来 | 出生时刻带上 `audience: [placeKey]`（与确认卡同一约定：投递是另一回事）。写在出生而不是投递成功之后——这次暂停**已经**发生在那间屋子的活上了，一次通道抖动不该把它从那个场所的视野里整个抹掉。别的场所照旧看不见，隔离函数没有被放宽，只是不再自相矛盾 |
| **徽标字面有两份映射表** | 服务端一份、决断条一份。加第七种模式的那天要同时想起来改两处，而漏掉的那一处不会报错，只会把新模式画成一个别的词 | `demandOf` 出服务的门之前就把 `badge` 定死（家族自己写的，或从模式推的）。客户端删掉那份表 |
| **`jumpToCard` 用数据拼 CSS 选择器** | `[data-card="${kind}:${id}"]`——今天的 id 全是哈希，看着安全，可 **id 是数据不是常量**：哪天某一族的 id 里带上一个引号或方括号，这里抛的是语法错，而抛错的时刻恰恰是有人正想找一件事在哪 | 扫属性，不拼选择器 |
| **返工轮次挤进了徽标** | `待验收 · 第 2 版` 把一个变长的事实塞进了一个固定词汇的槽（待确认/待裁决/待验收…）。设计原话是「轮次在**卡上**可见」，而卡上本来就有那一行「已返工 N 轮」 | 撤掉徽标覆写 |
| **两次测量不是同一个量** | 条首帧读 `getBoundingClientRect()`（含内边距），`ResizeObserver` 给的 `contentRect` 不含——左右各 20px，差 40。阈值附近这 40px 会让「第一次 resize」在什么都没真的变的情况下把 chip 数从 3 翻成 2，看上去像随机重排 | 观察器优先读 `borderBoxSize`，两次同量 |

**新增用例覆盖上面每一条**：留意层与归档两屏一致（承诺挂着不让话题变热、只等人答的话题仍是热卡）、冲突在它停下来的那间屋子里看得见（含「别的场所仍看不见」）、私语域的差距简报不从群视图漏出去（可见域法则）、重启中断的确认自己回到收件箱（此前那段手写查询只问 `pending`，一次重启之后它就再没有入口）、徽标出门前已是定值、窄栏少并排多折 +N。**全仓 719 条跑 717 通过**（两条红是 `packages/ui-yzj` 先前就在红的全局 bundle 补丁）。真实数据上复验：宽 791px 画三枚 +2，缩到 640px 干净地变两枚 +3。

## v3.10 翻案回执与 yapi 面实测（2026-08-21 下午）

技术方案 v3.10 对本清单做了裁决（4h ①-⑥），v3.9 同时给出承诺/纪要/日程三个新 adapter 的规格，并明写「**实测清单①-⑧先于任何 adapter 开工**」。本段先交实测，再交按裁决拾取的开发。

### 实测：先量，再决定造什么

技术方案把 adapter 押在八项实测后面，那八项此前没人打过。这里打了能打的，结果里**有两条改写了技术方案的事实基座**。

| 项 | 结果 | 依据 |
|---|---|---|
| ① aisteno 会话获取 | **网关是通的，缺的只是会话**——`POST /gateway/livestream/api/aisteno/list` 无凭证访问返回 `{"errorCode":10000018,"error":"当前会话超时"}`，**不是 404**。门在那儿、从公网路由得到，要的是一把会话钥匙 | 本机 curl，2026-08-21 |
| ② callBackUrl | 未打（要先有会话） | — |
| ③ meetingId↔stenoId | 未打（同上） | — |
| ④ 391 网关鉴权 | 未打（同上） | — |
| ⑤ user-action-item sourceType | **打不了，因为写入口在公网不存在**：`/api/internal/user-action-items` 返回 `{"errorCode":10000404,"error":"请求的URI地址不存在"}`；`/api/assistant/user-action-items/pending` 与加 `gateway/workassistant-service` 前缀同样 404。「零 gateway 化」从**文档推断**升级为**实测事实** | 本机 curl |
| ⑥ schedule/brief | 未打 | — |
| ⑦ **417 detail/queryByUser 真实字段** | **打了，而且推翻了两个字段的用法**（见下） | `yzj-cli calendar event get`（与 417 是同一批接口） + yapi JSON |
| ⑧ 知识库 docId ACL × 听众 | 未打（需要一次真实的速记上传） | — |

**⑦ 的两条更正，都要紧：**

**其一，「417 日程 V12」和 CLI 已有的 calendar 命令是同一批接口。** yapi 导出里 417 的路径就是 `/gateway/cloudwork/calendar/{detail,queryByUser,create,modify,cancel}`，而 CLI 二进制里的字符串一字不差。所以「唯一确认对第三方开放的写路径」这条是对的——**而且我们早就在走它了**，日程不需要新 adapter，需要的是把图接上去。

**其二，`workData` 与 `redirectUrl` 是写入字段，不是可读字段。** yapi 里它们只声明在 `create` / `modify` / `repeatMeeting` / `batchModify` 上；`detail` 不声明，实测响应里也确实没有（真实 detail 字段：`batchId` / `organizers` / `participants[含 openid, joinStatus, status, mandataryOid]` / `noticeTimes` / `files` / `images` / `agent` / `repeat` / `roomId` / `recordInfo`）。这改变两条结论：

- 技术方案说 `workData{msgId,groupId}` = 「**生成边**的真实落点」。**只对了一半**：它是官方的记法，但**写得进、读不回**——从平台**查不出**「这条日程是哪条消息生出来的」。所以那条出生边只能记在**我们的图上**，平台字段是它的一次单向投影。这恰是三角色定律自己的话：那是投影，不是证据源。
- `redirectUrl` 只在 `create` 上——**这反而是好消息**，而且方向比原文更明确：它是我们**写给平台**的，让平台自己的日程通知直接跳回 dsh 会话页。v3.9r 那条「应答环不外包——平台提醒必须回链图上可应答对象」因此不是希望，是一个建日程时就能填的字段。

**结论对开工顺序的影响**：日程可以现在做（接口已在手）；纪要卡在一把会话钥匙上（门是通的）；人类承诺叶子的写入口**在公网不存在**，`fallback = 日程投影 + IM 登记消息` 里的 IM 那一半本来就在跑。

### 自审：4h② 那一版**在真文档上根本读不出字**（同日）

`readGoalBody` 的第一版按 `text` 取块里的文字。对着真文档打了一次 `doc block list`，返回的形状是：

```
data.blocks = [ { type: 'doc', content: [ 节点… ] } ]
节点 = { type: 'heading', content: [ { type: 'text', content: '🏠 认识知识空间' } ],
        childNodes: [ …同一份内容… ], textContent: null }
```

**文字挂在 `content` 上，不是 `text`。** 所以第一版对任何真实文档都返回空串 → 上层判成「这份文档没有正文」→ 退回签发时的副本 → **一切看起来正常**。整段 4h② 等于没做，而且是以「做了」的样子没做。

最难堪的是它**测试通过**：夹具是照我自己的假设编的，测试和代码在一个谁都没验过的形状上达成了一致——而那种一致什么都不证明。这个仓库里 `stream.spec.ts` 顶上已经有一条注释在讲同一件事（当年用 `user-message`/`assistant-message` 这种编出来的节点类型，测试全绿，渲染出来一个字都没有）。**我又犯了一次。**

修法三处，外加一条纪律：

- **形状按实测重写**：递归走 `content`（字符串是叶子、数组是容器），`childNodes` 是 `content` 的副本所以只走其一（两个都走会把每段读成两遍），顶层每个直接子节点各占一行——成功标准是逐条判的，拼成一整行会让两条标准粘成一句话；
- **夹具换成从真实返回里抄下来的那一段**，并在注释里写明它的出处。以后再改这个解析，测试挡得住；
- **live 复验**：临时挂一个真 bridge（spawn `yzj-cli`）跑 `readGoalBody`，确认读出了那份文档的正文，跑完删掉。夹具证明逻辑，实跑证明形状——两样都要。

### 同一轮自审的另外三处

| 缺陷 | 为什么要紧 | 修法 |
|---|---|---|
| **指纹与正文各读一次 `doc block list`** | 不只是多打一次 CLI：两次之间有人改了正文，指纹会说「没变」而正文是新的那一版——**一个自相矛盾的回合，而且矛盾的方向恰好最坏**（说没变，却按新正文判） | `inspectGoalTruth()` 一次读取两样都出；`checkGoalTruth` 接受预取结果 |
| **`criteriaBasis` 仍记副本** | 4h② 的整个点是「判据换成真身正文」，可落库时记的还是副本——三周后回头看这条结论，`criteriaBasis` 是唯一能回答「当时照的是哪一份标准」的东西，而「照副本判」与「照正文判」是两种可信度完全不同的结论 | 优先记正文；读不到才退副本，并在字符串里明写「（读不到真身正文，照签发时副本判）」 |
| **`goalsPerTopic` 成了死代码** | 4h⑤ 换判据之后没人再读它。留着会让下一个人以为「一个话题挂几个目标」这件事仍然参与判断 | 删 |

### 4h① 状态回写真身：全组那半边终于活了（同日）

**「目标活着，不需要任何人去维护目标」此前只对操作者成立了一半。** 板上什么都对——挂接零操作、状态自动、产出自动；而全组打开云之家上那份目标文档，看到的还是立目标那天的样子。设计说这条边有**两个听众、两种刷新率**，第二个听众一直是空的：`goal/written-back` 连 schema 都没有。

新增 `goal-writeback` 族与 `applyGoalWriteback` 监听器。四条纪律，每条对应一种它会变坏的样子：

- **只在生与死两个时刻写。** 每次进度都推回去，那份共读的文档就变成一条日志流——而它的价值恰恰在于短到有人愿意读。改期、回执、移交一律不写（有用例锁）。
- **写过的不再写。** 每笔落一条 `goal/written-back`，重启先问「这笔写过没有」。少了它，重启扫一遍就会往一份全组在读的文档里再贴一遍同样的行。
- **失败也落一条。** 不落则每次重启无限重试，试到文档里全是它；而板上说「已回写」、文档里什么都没有，是幽灵承诺换了个通道复活。
- **死了要补生。** 一条在这套东西上线前就结束的承诺，`born` 那笔永远等不到事件触发；只写 `settled` 的话，文档里会冒出一行「已完成」而组里从没见过它被登记。两笔都补，`born` 在前。

**不弹第二张确认卡**：人在提案裁决那一刻已经签过字（卡上写着「确认即签发」），这里再弹一张就是同一个主权时刻收两次费——和代发登记话语同一个道理。写入本身仍走 guard 的写权限档。

**live 验证（一次性探针，全程零真实对象）**：在「我的知识」建一份可弃文档当目标真身，登记一条子承诺 → 文档里出现 `· 拉三家竞品 — 张锐 · 周五`；验收它 → 文档里再出现 `· 拉三家竞品 — 张锐 · 已验收`。两条 `goal/written-back` 均 `written`。事后两份探针文档已删除。

单元 12 条 + live 1 次。全仓 **735 条全绿**。

### 4h③ 当场建真身：把一件 agent 做得到的事，别再推给人（同日）

「agent 建不了文档」是一次**能力误判**——`yzj_doc_create` 与 `yzj_doc_block_insert` 一直在工具面里。误判的代价不是少一个功能，是提案卡上那句话把人赶出了产品：「先在云之家建目标文档，把链接跟确认一起发过来」。

改了两处，**人签发这一步一个字没变**：

- `goal_propose` 的工具说明现在明写：没拿到链接就**先建一份**——`yzj_doc_create` 建文档、`yzj_doc_block_insert` 把成功标准写进正文，再带着链接提案。后半句是 4h② 的直接后果：**评估是从正文里读回成功标准的**，只活在提案里的标准，是没人能拿来对照的标准。两次调用都走操作者平常的写确认。
- 卡上那句话从一条作业改成**两条路**：「回一句『建一份』让我把文档建好（成功标准会写进正文），或者自己建完把链接跟『确认』一起发过来。」

**「建一份」刻意不进 `replyHints`。** 那一列是卡上的**动词**，会被关键词解析成一个动作；而「建一份」是说给 agent 听的一句话（它去建文档、写标准、重新提案）。混进动词表就成了一个点下去没有对应动作的承诺——正是「没有不可兑付的信号」要禁的那种。这一条写进了用例。

**737 条全绿。**

## 事件枢纽 obj-event：日程五边落图（2026-08-21 傍晚）

按 §5.6 做的。接口早就在手（实测确认「417 日程 V12」就是 CLI 已有的 `calendar` 那批），缺的一直是**把图接上去**。

### 五条边，各自的落点

不复制日程。标题、时间、参会人、`batchId` 都从平台读——图上只记平台答不了的那几条：**服务**（这场会为哪个目标开）、**触发**（为它要准备什么）、**生成**（从哪句话长出来的）。**操作**与**聚合**平台自己有证据，不抄。

「生成」那条必须记在我们这儿，是实测逼出来的结论：`workData{msgId,groupId}` 是官方给的出生凭证字段，但**只声明在 `create`/`modify` 上，`detail` 不返回**——写得进、读不回。不在图上记，「这场会是从哪句话里长出来的」就没有第二处能答。

### 材料就绪度：三档，且不是字段

`ready` / `partial` / `none`，从挂在会上的承诺状态**推**出来。存成字段第一天就会撒谎——有人干完了忘了回来点一下，会前那一眼看到的还是「没准备好」。有一条用例专门锁它：关掉一条承诺，**不追加任何 `event/*` 事件**，就绪度自己变了。

三档到顶，不做百分比：再细的分辨率不会改变任何人会前的动作，只会让那一行变长。

### 三个动作，刻意都不含「替你派活」

`event_brief` 读，`event_link` 把**已经存在的**承诺挂上去，`event_post_materials` 把材料清单写进日程描述。**没有**「为此会准备 → 自动派活」——「为此会准备」在设计里是传送门 CTA，委派那句话仍然由人在会话里说。

清单只列**真的有产出的**：一份写着「待办、待办」的描述是第二块看板，不是简报。

### 实跑撞出来的两条（单元测试都没覆盖到）

**其一，改描述必须连标题一起送。** 只带 `description` 的请求被平台拒了：`code=4000 会议标题不能为空`——它要的是一份完整的会议，不是一个字段的补丁。改成先读回此刻的标题再一起写。用**刚读到的**标题而不是图里抄下的旧标题：这一读一写之间要是有人改了会议名，前者把它原样写回（我们没改它），后者会把别人的改名悄悄回滚。

**其二，字段名两侧不同名。** 事件里写 `materials`，枢纽读 `postedMaterials` → **永远读到 undefined**。后果不是少一句话：「写过就不再写」那道闸永远不闭合，每调一次就往一份全参会人看的日程描述里重写一遍，而会前简报永远在催「快去写」。和 4h② 那次是同一类错——**我断言了一个形状而没有去看它**。补了三条用例把这条路盖住。

顺带一条：写没写成材料清单**不写进事件的 `status`**——图的查询层按 `state.status` 过滤对象，而一场会的状态不是「材料写没写成」。

### 一次值得记下的假警报

第一版 live 跑出来「没写进去」，而日程描述里**明明写进去了**。原因在我临时搭的那个 bridge 替身：它把「输出不是 JSON」当成了失败，而 `calendar event update` 成功时回的是一行 `ok`。**真 bridge 是对的**（`ok` 看退出码，非 JSON 只是 `json` 留空）——**替身比生产代码更差，于是造了一个假的失败**。教训与「夹具照假设编」是同一条：验证工具本身也会说谎。

## 纪要双桥：decisions→目标提案 / actionItems→承诺提案（2026-08-21 夜）

按 §5.6 与设计 v4.16/v4.17 做的。**传输是一道门，映射不是**——所以映射今天就写、今天就测，传输留一个接缝。

实测（本轮早些时候）：`aisteno/list` 在公网网关上答的是 `{"errorCode":10000018,"error":"当前会话超时"}` 而**不是 404**——门在那儿、路由通，缺的只是一把用户会话钥匙。把映射押到传输之后，等于把最需要被推敲的部分留到最赶的那一天写。

### 两座桥，终点都是提案

`minutes.decisions[{content, basis, owner}]` → **目标提案带依据**；`minutes.actionItems[{text, assignee, dueDate, executors[]}]` → **承诺提案带 openId**。字段名取自 yapi 导出的真实声明（455 livestream），夹具照抄——这个仓库已经为「断言一个形状而不去看它」付过两次学费。

两份**分开**：决议是方向、待办是活，合成一张卡，人就得在同一次点击里既定方向又派活，而那是两个不同的主权时刻（签发 vs 逐条裁决）。

落库的**一条承诺、一个目标都没有**（有用例锁）。速记再准，抽出来的也只是稿子。

### 三级可信度：只有第一级挂人

绑定的 `openId` > AI 写的名字 > 「发言人3」。后两级照样进裁决，但**线索写进条目正文、不写进执行者字段**——写进去的后果不是「填错一个格」：确认那一刻会以操作者的名义把登记消息发进那个人的会话，而我们并不知道组织里叫这个名字的是不是他。回执里把这句话说给人听。

「发言人N」当成**认不出**而不是名字：它是速记认不出说话人时的占位，当名字挂上去，裁决面上会出现一条「发言人3 负责…」，读的人得先去猜那是谁。

### 去重按内容，不按时间

纪要**没有版本号**。按时间戳去重会把同一件事提第二遍——纪要被人编辑一下时间戳就变，而内容没变。指纹落在提案的 `sourceAnchor` 上；同一场会重复摄取一条不再提，新加一条就只提那一条（两条用例）。

### 两处如实的收窄

**参会人只作为证据，不冒充听众。** 设计说纪要要携带参会人听众集合，而图的听众词汇是 `placeKey`，表达不了「这几个人」。拿一个表达不了的东西当听众用，等于给了一个**假的隔离承诺**（§6.8 词汇卫生条款）。所以提案默认只有操作者看得见——而**确认那一刻就是人签发的越境**，纪要原文随代发消息进入新听众是合法的，因为有人签了字。

**速记侧只读，写在类型上。** `YzjMinutesSource` 只有 `since` 与 `detail`，没有任何写方法。`minutes/action` 确实能写回去，但那些待办**没有 per-item id、更新是全量替换**——写回去会把人在速记里手工改过的东西整段覆盖掉。这条铁律写在接口上，而不是写在注释里指望别人记得。

### 验证

单元 15 条。通道缺席时的回执**说清它卡在哪一环**（「会话超时，不是 404，缺的是钥匙」）——一句「没接上」会让人以为要去申请开接口，说清是钥匙问题才知道该去要什么。

**全仓 769 条全绿，八包 typecheck 与 build 干净。**

## 事件枢纽 UI + @成员补全（2026-08-21 夜）

### 一处必须先说的更正

我上一轮把「`redirectUrl` 回链」列为**最该先做、成本最低**的一项。**错了**：`yzj-cli calendar event create/modify` 根本不接 `redirectUrl` 与 `workData`——这两个词连二进制里都搜不到。它们在 417 的 API 声明里有，在**我们够得着的那一层**没有。

### 事件枢纽终于有人看得见了

此前它只有 agent 够得着——`grep` 整个 `next/surface/` 一个 `event` 都没有。现在它是**承诺板里的一段**，不是第四个入口：设计明写不增殖注意力入口（收件箱／卡徽标／决断条三层分工已经完整），而 v4.17 也把「今日日程」定为晨报的一个**段**、不是晨报本体。

一行三样东西：**几点 · 叫什么 · 准备好没有**。挂着的活折在下面，因为会前真正要决定的只有一件事：还差什么、要不要现在补一刀。

- **只读今天、且只读还没开完的**——昨天的会没有会前可言；范围一放大，这一段就长成一个日程列表，而云之家里已经有一个够用的日历了。
- **就绪度跟着承诺走**：有一条用例锁住「关掉一条承诺、不追加任何 `event/*` 事件，就绪度自己变了」。
- **图上没见过的会说的是「还没挂过东西」**，不是「没准备好」——两者差着一个「我们根本还没参与」。
- 挂着的活有产出、而材料还没进日程描述时，行下面明说一句：**参会的人在日程里看不到它们**。

### 自审：传送门差点把一场会当成目标

「为此会准备」和「委派」共用同一个传送门组件。第一版直接复用了 `goalRef`——于是**会的 id 会被当成目标写进 `goal-context`**，那个话题里此后每一条新承诺都挂上一个根本不是目标的 URI，把目标图污染掉，而没有任何地方会报错。

## 第一次把整套东西当成一个系统跑起来（2026-08-21 深夜）

按第一性原理选的这一步：**每个零件都验过、整机从没转过，那就不是一个能用的系统。** 这一整天我一直在加面——家族、推导、工具、界面——而三次「测试全绿但线上不工作」（真身正文读不出字、事件字段两侧不同名、bridge 的 `error` 字段根本不存在）都只有在**真的跑一遍**时才现形。所以停止加面，先看装配。

### 装配一开就抓到两个方向相反的错，正好互相抵消

打开真实实例的图日志，`goal/written-back` **零条**——而日志里躺着 11 条带 `parentGoalRef` 的承诺，实例今天重启过好几次。所谓「live 验过」的那次，是在一个我自己开好库的夹具里跑的；**真装配里它一次都没跑过**。

原因是补账那一遍在**插件挂载**那一刻就扫，而账号分区是**通道拿到身份之后**才 `selectAccount` 的——扫的时候库还没打开，`query` 返回空。

而假如它真跑起来了，会更糟：它会把**全部历史**的子承诺挨个补写进真实的目标文档，而那些文档是同事在读的。**一条三个月前出生、两个月前就关掉的承诺，今天补一行「已完成」进去不是修复，是往共读的文档里倒噪音。**

两个错方向相反，于是谁也没被发现。

### 修法：等库打开 + 记一道水位

**回写是「出生与死亡时刻」的一条边，不是一次对账。** 它只对上线之后发生的事负责——水位之前的东西不是「漏了」，是**不归它管**。新增 `goal/writeback-began`：第一次上线记下当时的 seq，之后每次重启读回同一个数，补账只覆盖水位之后那一小段（那正是补账本来要修的：崩在「文档写了但事件没落」之间的那一小截）。

**但「把一条旧承诺挂到目标上」照写**——那是**当下发生的一件事**（这个目标从此有了这个孩子），不是回溯。水位管的是启动时的回溯，不是新发生的挂接。

顺带修出两个：

- **水位读错**：第一版用 `rawEvents([])` 取最后一条 seq，而它是**按类型过滤**的——空数组意味着「一个类型都不要」，水位恒为 0，补账把全部历史当成新的。一个返回空的读取和一个「什么都还没发生」的库长得一模一样，正是这一族反复在防的那种错。
- **双写竞态**：「查一下写过没有」和「写下去」之间隔着一次 `await`——监听器和补账那一遍可以同时走到这里，双方都查到「没写过」，然后**同一行往一份全组在读的文档里贴两遍**。落库的幂等记录挡不住它：那条记录要等写完才存在。加了 in-flight 集合。

### 然后，闭环第一次在真装配里跑通

在真实实例上：建可弃文档 → 板上「立目标」签发（seq 237）→ **插件挂载、水位落在 238，回写零条**（历史没被倒进任何真实文档）→ 在无归属里勾一条挂到这个目标（seq 239）→ **`goal/written-back` 出现（seq 240）**，那份文档里真的多了一行：

```

```

→ 移出改挂（seq 241）→ 目标作废（seq 242）→ 探针文档已删除。

**这是回写第一次在真系统里工作。** 此前它只在夹具里工作过。

**778 条全绿，八包干净。**

### 收尾：一次偶发的红，和一个靠运气绿的等待

提交那一版之后全量跑出一次红（单跑十二次全绿，套件满载时每十次红一次），暴露了两件事：

- **`off()` 只摘监听器，补账那一遍还在路上。** 旧实例的补账与新实例的补账各有各的 in-flight 集合，两边都查到「没写过」→ **同一行往共读文档贴两遍**。热重载、合同变更、插件重挂都会走到这条路上。加了 `disposed` 闸，卸载之后补账立刻停。
- **夹具里那个 `settle()` 是靠运气绿的。** 它睡固定 8 拍，而 `graph.append` 落盘是真的磁盘 I/O——满载时 CLI 那次调用看得见、写下的事件还没落，断言读到 `undefined`。**固定睡眠是一个关于时序的假设，负载下一定会错。** 我这一整天都在说「靠运气绿比红更糟」，然后自己在夹具里写了一个靠运气绿的等待。改成轮询到静止：连续两次采样计数不变才算完。

改完连跑十次全量，**778 条稳定全绿**。

配套的三个判断，每个都对着一种「静悄悄地错」：

- `fenceOf()` **三值**：`undefined` 是「没看着」不是「没有」。看不着退回问图「这个目标

  一行裸账被当成标准。
- **同一份文档的回写排队走**：`inFlight` 挡的是同一笔写两遍，挡不住两笔撞同一份文档
  各贴一条栅栏。顺带买到 born/settled 在文档里顺序确定。
- `criteriaBasis` 退回副本时**记下为什么退回**：通道断了、文档被删、还是「线以上压根
  没写过标准」，三个月后这是三个完全不同的故事。

### 三、一次正在发生的生产故障：CLI 改了参数名，回写全断了一个下午

手敲一条 CLI 建探针文档时撞上的。**yzj-cli 今天 14:52 升到 0.1.4**，把 `doc block insert`
的 `--block-id` 改成了 `--parent-block-id`（而 `doc block list` **至今仍是旧名**，两条命令
一新一旧）。从那一刻起，线上每一笔目标回写都被 argv 解析直接拒绝，**一个字都没写进任何
一份文档**。上午那两笔 `written` 是升级前写成的。

比故障本身更要紧的是第二件事：**没有人知道。** `goal/written-back` 这个家族**一个读者都
没有**——失败照实落库，然后没有任何代码、任何面、任何人再看它一眼。这个文件开头就写着
「『组里到底知不知道』得有一个答案」，而那个答案此前只存在于日志里。**一条没有读者的
记录是注释，不是机制。**

所以除了改参数名，给它装了读者：写不进去开一条 **waiting**，照抄 `channel/health.ts`
（等待可应答、可投影、重启之后还在）。一个目标一条，不是全局一条——坏的是「这一份文档」；
id 里带**已成功笔数**当代次，因为等待是吸收态，没有代次第二次故障会撞在墓碑上。

| 命令 | 事实 |
|---|---|
| `doc block insert` | 父块参数是 `--parent-block-id` |
| `doc block list` | 父块参数仍是 `--block-id` |
| `insert` 省略 `--index` | **追加到末尾**（CLI 帮助写的「默认 0」不对） |

### 七、少一个动词是设计，悄悄换一个动词不是

清理探针时撞到的。我对 agent 说「把这两条探针作废掉」，它**没有作废工具**（`commitment/voided`

后果不是少做一件事，是**记录变成了假话**：操作者要杀掉的那条承诺，图上留下的是「有人报告
了进展」。而这套系统全部的价值就押在记录诚实上。

修法只有一句话，写进 `commitment_receipt` 的工具描述：**没有的动词就说没有，指回那个按钮**
——不要拿回执去顶 作废／顺延／移交／合并。

**没有作废**；作废只在目标行与卡上。两条探针承诺因此留着，等操作者自己按（那正是它该

### 八、自审：这一轮改动里我自己造的四个洞

review 时逐个走了一遍新加的路，四条真问题，全部修了并配了「拆掉实现会转红」的用例。

顺带确认两件本来担心的事**不是**问题：`waitingFamily` 在生产里确实注册了

## v3.11 / 设计 v4.18 场所的出生故事 —— 开发回执

按今天立下的规矩：**先量 CLI，再读方案**。量出来方案里有一条前提不成立，还撞出一族早就死掉的工具。

### 一、CLI 0.1.4 实测对表

| 技术方案 v3.11 说 | 实测（本租户，2026-08-21） |
|---|---|
| `im group create` 建群 ≥2≤10 成员 | ✓ `--name` + `--member-open-id …`（不含创建人） |
| **`im group search` 群搜索缺口解除——名录缓存降为兜底** | ✗ **六个关键词全答 `code=1110201 服务内部异常`（exit 1）** |
| `im group recent` | ✓ 可用，`{count, list:[{groupId, groupName,…}]}` |
| `group.members add/remove` 押阶段二 | **能力已经到了**（`remove` 要 `--yes`） |
| exit 3 协议 | ✓ `exit 3` + `error: confirmation_required: …追加 --yes 执行` |

**偏离①：名录缓存不降级。** 「搜索为主、名录为兜底」建立在一个不成立的前提上——照做会让会话
搜索**直接坏掉**。`yzj_im_group_search` 工具照建（它如实报出平台自己的错误码，租户修好即可用），
但**不接进选场所的热路径**，名录仍是主路径。工具描述里写明了这一点，并指引退回
`group_recent`——「搜不到」和「搜不动」不是一回事，不许合并成一句「没有这个群」。

**偏离②：拉人/移人的能力比方案预期早到。** 方案写「能力随阶段二平台 API」，而 0.1.4 已经有了。
**没有按早到就建**——这是方案的排期，不是实现能自己改的。事实记在这里供裁决。

### 二、撞出一族早就死掉的工具：五个删除，人点的头全落在空处

手敲 CLI 时撞见的。0.1.4 起，不可恢复的命令自己要一道确认（缺 `--yes` 答 exit 3
`confirmation_required`）。而**我们一个工具都没传过 `--yes`**——`yzj_doc_delete`、
`yzj_doc_block_delete`、`yzj_sheet_table_delete`、`yzj_sheet_record_delete`、
`yzj_calendar_event_delete` 全部如此，且五个**全在 guard 的强确认表里**。

于是完整的路径是：卡递到操作者面前 → 人按下「确认」 → CLI 拒绝执行 → 模型看到一句
`failed` → 它去编一个别的办法。**操作者签的字落在了空处。**

没有任何测试拦得住：单测打的是假 bridge，而假 bridge 不认 `--yes`。所以新加的用例断言的是
**发出去的 argv**，不是回包。

修法两条：五个工具补上 `--yes`（那是操作者那次签字的**兑现**，不是绕过它——两道门问的是同一
件事，人真正看得见的是我们这一道）；`failureDigest` 单独认 exit 3，说成它本来的样子：
「这条命令要求显式确认，而调用它的工具没有带上 --yes——不是你能绕过去的错误，也不该重试。」

### 三、v4.18 三句落地

**①创设人签发。** 两条路各有各的门：

- **agent 路**：新工具 `yzj_im_group_create`，guard 里是 **strong**。它和别的 strong 不同——那些
  是「删掉的回不来」，这一条是「**从此有一批人听得见这里说的每一句话**」，不可逆的是**边界本身**
  （群能解散，谁在那段时间里听见了什么收不回来）。人数越界在打出去之前就拦下：问过人再失败是
  最贵的一种失败。
- **桌面路**：传送门里按下「签发并建群」**就是那次签发**，不再弹第二张卡（一次主权时刻一次确认）。

**结果未知不自动重试**：超时或读不出 groupId 时，群**可能已经建好了**；重试的代价是组织里凭空多
一个群、多一批被拉进去的人。回的是一句让人去核对的话——核对走 `group recent`（刚建的排最前），
不走 `group search`（见偏离①）。

**②合同默认最严。** 运行态真相是通道的 `allowedGroupIds`（**单一事实源**——图上不再存一份
`served` 造第二本账，今天已经为这种分裂修过好几处）。新群不在这张表里，因此**默认就不在岗**，
这一条是构造上成立的。签发卡上那次「接入 agent」勾选（专项群默认勾上，因为它存在的理由就是让
agent 在这儿干活）落成 `birth.servedAtBirth`——那是历史，不是开关。

**③出生血缘携带语境。** `contract/updated.birth { sourceAnchor, inheritedGoalRef?, servedAtBirth }`，
零新族。`inheritedGoalRef` 的投影遵循既有可见域规则。

**未勾接入时的警示**（方案 v3.11r 收紧项）已落到结果面：「agent **没有**接入这个群：登记卡发过去
也不会有人接收回执，板上那条承诺会一直等不到动静」，并给出两条仍然走得通的路。出生要有呼吸，
而**呼吸包括回执可达**。

### 四、写代码时被单测当场逮住的两个

- **合同原样回写，只多一条出生记录。** `contractFor` 是「同 placeKey 最后一条赢」，随手填几个值
  写下去等于把新场所的合同**钉死**在我填的那几个值上、从此不跟随组织默认。我没打算改策略，却
  改了策略——这类「顺手写下一个我没想过的默认」不报错，只是三个月后有人发现这个群的记忆策略和
  别处不一样。
- **`version` 是 +1 不是原样抄。** 组织默认那份是 `version: 0`（「还没写过合同」），而 schema 要
  ≥1——原样抄下去这一笔**直接抛**，出生记录一个字都落不下，而群已经建出来了。

### 五、如实的缺口

- **建完不自动跳进去。** 新群里一条消息都没有，因而没有话题可跳；能说话的地方是它的主楼，而主楼
  按 `placeKey` 导航——那条路由此刻只到宿主手里（`setFrame`），传送门够不着。所以如实说「它会
  出现在会话列表里」，而不是跳去一个应用还不认识的场所然后显示一片空白。
- **建群没有在真组织里跑过。** 平台要求初始成员 ≥2 人（不含创建人），任何一次真实验证都会把**两位
  真同事**拉进一个新群——这是对外、影响他人、且撤不回来的动作，**等你点头再做**。argv 形状照
  `--help` 与单测双向锁住了。
- **实测⑨（群历史对新成员可见性）做不了**：需要第二个账号。它是 audience 动态解析正当性的事实
  前提——若平台对新成员隐藏入群前历史，动态解析须按加入时间切分。入 asks。

### 八、自审 v4.18：三句里我说错了一句，还牵出一道活的悬崖

上一轮我写「②合同默认最严——新群不在 `allowedGroupIds` 里，因此默认不在岗，**这一条是构造上
成立的**」。去查了一眼，**这句话是错的**：

```ts
private allowed(groupId: string): boolean {
  return this.config.allowedGroupIds.size === 0 || this.config.allowedGroupIds.has(groupId)
}
```

**空名单 = 全部放行。** 于是名单空着的部署里，新建的群**立刻在岗**——操作者明确不勾「接入」
也没有任何作用。设计的那句话落不到实处。

#### 根因：三值被压成两值

`setServed(id, false)` 做的是从集合里 `delete`，而落库那一层**本来就是三值的**
（`Record<string, boolean>`：有 true / 有 false / 没有）。值丢在「合并成一个 Set」那一步——
**「从没提过」和「明确说了不」长得一模一样**。这正是今天一整天在讲的同一条纪律（看不了 ≠ 没变、
`undefined` ≠ 空串），在合同这一族上被违反了。

而那个集合还**兼职表达配置**：空集是「这个部署没有名单」。两个含义挤在一个数据结构里，就有了
一道**双向的悬崖**，两个方向都是实的：

- **名单空着的部署里点开一个群** → 集合变非空 → **另外 45 个群悄悄下岗**。
  本实例现在就是这个状态：落库里只有一条 `true`，而界面上一片「未接入」。
- **名单只剩一个的部署里把它关掉** → 集合变空 → **agent 在 46 个真实工作群里同时上岗**。

后一种正是承诺板 `set-served` 那段注释在担心的爆炸半径（「46 行每行一个一键开关是在邀请人
不小心加宽 agent 的读写范围」）——而**那个开关自己就有这个洞**。

#### 修了哪一半，为什么只修一半

**修了的**：`onDutyIn()`（从私有方法拎成导出的纯函数，和同文件的 `deskSendPlan` 同一个范式）
先查 denied 再走空集捷径——**人明确说过的「不」，任何默认都不该盖过**。通道两处开关同时维护
两个集合，移交也一并挡住 denied。四条用例，拆掉那一行会转红。

配套让 v4.18 ② 真正站住：`create-place` 现在**两个方向都明说**——勾了写 `true`，没勾写
`false`，而不是「不勾就什么都不做」。落库那一层三值，写下去 denied 才拦得住。

**没修的**：`allowed` 变空时其余群集体上岗。denied 只护得住被点名关掉的那一个。真正的根是
「空集」身兼两职，而分开的两种修法——把「空 = 全开」改成「空 = 全关」（收窄，合 v4.18
「合同默认最严」），或让「空 = 全开」只由**配置**说了算（加宽）——**都会改变 agent 在 46 个
真实工作群里的触达**。那是账号主人的决定，不是实现能自己定的。**等裁决。**

（也没有写一条断言去钉住当前行为：把 bug 写成规格比不测更坏。测试文件里留了注释说明缺口。）

#### 同一轮自审顺手修的四处

- **超时 ≠ 没建成。** 建群超时时我原本回「建群没成」——而超时恰恰是「结果未知」最常见的样子，
  群很可能已经建好、人已经被拉进去了。读的人照这句话再点一次，就是凭空多一个群。现在说
  不知道，并指出核对的路。
- **成员去重。** 同一个人被选两次，`length` 凑够 2 而平台看到 1 个——过了我们的闸、死在对面，
  而人已经签过字了。
- **`placeKey` 别手拼。** `placeKeyFor` 是这条规则的唯一出处，抄一份迟早分家。
- **建群回包形状是猜的**（真验一次要拉两位同事进群）。改成本族既有的容错读法，且读不出来时
  不猜、不重试——如实说「可能已经建好了，去核对」。

#### 顺手量准的两件

- `--yes` 的位置：五个删除命令拿工具**此刻真正会发出去的那串 argv** 打了一遍，全部穿过参数
  解析打到 API（exit 1 是真 API 错，不是 exit 3、也不是解析错）。
- `--member-open-id a b` 的多值形状：故意漏掉必填的 `--name`，CLI 只抱怨缺 name，说明两个值
  都绑给了那个标志（对照组：真有游离参数时它报 `unexpected argument`）。零网络风险。

## 界面三处实报（窄宽度侧栏 / 图片占位符 / 内嵌图）

三条都在真界面上复现过再动手，其中两条的病根是同一个，第三条的病根是一句**没人回去重量过
的注释**。

### 一、窄宽度下侧栏不是收起，是压扁

宿主在窄宽度下把左区收到 ~35px（根节点自己带上 collapsed 类），而这一列照旧渲染整份收件箱。
实测：「◫ 承诺板 · 跨执行者」被挤成**一列一个字**（22px 宽 × 162px 高）、「收件箱」截成
「收件」、会话列表被撑到 **3908px 高**——每一行的每个字各占一行。

修法：这一列**自己量自己的宽度**（ResizeObserver，决断条同款），窄于 96px 就换成一条轨——
`＋ / ✋n / ✓n / ●n / ◫`，图标加计数，`white-space: nowrap` 兜底，一个字都不折。

判据用自己的盒子，**不去认宿主那个哈希类名**：类名是别人的实现细节，改一次名这条路就断，
而且断得无声。轨上只留「不需要一行字就能读」的东西——会话列表在 35px 里读不了，画出来只是噪音。

### 二、图片占位符和它要占位的图并排站着

两个形态，同一个病：

- **`[Images]` 单独一条**——`isPlaceholderOnly` 只认 `[图片]`。实测同一个租户里有三种写法
  （`[图片]` / `[Image]` / `[Images]`），取决于发送方客户端的语言。
- **「梳理的一版术语 FYI **[图片]**」+ 下面一张图**——占位符**夹在句子中间**，整条不等于
  占位符，所以此前那道闸够不着它。

修法：`withoutImageMarks(content, hasImages)`——**只在这条消息真的带着图的时候**才抹。那个
条件是唯一的安全绳：占位符是平台写给「画不出图的客户端」看的描述，我们画得出，所以它是一份
重复；但一条没有图、正文里恰好写着「[图片]」的消息，是有人在说话，不许吃掉。

（更严的做法是用 `desc` 段自带的 `start`/`length` 精确切除——实测那两个数是字符偏移且和正文
对得上（「梳理的一版术语 FYI\n」正好 12 个字符，段里写的就是 `start: 12`）。没走那条路是因为
它要在协议、桥、线、界面四处加字段；失手代价是一条带图消息里有人手打的「[图片]」被抹掉。
记在这儿，将来若出现更花的占位符，那条路是现成的。）

### 三、「这张图嵌在富文本里，云之家没开下载口」—— 这句话是错的

代码里那道闸的注释写着：「它们是另一个 id 空间，CDN 给的是占位图标，`file download` 直接回
`code=2005, Get download info failed`」。于是**所有富文本内嵌图一律画成灰盒子**。

实测（三个真实的内嵌图 id）：`yzj-cli file download --id <id>` **全部下得下来**，是真 PNG，
尺寸和 `desc` 段里声明的 `w/h` 一模一样（1156×797、1241×898、1080×1500）。而宿主取附件走的
**本来就是这条命令**。

当初那个诊断很可能是**拿错了参数名**打出来的——这个 CLI 的下载参数是 `--id`，写成 `--file-id`
会答 `unexpected argument`（我自己刚才就撞了一次），而那句错误传到诊断里就成了「拿不到」。
**一句「平台没开这个口」写进注释之后，就再没有人回去重量过它。**

真装配复验：那三张原本印「没开下载口」的图，现在会去取，并且渲染出来了（截图为证）。
顺带把死掉的 `inline` 字段从协议、桥、线上一起摘掉——没有读者的字段会烂。

### 四、顺手撞出的一处小谎

那个图槽在滚进视野之前什么都不请求（刻意的：一屋子截图急切加载会为每张图派出一个进程），
可兜底那句话写的是**「取图中…」**——于是一条历史里几十个从没被请求过的槽，个个都在说自己
正在取。看的人会等一个永远不会来的结果，然后以为是坏了。没在取就什么都不说。

822 tests pass（三连），8 包 typecheck + build 通过。三条都在 3090 上眼见为实。

### 五、承诺板「按目标」：目标名是一枚没做重置的原生按钮

现象：`v37目标-17733` 占了一条很长的灰色色块，短标题浮在正中。

实测计算样式：`appearance: auto`、`background: rgb(239,239,239)`（`buttonface`）、
`border: 2px outset black`、`text-align: center`、**`cursor: default`**——它是个 `<button>`，
而 `.goalName` 这条规则**只写了排版，没做原生按钮重置**，于是浏览器把自己那套画了上去。
配上 `flex: 1`，一个 100px 的标题被摊成 **623px**（占整行 56%）。

这一屋子每一个可点的东西都显式写了 `font: inherit / cursor / border / background`
（`.delegate`、`.assess`、`.room`…），只有它漏了。

修法两处：

- **补上重置**：透明底、无边框、左对齐、`cursor: pointer`、hover 才变色加下划线——它是
  **一个可以点进去的标题**，不是一枚按钮。
- **`flex: 1` 改成 `flex: 0 1 auto`**：点击区域要**正好是标题本身**。原先它吃掉整行余量，
  标题右边那一大片空白也是可点的，点一下空处就跳进目标页——那是会吓人一跳的意外。余量
  交给紧随其后的元数据（`.goalName + * { margin-left: auto }`）顶到行尾。`max-width: 52%`
  是给那种把 URL 当名字的目标留的：该被省略号截断，而不是把动词挤出行外。

改后实测：标题 100px（占 9%）、透明底、无边框、左对齐、手型；URL 那条占 46%、未截断、
最后一个动词距右边缘 14px、`scrollWidth - clientWidth = 0`（没有溢出）。

**扫同类全集**：静态扫了 client 下全部 tsx 里 `<button className={css.X}>` 用到的每一个类，
挑出规则体里既没有 `background` 也没有 `appearance` 的——4 个候选（`.quote`/`.send`/`.chip`），
运行时逐个复核**全是误报**（背景来自伴随规则 `.quoteLink`/`.badgeConfirm`，`.send` 是我的
正则漏了分组选择器）。板与群视图上跑检测器：**裸按钮 0 个**。`.goalName` 是全仓唯一一处。

这条没有单测能拦——「CSS 忘了重置原生按钮」不是逻辑。可复现的守卫是那个运行时检测器，
记在这里备用：

```js
[...document.querySelectorAll('button')].filter(b => {
  const c = getComputedStyle(b)
  return c.borderTopStyle === 'outset' || c.backgroundColor === 'rgb(239, 239, 239)'
})
```

**①催办统一**：`commitment-remind` 做的是——点一下，系统以操作者的名义把承诺卡重新投进

委派者（验收权 = 委派者∪操作者）由 **reduce 从内核记的 actor 盖上**，生产者不必配合——
让每个生产者去传，意味着历史上所有承诺永远没有它，且漏传一处就**静默失权**（没人报错，

免费改对的一处：**写回的「死」时刻自动变成了验收**（交付主张时承诺仍 open），组里不会
再看到一条没验收的活写着「已完成」。

## 多场景闭环测试 —— 补上一个形状上的空白

被问到「有没有做多场景闭环式测试」时，诚实的答案是**没有**。已有的两种测试都测不到那类错：

- **单件**：一个函数、一个家族、一张卡，各自对不对；
- **矩阵**（`loop-matrix.spec.ts`）：每个家族有没有生产者、每个动词够不够得到、两面答是不是
  等价——那是**横向**的完备性。

而这一天里逮到的 bug 几乎全长在**纵向**那条线上，无一例外都是**组合缺陷**：两个各自正确、
各自有绿测的东西，合起来撒谎。每一条都不可能被单件测试逮住，因为**每一件单独看都是对的**。

### `scenarios.spec.ts`：一条命从生走到死，每一步问「别处看见了什么」

七组场景，断言一律是「做了 A 之后，**B 面上**应该看见什么」——跨层，而不是就地：

| | 场景 | 它守住的那条组合 |
|---|---|---|
| S1 | 登记→催→交付→待验收→验收→终态→回写 | 栅栏在标准之下；**交付主张时组里还不该看见「已完成」** |
| S2 | 打回→返工→再验收 | 轮次活过那一轮；板上的假待验收信号被撤掉 |
| S3 | 验收权跟着委派者走 | 别人签发的活我验收不了；自己欠自己的不收两次费 |
| S4 | 方向轴三元 | 三格互斥且穷尽，「我旁观的」真的有人住 |
| S5 | 一屏混合数据的排列 | 待决 > 逾期 > 无信号 > 在跑 > 终态 |
| S6 | 回写只在生与死 | 交付主张／打回／改期一律不推回组里 |
| S7 | 墓碑律 | 迟到的完成、直接补 delivered 事件，都唤不醒作废的 |

**10 条全部逐个证明能红**：破坏「主张即交付」这一条语义时，10 条里**6 条同时塌**——那正是
纵向闭环该有的样子。其余四条各自用定点破坏逼红过（取消第三格方向、验收人不省略、取消
「主张即验收」、拆掉墓碑律）。

### 这一跑逼出来的两个真问题

**A. 板上有徽标、没动词。** agent 正确地拒绝了代人验收，并告诉操作者「去承诺板上那张卡按
验收」——而板上当时**没有那颗按钮**。徽标竖起来了、动词没跟上，等于把人指到一堵墙上。

顺带说，agent 那段话本身是今天早些时候那条修正在真装配里的生效：「我这边没有验收这个

## 扫一遍按钮：CTA 是话语的按钮形态（2026-08-24 晚）

起因是一句提问：「目标里面的『拆解』『评估』的交互逻辑好像和设计稿 demo 中的不一样，
是否还有其他按钮也有这个问题？」——有，而且这条界线干净得出乎意料。

### 界线：`place` 的传送门全对，`private` 的传送门全错

全产品只有 11 个传送门调用点。按语态一分：

| 语态 | 动词 | 判定 |
|---|---|---|
| `place` | 委派 ×2、催 ×3、差距→委派 ×2、为此会准备 | 全对 |
| `private` | **拆解、评估 ×2、以新基准重估、问这个目标** | 全错 |

原因是同一条：**场所（听众）是社交决策，必须问；私语域是规则，不问。** 对着一个只有
一个合法答案的问题弹一屏，再把自己写好的句子塞进输入框等人按发送，三步里两步是纯损耗，
而且第三步给了人一个错觉：这句话是他说的。

技术方案 §5.3 **A6.1 拆解六步／评估五步**（v3.12，同一天定的）把这条钉死过：「①⚡ CTA
或话语『帮我拆』——**CTA 只是话语的按钮形态**：按钮提交 = 向 agent 发一条 canonical 话语
turn，**无独立 RPC 路径**；**该 turn 落点 = 操作者私语域**」。demo 也是一按即进「备料中…
（仅你可见 · 私）」，全程没有人按过发送键。

**这不是随手写错的。** 本文件 8/20 那条写着「目标行两个 CTA：委派 ↗ 与 评估。两个都只问
一件事——在哪个会话里说——然后跳进去」，那是照 v3.5/v4.9 的读法，当时没错；A6.1 是后来
才把时序钉到开发规格级的，而代码没跟着走。

### 第五处是另一种错：名字对，语态错

「🔍 问这个目标」自己的注释写着轻问（一次性只读投影：不开任务、不写任何东西），带的却是
`private`——一次**完整的 agent turn，写工具全部可用**。一颗写着「问一下」的按钮按下去可能
动手写东西，是最不该错的方向。`Errand.voice` 补第三格 `'ask'`；轻问够不着时（会话不是
云之家话题）当场降级并说明，而**窗口读不到时不下断言**（看不了 ≠ 没有）。

### 同族欠账三笔

- **「🤝 先和 agent 磨一磨」整个缺席**。立目标表单只给了「想清楚了的人」一条路，而最常见
  的处境恰恰是还没想清楚——尤其「怎么算完成」那一栏，它是日后差距简报唯一的对账基准。
- **为此会准备不拟稿**——连催办都拟稿了。
- **委派／差距→委派两级缩放各写各的句子**（板上那句只丢出一条光秃秃的标准原文）。两级
  各说各话，正是目标页存在时最先长出的裂缝；收成一份实现（`commission.ts`）。

句子模块把两类的分界写在文件里：**完整句**（按下即说，落点由规则定死）与**起头**（里头有
一块是人的，只摆主语）。混掉这条线两个方向都会出错——把完整句做成起头是让人替按钮按一次
发送，把起头做成完整句是替人把话说了。起头一律不预埋 @ 触发词（demo 预埋，我们不：改写
别人要发出去的话是越权）。

### 顺带补的一跳：待答的差距简报按得下去

板上那句「验收与继续在那张简报卡上答」既不说卡在哪、也不给门。`BoardAssessment.sessionId`

### 事件枢纽落在右栏

板上一场会只占一行，一行装得下的只有三样：几点、叫什么、准备好没有。而看见「还差
一些」之后人下一个动作永远是「差什么」——那一屏放不进这一行，也不该把板撑成第二个
日历（板的合法增量只有对账排列、一跳指路、就近动词）。所以标题成了门：**中栏点一下，
右栏接管**，与工件预览同一条纪律、同一种形状。

枢纽只存「看的是谁」，内容每次重读——就绪度要**随着交付自动翻绿**，拿快照就会越看
越旧。四段：关联任务（每件带一跳去它在干的话题）/ 材料 / 日程描述（全参会人看得见的
那一版；材料没写进去要在这儿说）/ 为此会准备（传送门，不替人派活）。

三处「空」各说各的：没挂东西 = **合法状态不是没准备好**；没有期待的材料 = 就绪度未
激活；日程描述是空的。把语义空缺渲染成负面状态，是这套设计点名要避免的谎。

地点/组织者/描述取自平台那条 `event list` **本来就回**的字段（实测 `meetingPlace` /
`personName` / `content`），不为它们多打一次 `event get`；平台用空串表示「没填」，空串
不当内容渲染。「在云之家打开」**没有做**：这条 list 的 `url` 实测是 null，给一扇死门
比不给更坏。

抽屉开不出来时要**说一声**：实测当前会话为空时宿主右栏打不开，而从板上点会恰恰常在
这个状态——那时人看到的是「什么都没发生」。`revealAside()` 如实回答，板上给话。

### 委派五步

**②两维真选择**：先问谁来做，再问在哪儿说——**执行者决定场所的选项集**，顺序不能倒。
派给 agent 的活只在群里说得通；派给人的活公开说与私下说是两句不同的话。场所名旁边
写明「这句话会让谁听见」（公开委派/公开登记/私下登记此前在列表里长得一模一样）。与
那个人的私聊按名字认——平台不给「私聊对面是谁」的字段；认不出来如实说没有，并指出
那条自己走得通的路（先去私聊一句，话题就长出来了）。

**③话语骨架，不是稿子**：规格明写「任务内容由人说，agent 不发明委派内容；demo 为演示
流畅预填了示例内容，**实现勿照抄**」。所以登记句式只带那个人的名字，做什么与什么时候
前是两个空〔…〕——一句像样的示例会被原样发出去，而那句话是我们编的，却挂在他名下。

**受话**补在输入框里，不补在句子里：摆进去，看得见、删得掉；删掉就降级成一句普通的
话。这和「发送时替人改写句子」是两件事。

**实测逼出一个**：句子进了框、**@ 没有**。那一拍读的 `window_` 还是上一个会话的（刚
跳过来，新会话那次 fused 还没回来），而从板上跳进来时上一个会话常常压根没有。改成
记账——先记下「这句欠一个受话」，等触发词到了再补，且补之前确认框里还是我们放的那串
字（人动过手，那句话就是他的了）。修完实测：`@next 登记承诺：〔要做什么〕，代少兵
负责，〔什么时候前〕。`，chip 上那行「句子里带上 @next」的提醒随之自动消失——两个
半边互为对账。

**未做并明标**：④「登记话语不开话题」。我们的话题是**入口处**铸的（@ 即 admit，
session 就是话题），而「这句是登记还是委派」按规格是 **LLM 语义判定**——那要等 turn
跑起来才有答案，而 turn 需要一个 session 才跑得起来。改它是通道层的动刀，不是这次
UI 的范围。⑤两路落库上板已经由 agent 那条既有路径承担（登记即观察，板行随之长出）。
