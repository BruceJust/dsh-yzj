# 剧本 2 · 外勤销售的一天 —— 孙莉

> 设计压力测试 · 2026-08-17 · 被测对象：[终极形态设计方案 v3.6](../终极形态设计方案.md)（唯一设计事实来源）
> 人物类型：**外勤大客户销售 = 手机为主设备的 DSH 操作者**——对"桌面优先"的最强反例候选。
> 探针：① 全天只有手机（委派/监控/审批/验收全靠云之家 DM 兜底）；② 口述→走访记录进表格；③ 经理群同步 + 报价的人类审批链；④ 约外部客户复访；⑤ 合同 word 比对标准条款；⑥ 周五桌面补一周的验收与记忆债。

---

## 一、人物与前提

**孙莉**，34 岁，瑞康医疗器械经销公司华东区大客户销售。卖的是监护仪、呼吸机和影像设备，客户是各地医院的设备科和采购办。一周四天在外面跑：高铁、网约车、医院走廊、住院部电梯口。只有周五在杭州办公室。**手机是她的主要设备**——笔记本在背包里，一周开不了两次。

公司这个季度给销售条线配了 DSH agent。孙莉的 agent 用专用云之家账号「云小助」，在她的私聊列表里，也在「华东销售部」群里。她的经理是销售总监赵敏。公司的报价规矩：销售自主权限 9 折，9 折以下要总监批，8 折以下要总经理批。

她对 agent 的态度很实际：**能替我打字、替我记住、替我盯着的，都给它；要我坐到电脑前才能干的，等于没有。**

## 二、剧本

### 周二 · 客户日

**07:05，杭州东站。** 孙莉挤上 G7538，今天两家：上午市一院采购办（催中标后的合同流程），下午三点省立医院设备科王主任（新一轮监护仪采购，关键单子）。落座后她打开云之家，给云小助发私聊：

> "今天下午见省立王主任。把省立这单的历史成交价、上次拜访的遗留问题、还有迈瑞那款竞品的对比要点整理一条发我，十点前。"

发完她靠着椅背闭眼。这是她的委派方式：一段话，一个截止时间，全部在私聊里。她从来没打开过公司说的那个"桌面工作台"——不是不想，是**她的工作发生的地方没有桌面**。

**08:40。** 微信弹出来，王主任："孙经理，下午临时有个院务会，能不能改上午11点？" 她心口一紧——上午已经排了市一院。她回"没问题王主任，11点到"，然后立刻切到云之家：

> "省立改到今天11:00，日程改一下。市一院挪到下午2点半，帮我拟一条给李科长的改期说明。"

云小助秒回："收到。改日程需要确认：将「省立医院·监护仪拜访」从15:00改至11:00 —— 回复 1 确认 / 2 取消"。她回了个 1。第二条确认接着来，她又回了个 1。**改期说明拟好了，但发不出去——李科长在市一院，不在瑞康的云之家里。** 她把话术复制出来，粘到微信发给李科长。心里嘀咕：它能改我的日程，可我的客户它一个都碰不到。

**09:15，高铁进隧道群。** 信号在一格和无服务之间跳。云小助整理的省立要点卡片加载了一半，图片出不来。更麻烦的是有一条待确认卡在那儿：agent 要把改期记录写进部门的《拜访计划表》，等她确认。她盯着转圈的界面骂了一句。**09:40 出隧道**，消息一股脑涌进来——那条确认请求还在等着，没有因为超时自己放行，也没有重复轰炸，只是安静地挂着。她回 1。这一点她认：**它等得起，不瞎动。**

**10:55，省立医院设备科。** 见王主任前她最后扫了一眼云小助发来的要点：去年中标价、科室遗留的售后工单、迈瑞对比的三个打点。谈到一半王主任压价："迈瑞那边给到相当于你们 8.8 折的水平。" 孙莉权限只有 9 折。她没接价格，把话引到临床科室的使用反馈上，心里已经在盘算怎么跟赵敏开口。

**13:20，医院停车场的网约车里。** 拜访完的孙莉像被抽掉了半管血。以前这个时刻是她最恨的：CRM 里的走访记录拖到周五就面目全非。现在她对着云之家按住语音键说了一段——**发现云小助对语音消息毫无反应**。她只好切到输入法的语音转文字，对着屏幕口述了六分钟：到场人员、王主任关心的三个点、8.8 折的竞品压价、设备科李工提了一句"院里倾向国产替代"、下一步动作。转出来的文字错字连篇，她懒得改，直接甩给云小助：

> "整理成走访记录，按咱们的模板，写进《大客户走访记录表》省立那行。错字你自己顺。"

一分钟后确认请求来了："将走访记录写入《大客户走访记录表》（新增1行，7列）——回复 1 确认"。她回 1，把手机扣在腿上闭眼。**这六分钟的口述换掉了以前周五晚上的四十分钟**——如果语音能直接喂进去，还能再省一半。

**14:05。** 车上她继续："按 8.8 折做一版省立的报价单，明细到型号。做完先别发，8.8 超我权限，要赵总批。另外把今天的进展同步到华东销售部群里省立那个话题。" 云小助在群里省立话题下发了三行进展摘要，末尾写着"报价单草稿已备，折扣 8.8 需总监核价"。赵敏十分钟后在话题里回："8.8 可以做,账期压到 60 天以内,把付款条件写死。" 孙莉看到了,但她清楚**这句话在公司流程上不算数**——价格审批得走云之家审批中心的《特价申请》流程。她让云小助把特价申请的材料理好,自己在手机上进审批应用填单、提交、选赵敏。然后是两头等:**云小助在等她确认报价单写入,她在等赵敏批特价,两条审批线在她手机里各跑各的,互相看不见。** 15:40 赵敏批了,她截了个图发给云小助:"批了,报价单定稿吧。"确认、回 1、生成。

**15:55。** 王主任微信发来一个 word:"孙经理,合同我们法务改过了,你看下。" 她在微信里把文件转存,再从云之家发给云小助:

> "跟咱们的标准合同条款比一下,列出所有改动,标出哪些能接受哪些不能。标准条款在知识库《销售合同标准模板v4》。"

云小助回:"文件已收到,开始比对。" 二十分钟后一份《省立合同差异比对》文档链接发过来:12 处改动,3 处标红(违约金比例、验收周期、付款节点)。她在手机上点开云之家文档看完,把 3 处标红转述给公司法务的同事。**这一趟她没打一个字的对比,只做了判断。**

**16:30,回程高铁。** 她安排下周:"约王主任下周三上午复访,把院线国产替代那个话题带上,提前一天提醒我准备材料。" 云小助建了日程、拟了邀约话术,然后诚实地说:"王主任不在组织内,日程邀请无法送达,话术请您转发;'提前一天提醒'我目前做不到定时提醒,建议您自己设一个。" 她哭笑不得:**约的动作它做了一半,提醒它干脆做不了。**又是复制、切微信、粘贴、发送。

**18:40,快到杭州东。** 云之家里躺着三条待验收:走访记录、报价单、合同比对。她一条条扫了眼标题,在各话题里回"收了""收了""收了"。**报价单她其实只看了首页合计价。**眼睛已经睁不开了。

### 周五 · 办公室半天

**09:10,办公室,一周第一次打开桌面工作台。** 收件箱 triage 区排着这一周的债:2 条待确认(周四挂起的两个写操作)、4 条待验收、若干未读。她从上往下清。

**09:40,债爆了一颗。** 点开周二报价单的工件预览——IBP-2000 那行的单价套的是旧价目表,比新价低了 4 个点。她周二在高铁上只看了合计。她在话题里说"IBP-2000 单价用错了,按 8 月价目表重出",任务重开,十分钟后新版出来,这次她逐行看完才点验收。**周二的"收了"是假的,周五才是真验收——但周二那次验收已经触发过记忆蒸馏了。**

**10:20,记忆面板。** 省立这个场所的记忆里躺着一条:"王主任倾向国产替代"。不对——那是设备科李工说的,王主任本人从头到尾没表过态,这条要是带进下周三的复访话术里就是事故。她删掉,改成"设备科李工(非决策人)提及院内有国产替代倾向,王主任未表态"。她顺手翻了翻其他条目,又发现记忆全挂在"华东销售部群"和"省立话题"底下——**市一院的事、省立的事、李科长的偏好、王主任的忌讳,按'在哪个群聊过'切碎存放,而她脑子里明明是按客户存的。**

**10:50,场所合同。** 一周被确认请求打断了十几次,大半是写走访记录表这类她永远会同意的操作。她在设置里把「华东销售部」场所的写权限从"全确认"调成"标准写预授权",把《大客户走访记录表》所在的域开了绿灯。**这个开关手机上没有,只能周五拨。**

**11:30,轨迹抽查。** 合同比对那单事关重大,她点进轨迹看了一遍:agent 读了标准模板 v4、读了客户 word、比对逻辑清楚,没有幻觉引用。她放心了一点。顺手把下周三复访的材料清单跟云小助过了一遍——然后在自己手机的系统闹钟里,设了一个下周二 17:00 的提醒。

**12:05,合上电脑。** 她算了笔账:agent 这周替她省了大概四个小时的打字和整理;但她也为它垫付了新的成本——每一次复制粘贴到微信,每一次两头等审批,每一次周五才能拨的开关。**这个 agent 是个好内勤,但她的战场在外面,而它的完整体只活在办公室那块屏幕里。**

*(剧本约 3100 字)*

## 三、逐环节走查 · 缺口表

> 缺口分类:缺失 / 不合理 / 已知推迟-域F / 已知推迟-移动 / infra上限 / 无缺口(正面确认)。严重度:高 / 中高 / 中 / 低。

| # | 剧本环节 | 用户期望 | 设计现状 | 缺口分类 | 严重度 | 第一性判断 |
|---|---|---|---|---|---|---|
| 1 | 全天手机完成操作者全环(探针①贯穿) | 委派/监控/steering/审批/验收/记忆维护六个动词全部在手机可达 | A1/A2/A3/A5 均话题内可达,DM 兜底审批(P1)覆盖审批;但记忆**删改**(C4 面板)、硬合同编辑(G1)、轨迹查看(D6)、对象预览验收(D5)均为桌面独占,移动工作台推迟 P5 | 已知推迟-移动(表层)/**不合理(深层)** | **高** | 对外勤操作者,兼容投影事实上成为主投影——设计明言兜底"永不作为主形态设计",却让手机为主的操作者天天以它为主形态。检验标准③以 surface(桌面单屏)定义完整价值,应改以**动词×投影的完备矩阵**定义:每个操作者动词在每个投影上要么可达、要么显式降级 |
| 2 | 私聊里与 agent 连续对话(孙莉的主要工作面) | DM 是一条连续会话,像跟真同事聊天 | A0 边界规则为群/话题形态设计:私聊无原生话题,裸消息"自成话题根"→ DM 流将碎成 N 个会话;逐条回复锚定在手机上是重摩擦;"频道级会话/轻问"明确推迟域 F | 不合理 + 已知推迟-域F | **高** | 会话边界的"可读性铁律"在群里成立(UI 分组=心智),在 DM 里恰好反转:DM 的 UI 分组是**一条流**,用户心智也是一条流,自成根规则在此制造了 UI 上看不见的边界——违反了铁律自身。DM 场所应默认频道级连续会话,`/new` 换代 |
| 3 | 报价的人类审批链(探针③) | 赵敏的核价成为任务图上的一环:agent 知道在等谁、批没批、凭据在哪 | 审批对象(A2)仅接受**操作者本人** openId 应答;G1 审批策略仍是操作者中心;业务审批(特价申请)与 agent 写门禁是两条互不可见的线;赵敏话题内表态只能算 steering,无凭据效力 | **缺失** | **高** | 设计把"审批"只建模为**权限门禁**(agent 可不可以写),没有建模**业务决断**(这个价可不可以报)。真实组织的委派链是人机交织的:任务终态前常有一个非操作者人类的决断点。审批对象应支持"应答人=指定人类成员"或至少支持挂接外部审批凭据,否则 agent 永远在人类审批链断裂处装死 |
| 4 | 让 agent 约外部客户复访(探针④,及改期通知李科长) | agent 端到端把客户约成 | 会话图的组织基座=云之家,图止于组织边界:外部客户无身份、无通道、无场所、无记忆位;日程邀请送不达;设计全文未涉及外部参与者 | **缺失** | **高** | 采纳轴只处理了"装没装"的同事,没处理"根本不在组织里"的客户——而销售的价值网络主体恰在组织边界外。诚实的终态是**筹备员模式**(拟稿+建日程+留痕,人肉走最后一公里微信),但这应成为显式设计(如"外部联系人影子档案":名字/微信备注/话术出口),而非留白让用户自己发现 |
| 5 | 口述要点→走访记录(探针②) | 对着 agent 说话,语音直接变成表格里的记录 | 设计无语音模态只字未提;CLI 能力面未含语音消息摄取;现状靠输入法语音转文字曲线救国 | infra上限 + 缺失 | **高** | 外勤场景的输入带宽瓶颈在"手忙/眼累",语音是该场景的第一输入模态。这不是 nice-to-have:探针②之所以成立(四十分钟→六分钟),前提是口述成本趋零。应进 infra ask 清单(语音消息拉取/转写),与 webhook 同级 |
| 6 | 客户知识的沉淀(周五记忆维护时暴露) | 按**客户**沉淀:王主任的忌讳、李科长的偏好、省立的采购节奏,走到哪带到哪 | C1 记忆跟**场所**走(群/联系人),防泄漏正确;但外部客户不是云之家联系人,无记忆位;客户知识按"在哪个群聊过"切碎 | 缺失 / 不合理 | **中高** | 场所记忆解决的是"谁能看见"(权限),回答不了"关于谁"(主体)。销售的复利单位是客户实体,不是聊天场所。需要在场所记忆之上加一层**实体索引**(客户档案聚合各场所中关于该实体的记忆),权限仍按来源场所裁剪——否则复利率因子在销售岗位上大打折扣 |
| 7 | 手机浅验收 → 周五发现报价单错误 | 错了能重开、记忆能纠正,且浅验收不留毒 | A3 拒收重开✓(话题内提要求即重开);但**蒸馏耦合于归档**,周二假验收已触发蒸馏,错误事实可能已入记忆;重开后旧蒸馏条目如何回滚未定义 | 不合理 | **中高** | 验收质量是记忆质量的上游。移动兜底把验收变得极便宜(回个"收了"),便宜的验收+自动蒸馏=复利被污染。蒸馏应延迟或可追溯:重开任务自动标记/冻结其上次蒸馏产物,或蒸馏带任务版本号 |
| 8 | DM 兜底审批在借身期(P1)由谁发出 | 私聊里有个明确的"对方"发确认请求 | A2 DM 兜底排在 P1,专用账号(B1)在 P2;借身期 agent 以操作者身份说话,"操作者给自己发私聊审批"的形态未定义 | 缺失(设计含糊) | **中** | P1 与 P2 的排序造成一个自指窗口期。要么 DM 兜底事实上依赖 B1 提前(承认之并调整卡点标注),要么定义借身期形态(如自聊窗口/群内私 @),不能留给实现者即兴 |

## 四、第一性洞察(按重要性排序)

1. **"桌面优先"的隐含人设错配——完整价值应按"动词×投影矩阵"定义,而非按 surface 定义。** 设计的检验标准③把操作者完整价值锚在"桌面单屏",默认操作者是坐办公室的人;孙莉证明存在整个岗位族(销售/实施/售后巡检),其操作者动词大部分发生在手机上。设计其实已经内含解药:§1.4"设计对象,不设计界面功能"+ 审批对象的多投影已经证明动词可以廉价地到达任何投影。要做的只是把这条原则**贯彻到全部六个动词**:验收、轻量记忆纠正("这条记错了,是李工说的")、合同建议采纳,都应有 IM 习语的兜底投影;桌面保留的应只剩"结构化编辑与深审计",而不是"质量与卫生的全部"。
2. **审批被单义化为权限门禁,漏掉了人类决断点。** 任务图上真实存在"等一个非操作者人类拍板"的节点(核价、法务、总经理),设计对它没有对象——agent 在人类审批链断裂处只能装死或靠操作者人肉转录。
3. **会话图止于组织边界,而销售的价值网络主体在边界外。** 外部参与者(客户)无身份、无通道、无记忆位;"筹备员模式+影子档案"是诚实的最小终态,应显式设计而非留白。
4. **廉价验收 + 自动蒸馏 = 复利污染。** 移动兜底降低了验收成本,却让未经检验的事实直接进入记忆;蒸馏需要与任务版本/重开状态挂钩。
