## 一、三个结构级结论（模型层，多剧本独立收敛）

### S1 会话图缺一类节点：工作对象（承诺）——五个剧本收敛，最大缺口

各剧本的独立表述：
- 剧本1：管理单位是"承诺"（谁在何时交付什么），人类任务不入图 → mission control 只有半张图；
- 剧本3：流程无真身——六周招聘岗位在图上没有对应节点，管道表格被迫成为总线；
- 剧本4：会后决议拆成 8 个行动项发给 8 个人后**从图上消失**；
- 剧本5：流程是组织的**复利单元**（第三单元，在"会话=交互单元、工件=工作单元"之后）；催收四部门需要父任务-子会话结构；
- 剧本6：高管让 agent 盯三个经理的进度——agent"看得见群，看不见承诺"。

**裁决：真缺口，且是当初业界调研结论的回响**——"C 门面 + A 协议 + B 记录"三层中，我们建满了 C（身份记忆）和 A（委派协议），**模式 B（任务对象中心）只建了工件一半**。修复不动三轴模型：

- **承诺节点**：`{做什么, 执行者(人|agent), 期限, 状态, 所属流程, 来源会话, 血缘}`——执行者是 agent 时即现有话题会话的任务面；执行者是**人**时 agent 是观察者+（F-read 供电后的）跟催者；
- **流程节点**：承诺的模板化容器——结构（模板/子任务/系列/重复同构）**现在建**，推力（定时触发）仍归域 F。剧本5 的判词成立："推迟结构等于把复利率因子在重复性工作这个最大场景上判缓刑"，D8"现在建边将来供电"原则原样适用；
- **两个新取景框**：跨执行者（部门 mission control：人+agent 的承诺一屏）与跨时间（周报/月结总控的 pull 版汇总）——收件箱（注意力）、群视图（场所）之外的第三、第四投影面；
- **对象枢纽**：D8 事件枢纽的空间对偶（长期活对象如需求池：对象轴记忆、变更史、关联会话）——剧本4 命名，剧本3/5 需要。

### S2 域 F 一分为二：F-read 与 F-act——路线图的一个结构性错误

剧本6 的判词："**信任门槛是写权限的函数，不是主动性的函数**。"高管三刚需（轻问一个数、晨报、盯承诺）全部只读、零自主决策、信任成本趋近于零，却被"主动性放大不可信"整体推到 P6——而被优先建成的委派写闭环才是信任成本最高的部分。路线图按"操作者=重度委派者"校准，对最有预算决定权的画像几乎完全倒置。

**裁决：拆。**
- **F-read**（提前至 P2 前后，依赖仅为 DSH 调度器 + 现有只读工具）：轻问（本质是"**一次性投影**"的缺位，不是主动性——问一个数不该得到 ack+话题卡+文档+待验收全家桶）、晨报（cron+只读+DM 投递）、盯承诺（观察 S1 的承诺节点——供电关系：S1 建节点，F-read 才有东西可盯）、`/status` pull、碎片入池的低摩擦 pull（引用+「入池」）；
- **F-act**（维持 P6）：自主写、代发、ambient 回复。

### S3 隔离函数的自变量是"听众集合"，不是"agent 驻地"——隐私模型重述

剧本4 核心洞察，剧本1（组织级事实两群各删一遍、副本各自腐烂）、剧本2（客户知识被场所切碎）、剧本3（三面试官反馈散落各联系人场所）、剧本6（机密）四方印证。设计自己的检验句"这句话谁听得见"早已给出答案，但记忆与检索被焊死在"场所"上。重述为三条：

1. **私语态读取以提问者本人的可见域为界**（吴凯本来就看得见销售群——agent 替他跨场所检索对人是零泄漏）；公域输出按在场者最小交集隔离；
2. **合法越境的唯一通道 = 人签发的工件化脱密**——已在事实上实践（需求池、A4 摘要天然跨场所流动）但从未成文：成文 + 越境审计 + 血缘记录；
3. **记忆的轴扩展**：场所轴之外补**实体轴**（客户/对象——销售的复利单位是客户不是群）与组织轴（组织级事实单一权威副本，场所记忆引用不复制）；**"永不记忆"入硬合同**枚举项——能力越界可撤销、记忆越界不可撤销，机密场所的记忆策略必须是 guard 级条款（剧本6 致命级）。

## 四、外部实体（阶段化设计）

三个剧本（销售的客户、HR 的候选人、高管的外部顾问）证明组织边界外的实体是真实工作的常客，设计全文未涉及。**阶段化**：
- **近期（无 infra 依赖）**：外部实体作为图上的**影子节点**——无触达通道，但有身份位（挂实体轴记忆、承诺、上下文）；出流走 P4 脱敏导出；
- **中期（infra ask）**：邮件/短信通道、外部日程邀请、附件/邮件入站摄取。

## 五、infra asks 增补

语音模态（外勤第一输入带宽，剧本2）；会议同步会话/纪要摄取（会中记录的正路是接会议基础设施，不是把 IM agent 塞进会议室，剧本4）；企业既有审批流 API（offer/核价与 agent 审批双链互见，剧本2、3）；ERP 等业务数据面（轻问的上限=数据面覆盖率，剧本6）；已有条目维持：webhook、搜索、原生话题。

## 六、该拒绝的诱惑（压测后维持不做）

1. **完整项目管理子系统**——S1 保持最小（节点+边+两个取景框），不做甘特图/依赖图/资源视图；
2. **Motion 式任务排期**——维持拒绝；
3. **自动语义入池、ambient 回复**——维持域 F-act；
4. **为会中实时性重写架构**——"同一张图两个 SLA"值得研究，但会议场景的正路是 infra（纪要摄取），不是实时化改造；
5. **自动归并 DM 碎片**——P2 用"默认连续"解决，仍不做语义归并。

## 七、压测确认的强项（保持不动）

**DM 兜底审批**（六个剧本五个高光：高铁、银行排队、产线、车上）、事件枢纽与材料就绪度、双语态隔离（谈薪、判例检索）、终态退租、异步语义抗弱网、治理拨盘、场所内会话互读、工件出入流。——委派协议（域 A）与审批对象（多投影）是整个设计被验证得最扎实的部分。
