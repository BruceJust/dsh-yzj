# 剧本 6 · 高管的两天 —— 罗总（200 人公司总经理）

> 设计压力测试剧本。对照文档：[`终极形态设计方案.md`](../终极形态设计方案.md)（v3.6，唯一设计事实来源）。
> 画像：**非重度工具使用者的高管操作者**——公司给高管配 DSH，罗总本人即"操作者"，但他不具备设计文档默认操作者画像（重度委派者、愿意学习概念、自任管理员）的任何一条。
> 探针：① 轻问优先级 ② 晨报刚需 ③ 机密性与场所隔离极限 ④ 跨人任务追踪（盯人不盯 agent）⑤ 会议中即时查数 ⑥ 组织外分享 ⑦ 概念负担。
> 剧本中【E*】标记对应第二部分走查表环节编号。

## 第一部分 · 剧本

### 第〇幕 · 人物

罗总，52 岁，200 人制造加贸易公司的总经理。一天 6 个会，微信、云之家、电话三线作战。云之家他只会三件事：发消息、看群、批流程。上个月公司给高管配了 DSH——IT 负责人小陈在他办公室的台式机上装好了"工作台"，教了十分钟。罗总记住了一件事：在群里 @云小助，它会干活。

他对一切新工具的全部耐心是：**能不能第一次就给我我要的东西。**不能，就回到打电话。

### 第一天（周二）

**7:40，车上。**【E15】他想知道昨天华南的回款到账没有。云之家手机端翻了六个群——财务日报群的表格停在上周五，经营分析群最后一条是转发的行业新闻。他想问"那个 AI"，但手机通讯录里根本没有这个东西——小陈说过"您得在电脑上才能私下问它"（借身期没有专号，agent 不是通讯录成员；私语只在桌面工作台）。他放弃，打电话给财务总监老蒋。老蒋在送小孩，说九点半给他。

**一个数字，两个人，两个小时。**这是他每天要重复十几次的事，也是他对"公司给我配了个 AI"这件事的全部期待所在。

**9:00–11:20，连着两个会。**云之家未读 47 条，一条没看。散会后他用两分钟扫了一遍：43 条与他无关，3 条该看，1 条急——华东一个大客户投诉发货延误，两小时前发的。他不需要看全部，他需要有人告诉他**哪三条重要、哪一条急**。目前没有任何人、任何东西干这个活。秘书能筛日程，筛不了业务轻重；那个号称智能的工作台，把 47 条原样堆在那里。

**11:30，办公室，会议间隙。**【E1】台式机工作台开着。他凭记忆在经营分析群里打："@云小助 上月华南回款多少"。

几秒后 agent 回帖："已收到，正在为您核查上月华南回款数据。回复本条消息可在此任务上继续。"群里长出一张话题卡。两分钟后它交付了：一个云之家文档链接《上月华南回款核查》，里面有数据来源、口径说明、分月明细表，最后一行是数字：387 万。桌面收件箱同时多出一条"待验收"。

罗总盯着屏幕看了五秒。**他要的是"387 万"三个字，十秒钟，出现在他那句话下面。**他得到的是一个流程：一次 ack、一张话题卡、一份文档、一条待验收。"这玩意儿把我一句话当成一个项目在办。"他点开文档又关掉，没有点任何验收。【E13】

**12:10，午饭后。**【E2】他想起竞品上月降价的事——当时是销售南区群里炸开的，后来说要出应对方案，再后来就没下文了。他回到工位，用小陈教的"私下问"（工作台私语）问："竞品降价那个事，现在怎么样了？"

agent 反问："请问您指的是哪个群或话题里的事项？我可以查看指定场所的会话记录。"

他愣住了。**他不记得是哪个群——记得住的话还问你干什么？**agent 解释它可以逐个翻群，但云之家接口不支持搜索，只能一页 20 条地翻。五分钟后它翻到了，给出一个还算靠谱的摘要：方案拖在市场部，上周说本周给。罗总的评价："比问人快一点，比我想要的慢十倍。"

**14:00，经营会，会议室，笔记本投屏。**【E4】【E5】讨论华东库存时他说"我问一下 AI"，当众在工作台里问："华东 Q2 库存周转天数。"

九十秒。会议室安静地看着投影上的转圈，有人开始低头看手机。数字最后出来了，是对的——但**当众等一分半，比查错更难堪**。他决定以后开会前先偷偷问好。

更糟的是投屏那一刻他没意识到：工作台左栏列着他的全部场所，倒数第三行是"高管群"，旁边一张活跃话题卡——"组织优化测算 [运行中]"。散会后副总老周私下提醒了他。他后背发凉。

**16:00，办公室。**【E10】他把三个经理叫来当面布置：市场部周五前出竞品应对方案；生产部下周三前出成本压缩清单；HR 本周内出招聘冻结影响梳理。人走后，他对工作台说："这三件事，帮我盯着。"

agent 很诚实：它可以在对应群里建话题、发任务说明，但它**没有"盯着一个人"的能力**——它能执行任务，不能追踪别人执行任务；到期提醒、进度跟催都做不了。它建议罗总"随时来问，我可以去翻这三个群的最新消息"。

罗总说："那盯的人还是我。"

**18:30，高管群。**【E6】【E9】五个人，讨论组织优化——直白说，裁员 15%，两个部门合并。打字之前罗总先单独问小陈："高管群的东西，那个 AI 会不会记下来？会不会在别的群说出去？"

小陈晚上十点回了他一长段，是个诚实的答案：每个群的记忆彼此隔开，高管群的记忆不会被带进别的群——这层设计是可信的。但有三个"但是"：第一，只要在这个群用过 agent，任务归档时它**默认自动提炼记忆**，而配置项里有"是否接单""写权限""工具开关"，**唯独没有"永不记忆"这个开关**；第二，眼下唯一保险的办法是把高管群整个设为"不接单"——那 agent 在这个群就彻底废了，连"帮我把这段讨论整理成表"都不行；第三，它关于"罗总这个人"的记忆（联系人记忆）会在哪些场合被带上，文档里没写清楚，他不敢打包票。【E7】

罗总只听懂了翻译过来的一句："**要么它可能记住，要么它完全不能用。**"他选了后者。

还有一件事让他心里没底。【E16】公司给五个高管都配了 DSH——也就是说这个群里理论上盘着**五个 agent**，每个人的助理都"在场"。副总老周要是让他的 agent 整理群里讨论，记忆落在老周那边，罗总关自己这边的开关管得着吗？"一个群里五个 AI 各记各的账"，这画面让他想起前几年钉钉里泛滥的机器人。小陈承认："这个场景，文档里……还没写。"

**21:20，家里书房，工作台私语。**【E8】他让 agent 按他口述的口径悄悄整理一版《组织优化测算表》：两个部门的人力成本、补偿金估算、时间线。agent 做得很好，存成了云之家文档。

他盯着那个链接，问了小陈当天最后一个问题："这个文档存在哪？谁能看到？"小陈说默认在他个人文档空间，理论上只有他能看，"但 agent 交付时的默认权限这块，我得再确认一下"。

"理论上"三个字让罗总把文档下载成 Excel，然后把云上那份删了。

### 第二天（周三）

**8:00，车上。**【E3】昨晚他跟小陈说了他真正想要的东西："每天早上八点，把昨天的回款、出货、现金余额，三个数，发到我手机上。别的都不用。"

小陈的回答让他困惑："它现在'不会自己动'，所有动作都要有人先开口。定时主动推送在规划里，但排在最后一期，前面还有五期。"

罗总："我不要它'自己动'。我要它**每天替我做同一件我授权过的事**。这也叫'自主'？"

这句反问，小陈没答上来。

**9:30，部门周会群。**【E6】他要在群里 @云小助 查一个物流数据，手指悬在发送键上停了两秒——**它昨天"读过"高管群吗？会不会哪句话带出来？**理智上小陈说过隔离可信，但他没有任何地方能亲眼"看见"这种隔离。他把那句话删了，自己去翻报表。

**信任的成本不是泄密本身，是每次开口前的这两秒。**

**11:00，办公室。**【E10】他问 agent："昨天那三件事，什么进展？"agent 去翻了三个群：市场部经理在群里回了初稿提纲（有证据）；生产部群里零动静（无信号）；HR 的进展是今早电梯里当面汇报的（agent 不可见）。汇总结果：一个准确，一个未知，一个过时。

罗总明白了：**它看得见群，看不见承诺。**

**14:00，董事会材料。**【E11】上月 agent 整理的《华南回款分析》确实不错，他想转给董事会的外部顾问方老师——方老师不在公司组织架构里。他发现没有任何"外发"通道：文档锁在云之家组织内，外链要么开到危险的程度、要么开不了；而且文档末尾附着"数据来源与读写清单"，列着内部表格的名字。最后他让秘书**复制粘贴进 Word、删掉最后一节、邮件发出**。AI 时代的最后一公里，是 Ctrl+C。

**16:00，办公室，小陈来"培训"。**【E12】小陈想教他配置"场所合同"，讲到第三分钟："每个群相当于跟 agent 签了不同的合同；合同分硬的和软的，硬合同只能在面板改，软合同可以对话改；群里的对话叫话题，话题就是会话；跟它说话分公开和私语两种语态；左边侧栏是租约制的，任务完结自动退租——"

罗总抬手打断："小陈。我招一个助理，不需要他先给我讲他的神经系统。**我说话，他办事，办不了他来问我。这里面有几个概念？**"

他顿了顿，补了句真话："公开私语这个我懂——哪句话能让下面听见，我比你们都清楚。别的我不想知道。"

**17:30，下班前。**他瞥了一眼工作台：收件箱躺着六条"待验收"，最早的是周一的。他一条也不会去点。【E13】

关机前他给这两天做了总结。他要的东西自始至终只有三样：

**问一句，十秒有数；每天八点，一张纸；布置的事，有人盯。**

第三样今天做不到，第二样排在最后一期，第一样——被当成项目在办。

"工具是好工具，"他对自己说，"就是还没想明白**老板是用来干嘛的**。"

## 第二部分 · 逐环节走查（缺口表）

严重度：致命（该画像下一票否决/弃用级）> 高 > 中 > 低。缺口分类按题设四类，可复合。

| # | 剧本环节 | 用户期望 | 设计现状 | 缺口分类 | 严重度 | 第一性判断 |
|---|---|---|---|---|---|---|
| E1 | 11:30 问"上月华南回款多少" | 像问秘书：十秒回一个数，无 ack、无话题卡、无文档、无待验收，问完即结束 | 一切 @ 统一走"话题=会话=任务"全生命周期（A0 ack 物化话题、A3 终态验收、A4 过程摘要、D1 收件箱条目）；"轻问 vs 任务"区分被显式推迟到域 F（A0 边缘案例表） | 已知推迟-域F（但推迟理由错位） | **致命** | 轻问被归入"主动性"是分类错误：Devin `!ask` 区分的是"一次性对话 vs 持久任务"，与主动性无关。对高管画像，问答是主契约、委派是例外——会话图不必改，缺的是"不留租约、不产工件、阅后即终态的一次性投影"。这是价值排序问题，不是功能排期问题 |
| E3 | 8:00 "每天八点三个数发我手机" | 一次授权，永久执行；只读、定时、定内容 | 域 F 明确推迟至 P6（"主动性放大既有的不可信"）；CLI 无 reminder/webhook，推力只能来自 DSH 调度器（D8 已述） | 已知推迟-域F | **致命** | 只读定时报告不需要"信任地基"：无写入、无自主决策，风险≈零。"主动性放大不可信"的论据只适用于**写自主**，晨报被连坐。DM 兜底（A2）已证明 gateway 能主动发消息，缺的只是一个 cron——信任门槛是写权限的函数，不是主动性的函数 |
| E6 | 18:30 高管群谈裁员，要求"绝不进任何记忆" | 本场所内容零蒸馏、零沉淀、零互读，且**可被证明** | C1"记忆跟场所走、群记忆不跨群"方向正确；但 G1 硬合同枚举项（接单/触发者/写权限级/工具面/审批策略/模型列表）**没有"记忆策略"一项**；C3 归档自动蒸馏默认开启 | 缺失（硬合同缺关键条款） | **致命** | 记忆是场所合同里最应该"硬"的一项，却不在硬合同里。能力越界可撤销，**记忆越界不可撤销**（写入即已读过）。机密场所需要硬合同级的"记忆=off"，并在 UI 上可见（罗总"看不见隔离"的两秒犹豫，就是隔离不可见的代价） |
| E8 | 21:20 私语产出《组织优化测算表》 | 工件只有他一个人能看，且这一点无需"理论上" | 工件落云之家文档（工件优先原则），但**工件默认存储位置与 ACL 继承规则未规格化**；A4 过程摘要"非平凡任务默认开启"在机密任务上同样适用 | 缺失 | **致命** | 工件优先的设计里，**工件 ACL 就是信息边界本身**。"权限跟场所走"必须延伸为"工件 ACL 继承场所"，否则场所隔离在出流处破口——上下文守得再严，产物裸奔等于白守 |
| E10 | 16:00 布置三个经理三件事，"帮我盯着"；次日问进展 | agent 追踪**人的承诺**：到期提醒、进度信号汇总、无进展预警 | 图对象只有 审批/任务/工件/记忆，任务对象预设 agent 是执行者；"人的承诺"不是图对象；到期跟催/盯群归域 F；pull 式问询可行但盯的人还是罗总 | 缺失（对象缺位）+ 已知推迟-域F（推力部分） | **致命** | 高管委派的主形态是"派人"不是"派 agent"。会话图缺一类节点：**承诺对象**（承诺人/事项/期限/证据流），生命周期与 agent 任务不同（无工件验收，只有对人类信号的观察）。按 D8"现在建边、将来供电"的同款逻辑，承诺对象本可在 P1 建模，域 F 只是日后给它接上推力 |
| E2 | 12:10 "竞品那个事怎么样了" | 不指明场所，agent 在他有权看的全部范围内找到并汇总 | 记忆跟场所走、会话互读限同场所、组织记忆暂缓、CLI 无消息搜索（infra ask 在列） | 缺失 + infra上限 | 高 | 高管的问题天然跨场所。venue-scoped 记忆对防泄漏是安全特性，对"老板视角"是能力天花板——需要"以操作者本人权限做跨场所只读检索"的聚合层（他本可逐群翻，agent 替他翻不是越权），这与 E6 的隔离不矛盾：隔离约束的是**说**，不是操作者本人的**读** |
| E4 | 14:00 会上当众查数，等 90 秒 | 会议节奏内出数（<30s），否则宁可不用 | 非目标 2"不追实时性（5s 轮询对委派模式够用）"；CLI 无搜索、单页 20 | infra上限 + 不合理（非目标适用域过宽） | 高 | 延迟容忍度是**交互模式**的属性，不是产品的属性：委派可等五分钟，轻问只能等三十秒。同一张会话图需要两个 SLA；"委派模式够用"不能覆盖高管的主用法（E1 的另一面） |
| E5 | 14:00 投屏时暴露"高管群·组织优化测算 [运行中]" | 共享屏幕时机密场所整体不可见 | D1 统一收件箱以"操作者全部会话进侧栏"为荣；无演示/专注模式，无按场所静默显示 | 缺失 | 高 | "单屏完成一切"的反面是"单屏暴露一切"。聚合面在物理共享场景需要按场所隐身的能力——这是场所合同缺失的**显示维度**（此前合同只管能力维度）。话题卡标题本身就是机密（"组织优化"四个字足以引发全公司地震） |
| E7 | 小陈答不上"联系人记忆在哪些场合被带上" | 关于"我"的记忆绝不在别的场所把机密带出来 | C1 列出联系人记忆分层，但**未定义其注入作用域**；"不跨群"铁律只写了群记忆 | 缺失（规格空洞） | 高 | 联系人记忆是唯一"合法跨场所"的记忆层（人出现在一切场所），因此需要**最严格的进入门槛**：只收偏好类事实（格式、称呼、习惯），禁收事件类事实（他在谋划什么）。这条红线目前不存在 |
| E12 | 16:00 "培训"被打断："我不想学这些" | 零概念上手：说话、办事、被问。他愿意懂的只有"谁听得见" | 话题/语态/场所/合同/租约/generation/fork/命令全部面向单一操作者画像；G3"操作者即管理员"；无分层披露、无托管管理角色 | 不合理（操作者画像单一） | 高 | 概念分两类：**镜像组织现实的**（谁听得见=语态/场所）高管天生就懂、无需教；**镜像系统机制的**（租约/合同/换代）必须全部埋进默认值。真正缺的是"操作者 ≠ 管理员"的角色拆分——IT 管硬合同与 preset，高管只负责说话；目前二者被 G3 焊死在同一个人身上 |

### 走查小结：探针回收

- 探针①（轻问）：E1/E2/E4/E14/E15 —— 高管主用法整体落在设计的推迟区与 infra 天花板上。
- 探针②（晨报）：E3 —— 刚需被域 F 整体推迟连坐，推迟论据不适用于只读定时。
- 探针③（机密）：E5/E6/E7/E8/E9/E16 —— 隔离方向正确，但硬合同缺记忆条款、工件 ACL 未规格、联系人记忆作用域空洞、聚合面无隐身、多操作者同场所无公约；"说漏嘴"的直接答案是"结构上不会（场所注入隔离）"，但**用户无法看见这个保证**，于是行为上等同于不可信。
- 探针④（盯人）：E10 —— 会话图缺"承诺对象"，agent 能执行不能观察。
- 探针⑤（会中查数）：E4/E5 —— 时延 SLA 与投屏隐身双缺。
- 探针⑥（外发）：E11 —— 组织外是投影矩阵的空白格。
- 探针⑦（概念负担）：E12/E13 —— 概念该按"镜像现实/镜像机制"分流，角色该按"操作者/管理员"拆分。

## 第三部分 · 最重要的第一性洞察

**路线图的价值排序按"操作者=重度委派者"校准，对高管画像几乎完全倒置；而被推迟的恰恰是信任成本最低的部分。**

罗总的三样刚需——问一句（轻问）、每天一张纸（晨报）、布置的事有人盯（盯人）——全部是**只读**行为：不写文档、不做自主决策、不代表任何人说话。它们对信任基础设施的需求趋近于零，却被"主动性放大既有不可信"（域 F 推迟论据）和"轻问服务于主动性"（A0 裁决）整体推到 P6 之后；与此同时优先建成的 P1-P4 委派闭环（写操作、审批、验收）是信任成本最高的部分。**信任门槛是写权限的函数，不是主动性的函数**——域 F 应一分为二：F-read（晨报/盯人推力/轻问投影：cron + 现有只读工具 + gateway 发消息即可，P1 级地基已够）与 F-act（写自主：跟催代言、自动执行，维持原推迟）。不拆开这一刀，产品对"200 人公司里最有预算决定权的那个用户"的前六个月价值趋近于零。

### 次要洞察（记录备用）

1. **记忆条款必须入硬合同**：能力越界可撤销、记忆越界不可撤销，"永不记忆"是机密场所的一票否决项（E6/E9）。
2. **工件 ACL 继承场所**，否则场所隔离在出流处破口（E8）。
3. **会话图缺"承诺对象"**：agent 任务（agent 执行）与人的承诺（agent 观察）是两类节点，后者是高管委派的主形态（E10）。
4. **概念两分法**：镜像组织现实的概念（谁听得见）免教，镜像系统机制的概念（租约/合同/换代）全部埋进默认值；操作者与管理员拆为两个角色（E12）。
5. **隔离必须可见才可信**：结构上不泄漏 ≠ 用户敢开口；每次开口前的两秒犹豫是隔离不可见的持续税（E6）。
