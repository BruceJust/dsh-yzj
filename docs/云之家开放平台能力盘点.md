# 云之家开放平台能力盘点（vs yzj-cli 现状）

> 2026-08-18 · 基于开发者平台文档全量抓取（www.yunzhijia.com/opendocs + open.yunzhijia.com 新站，docsify 底层 markdown 源逐页读取，无编造；两个调研 agent 交叉覆盖）。
> 结论先行：**我们技术方案里的三条"红线事实"（无 push / 无卡片 / 无机器人身份）全部只是 CLI 层约束——平台层能力齐全**。CLI 是官方开放面的一个薄子集，且部分走的是非官方内部接口。演进不必等 CLI 补齐：平台 API 可由我们的 transport 层直连（HTTPS + token），CLI 只是适配器之一。

## 一′、yzj-cli 0.1.6 增量（2026-09-03 实测，0.1.4 → 0.1.6）

| 新命令 | 平台语义（实测） | 对本设计的意义 | 处置 |
|---|---|---|---|
| `im message search --keyword` | **跨会话内容检索**：当前用户全部可见范围，按群聚合返回（`matchedMessageCount` / `hasMoreMessages`），可按群 / 发送人 / 被 @ 人 / 时间段筛 | **推翻分册接缝⑦的事实前提**（此前：平台无跨会话内容搜索面，`im group search` 只是群名录）。能力已到，**面**未定 | 已落 agent 读工具 `yzj_im_message_search`（F-read，可见域本含）；桌面搜索面是否落座 = 主册 §7 产品裁决，待 Bruce |
| `whoami` | 个人授权身份：openId / orgId / name / 部门 / 职务 + **`tokenStatus` / `expiresAt`** | 登录快过期此前只能以一串莫名失败被发现；现在有可读原料 | `yzj_whoami` 已改走原生命令并带出登录态。通道 `identity()` 仍走 `contact user get`（启动关键路径，未动）——建议下一步改用并把「登录已过期」做成诚实状态 |
| `im message recall --msg-id` | 撤回**本人**消息，有时限，服务端判定，不可逆 | 关闭"平台也没有"第 1 条的一半。设计上撤回是社交动作（"说出去才算数"、社交摩擦不碰） | **未接**。若接：强确认级、仅限 agent 自己发出的消息、任何编排路径不得自动调用——是否给 agent 这个动词，待裁 |
| `im group rename --group-id --name` | 改群名（需在群内；管理员限制时需管理员） | 建群流程（4i）之后的一处小修理 | **未接**。可作 standard 级可逆写工具，价值低，有场景再接 |

**破坏性变更（比四条新命令更要紧）**：0.1.6 把**所有**成功输出统一包进信封 `{ success: true, identity, data: … }`（`global.md` 「输出格式」），0.1.4 是裸数据。全局升级当场把 **3090 与 3080 一起打断**（两边 identity 读到整只信封，`openId` 在 `data` 里，通道以为登录没了；`doc workspace list` 渲染成「(no workspaces)」这种恰好为空的屏幕）。处置：①全局**回退 0.1.4**（3080 旧系统不动，它按裸数据解析）；②next/ 的桥接层在**唯一入口**剥壳（`unwrapEnvelope`，认形状不认版本，两种输出都吃）；③0.1.6 装在独立前缀 `~/.yzj-cli-0.1.6`，3090 经 bridge `binary` 配置指过去——**两个实例各钉各的 CLI**，全局不再是共享的升级面。

**一处随之待裁的读侧策略**：`yzj_im_message_list` 与新的 `yzj_im_message_search` 在**场所回合**里都能读到操作者可见的**其他**群——读是 F-read 可见域内合法，"说"才受听众集合约束。要不要在 place turn 里把读侧按听众集合收窄（默认只搜当前场所），两个工具应同一裁决。

**未变的缺口**（0.1.6 未动）：三墙（reaction / 富文本内嵌图片下载 / 群成员列表）、日历 recurrence 与跨天查询、消息流订阅、消息编辑。

## 二、平台也没有的（真实硬约束，不随 CLI 演进消失）

1. **普通消息编辑无 API**（消息卡片的 update 是唯一例外）——"卡片 = 唯一可变消息"仍成立。~~撤回无 API~~ **2026-09-03 更正：yzj-cli 0.1.6 起有 `im message recall`**（仅本人消息、有时限、能否撤由服务端判定、不可逆）——撤回是**消失**不是可变，卡片作为对象投影载体的地位不受影响；
2. **无通用消息流订阅**（没有"群新消息 webhook"）——读群语境、话题上下文仍只能轮询（真人/CLI 通道长期保留的根本原因）;
3. **无"以应用身份发裸文本消息"接口**——应用侧主动触达必须走机器人/公共号/待办三通道；
4. 机器人**按群存在**（逐群 UI 创建、token 互不通用）、只收 @ 文本；
5. 桌面 IM 内嵌小程序窗口等形态标注"暂未对外"。

## 三、接入前提（共同依赖，演进门槛）

- **公网可达 HTTPS 回调端点**：对话机器人/卡片按钮/待办 passUrl/组织变更/审批推送全部是"云之家 POST 到我方"——DSH 是本机进程，需要**回调中继**（云函数/轻量服务器转发到本地，或内网穿透）。这是阶段二的第一块基建。
- **组织管理员配合**：应用注册（appId/secret）、资源密钥（resGroupSecret 分只读/可编辑）、机器人逐群创建、应用设审批类（signKey）。
- 频控与配额：app 3500/team 2000/resGroupSecret 1500 次/分，单 IP 20 万/时；机器人 60 条/分/个；公共号同内容 10 分钟防重。

## 四、通道与身份演进三阶（对技术方案的输出）

| 阶段 | 入站 | 出站 | 身份 | 前提 | 对应技术方案 |
|---|---|---|---|---|---|
| **一（现在，P1）** | CLI 轮询（真人账号） | CLI 发文本（真人名义） | 寄生操作者真人账号 | 零（现状即得） | v2.1 全案，不变 |
| **二（平台混合）** | **对话机器人 @ 回调**（触发秒级）+ 轮询保留（读语境） | 群机器人 webhook + **消息卡片（可更新、带按钮）** + 待办投影 | 真人（读）+ 机器人（收发） | 回调中继；管理员开通；测试群机器人 | transport 第二适配器 `platform-api`；cards 第三渲染通道"原生卡"；`updateStrategy:'edit-in-place'` 激活 |
| **三（应用身份）** | + 公共号回复回调、组织/审批/日程事件回调 | + 公共号 DM、审批代发起、组织镜像 | **企业应用**（三级 token），真人通道仅余"读消息流" | 应用注册、team/资源密钥、OA 轨真实需求 | B1 专号升级为应用身份；OA 轨 adapter；组织镜像服务 |

**证据门**（沿用冻结纪律，不提前建）：阶段二触发器 = P1 dogfood 中轮询延迟/真人名义成为真实疼痛 + 管理员凭据到位；阶段三触发器 = 多操作者/OA 对接真实需求。P1-lite 范围不因本盘点改变——但 v2.1 的接缝（transport 适配器抽象、cards 渲染通道注册制、updateStrategy、track 字段）已保证三阶演进不动核心。

## 五、给 yzj-cli 的增强建议清单（若走 CLI 补齐路线）

`robot` 子命令族（webhook 凭据管理/send/serve 回调端）> `card send/update`（templateId+dataContent+outTrackId）> `todo create/action` > `org tree/members/sync`（app token）> `group create/member` > 消息编辑（若 app 能力开放 API）> 日程 recurrence。——与 transport 直连平台 API 二选一或并行，接缝一致。

## 六、yapi 全量导出盘点（2026-08-21，内网 YApi 分组 393：9 服务 749 接口，docs/yapi_export/）

> 与前五节（open.yunzhijia.com 公开开放平台）的关键区别：本节是**内网服务 API 面**——能力远大于公开面，但可达性分层（见 §6.5）。全部接口 YApi 状态 undone（维护标记），字段可能漂移。

### 6.1 AI 速记闭环（livestream/aisteno 22 接口 + workassistant-ai-agent 纪要族）

- **数据形态**：`detail(stenoId)` 返回主表（title/summary/note/viewStatus/enhanced/docId/durationSeconds）+ 转写段（seq/speakerId/text/startTime，游标分页）+ `minutes`（MinutesOutput：**decisions[{content, basis, owner}]**、coreConclusions、summaryTree、coreSpeeches[{speaker,rawQuote}]、speakerStats、sections、**actionItems[{text, assignee 文本, dueDate, status, executors[]（含 openId/oid/name/department）}]**）。
- **跨服务桥**：`transcriptId == stenoId`（391 result 双别名路径确证）；`download(types=[summary|transcript|minutes])` 生成知识库 Markdown 文档返回 docId；finish 后 summary/transcript **自动上传知识库**（kbUploadStatus 轮询）。
- **摄取通道**：无任何第三方 webhook。`list` 过滤仅 page/时间/enhanced/keyword、**无 creator 参数**（范围=当前登录身份）→ 摄取 = **每用户一条增量轮询线**（updateTime 增量，viewStatus=FINISHED + enhanced=true 时拉 detail）。唯一翻案线索：15 服务 `workSetting/callBackUrl`（时间助手企业回调地址，载荷未文档化，**待实测**）。
- **硬约束**：速记侧 actionItems **无 per-item ID、update 为全量替换**——第三方写回会覆盖用户手工编辑，**对我们只读**；纪要重生成无版本号（"最近一次 SUCCESS"）→ 提案需内容级 diff；**meetingId↔stenoId 映射两文档均缺失**（需实测找桥或时间+参与人启发式）。
- **发言人**：speakers 返回 speakerId/name/**userId（通讯录手动绑定后才有）**/占比/时间段；rename 支持 GLOBAL/LOCAL/MERGE 幂等。→ "谁说的→谁的承诺"三级可信度：绑定 userId > AI assignee 文本 > 发言人N。

### 6.2 待办四层体系（workassistant-ai-agent + workassistant-service）

- **①提案池 action-items**（391）：AI 从会议/聊天/通用文本提取（extract 家族含 SSE 流式；输入 content+participantUserIds，输出含 **evidence 原文证据**/contextSummary/suggestedTime/sourceId=meetingId；无置信度无字符锚点）→ PENDING → 组织者编辑/confirm/`confirm-and-convert`（转正+讯通推送+按责任人拆分）。
- **②平台侧正式待办 user-action-items**（平台视角的"真身"；**对 dsh：承诺真身在图，此为执行者侧投影面——代发登记话语为主、待办写入为副**，见设计方案 v4.17 对接裁决刀）：`ownerUserId 单值 + assignerUserId + evidence + sourceType/sourceId`；责任人第二道门 `confirm/reject（带 reason）`，15 侧才有 `/complete`（**无 body 不押证据**）。**internal 写入口**：`POST /api/internal/user-action-items`（sourceId+title+ownerUserIds，**创建或更新** upsert 语义）+ `DELETE .../source/{sourceId}` 级联清理 → **(sourceId, ownerUserId) 是平台幂等键**。
- **③老个人待办 /workassistant/todo**（9 接口，无指派概念）——正被迁移为"备忘录"，勿用。**④速记纪要内嵌 actionItems**（6.1，只读）。另有 V11 worktask（32 接口）与 V12 project（45 接口）两套重型任务体系，独立于待办。
- **推送**：push/batch-push 走**讯通**；完成回流**零 webhook 只能轮询**（pending/overdue/upcoming/statuses 过滤）。sync-to-calendar 仅弱标记（记 calendarEventId，不建日程不双向）。

### 6.3 日程/时间助手（417 日程 V12 + 391 冲突族 + 15 会议/日程双实体）

- **V12 create**（`/gateway/cloudwork/calendar/create`）：**显式 openid（以谁的名义）**；提醒三层（noticeTime/noticeTimes 多次/customSMSNoticeTime 短信）；actors/meetOrganizers/leaders/sponsorInfo；**agent 代建字段**（有正式授权面板 getAuthorizedAgentList）；roomId（queryRoomsByTime 返回是否需审批）；**workData{msgId,groupId}**（IM 消息→日程出生凭证）；**redirectUrl.detail**（"通知弹窗和列表场景优先使用"——官方回链挂点，可直跳 dsh 会话页）。repeatMeeting：5 种固定频率、不跨天、最长一年、服务端展开为 meetingIds[]（batchId 聚合）；batchModify/batchCancel = this-and-following。
- **冲突族**（391）：detect 返回 conflicts+**strategy{type:SHORTEN|DELEGATE|RESCHEDULE, reason}**（建议）+ detect-summary 成文（"检测到1处冲突，建议《周会》提前结束15分钟"）；**四个执行接口（shorten/reschedule/delegate/entrustJoin）无平台确认直接落库**——确认门必须在 dsh 侧；entrustJoin 例外自带应答链（agreeBeEntrusted，半门）。**找时段**：participant-availability（今明两天占用+推荐时段 score/reason/谁没空）、-rule 纯规则版、15 开放接口 commonFreeTime/search（ALL_FREE/PARTIAL_BUSY/NEXT_DAY_ALL_FREE）。
- **brief**：`calendar/schedule/brief`（open-api 标签，响应结构未导出待实测）；`inner/calendar/executive/brief` 返回**成文晨报**（content+统计）；workspace-card + bizAiInsight 结构化半成品。
- **提醒/触达**（15）：服务端调度的声明式提醒 + 手动短信（含冷却）/语音电话/一键催办/noticeLater snooze/卡片 + **ICS 日历订阅**。应答：meeting/join、newwork/accept（0 未响应/1 拒/2 受 + reason）、quit；评论按 tag 挂载（task/meeting/worktask 共用，含操作日志位）。
- **结论修正**：「推力只能来自 DSH 调度器」拆半——**对人的推力平台原生齐备（DSH 不自建对人提醒）**；对 agent 的推力仍靠轮询（queryByDay/queryByRange/pageRecentList 游标为轮询而备）。
