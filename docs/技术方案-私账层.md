## 0. 一句话与总判据

**组织的图记承诺的一生，金库记你的判断的一生——两本账，两种可见性，永不合流。**

私账层 = P–agent–P′ 回路的工程形态。**P′ 环行八环**（一切实现对照此表验收，缺一环即割裂债）：

```
裁决 →（立约·可选）→ 事实回流 → 对表归因 → 判例入账 → 模式浮现（滚动）→ 回喂（后视镜/换挡）→ 再裁决
```

总判据（全分册通用，§10 有断言形态）：
1. **三不入**：私账对象不进收件箱、不进决断条、不进任何可应答聚合徽标——由**存储分离结构性保证**（不靠 filter）；
2. **单向耦合**：私账引用组织图锚点，组织图**永不**引用私账——由**依赖方向与 schema 双重机械保证**；
3. **持镜人**：agent 只在人发起的时刻消费私账；组织侧行为路径结构性读不到私账；
4. **回路合环**：模式必须能经人签发的规则（后视镜/换挡）回到下一次裁决时刻——金库不是目的地 app；
5. **金库照现在的你**：判例永续（史）、模式滚动派生（近 90 天，零存储）——不给人建档案。

## 1. 分册边界

**本分册管**：私账存储（pgraph）、私账事件族全量词汇、私账对象族（立约邀约/预期/校准回执/换挡/后视镜/邀约疲劳）、私语通道与金库的桌面投影、私账治理（硬合同工程兑现/部署开关/取走销毁）、P1 降级明标、验收断言、实施顺序。

**留在主册管**（本分册只指认不重述）：组织图词汇与数据律原文（§3）、可应答对象系统内核（§4——本分册**复用其组件与状态机，不复用其存储**）、授权租约本体（`lease/*` 是组织侧既有对象——两读的「设为租约」出口落组织图，换挡史才落私账）、条尾入口条款（§7.1 条长治理信号——两读是其语义扩员零新入口）、guard 与合同三层（§6.4/§8）。

**依赖方向铁律（持镜人条款的机械保证，v1.1 精确化）**：

```
pledger 包 ──依赖──▶ graph（日志内核复用）· cards（卡型组件/状态机复用）· 组织图服务（只读锚点解析）
                   · channel 投递 API（自聊 DM 出站——只出不进）· 既有注册面（见下）
objects / tools(组织工具) / channel / scheduler(组织侧 watcher) ──✕ 禁止 import pledger──
surface ──依赖──▶ pledger（仅渲染消费：金库视图/私语流/后视镜条/两读卡/档位生效面）
```

**依赖倒置经注册面（v1.1）**：pledger 是标准 cordis 插件，经**既有对象族注册面**把自己挂进系统（卡型注册进 cards、工具注册进 tools 工具面【按 viewer 条款】、订阅挂 `yzj-graph/appended`、定时器自带）——组织侧包只持有注册面抽象，**代码里不出现 pledger 符号**。**pledger 自带 effect 时间轮（v1.1 自纠）**：检验点到期、疲劳窗口等时间驱动逻辑由 pledger 内部 effect 定时器承担——scheduler 包在 ban 名单内，**不得挂靠**（否则实现者第一天就违 ban）。组织侧编排（提案生成/路由/评估/委派/回执）在**依赖图上就够不到**私账——"agent 不因你的误判史改组织侧行为"不靠自律靠链接器。CI 断言：import-ban lint（§10-②）。

## 2. 存储：第二本账（pgraph）

- **形态**：复用 graph 包日志内核，**第二个 store 实例、不同宪法**——`createGraphStore(root, policy)`；`~/.dsh-next/yzj-next/pledger/<operatorOpenId>/pledger.jsonl` + atomic-write 快照。信封同款 `{v, sv, seq, time, type, data, actor}`；单进程单写者；启动快照+尾部重放。**host 内存不是真身**（确认卡教训适用）：邀约/回执/预期的待答态全部落日志，重启可恢复。
- **归属键 = operatorOpenId（人，非 accountKey）**：账本随人不随部署实例；P1 单操作者下与登录真人一致。多操作者期每人一份文件，互不可见由文件边界保证。
- **policy（与组织图的三点宪法差异）**：①viewer 只接受 operator（**place viewer 的查询在 API 形态上不存在**——不是返回空，是无此入口）；②审计导出路径不可触及（对称保留律第二例外区——审计导出投影的重放过滤器根本不挂 pgraph 源）；③**组织与他人不可导出、本人可整体取走与销毁**——目录自包含（无外部索引、无组织图反向引用），拷走目录即取走全账；销毁 = 目录删除，入口经 `/vault destroy` 两段式确认（不可逆人签发终态同款门）。
- **跨账引用单向**：pgraph 事件可携组织图锚（`{graphSeq}`、cardRef、msgAnchor、URI）；**组织图任何事件 schema 不含 pledger 引用字段**（zod 层无此字段即写不进——schema 面保证，与依赖面双保险）。
- **部署二值开关**：`pledger.enabled`（bundle 配置）。关 = 不建目录、不注册工具、不渲染任何入口；**不存在"启用且组织可见"的配置项**——明拒的构造性兑现（没有这个旋钮，就不会被拧到危险档）。**中途关闭不删数据（v1.1）**：已有目录原样保留，重开即续——**destroy 两段式是唯一删除路径**；私账亦**无墓碑事件**：更正全走追加语义（answered 追加/dismissed-reopened/withdrawn 留痕），整账销毁是唯一抹除。

## 3. 词汇表（私账事件族全量——只存在于 pgraph，组织图零新增）

```ts
/* —— 预期（对话式立约）—— */
'expectation/opened'     // { text（赌注原文——产婆术：必须是人亲口的话语，agent 不得生成不得改写）,
                         //   checkpoint: { text, ts? }（检验点两层——主册 due 同构：话语真身+解析投影可空可纠）,
                         //   verdictRef（组织图裁决锚——本预期依附的裁决）, evidenceRefs[]（邀约出处的组织侧锚）,
                         //   idemKey = verdictRef }
                         // 不可回填 + 不可改笔的机械保证：同一 verdictRef 至多一次 opened（幂等锚），
                         // 无 updated 事件（改赌注 = withdrawn + 不可再 opened——见下）
'expectation/withdrawn'  // { reason }——唯一退出动词（撤回留痕不删史；前提消失时撤回是诚实不是失败）；
                         //   withdrawn 后同 verdictRef 的 opened 被幂等锚吸收 no-op（堵"临近检验点改口"）
'expectation/settled'    // { calibrationRef }——对表归档（由校准回执归因触发；检验中→已对表的迁移时刻）

/* —— 图外事实的人工补登（v1.1 补第七型——环3 的词汇地板）—— */
'fact/noted'             // { text（人的原话——原话直存律，见下）, about: verdictRef | expectationId,
                         //   anchor?（私语话语锚） }
                         // "跟踪≠监工"对私账适用：系统不猜图外，图外事实（线下评审/口头反馈/邮件结果）
                         // 唯一入口 = 人在私语域一句话补登（同组织侧补登语法）；检验点到期 agent 问一次
                         // 结果，人的答复经此落账——P1 事实回流的主路径

/* —— 校准回执（恒带"校准"前缀，与组织侧交付回执 receipt/* 词汇卫生分立）—— */
'calibration/opened'     // { verdictRef,
                         //   factRef: OrgAnchor | FactNotedRef（v1.1 扩域）——事实源三分：
                         //     ①图内结构性事实（终态/reopened/同 goalRef 血缘新边/租约重签摘要——
                         //       结构匹配优先，"结构性判定先于语义判定"既有纪律）
                         //     ②fact/noted 人工补登（图外事实唯一入口）
                         //     ③ambient 语义识别（F-read 线，押门——P1 不做）,
                         //   expectationId?（无则为隐式预期路径——裁决本身即预期）,
                         //   evidence[]（证据行：只许事实与假设措辞，禁心理判词——prompt 纪律 + review 断言）,
                         //   idemKey = (verdictRef, factRef) }   // 同一事实多次回流不重复出执
'calibration/answered'   // { attribution: 'q1'|'q2'|'q3'|'q4' }（对了因判断/对了因运气/错了因判断/错了因世界）
                         //   归因由人下，agent 不代下；可纠 = 追加（最新生效，更正即追加律）
'calibration/dismissed'  // 第五出口「配对错了」：事实与裁决无关（宁空勿错私账版——dlvinfer"不是交付"同族）；
                         //   吸收态：判例不入任何派生查询；同 idemKey 不再出执
'calibration/reopened'   // dismissed 的纠回（更正即追加，不改史）——四格重新可答

/* —— 换挡与回喂 —— */
'gear/shifted'           // { family（提案族 key：'write-confirm'|'goal-breakdown'|…开放注册）,
                         //   gear: 'lease'|'default'|'weight', entry: 'tail'|'vault', evidenceSnapshot? }
                         //   换挡史私有；「设为租约」的租约本体 = 组织图 lease/granted 既有事件
                         //   （创建走强确认既有——两读只是它的第二个发现入口），本事件只记你换过挡
'mirror/toggled'         // { family, patternKey, on }——后视镜 = 负重档的显示形态（#61 回喂环）；
                         //   人签发的私账规则：agent 只执行显示，默认不开、随时可关
'invite/declined'        // { family }——邀约不立留痕（疲劳治理的计数原料：连续 N 次 declined → 该族降频停问）
'invite/reopened'        // { family }——重开主权在人、入口在金库（降频的唯一恢复动词）
```

**判例与模式无事件**：判例 = `calibration/answered` 留痕本身；**模式 = 纯派生查询**（滚动窗口近 90 天/近 N 次，零存储）——模式滚动律的机械保证：没有累积存储就没有档案可建。金库四区（检验中/已对表/已撤回/模式）与换挡台全部是投影查询。

**原话直存律（v1.1——产婆术的参数面保证，viewer 铁律同款）**：`expectation.text` 与 `fact/noted.text` 由**编排层从人的话语原文（或其选段）锚定注入，模型无 text 参数**——agent 连转写你的赌注的通道都没有（"agent 不得生成不得改写"不靠 prompt 恳求靠参数面；prompt 层面的措辞纪律只剩 evidence[] 一处，配 review 断言）。

## 4. 私账对象族（obj-pledger）

复用主册 §4 CardDefinition 与动作总线（**组件与状态机复用、存储不复用**——卡实例落 pgraph，故 `pendingAnswerables`（组织图查询）结构性不含它们，三不入零 filter 达成）。投影通道收窄为两条：**桌面私语面/金库**（渲染通道②）+ **自聊 DM 文本**（通道③的自聊特例——自聊仅操作者可见，不泄漏；群文本通道与原生卡通道对私账对象**不存在**）。

- **立约邀约卡**（单答家族）：动作 = 立个预期（进入输入态——textarea 由人写，产婆术：无预填内容；「帮我写」得到维度不得到句子）/ 不立（`invite/declined`）。**出处限组织侧事实（#61 收紧⑤的机械保证）**：邀约生成器的**输入面**只含本次裁决对象及其组织图锚，**不含任何 pgraph 查询**——镜子等人来照的实现形态是"生成器根本看不见镜子"。**触发点 P1 收窄明标**：验收卡 accept 时刻 + 差距简报验收时刻（两个高信息裁决）；确认卡不触发（高频低信息——邀约变 nag）。**疲劳治理**：同族连续 3 次 declined → 停问（编排层 gate 读 declined 计数）；`invite/reopened` 恢复，入口仅在金库。**一次性**：不追问、不老化、不催——未答邀约静躺私语流。
- **预期对象**：出生 = 人发送赌注话语（selfdm turn）→ `expectation/opened`（text 走原话直存律）；**立约时窗（v1.1——不可回填的第二把锁）**：幂等锚只防重复不防**事后补立**（对历史裁决锚补 opened 会绕过"预期只在裁决时刻出生"）——P1 立约**仅经现行邀约卡的输入态**触发（邀约绑定其裁决，"裁决时刻出生"的机械宽解=邀约还开着时刻就还开着）；无邀约语境的话语立约押扩员（届时须校验裁决同 turn 语境）；检验点解析同 due 两层（强解析禁止、可纠）；**检验点到达（pledger 自带时间轮）且图内无匹配事实** → agent 在私语域问一次结果（等待语义——问结果合法可跟进；索要预期非法）；答复经 `fact/noted` 落账（人工补登路径——系统不猜图外）。金库投影三态：检验中 / 已过检验点待对表 / 已对表（settled）+ 已撤回区。
- **校准回执卡**（单答家族 + 第五出口）：出生 = pledger watcher 按**事实源三分**匹配（§3 v1.1：图内结构性事实走**结构匹配**——被裁决对象的 reopened/同 goalRef 且 sourceAnchor 回指的血缘新边/租约重签摘要，结构性判定先于语义判定；fact/noted 走 about 显式指认零推断；ambient 语义识别押门）；正文 = 当时（预期原文或隐式预期措辞）× 事实（锚一跳可回——组织图锚或 fact/noted）× 证据行（含"当时已在档"的简报/锚引用——一跳回组织侧对象，逐级兑付对私账适用）；动作 = 四格归因（q1-q4，候选注只给证据与假设）+ **配对错了**（dismissed）+ 纠回（reopened）；文本投影（自聊 DM）应答走既有关键词动作总线（cards 复用——先答先赢跨投影原样成立）。**未答不成欠账**：不老化、不可催、不进任何聚合——这本账的债主是你自己。
- **换挡台**（金库区块，非卡）：提案族注册表（P1 三族：标准写确认 / 目标拆解提案 / 交付前自检【多操作者期执行者侧】，开放注册）；每族三档 gear + 证据行（组织图派生：近 90 天通过率/中位停留【本人行为事实——可入私账证据，**永不进组织侧通道与模型调优**】）+ 换挡动词。**档位生效面**：`weight` = 桌面渲染层对该族卡片摆开证据、不预选、无一键通过（**仅操作者桌面**，文本投影不变——组织侧无人知晓你的档位）；`lease` = 引导至组织侧租约创建既有流程（强确认既有），成功后记 `gear/shifted`；`default` = 无状态。
- **后视镜条**（#61 回喂环）：`mirror on` 的 (family, patternKey) → 该族组织侧卡片在**桌面渲染通道**追加仅操作者可见的判例条（判例 chip 一跳回金库；"判断仍由你下"文案随条）；**永不进文本通道**（文本投影落组织场所，一混入即泄漏）；实现 = surface 渲染组合 `pledgerStripFor(cardType, ref)`，卡组件本体零改动（接缝⑤）。
- **重签即对表（#61 收紧④）**：租约到期 → 重签提议卡（组织侧 lease 族既有）**附期间证据摘要**（该租约 scope 命中的自动放行计数 + 异常记录——组织图派生，与私账无关，未启用 pledger 也生效）；pledger 启用时同步出校准回执（你的租约裁决 × 期间事实）——换挡也是裁决、也有回执，租约不成为回路的出口。

## 6. 数据律适用表（主册 §1.9 七条 + 私账三特有律）

| 律 | 私账适用形态 |
|---|---|
| 真身唯一 | 私账真身 = pgraph 日志（host 内存不是真身；待答态即图数据重启可恢复——邀约/回执/预期全落日志） |

| 更正即追加 | 归因可纠（answered 追加最新生效）、dismissed/reopened、withdrawn 留痕不删史；**预期例外收紧：无 updated**（不可改笔——改笔通道在 schema 上不存在） |

## 10. 验收断言清单（分支合并门槛，全绿才并）

① **三不入负样本**：走完"验收→邀约→立约→回执"全链，`pendingAnswerables` 快照前后 diff 为空；收件箱/决断条/一切徽标计数不变（demo v5 已演，此处为自动化断言）。

⑥ **邀约输入面**：邀约生成调用栈无 pgraph 读取（静态断言 + 运行时 spy）。
⑦ **疲劳治理**：同族连续 3 declined 后第 4 次触发点静默；reopened 恢复。
⑧ **通道纪律**：renderText/原生卡/群投影输出含私账内容即断言失败（金库文案、判例文字作 canary 字符串）。

⑩ **部署开关**：enabled=false 下零目录、零工具注册、零入口渲染、六接缝全部 no-op 回落。
⑪ **取走与销毁**：目录拷贝后独立可读（自包含）；destroy 两段式、执行后组织侧零残留引用。
⑫ **八环走查**（人工验收脚本）：demo v5 主线在 next/ 实现上复演——裁决→立约→回流→归因→判例→模式→后视镜在下一张卡在场→再裁决，每环既可见又可动。

### 11.1 首轮自审抓到的七处（全部已改，各有用例）

> 这七处**没有一处会报错**。它们只会安静地把这本账变成一件让人烦的东西——而一本让人烦的
> 判断账本，第二个月就不会有人再打开。所以它们比任何一条编译错误都值得写下来。

| # | 症状 | 为什么它是错的 | 改法 |
|---|---|---|---|
| 1 | **检验点落在过去** | 拿承诺的 `due` 当检验点，可 `due` 是交付期限，而验收发生在交付之后——立完约当场就被时间轮追问「后来怎么样了」 | 检验点取**还没开的那场会**（事件枢纽的服务边，§5.6 既有，也正是设计原文「使用场合就是明早的评审」）；退回未来的 `due`；两者都没有就**不给戳**——无戳不参与时间轮 |
| 2 | **一份事实配十次裁决** | 一个目标下验收过十条活，一份差距简报落地 → 十张回执、十条 DM，其中至少九张人一看就该按「配对错了」。**第五出口存在是因为配对可能错，不是因为我们该批量制造错配** | 一份事实**至多出一张执**，配 `seq` 最近的那一次裁决；其余留在金库待对表，由人自己补登配对 |
| 3 | **血缘规则没有时间边界** | 「同目标 + 同对话」在忙碌的目标里等于**每一次新登记**都对上一次验收出一张执；三周后同一间屋子里的活，因果只剩「碰巧在一起」 | 强路径 = 转包子边（图上明写的因果）；弱路径加**一周**窗口 |
| 4 | **回执已在等你，时间轮还问一遍** | §4 写的是「检验点到达**且图内无匹配事实**」，实现漏了后半句。问一个自己刚放上去的答案，比不问更伤信任 | 有回执就跳过 |
| 5 | **证据行时态错了** | 「当时那个对象最后一次变动」读的是 `updatedAt`——事实刚改过它，于是这行写着「当时」说的是「现在」。**一句时态错了的事实已经不是事实**，而证据行是 prompt 纪律仅存的一处 | 换成真正关于当时的：裁决落在图上第几条边，一跳可回 |
| 6 | **换挡台第三行标题不成立** | 分册叫它「交付前自检【多操作者期执行者侧】」，可 P1 只有操作者一端，那一行的证据说的全是你的**验收**裁决 | 改名「交付验收」（键 `delivery-acceptance`）；多操作者期执行者侧的自检是同一族的第二个入口，那时这名字仍然对 |
| 7 | **两处字面各写一份** | 后视镜条上印内部 id（门上写着人读不懂的键 = 把门画成墙）；销毁口令在客户端与服务端各一份（对不上 = 按钮亮着而服务端拒绝） | 条上印模式自己的名字；口令由服务端发，界面只转述 |

### 11.2 二轮自审又抓到两处（同样已改，同样有用例）

第二轮只问一个问题：**这套东西用满三个月之后，屏幕上会是什么样子。** 答案抓到两处，
都是同一种病——在小数据上看着刚好，在真实数据上变成 nag：

| # | 症状 | 为什么它是错的 | 改法 |
|---|---|---|---|
| 8 | **负重档说了不做** | `spreadEvidence: true` 发出去了，界面只多印一句「证据摆开」，参数照旧截到 200 字。**说明文字占位同罪**：写着摆开却仍然截断，这张卡自己在说假话 | 负重档下参数不截断；验收卡额外摆出交付主张原话与返工轮次——摆的是**同一份图上的数据**，不是新造的话 |
| 9 | **每张答完的卡都挂一块两读** | 一段长会话里二十次确认 = 二十块「这类确认还需要你吗」。而它问的偏偏是「你是不是被问烦了」——用重复二十遍的方式问这个问题，本身就是答案 | ①这一族攒够 **5** 次裁决才问（和决断条 `FATIGUE` 同一个数：那里是「同时挂五件待答」，这里是「这一类你答过五次」）；②这一屏上**一族只挂最新那一张**——零新入口的意思是既有的条尾位置只有一个，扩成两读不该扩成二十个 |

**留着没改的一处**：`reflowOnGraphEvent` 每来一条组织图事件就全量扫一遍 `answer/recorded`
（O(事件数)）。它和这套代码里既有的 `allProjections` / `contractFor` 同一种写法，P1 的量级
下不构成问题；真要动，该和它们一起动，而不是在这里单开一份索引。

**两轮自审的共同形状，值得单独记一句**：九处里有六处（2、3、4、8、9，加上 DM 那一处文案）
是同一类错——**在一条数据上跑通了，在一百条数据上就变成骚扰**。这本账的失败方式不是崩溃，
是让人第二个月不想再打开它；所以「跑通了」从来不是这层的验收标准，「三个月后还愿意打开」
才是。

## 附录 B：技术决策（PTD）

PTD-1 **第二 store 实例而非新内核**：复用 graph 日志内核换 policy——数据律实现单一来源，私账宪法差异全部落在 policy 层｜PTD-2 **三不入靠存储分离不靠 filter**：pendingAnswerables 跑在组织图上、私账卡活在 pgraph 上——漏加 filter 的事故类在结构上不存在｜PTD-3 **持镜人靠依赖方向**：组织侧包 import-ban pledger——"agent 不因误判史改组织行为"由链接器保证非自律｜PTD-4 **单向引用双保险**：依赖面（import-ban）+ schema 面（组织图事件无私账字段）｜PTD-5 **模式零存储**：滚动派生查询强制窗口参数，聚合评分在 API 上不可构造——明拒的类型化｜PTD-6 **不可改笔 = 无 updated 事件**：改笔通道在词汇表上不存在，非运行时校验｜PTD-7 **租约本体留组织侧**：两读的 lease 出口落组织图既有 lease/granted（guard 消费它），私账只记换挡史——免确认是组织侧行为，其审计必须留在组织侧｜PTD-8 **归属键 = operatorOpenId**：账随人不随实例——并存期/迁移/多实例下账本唯一｜PTD-9 **邀约出处限组织侧 = 输入面限制**：生成器签名不含 pgraph 能力，非 prompt 恳求｜PTD-10 **组织侧接缝封闭清单**：六点白名单入 review 规则——分支越权可机械判定｜PTD-11（v1.1）**fact/noted = 环3 的词汇地板**：图外事实唯一入口是人工补登（"跟踪≠监工"对私账适用——ambient 语义识别押门；没有这一型，事实回流环只对图内结构性事实成立=环断）｜PTD-12（v1.1）**原话直存 = 参数面而非 prompt 面**：text 由编排层锚定注入、模型无此参数——产婆术在最关键的表达（赌注/事实陈述）上不依赖模型自律｜PTD-13（v1.1）**不可回填双锁**：幂等锚（防重复）+ 立约时窗（防事后补立）——单锁可绕｜PTD-14（v1.1）**pledger 自带时间轮**：时间驱动不挂 scheduler（在 ban 名单内）——依赖方向铁律对定时器同样成立｜PTD-15（v1.1）**接缝①=通用事件非专用钩子**：组织侧 emit verdict-settled 而不知有订阅者——"组织侧代码零 pledger 符号"从 lint 约束升为架构事实。
