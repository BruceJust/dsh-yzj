## 0. 一句话与总判据

**组织的图记承诺的一生，金库记你的判断的一生——两本账，两种可见性，永不合流。**

私账层 = P–agent–P′ 回路的工程形态。**P′ 环行八环**（一切实现对照此表验收，缺一环即割裂债）：

```
裁决 →（立约·可选）→ 事实回流 → 对表归因 → 判例入账 → 模式浮现（滚动）→ 回喂（后视镜/换挡）→ 再裁决
```

总判据（全分册通用，§10 有断言形态）：

1. **三不入**：私账对象不进收件箱、不进决断条、不进任何可应答聚合徽标——由**存储分离结构性保证**（不靠 filter）；
2. **单向耦合**：私账引用组织图锚点，组织图**永不**引用私账——由**依赖方向与 schema 双重机械保证**；
3. **持镜人**：agent 只在人发起的时刻消费私账；组织侧行为路径结构性读不到私账；
4. **回路合环**：模式必须能经人签发的规则（后视镜/换挡）回到下一次裁决时刻——金库不是目的地 app；
5. **金库照现在的你**：判例永续（史）、模式滚动派生（近 90 天，零存储）——不给人建档案；
6. **账要自持（v2.0，#62-A）**：判例内容**不依赖组织图可解析**——**快照是真身，锚是导航**；拷走目录 + 一份人可读判例册 = 完整的一本账；
7. **入口不垄断（v2.0，#62-B）**：凡私账能力，**金库是汇总处不是唯一入口**——最想合环的时刻在现场（#61 条款对自身适用）。

## 1. 分册边界

**本分册管**：私账存储（pgraph）、私账事件族全量词汇、私账对象族（立约邀约/预期/校准回执/换挡/后视镜/邀约疲劳）、私语通道与金库的桌面投影、私账治理（硬合同工程兑现/部署开关/取走导出与销毁/邀约配额）、搜索面条款、P1 降级明标、验收断言、实施顺序。

**留在主册管**（本分册只指认不重述）：组织图词汇与数据律原文（§3）、可应答对象系统内核（§4——本分册**复用其组件与状态机，不复用其存储**）、授权租约本体（`lease/*` 是组织侧既有对象——两读的「设为租约」出口落组织图，换挡史才落私账）、条尾入口条款（§7.1）、桌面搜索面本体（主册 §7 目前无此面——pledger P1 只做金库内检索，接缝⑦ 为预留）、guard 与合同三层（§6.4/§8）。

**依赖方向铁律（持镜人条款的机械保证）**：

```
pledger 包 ──依赖──▶ graph（日志内核复用）· cards（卡型组件/状态机复用）· 组织图服务（只读锚点解析 + 活性探测）
                   · channel 投递 API（自聊 DM 出站——只出不进）· 既有注册面（卡型/工具/事件/搜索 provider）
objects / tools(组织工具) / channel / scheduler(组织侧 watcher) ──✕ 禁止 import pledger──
surface ──依赖──▶ pledger（仅渲染消费：金库视图/私语流/后视镜条/两读卡/档位生效面/搜索结果项）
```

**依赖倒置经注册面**：pledger 是标准 cordis 插件，经**既有对象族注册面**把自己挂进系统（卡型注册进 cards、工具注册进 tools 工具面【按 viewer 条款】、订阅挂 `yzj-graph/appended` 与 `verdict-settled`、搜索 provider【v2.0 第七接缝，**预留**——主册 §7 目前无全局内容搜索面，P1 只做金库内检索】、定时器自带）——组织侧包只持有注册面抽象，**代码里不出现 pledger 符号**。**pledger 自带 effect 时间轮**：检验点到期、沉降窗口、配额日切等时间驱动逻辑由 pledger 内部 effect 定时器承担——scheduler 包在 ban 名单内，**不得挂靠**。组织侧编排（提案生成/路由/评估/委派/回执）在**依赖图上就够不到**私账——"agent 不因你的误判史改组织侧行为"不靠自律靠链接器。CI 断言：import-ban lint（§10-②）。

**组织图只读接口的三个用途（v2.0 精确化）**：pledger 对组织图的读只允许三种形态——①**导航**（把锚渲染成可点的一跳回）②**活性探测**（`isAlive(anchor): 'live' | 'dead' | 'unknown'`，返回**布尔性状态不返回内容**——锚死显形的唯一数据源）③**幂等键**（锚作为 idemKey 的组成）。**取内容一律非法**：正文渲染只读快照（§3 立此存照律）——故组织图不可达（取走后的目录、组织侧墓碑、并存期切实例）时，私账**内容零缺失、只是不再显形与不再可跳**。

## 2. 存储：第二本账（pgraph）

- **形态**：复用 graph 包日志内核，**第二个 store 实例、不同宪法**——`createGraphStore(root, policy)`；`~/.dsh-next/yzj-next/pledger/<operatorOpenId>/pledger.jsonl` + atomic-write 快照。信封同款 `{v, sv, seq, time, type, data, actor}`；单进程单写者；启动快照+尾部重放。**host 内存不是真身**：邀约/回执/预期的待答态全部落日志，重启可恢复。
- **归属键 = operatorOpenId（人，非 accountKey）**：账本随人不随部署实例；P1 单操作者下与登录真人一致。多操作者期每人一份文件，互不可见由文件边界保证。
- **policy（与组织图的三点宪法差异）**：①viewer 只接受 operator（**place viewer 的查询在 API 形态上不存在**——不是返回空，是无此入口）；②审计导出路径不可触及（对称保留律第二例外区——审计导出投影的重放过滤器根本不挂 pgraph 源）；③**组织与他人不可导出、本人可整体取走与销毁**。
- **自包含三件套（v2.0——"拷走即取走全账"的兑现，#62-A1/A2）**：目录内容 = ①`pledger.jsonl`（原件，机器可重放）②`判例册.md`（人可读全史，`/vault export` 生成/刷新）③`README.md`（硬合同五条 + 格式说明 + "本目录不依赖任何外部系统"声明）。**自包含的真正门槛不是"没有外部索引"，是"没有外部依赖的内容"**——由立此存照律（§3）在写入面保证，而非导出时补救（导出时组织图可能已墓碑，那时再去解析就晚了）。
- **跨账引用单向**：pgraph 事件可携组织图锚（`{graphSeq}`、cardRef、msgAnchor、URI），且**恒与其快照文本同行**（§3）；**组织图任何事件 schema 不含 pledger 引用字段**（zod 层无此字段即写不进——schema 面保证，与依赖面双保险）。
- **部署二值开关**：`pledger.enabled`（bundle 配置）。关 = 不建目录、不注册工具、不注册任何 provider、不渲染任何入口；**不存在"启用且组织可见"的配置项**——明拒的构造性兑现。**中途关闭不删数据**：已有目录原样保留，重开即续——**destroy 两段式是唯一删除路径**；私账亦**无墓碑事件**：更正全走追加语义（answered 追加/dismissed-reopened/withdrawn 留痕），整账销毁是唯一抹除。
- **取走与销毁的三个出口（v2.0）**：`/vault export`（刷新判例册，读操作**不留痕不写事件**——读自己的账是自由）／目录直接拷贝（三件套自包含）／`/vault destroy`（两段式确认，不可逆人签发终态同款门）。**逐级兑付定律对取走律适用**：给不出人能读的东西的"可取走"，是明拒条款上的幽灵信号。

## 3. 词汇表（私账事件族全量——只存在于 pgraph，组织图零新增）

### 3.1 立此存照律（v2.0——schema 里不存在裸锚）

```ts
/* 唯一携锚形态：文本必填、锚可空。pgraph 的任何 schema 位置都不得出现独立的 OrgAnchor 字段 */
type AnchoredText = {
  text: string          // 当时的人可读摘要（组织侧内容的照片）——必填，写入时刻定格
  at: string            // 快照时刻（ISO）——"当时"的时间坐标
  anchor?: OrgAnchor    // 可空的导航/活性探测/幂等键；渲染正文时永不解析它
}
```

**三句成文**：①**私账存的是照片，不是链接**；②**锚的三个合法用途 = 一跳回 / 活性探测 / 幂等键**；③**取内容一律非法**——正文渲染函数的入参类型里根本没有组织图 service（参数面保证，与原话直存律同款）。类型面断言见 §10-⑯。

### 3.2 事件族（七型，v2.0 零新增族、只补字段）

```ts
/* —— 预期（对话式立约）—— */
'expectation/opened'     // { text（赌注原文——产婆术：必须是人亲口的话语，agent 不得生成不得改写）,
                         //   checkpoint: { text, ts? }（检验点两层——主册 due 同构：话语真身+解析投影可空可纠；
                         //     ts 为空 = 只等事实不等时间，时间轮不触发、走事实回流与人工补登）,
                         //   verdict: AnchoredText（v2.0 由 verdictRef 升格——快照 = 裁决的人可读摘要，
                         //     文本由接缝① 的 verdict-settled 事件携来；锚在 .anchor 里）,
                         //   evidence: AnchoredText[]（邀约出处的组织侧摘要 + 锚）,
                         //   idemKey = verdict.anchor }
                         // 不可回填 + 不可改笔的机械保证：同一裁决锚至多一次 opened（幂等锚），
                         // 无 updated 事件（改赌注 = withdrawn + 不可再 opened）
'expectation/withdrawn'  // { reason }——唯一退出动词（撤回留痕不删史；前提消失时撤回是诚实不是失败）；
                         //   withdrawn 后同锚的 opened 被幂等锚吸收 no-op（堵"临近检验点改口"）
                         //   v2.0：锚死显形只显形不代写本事件（§4 锚死显形——代撤即代产）
'expectation/settled'    // { calibrationRef }——对表归档（由校准回执归因触发）

/* —— 图外事实的人工补登（环3 的词汇地板）—— */
```

## 4. 私账对象族（obj-pledger）

复用主册 §4 CardDefinition 与动作总线（**组件与状态机复用、存储不复用**——卡实例落 pgraph，故 `pendingAnswerables`（组织图查询）结构性不含它们，三不入零 filter 达成）。投影通道收窄为两条：**桌面私语面/金库**（渲染通道②）+ **自聊 DM 文本**（通道③的自聊特例）；群文本通道与原生卡通道对私账对象**不存在**。

### 4.1 立约邀约卡（单答家族）

- **动作** = 立个预期（进入输入态——textarea 由人写，产婆术：无预填内容；「帮我写」得到维度不得到句子）/ 不立（`invite/declined`）。
- **出生三段式（v2.0 核心重构，#62-B4）**——判据、治理与生成三权分立：

  | 段 | 名 | 输入 | 是否读 pgraph | 职责 |
  |---|---|---|---|---|
  | ① | **谱**（`isPledgeable`） | `verdict-settled` 的 `kind` | **否**（纯函数） | 四判据：有人签发的裁决留痕／有可命名检验点／事实会自行回流／**信息量否决位** |
  | ② | **门**（`inviteGate`） | 裁决锚 + 族 key | **是** | 幂等（同锚一次）· 族级连续 declined ≥3 停问 · **全局日配额**（P1 = 2/日）· 时窗 |
  | ③ | **笔**（`inviteRender`） | 裁决锚 + `titleText` + 检验点候选 | **否**（签名不含 pgraph 能力） | 出卡文案——出处限组织侧事实（#61 收紧⑤的输入面保证） |

  **门与笔分立**是本轮最重要的接口纪律：**门读账，笔不读账**——疲劳治理必须读私账（否则治不了），而"镜子等人来照"要求生成器看不见镜子；v1.x 把两件事都叫"编排层"，实现者会顺手把 gate 的 pgraph 句柄传进 generator。断言 ⑥ 只约束笔。
- **裁决面全集谱（v2.0 定谱，取代 v1.x 的两点枚举）**：

  | 裁决 | ①留痕 | ②检验点 | ③回流 | ④信息量 | P1 |
  |---|---|---|---|---|---|
  | 验收 accept / reject | ✓ | 使用场合/下一轮 | 图内结构性 | 高 | **✓** |
  | 差距简报验收 | ✓ | 下次评估 | 图内结构性 | 高 | **✓** |
  | 委派签发（含拆解落库） | ✓ | `due` 既有两层 | 交付/验收边（图内） | 高 | **✓（v2.0 新入）** |
  | 打回 · 返工 | ✓ | 下一轮交付 | 返工轮次对象 | 高 | **✓（v2.0 新入）** |
  | 租约签发 | ✓ | 90 天到期 | 重签卡期间摘要 | 高 | **✓**（#61 重签即对表） |
  | 标准写确认卡 | ✓ | 弱 | 弱 | **低（否决）** | ✗ |
  | 目标签发 | ✓ | 跨季 | 慢 | 高 | 押证据门 |
  | 移交 / 作废 | ✓ | 模糊 | 弱 | 中 | 押证据门 |

  **扩触发面必同扩治理面**：五个入口各自克制、合起来仍是骚扰——故 ② 门同时加**全局日配额**（上位法 #62-4 的对偶）。配额行在金库换挡台可见可调（P1 可调值域 0-3，0 = 全关邀约）。
- **一次性**：不追问、不老化、不催——未答邀约静躺私语流，且参与静默沉降（§4.5）。

### 4.2 预期对象

- **出生** = 人发送赌注话语（selfdm turn）→ `expectation/opened`（text 走原话直存律，verdict 走立此存照律）。
- **立约时窗（不可回填的第二把锁）**：P1 立约**仅经现行邀约卡的输入态**触发（邀约绑定其裁决，"裁决时刻出生"的机械宽解 = 邀约还开着时刻就还开着）；无邀约语境的话语立约押扩员。检验点解析同 due 两层（强解析禁止、可纠）；`ts` 为空 = 只等事实不等时间。
- **检验点到达**（pledger 自带时间轮）**且图内无匹配事实** → agent 在私语域问一次结果（等待语义——问结果合法可跟进；索要预期非法）；答复经 `fact/noted` 落账。
- **锚死显形（v2.0，#62-A3）**：pledger watcher 见预期所锚对象进终态/墓碑/作废/`transferred` → 派生态 `premiseState = 'changed'`，该行显形「⚠ 前提已变：<快照标题> 已作废/已移交」+ **就地双出口**（撤回 / 照旧对表）。三条纪律：①**不自动写 `withdrawn`**——撤回是人的诚实动作，代撤即代产（断言 ⑱ 检查事件流）；②**零事件**——`premiseState` 是查询层产物（活性探测 + 快照），不落账；③**组织图不可达时退化为 `'unknown'` 并不显形**，判例内容完整（取走后的目录里没有虚假的"前提已变"）。回程律对私账的兑现：**锚有余生，预期也有**。
- **金库投影四态**：检验中（含前提已变显形）/ 已过检验点待对表 / 已对表（settled）/ 未对表（沉降区）；外加已撤回区。

### 4.3 校准回执卡（单答家族 + 第五出口）

- **出生** = pledger watcher 按事实源三分匹配（§3.2）。
- **正文三段**：**当时** × **事实** × **证据行**——三段**全部渲染 `AnchoredText.text`**，锚只做右上角的一跳回按钮（渲染函数入参无组织图 service，断言 ⑯）。
- **「当时」栏两态（v2.0，#62-C7 隐式预期不措辞化）**：
  ```ts
  renderWhen(input: { expectationText: string } | { verdictSnapshot: AnchoredText }): string
  ```
  有显式预期 → 直出人的原话；**无显式预期 → 只陈列裁决事实本身**（`「你在 8/30 10:30 验收了《竞品对比 · 评审表》」`，模板拼装的纯函数），**不代人推演其含义**——v1.x demo 里的"隐式预期即'它已经够好，评审能过'"是 agent 替你写好了你当时在想什么，与预填出处律、归因候选措辞同族违规。**第三种输入在类型上不可构造**（联合类型封闭，无模型通路）。
- **动作** = 四格归因（q1-q4，候选注只给证据与假设）+ **配对错了**（dismissed）+ 纠回（reopened）；文本投影（自聊 DM）应答走既有关键词动作总线。
- **就地合环行（v2.0，#62-B5）**：`answered` 终态**必带**合环动词条 `pledgerLoopbackRow(family, patternKey)`——「🪞 给这类卡开后视镜」/「⚖ 调档：租约|默认|负重」/「关镜」，落 `mirror/toggled` 与 `gear/shifted` 且 `entry: 'receipt'`。**通则**：凡"人刚获得一个判断"的时刻，合环动词就近——判断刚出炉、动机最热，而金库是汇总处不是唯一入口。#61 条款升格并对自身生效（断言 ⑳）。
- **未答不成欠账**：不老化、不可催、不进任何聚合——这本账的债主是你自己；显示层兑现见 §4.5。

### 4.4 换挡台（金库区块，非卡）

- 提案族注册表（P1 三族：标准写确认 / 目标拆解提案 / 交付前自检【多操作者期执行者侧】，开放注册）；每族三档 gear + 证据行（组织图派生：近 90 天通过率/中位停留【本人行为事实——可入私账证据，**永不进组织侧通道与模型调优**】）+ 换挡动词。
- **档位生效面**：`weight` = 桌面渲染层对该族卡片摆开证据、不预选、无一键通过（**仅操作者桌面**，文本投影不变）；`lease` = 引导至组织侧租约创建既有流程（强确认既有），成功后记 `gear/shifted`；`default` = 无状态。
- **两行治理（v2.0）**：邀约频率行（`invite/reopened` 的唯一入口）+ **全局日配额行**（0-3，P1 默认 2）。
- **重签即对表（#61 收紧④）**：租约到期 → 重签提议卡（组织侧 lease 族既有）**附期间证据摘要**（该租约 scope 命中的自动放行计数 + 异常记录——组织图派生，未启用 pledger 也生效）；pledger 启用时同步出校准回执。

### 4.5 静默沉降（v2.0，#62-B6——零事件的显示层律）

**"未答不成欠账"此前只是文字承诺**：私语流里平铺堆积的回执与邀约，会自己长出欠账感——**堆积是催办的被动形态**，私语通道会变成第二个收件箱。工程形态三条（全部是渲染层派生，零事件、零字段）：

1. **折叠归并**：同类未答私账卡 ≥ 2 张（P1 阈值）→ 私语流合并为一行「3 张待对表 · 一起看 ›」（一跳金库，逐级兑付合规——**归并条是门不是徽标**）；最新一张保持展开（最近的语境不折叠）。
2. **沉降**：预期过检验点 > 14 天（P1）未对表、或回执 > 14 天未答 → 金库从「待对表」移入「未对表」区，私语流不再保留其位。
3. **三不变**：沉降**不变红、不计数、不催**，且**不产生自聊未读**（未读只由新消息产生、读即清——接缝②语义不动）。沉降区的行**仍可动**（补登事实 / 撤回 / 归因），只是不再打扰。

### 4.6 私账动词族明拒（v2.0，#62-D9）

私账卡与金库行的 `actions` 白名单 **∩ {forward, quote, share, cite, mention} = ∅**；surface 的转发/引用/提及 source picker **数据源只跑组织图查询**，pgraph 不在其可选源注册表里。**不给动词就不会误用**——#57「占位即全域不可达」的反向应用：此处的不可达是特性。人自己复制粘贴是人的自由，**系统不递刀**。断言 ㉔。

## 6. 数据律适用表（主册 §1.9 七条 + 私账五特有律）

| 律 | 私账适用形态 |
|---|---|
| 真身唯一 | 私账真身 = pgraph 日志（host 内存不是真身；待答态即图数据重启可恢复） |
| 先答先赢 | 单人多投影并发归因按 pgraph 追加序首答生效——机制原样复用 |
| 更正即追加 | 归因可纠（answered 追加最新生效）、dismissed/reopened、withdrawn 留痕不删史；**预期例外收紧：无 updated**（改笔通道在 schema 上不存在） |
| 真身之变 | **v2.0 改写**：回执/预期引用的组织图对象被墓碑/作废 → **判例内容零影响**（快照是真身），只影响两件事——一跳回失效、`premiseState` 显形；私账不反向要求组织图保留。"锚失效不蒸发内容"由此**从口号变成结构** |
| 环境快照 | **v2.0 升格为立此存照律**：不再是"记依据版本"的锚语义自带，而是**写入面强制**——`AnchoredText` 是唯一携锚形态，无快照即写不进（§3.1） |
| 对称保留 | **判例永续、模式滚动**（滚动是派生窗口不是删除）；**审计导出不可触及**（第二例外区）；**取走导出是读操作不留痕**（读自己的账是自由） |
| 幂等锚 | expectation=verdict.anchor；calibration=(verdict.anchor, fact.anchor ?? factNotedId)；gear/mirror/invite 按 (family[,patternKey]) 最新生效 |

**私账五特有律**（v1.1 三条 + v2.0 两条）：

1. **单向引用**——组织图 schema 无私账字段；
2. **viewer 单态**——API 无 place 查询形态（工具面与搜索 provider 同款）；
3. **滚动模式**——模式查询强制窗口参数，无"全史聚合"查询形态（"判断力得分"在 API 上不可构造）；
4. **立此存照（v2.0）**——pgraph schema 中不存在裸锚，正文渲染函数入参无组织图 service；**能派生就不落账**（锚死显形/沉降/分布镜三个新态全部零事件）；
5. **入口不垄断（v2.0）**——私账能力注册表校验：**任一能力的入口 ≥ 2**（金库 + 至少一处就近），"唯一入口在金库"即 CI 红。

## 7. 桌面投影

- **私语通道（selfdm）**：操作者自聊/私语流承载邀约与回执（既有私语侧的两位新住客——磨稿在工作夹、轻问在各会话，零新 surface）；agent 开口必有出处（出处随卡可见）；**折叠归并与沉降见 §4.5**。
- **金库视图**（surface 新视图，左栏私语段入口）：
  - **Header**：硬合同 chips（仅你可见/不入组织图/组织不可导出·本人可取走/永不绩效/审计不可触及/图→金库单向）+ **两个终局动词**（`取走（导出判例册）` / `销毁` 两段式）——硬合同的每一条都要有一个可按的按钮，**说明文字占位同罪**（#57）。
  - **六区**：检验中（含「前提已变」显形）· 待对表 · 已对表 · **未对表（沉降）** · 已撤回 · 模式。
  - **换挡台**（三族三档 + 证据行 + 邀约频率行 + **全局日配额行**）——回路的合环阀。
  - **明拒 footer**：无分数/无排名/无画像/无建议倾向/无团队视图——投影层无聚合评分查询可用（§6 特有律③）。
- **证据面（金库右栏对象面，v2.1 = #61 澄清① × #62-A 接缝）**：右栏语义单一形态不变（"中栏是流、右栏是物"）——金库的物 = **判例的证据锚**。选中判例/预期/回执行 → 右栏归集其 `AnchoredText[]`（当时的裁决快照、简报条目、事实、工件引用），逐条三层：**摘要为主**——第一行永远是私账自存的人可读快照（照片；断组织图零缺字）；**锚为辅**——「回真身 ↗」一跳 + `isAlive` 活性探测（§2 组织图只读三用途的显示层消费者）；**锚死显形**——`dead` 时快照原样在场、行上「真身已变/已亡」徽记（`unknown` 不显形——认识论诚实同款；否则证据面纯靠锚 = 判例是空壳在显示层的复发）。**对表不出屏**：证据面在场时中栏行内四格可答——"验收不出屏"的私账对偶（边看证据边下归因）。**预览分层裁决（PTD-26）**：锚活时的只读预览由 **surface 层调组织侧既有对象面预览通道**（viewer=operator 的合法组织图读——操作者本可见这些对象，§1.6 零泄漏；类型面可辨：证据面自身的渲染函数入参**无组织图 service**，预览是 surface 的另一条独立调用），**pledger 层仍不取内容**（§2 三用途不破）；锚死预览消失、快照仍在——**对表不出屏在组织侧对象亡故后依然成立**。**默认态 = 待对表首项的证据备料**：打开金库 = **人发起的回看时刻**（持镜人条款"人发起"的消费时刻定义——agent 此刻聚合证据合法，**备料不定案**）。
- **金库 ≠ 记忆（v2.1 = #61 澄清③）**：金库语境下右栏**记忆 tab 空态明标**「金库内容永不入记忆库——记忆是 agent 的复利、金库是人的复利」（空态出生故事；两本复利账在右栏也不合流）；工程保证见 §8 记忆隔离。
- **金库行内动词族**（#57「占位即全域不可达」的私账版，v2.0 补三行）：检验中行 = 撤回（+ 前提已变时的「照旧对表」）；待对表行 = 补登事实 + 撤回；已对表行 = 改归因 + **就地合环（开镜/调档）**；**未对表行 = 补登事实 + 撤回（沉降不剥夺可动性）**；已撤回行 = 只读（撤回是终态——诚实退出不悔棋）；模式行 = 后视镜开关；**分布镜行 = 四格各自的判例门**；换挡台行 = 三档 + 频率 + 配额。**每行既可见又可动**。
- **归因分布镜（v2.0，#62-C8）**：模式区首行陈列滚动窗口内四格分布 `q1/q2/q3/q4 各 N`，每个数字是门（点开 = 该格判例列表）。**无判词的类型化保证**：
  ```ts
  attributionDistribution(window: RollingWindow): { q1: number; q2: number; q3: number; q4: number; cases: Record<Quad, CaseRef[]> }
  //                                              ^ 返回类型无任何 string 字段 —— 判词在 API 上不可构造
  ```
  渲染文案是**静态常量**（不经模型）。**陈列是镜子，解读是教练**：单次归因防不住"永远选 q4"，分布能；而一旦系统替你解读分布（"你在推卸责任"），它就从镜子变回教练。断言 ㉓。
- **后视镜条 / 条尾两读 / 档位生效**：见 §4；三者共享「仅操作者桌面渲染层」纪律——**私账内容离开桌面通道即事故**（文本/原生卡/群面零渗透，断言 ⑧）。
- **搜索面（v2.0，#62-D10——含降级明标）**：查看者样本律此前只裁了聚合面与导出面，**搜索是第三个漏口**；但本设计目前**没有跨会话的内容搜索面**（主册 §7 事实核对：`im group search` 是群名录搜索），故本条**一半是现在成立的负向条款、一半是预留**：
  - **现在成立**：组织侧一切索引与检索路径**结构性不遍历 pgraph**（不靠过滤——索引器不认识这个 store）；
  - **P1 形态**：本人检索走**金库内的检索框**（pledger 自有，跨六区 + 判例正文的本地检索，落点即金库行；仅 viewer=operator 可构造）；
  - **将来**：全局搜索面落座时按 viewer 条款注册 provider（place 会话中**不存在**而非被过滤），结果标「私账」域徽记、落点仅 vault/selfdm、与组织侧结果分段不混排计数。
  **不把不存在的面写成已存在的接缝**——预留就明标为预留（接缝⑦ 的两段式断言 ㉕ 同此）。
- **查看者样本律**：私账对任何非本人查看者**结构性不存在**（非渲染过滤——存储与 API 层面无路径）；fixture 断言：place viewer 全查询面（含搜索）碰不到 pledger 数据。

## 8. 治理

- **硬合同（v4.25r 五条）工程兑现**：仅本人（§2 policy①）/不入组织图（§2 单向引用）/组织不可导出·本人可取走销毁（§2 policy③ + **自包含三件套 + 判例册导出**）/永不绩效聚合（§6 特有律③）/审计不可触及（policy②）。**v2.0 补第三条的实质兑现**：拷得走 ≠ 取得走——判例册是"可取走"从法条变成事实的那一步。
- **持镜人条款**：依赖方向铁律（§1）+ **门与笔分立**（§4.1）+ 档位与后视镜由人签发（gear/mirror 事件的 actor 恒为 operator，agent 无此工具）。**本人行为事实**（停留中位数等）可入私账证据行，采集与存储全在 pledger 域，**永不进组织侧通道与任何模型调优管道**。
- **私账合同面板（v2.1 = #61 澄清②——判断力档案硬合同与合同面板同构）**：与场所合同面板**同一语法同一组件族**。**硬区** = 五硬项 + 持镜人条款，每条列其**机械保证形态**（存储分离/import-ban/无查询形态/policy/参数面——面板陈列的是"为什么改不了"，不是"请勿修改"）；**软区 = 换挡台参数**（全局日配额/沉降参数/降频阈值——可调项恰是软合同的同构位），面板只读陈列 + 跳转金库，变更全走金库动词、人签发；**agent 无提议权**（场所合同 agent 可提议软项变更，私账合同不行——这份合同的**另一半签署人是你自己**，没有对方代表可以递案）。金库 Header 的硬合同 chips = 面板入口的摘要形态（信号即门——点击开面板；chips 不再是终点，"说明文字占位同罪"对 chips 自身适用）。
- **记忆隔离（v2.1 = #61 澄清③）**：蒸馏管道对 pgraph **无通路**——obj-memory 在 import-ban 名单内、蒸馏器输入面无 pgraph 类型（**免费于依赖方向铁律，但必须成文**：免费的保证不成文就会被当成没有的约束——实现者顺手把金库判例蒸进记忆库只需一行代码，禁令必须先于那一行存在）；反向同禁：pledger 依赖面无 memory 服务（金库不写记忆库）。断言 ㉗。
- **工具面**：新增模型工具仅两个——`pledger_query`（只读，guard 条款：viewer=operator 的 turn 才注册进工具面；place turn 中此工具**不存在**而非被拒绝）+ `pledger_register`（立约/归因/换挡的话语路径落账，同 viewer 条款，**schema 无 text 参数**）；组织侧 41 工具零变更。
- **邀约配额**：族级连续 declined ≥3 停问（`invite/reopened` 恢复）+ **全局日配额**（P1 默认 2/日，金库可调 0-3）——扩触发面的对偶。
- **部署**：`pledger.enabled` 二值；3090 试运行先行（dogfood），3080 旧系统永不接入（并存期私账只有一本——账随人不随实例，切换时目录原样保留）。

## 10. 验收断言清单（分支合并门槛，二十七条全绿才并）

**v1.x 十五条**

① **三不入负样本**：走完"验收→邀约→立约→回执"全链，`pendingAnswerables` 快照前后 diff 为空；收件箱/决断条/一切徽标计数不变。
② **单向引用双保险**：import-ban lint（组织侧包 import pledger 即 CI 红）+ 组织图全事件 zod schema 无 pledger 引用字段断言。
③ **不可改笔**：同裁决锚二次 opened 幂等 no-op；withdrawn 后 opened 亦 no-op；无 `expectation/updated` 类型。
④ **回执幂等**：同 (verdict, fact) 二次回流不出第二执；dismissed 后不再出；reopened 可再答。
⑤ **滚动模式**：模式查询无窗口参数即类型错误；窗口外判例不入计数、日志仍在。
⑥ **邀约输入面（笔）**：`inviteRender` 调用栈无 pgraph 读取（静态断言 + 运行时 spy）——**门可以读，笔不可以**。
⑦ **疲劳治理**：同族连续 3 declined 后第 4 次触发点静默；`invite/reopened` 恢复。
⑧ **通道纪律**：renderText/原生卡/群投影输出含私账内容即断言失败（金库文案、判例文字作 canary 字符串）。
⑨ **viewer 单态**：place viewer 构造 pledger 查询 = 编译期/API 层不可达。
⑩ **部署开关**：enabled=false 下零目录、零工具注册、零 provider 注册、零入口渲染、七接缝全部 no-op 回落。
⑪ **取走与销毁**：目录拷贝后独立可读；destroy 两段式、执行后组织侧零残留引用。
⑫ **八环走查**（人工验收脚本）：demo v5 主线在 next/ 实现上复演——每环既可见又可动。
⑬ **原话直存**：`pledger_register` 工具 schema 无 text 参数（静态断言）；`expectation.text` 与人的原话语逐字节一致（集成断言）。
⑭ **立约时窗**：无现行邀约时对历史裁决锚 opened = 编排层拒绝留痕（非幂等 no-op——要能区分"重复"与"越窗"两种拒因）。
⑮ **事实回流三分**：结构匹配用例（reopened/血缘新边/重签）各一 + `fact/noted` 补登用例 + 语义识别路径不存在断言（P1）。

**v2.0 十条（#62）**

⑯ **立此存照（无裸锚）**：*静态*——pgraph 全 schema 中 `OrgAnchor` 不作为独立字段类型出现（只在 `AnchoredText.anchor` 内）；正文渲染函数入参类型不含组织图 service。*集成*——**断开组织图 store 后**金库六区、回执正文、判例册全渲染**零缺字**。
⑰ **人可读取走**：`/vault export` 产物在无组织图、无本系统的环境下可读（纯 markdown）；判例册每条含「当时/事实/证据」三段文本；全文 grep 无 id-only 悬挂引用；导出为读操作——事件流前后无新增。
⑱ **锚死显形**：被锚对象进终态/墓碑/`transferred` → 该预期行显形且给出双出口；**事件流零新增**（不自动写 `withdrawn`——代撤即代产）；组织图不可达时 `premiseState='unknown'` 且不显形，内容完整。
⑲ **判据三段式**：`isPledgeable` 为 pledger 内纯函数（无 pgraph、无 IO）；组织侧 `verdict-settled` 发射点 grep **无任何立约/邀约判据分支**；谱表八类用例（5 ✓ / 1 ✗ / 2 押门 skip 明标）。
⑳ **就地合环 + 入口不垄断**：`mirror/toggled` 与 `gear/shifted` 的 `entry` 值域含 `'receipt'`，且回执 answered 终态渲染必含合环动词条；**能力入口注册表校验**——任一私账能力的入口数 ≥ 2，出现"唯一入口 = vault"即 CI 红。
㉑ **静默沉降**：沉降与折叠**零事件写入**；沉降前后自聊未读数与一切计数不变；折叠归并条无数字徽标且可一跳兑付到金库；沉降区行的动词仍可执行。
㉒ **隐式预期不措辞化**：`renderWhen` 为纯函数、调用栈无模型调用；联合类型封闭（第三种输入类型上不可构造）；无显式预期路径的"当时"栏输出与 `verdictSnapshot.text` 逐字节可推导。
㉓ **分布镜无判词**：`attributionDistribution` 返回类型无任何 string 字段（静态断言）；渲染文案取自静态常量表；分布查询同样强制滚动窗口参数（与断言 ⑤ 连通）。
㉔ **动词族明拒**：私账卡与金库行的 actions 集合 ∩ {forward, quote, share, cite, mention} = ∅；转发/引用/提及 source picker 的数据源注册表不含 pgraph。
㉕ **搜索面（两段）**：*现在必绿*——组织侧一切索引/检索构建调用栈无 pgraph 读取；金库内检索框在 place viewer 下不可构造；检索结果落点仅金库行、不进任何导出投影。*随全局搜索面落座解锁*——place viewer 下 pledger provider **未注册**（非返回空），结果与组织侧分段不混排。**第二段在搜索面落座前记为 skip 并明标**（不假装断言了不存在的面）。

**v2.1 两条（#61 对象面澄清 × #62-A 接缝）**

### 11.1 首轮自审抓到的七处（全部已改，各有用例）

> 这七处**没有一处会报错**。它们只会安静地把这本账变成一件让人烦的东西——而一本让人烦的
> 判断账本，第二个月就不会有人再打开。所以它们比任何一条编译错误都值得写下来。

| # | 症状 | 为什么它是错的 | 改法 |
|---|---|---|---|
| 1 | **检验点落在过去** | 拿承诺的 `due` 当检验点，可 `due` 是交付期限，而验收发生在交付之后——立完约当场就被时间轮追问「后来怎么样了」 | 检验点取**还没开的那场会**（事件枢纽的服务边，§5.6 既有，也正是设计原文「使用场合就是明早的评审」）；退回未来的 `due`；两者都没有就**不给戳**——无戳不参与时间轮 |
| 2 | **一份事实配十次裁决** | 一个目标下验收过十条活，一份差距简报落地 → 十张回执、十条 DM，其中至少九张人一看就该按「配对错了」。**第五出口存在是因为配对可能错，不是因为我们该批量制造错配** | 一份事实**至多出一张执**，配 `seq` 最近的那一次裁决；其余留在金库待对表，由人自己补登配对 |
| 3 | **血缘规则没有时间边界** | 「同目标 + 同对话」在忙碌的目标里等于**每一次新登记**都对上一次验收出一张执；三周后同一间屋子里的活，因果只剩「碰巧在一起」 | 强路径 = 转包子边（图上明写的因果）；弱路径加**一周**窗口 |
| 4 | **回执已在等你，时间轮还问一遍** | §4 写的是「检验点到达**且图内无匹配事实**」，实现漏了后半句。问一个自己刚放上去的答案，比不问更伤信任 | 有回执就跳过 |
| 5 | **证据行时态错了** | 「当时那个对象最后一次变动」读的是 `updatedAt`——事实刚改过它，于是这行写着「当时」说的是「现在」。**一句时态错了的事实已经不是事实**，而证据行是 prompt 纪律仅存的一处 | 换成真正关于当时的：裁决落在图上第几条边，一跳可回 |
| 6 | **换挡台第三行标题不成立** | 分册叫它「交付前自检【多操作者期执行者侧】」，可 P1 只有操作者一端，那一行的证据说的全是你的**验收**裁决 | 改名「交付验收」（键 `delivery-acceptance`）；多操作者期执行者侧的自检是同一族的第二个入口，那时这名字仍然对 |
| 7 | **两处字面各写一份** | 后视镜条上印内部 id（门上写着人读不懂的键 = 把门画成墙）；销毁口令在客户端与服务端各一份（对不上 = 按钮亮着而服务端拒绝） | 条上印模式自己的名字；口令由服务端发，界面只转述 |

### 11.2 二轮自审又抓到两处（同样已改，同样有用例）

第二轮只问一个问题：**这套东西用满三个月之后，屏幕上会是什么样子。** 答案抓到两处，
都是同一种病——在小数据上看着刚好，在真实数据上变成 nag：

| # | 症状 | 为什么它是错的 | 改法 |
|---|---|---|---|
| 8 | **负重档说了不做** | `spreadEvidence: true` 发出去了，界面只多印一句「证据摆开」，参数照旧截到 200 字。**说明文字占位同罪**：写着摆开却仍然截断，这张卡自己在说假话 | 负重档下参数不截断；验收卡额外摆出交付主张原话与返工轮次——摆的是**同一份图上的数据**，不是新造的话 |
| 9 | **每张答完的卡都挂一块两读** | 一段长会话里二十次确认 = 二十块「这类确认还需要你吗」。而它问的偏偏是「你是不是被问烦了」——用重复二十遍的方式问这个问题，本身就是答案 | ①这一族攒够 **5** 次裁决才问（和决断条 `FATIGUE` 同一个数：那里是「同时挂五件待答」，这里是「这一类你答过五次」）；②这一屏上**一族只挂最新那一张**——零新入口的意思是既有的条尾位置只有一个，扩成两读不该扩成二十个 |

**留着没改的一处**：`reflowOnGraphEvent` 每来一条组织图事件就全量扫一遍 `answer/recorded`
（O(事件数)）。它和这套代码里既有的 `allProjections` / `contractFor` 同一种写法，P1 的量级
下不构成问题；真要动，该和它们一起动，而不是在这里单开一份索引。

**两轮自审的共同形状，值得单独记一句**：九处里有六处（2、3、4、8、9，加上 DM 那一处文案）
是同一类错——**在一条数据上跑通了，在一百条数据上就变成骚扰**。这本账的失败方式不是崩溃，
是让人第二个月不想再打开它；所以「跑通了」从来不是这层的验收标准，「三个月后还愿意打开」
才是。

**这一轮改动的形状**：本轮**零新事件族**（v2.0 的承诺兑现），只有字段补齐（`AnchoredText` 换掉
全部裸锚）、枚举扩员（`entry` 补 `'receipt'`、`verdict-settled` 从两点扩到五类）、派生查询
（沉降 / 锚死显形 / 分布镜）与两个新面（证据面右栏、金库内检索框）。**扩触发面的同一次提交里
加了全局日配额**（PTD-20）——五个入口各自克制、合起来仍是骚扰，分两次做就会有一个中间版本
在骚扰人。

**接缝面的实话**：接缝① 的 payload 从 4 个键变成 6 个（多了 `kind` 与 `titleText`）。`titleText`
是**故意**携来的——组织侧是唯一知道标题的人，它不随事件走，下游就只能回头解析锚，而那正是
「判例是空壳」的成因。组织侧仍然**不知道有人在听**：它只用自己的话说清这是哪一种裁决，判据
一个字都不在那一边。

**在实例上验到的一处（这一条只有真账本能抓到）**：3090 上已经有一本 v1.1 时代写下的账
（49 条）。新代码读它，三条判例的「事实/证据/当时裁决」全部渲染成「（这一段没有留下快照）」
——而那句话是**假的**：v1.x 的行里本来就带着全部文本（`verdictRef.label` / `factText` /
`evidence: string[]`），只是叫别的名字。**一句错的诚实比一句对的沉默更伤**：人会以为自己的
判断记录丢了。

两件事因此补上：

- **读时升级**（新文件 `compat.ts`，挂在三个族的 `reduce` 上）。不迁移、不重写日志——改写历史
  在这本账上是明拒的（更正即追加，销毁是唯一抹除）；读的时候把旧形状折成照片。**升级的输入
  全部来自这本账自己**，一次组织图读取都没有发生（§2 三用途不破）。用例断言升级后日志一行没变。
- **`PLEDGER_FOLD_VERSION` 1 → 2**。读时升级住在折叠里，而落盘快照是折叠的**结果**——不 bump
  的话，已经跑起来的部署会一直读旧形状折出来的状态。**这个 bump 本该跟着 v2.0 的 schema 改动
  一起做**：那条规则就写在这个常量的注释里（「任何影响折叠结果的改动都要 +1」），而它被漏了
  整整一轮。用例现在盯着这个数字。

**这一轮自己抓到的另两处**：

其一，**合环行写在注册表上，屏幕上找不到**。`loopback` 只挂在 `answered` 终态的回执上，
而金库与自聊两个客户端都整片滤掉了 answered 行——于是 `receipt:就地合环行` 是一个**只存在
于注册表里的入口**，而注册表恰恰是入口不垄断律的执法机关。改法三处：desk 只给**最近答完的
那一张**留合环行（否则一屏二十行「要不要开后视镜」，用重复二十遍的方式问「你被问烦了没有」）、
两个客户端都放行带合环行的 answered 卡、自聊那一侧补上 `loopback` 回调。用例从数字段改成
**数按钮**——这个 bug 能活下来，正因为原来的用例只看数据不看屏幕。

其二，入口注册表初稿把 `补登事实` 的入口写成「`selfdm:回执卡`」——而回执卡
的动作里根本没有补登。**写下一个不存在的入口，比少写一个更坏**：执法机关自己开出了假证明
（说明文字占位同罪的注册表形态）。现在每一条入口都对得上代码里的一个真实位置，两处对不上的
改成了明标的 `vaultOnly`。

## 附录 B：技术决策（PTD）

PTD-1 **第二 store 实例而非新内核**：复用 graph 日志内核换 policy——数据律实现单一来源，私账宪法差异全部落在 policy 层｜PTD-2 **三不入靠存储分离不靠 filter**：pendingAnswerables 跑在组织图上、私账卡活在 pgraph 上——漏加 filter 的事故类在结构上不存在｜PTD-3 **持镜人靠依赖方向**：组织侧包 import-ban pledger——"agent 不因误判史改组织行为"由链接器保证非自律｜PTD-4 **单向引用双保险**：依赖面（import-ban）+ schema 面（组织图事件无私账字段）｜PTD-5 **模式零存储**：滚动派生查询强制窗口参数，聚合评分在 API 上不可构造——明拒的类型化｜PTD-6 **不可改笔 = 无 updated 事件**：改笔通道在词汇表上不存在，非运行时校验｜PTD-7 **租约本体留组织侧**：两读的 lease 出口落组织图既有 `lease/granted`，私账只记换挡史——免确认是组织侧行为，其审计必须留在组织侧｜PTD-8 **归属键 = operatorOpenId**：账随人不随实例｜PTD-9 **邀约出处限组织侧 = 输入面限制**：生成器签名不含 pgraph 能力，非 prompt 恳求｜PTD-10 **组织侧接缝封闭清单**：七点白名单入 review 规则——分支越权可机械判定｜PTD-11 **`fact/noted` = 环3 的词汇地板**：图外事实唯一入口是人工补登｜PTD-12 **原话直存 = 参数面而非 prompt 面**：text 由编排层锚定注入、模型无此参数｜PTD-13 **不可回填双锁**：幂等锚（防重复）+ 立约时窗（防事后补立）｜PTD-14 **pledger 自带时间轮**：时间驱动不挂 scheduler（在 ban 名单内）｜PTD-15 **接缝① = 通用事件非专用钩子**：组织侧 emit 而不知有订阅者。

**v2.0 新增（#62）**：

PTD-16 **`AnchoredText` 是唯一携锚形态**：把"存快照"从纪律变成**类型不变式**——schema 里没有裸锚的位置，实现者**想只存锚都写不出来**。同族先例：无 `updated` 事件（PTD-6）、工具 schema 无 text 参数（PTD-12）——本设计第三次用"通道不存在"取代"运行时校验"｜PTD-17 **锚的用途三分（导航/活性探测/幂等键），取内容非法**：把"锚失效不蒸发内容"落成**渲染函数入参不含组织图 service**；副作用是取走后的目录行为可预测——内容全在、只是不再显形不再可跳｜PTD-18 **锚死显形是派生态不是事件**：与模式滚动律同源——**能派生就不落账**（落账即档案）；且不自动写 `withdrawn`——代撤即代产（产婆术对"诚实退出"这个动作同样适用）｜PTD-19 **判据三段式：谱纯／门读账／笔不读账**：v1.x 把三件事都叫"编排层"，实现者会顺手把 gate 的 pgraph 句柄传进 generator，"镜子等人来照"当场破功——**接口纪律优于代码评审**｜PTD-20 **扩触发面必同扩治理面**：触发从 2 点扩到 5 类的同一次提交里加全局日配额——五个入口各自克制、合起来仍是骚扰；**扩员与疲劳是同一个动作的两面**，分两次做就会有一个中间版本在骚扰人｜PTD-21 **入口不垄断由注册表校验**：#61 的条款（凡只能在金库获得的能力即违规）此前只是文字，v2.0 落成 CI 可判定的能力-入口表——**给自己立的法要有自己的执法机关**｜PTD-22 **「当时」栏两输入联合类型**：隐式预期不措辞化靠**第三种输入不可构造**，不靠 prompt 里写"不要推演"｜PTD-23 **分布镜返回类型无 string**：无判词从措辞纪律升为类型约束——**能返回文本的接口迟早会返回判词**｜PTD-24 **明拒靠不注册动词**：转发/引用/提及的 source picker 不含 pgraph——不给动词就不会误用（#57 占位律的反向应用）｜PTD-25 **搜索面按 viewer 注册而非按结果过滤**：place 会话里 provider **不存在**——与工具面 viewer 条款同款；**过滤器会被绕过，不注册不会**。附带一条自纠纪律：本轮首稿把接缝⑦ 写成“surface 搜索面开放 provider 注册”，而主册 §7 事实上**没有内容搜索面**——**不把不存在的面写成已存在的接缝**，预留就明标为预留（v3.15“CLI 发布说明不算实测”的教训自反）。

**v2.1 新增（#61 对象面澄清 × #62-A 接缝）**：

PTD-26 **证据面预览分层：快照是私账的真身、预览是组织侧的礼貌**——设计要"锚对象只读预览"、§2 要"pledger 取内容非法"，两条的消解在**分层**而非取舍：只读预览由 surface 调组织侧既有对象面预览通道（viewer=operator，操作者本可见、零泄漏），pledger 层的证据面渲染入参仍无组织图 service——锚死时预览消失、快照仍在、**对表继续**。不裁这一刀，实现者要么让 pledger 解析锚内容（判例空壳复发）、要么禁掉预览（违设计）——两个都错｜PTD-27 **两本复利账互不蒸馏**：记忆隔离免费于依赖方向铁律，**但免费的保证不成文就会被当成没有的约束**——实现者顺手把金库判例蒸进记忆库只需一行代码，禁令必须先于那一行存在（成文 + canary 断言 + 依赖面三重）；显示层对偶 = 金库语境记忆 tab 空态明标（空态出生故事：说清"为什么空"而不是恰好为空）。
