## 0. 系统一句话与总判据

**一张会话图，任意投影**：云之家是组织基座（身份/消息/文档/日程，经 CLI 与平台 API），deepseek-harness 是宿主与轨迹底座，**会话图是唯一的产品实体**；桌面工作台、云之家原生消息、移动轻应用全部是图的投影。

**摩擦再分配（v4.13，终极价值层）**：本产品是**组织的摩擦再分配机**——把摩擦从搬运处移走（损耗性归零）、安放到决断处（主权性保留并显式设计：签发/裁决/验收的确认流不是待优化的阻力，是承诺的重量本身）、不碰社交处（B4/听众人选/公开私下委派）。**摩擦检验句（对一切"更顺畅"的提案过刀）**：每当让某件事变容易，先问这件事的难度是不是在保护什么——"自动挂接更聪明""一键验收""代发催办""跳过逐条确认"皆须过此刀。frictionless 的尽头是没人签字、承诺无重量的自动化空转。

总判据（全设计域通用）：
1. **一个话题一个窗口**——IM 流与 agent 轨迹是同一个东西的两个侧面；
2. **每次开口知道谁听得见**——听众集合是隔离函数的自变量；
3. **七动词 × 投影完备**（v4.6）——委派/监控/steering/审批/验收/记忆维护/**作为同事说话**在任何投影可达（IM 文本兜底）——委派是对话的特例不是对话的全部，"人和人说话"是母集；
4. **管理者一屏**——部门全部承诺（人+agent）一个取景框；
5. **人只在决断点**——回执/状态/链接的搬运全部是图的回程，人不做泵；
6. **卡片三定律**——卡=图对象投影；消息载句柄不载状态；任一投影动作经授权者做出全局生效。

话题锚定四级回退（DM=`direct` 常量 > `replyRootMsgId` > 耐久 message→topic 索引含 agent 回帖 > 父链防环 > 自成根）；域分隔哈希铸键+账号分区；turn 级授权（source 派生、turn/start 截断、逃逸封禁、身份 pin 复验、撤销事件化）；幂等入站（processed 去重、pending 先持久后执行、终态重投不重跑、交付未知不双帖）；首见群发现 continuation；自发 leading 命令回捞；账号切换熔断；同话题串行/跨话题并行+全局闸；idle 释放可 resume；cancel 不静止→quarantine；出站纪律（回帖锚定、进度上限、回帖 id 入话题索引）；CLI 通道（spawn 无 shell、超时 SIGKILL、截断、npm launcher、非零退出是结果）。

### 3.3 服务 API 与 viewer

`append / isRevoked / contractFor / topicHandle / pendingAnswerables / query(viewer, q)` + cordis 事件 `yzj-graph/appended`。

**viewer 铁律**：由 orchestrator 按 turn 的 `user/message.source` 推导并钉入（群 turn=place、私聊=operator），**模型无此参数**。完整双域语义：**读取按提问者可见域**（私语态跨场所检索以提问者本来可见为界）+ **输出按在场者最小交集过滤**（公域回答前过受众过滤器）。**audience×viewer 桥接**：place 查询=audience 等值匹配；operator 查询=其在场语境全量；audience 存 placeKey/openId 不展开成员（成员解析随组织镜像补全）。

### 3.4 读取域与保留（对称保留律）

默认历史永续，收敛靠视图、清理只在派生缓存。**永不记忆场所**：图对象可读域收敛至合同指定、**审计导出不可触及**、保留期与抹除权是硬合同条款——read-domain 过滤钩子从第一天在 query 与一切导出投影的路径上。已知边界：session 日志经 harness 轨迹视图的读取是宿主路径（RFC-3 session 级读取 ACL ask；到位前以工作区隔离近似）。撤销类硬项（永不记忆、租约撤销、authority-revoked）**穿透会话快照**逐调用实时查；配置类随快照（版本入 env/snapshot）。

```ts

// 状态机校验 allowedActors → answer/recorded 全量留痕 → 首答生效 → 图事件 → 各投影刷新
```

**可应答分类学（v3.8 = v4.15 全名册）**：家族按**六交互模式**归类（模式有限、场景实例开放——同构复制原则）：①单答确认（确认卡/租约创建/冲突确认/**交付推断提议卡**【v3.12=v4.20：「这像是『X』的交付——挂为交付回执？」，投给执行者本人——场景实例开放性的又一例证，家族即接口零改动收编】）②逐条裁决（裁决卡/提案裁决/移交裁决）③**双动词验收**（**验收卡——第六员，v4.14"交付即出卡"**：终态回帖升格为可应答对象，验收/拒收动词长在交付上，拒收返工再验收同卡循环；"找不到验收项"的病根是它长得不像等你的东西；**v3.12=v4.21 冻结内澄清：不分执行者类型**——人类承诺的交付回执确认同样出卡，见 §5.2）④签发（目标签发卡）⑤多出口评估（差距简报）⑥待答询问（定向询问/转办认领——IM 习语形态回复即应答，押采纳门）。**全局三层定律**：**阻塞待答**（上述家族→进决断条/决断层，先答先赢）；**默认生效可纠**（挂接推断 ack/回执状态提议/蒸馏公示——宁默认勿阻塞，**不进条**：塞进条=把可纠升格成待答，用户被迫为每个默认值签字，零维护阵亡）；**信号+就近动词**（逾期/等待超期/老化/staleness/真身之变——是信号不是对象，留意层）。**家族即接口条款**：一切"需要你"投影 = **「本语境内未应答可应答对象」抽象查询的投影，不枚举类型**——增员零改动收编（本设计的 `pendingAnswerables` API 天然即此形态，实现若枚举须标注 P1 降级）；**@提及的普通消息不进家族**（社交召唤归未读——决断面只收图对象，否则变第二收件箱）。

**设计原则的工程兑现**：凡向人提出问题的东西——确认、裁决、验收、租约提议、提醒、定向询问、转办、冲突暂停——**都是可应答对象而非文本**；应答即回写、任一投影生效。LLM 直出卡片走具名窄工具（参数即 schema，校验闸口；无 `card_emit` 通用位；自由卡型归 host-runner 试验通道）。

**四条渲染通道**：① harness 会话流（toolview keyed 组件 + 活状态 RPC；耐久=官方 approval 审计事件+图日志，presentationMeta 仅富化已执行写结果）；② 桌面工作台各视图（§7，graph 查询直渲染）；③ 云之家文本（renderText+句柄+关键词应答）；④ **云之家原生消息卡**（模板 templateId+JSON 数据+按钮回调+按人独享状态+updateCardMsg 活更新——未装我们客户端的同事也能点按钮；经 relay 收按钮提交回调）。

## 5. 对象族完整规格

### 5.1 审批家族（obj-approval / obj-verdict / obj-lease）

- **确认卡**：guard `ask` → `approval/opened`（待答态即图数据）→ 四通道投影 → 任一侧应答 → resolve waterfall。粒度拨盘：对场所/对人/对事；连环审批批量化+节流（同会话同目标标准写可合并确认）。安全底线：强风险（删除类）永远确认，放宽的只是到达路径与重复疲劳。
- **裁决卡**：面向"agent 发现的事"（对账差异、异常清单）与"agent 提取的承诺提案"（纪要→批量承诺）。逐条证据锚点，条目级 确认/驳回/挂起——挂起不阻塞其余执行、挂到父承诺/验收处亮相绝不静默丢失；**转办**：对某条发现一键立 executor=人 的承诺，自动携证据锚与血缘。
- **授权租约**：对象级+期间级可过期预授权（"本表本期写入免确认，8/1-8/5"）。创建走强确认；发现入口在疲劳现场（确认卡上「设为租约?」，桌面与 DM 同权）；期中可撤销（撤销穿透快照即时生效）；到期自动收回、租约史保留为审计证据；租约清单在场所合同面板。guard 判定序：逃逸封禁 → 身份复验 → 租约命中放行 → 合同写级 → ask。

### 5.2 任务 / 等待 / 冲突 / 拒收（obj-task）

- **终态与验收卡（v3.8：交付即出卡；v3.8r 三条语义收紧）**：任务终态回帖**本身升格为验收卡**（可应答对象，双动词验收/拒收 + 作废，与并排预览联动 = 边看交付边裁决的验收原生姿势；已交付的"验收条"即其雏形，按第六员语义对齐命名与家族注册）。**三条收紧**：①**只有"有交付的完成终态"出验收卡**——失败/超时/空回合走既有自动作废路径（不出卡：让人验收不存在的产出，正是此前修过的僵尸问题）；②**终态回帖 = 过程摘要 = 验收卡是同一条消息、同一个对象的一体三面**（摘要是它的正文、验收动词是它的交互面——不是三条消息，实现者勿双发）；③**验收卡 `allowedActors` = 该任务委派者 ∪ 操作者**（委派者验收自己委派的活是主权本义；P1 单操作者下二者常同一人，群内同事委派的任务其验收权随之——多操作者期随 audience 细化）；验收（自然语言/`/done`/卡上动词）→ 归档 → 蒸馏 → 侧栏退租；**拒收**携返工轮次+新旧交付工件版本锚（diff 视图可重建），返工触发蒸馏回滚（tombstone），**拒收→返工→再验收同一张卡循环**（轮次在卡上可见）；**作废**（对方不认账/永久无回执）。**家族延伸：人类交付回执同样出卡（v3.12 = v4.21 冻结内澄清）**——"交付即出卡"不分执行者类型：人类承诺的交付回执**确认时**（话语/行为/结构化三门任一，§5.3 回程）在**登记场所**生成验收对象，`allowedActors`=委派者∪操作者同规则、返工同卡循环同规则——人执行承诺的终态自此可达（此前板上人执行行是断头路：登记有呼吸、交付无验收落座）。**交付锚**：回执引用工件则锚工件（行为回执=甩的那个文件）、纯话语回执（"发了"无附件）锚回执消息本身——被验收的是交付主张，拒收=不认可主张；**三门的"确认时点"各按其模式**：话语门=receipt/recorded 生效即出卡（执行者亲口主张即确认——该门本属默认生效可纠类，无第二道确认）、行为门=执行者应答提议卡、结构化门=平台 complete 动作本身；**回执被纠正（ack 可纠窗口/更正追加）→ 验收卡级联作废**（墓碑+吸收态防复活——卡随主张生随主张死，不悬空；**v3.12r 边界：级联只及未终态卡**——已验收后纠正到达 = 迟到应答走既有竞态定律【先答先赢+高声回执，已执行不可撤销】，推翻已验收终态只能走人的显式动词，不由纠正自动触发）；**v3.8r ① 边界不动**：失败/作废/永久无回执仍不出卡（验收不存在的产出仍是僵尸禁区）。
- **等待**：对象化（被等待者+已等时长），等第三方一等公民；超时升级（escalated 非终态，喊得更响）；任务取消级联关闭；同因幂等复用。系统级等待：通道离线自动开（通道健康 6.5）。
- **冲突可见**：排队 steering 与进行中工作相反 → `conflict/flagged` + 任务原生场所回帖亮出 + 可应答暂停（确认继续/取消）；DM 来源另发应答入口副本，先答先赢。检测形态：编排层语义比对为终态，模型自觉（prompt+`conflict_flag` 工具）为过渡（H18 观察）。

### 5.3 承诺 / 流程 / 目标（obj-commitment）

- **登记**：agent 执行者证据晋升（写动作/期限/显式委派才铸，防"问个数得全家桶"）；人类执行者显式登记（`commitment_register` 走确认）。**挂接三时刻（v3.4，v4.8 收拢——六路径是机制完备性清单，三时刻才是用户动线）**：①**出生时刻**（多数挂接应零操作发生于此）——**语境继承**：挂接引用是语境的属性，新工作从语境继承（从目标 hub 委派 / 已挂目标的话题内追加 / 承诺语境子会话——统一旧路径②⑤⑥；继承非推断，ack 亮出可纠）+ **显式说**（委派语句提及目标/引用 chip）；②**ack 时刻**——无语境无显式才保守推断，宁空勿错；③**事后时刻**——`/link` 补挂 + 承诺板「无归属」组批量补挂。**判定序（v4.9 定）：显式提及 > 语境继承（确定性）> 保守推断（ack 亮出可纠）> 无归属组兜底**。**未挂是合法状态不是错误**（强制对齐产生垃圾对齐——OKR 工具十年教训；「无归属」组把对齐债务从"看不见"变成"拉一下就看见"）。

- **目标 = 复合承诺，真身外挂；立目标 = 登记动词复用（v3.4，v4.8）**：**「立目标」不是新动词**——登记一个 `{executor: owner 本人, 验收: 人工, goalRef: 云之家《目标表》真身 URI}` 的承诺，登记机制原样复用（真身行经既有 sheet/doc 工具+确认流创建）。**三个入口，一条铁律（人签发——agent 觉得"这像个目标"只能提案，不能落库）**：①**AI 速记 → 提案裁决**（主产地；事实升级：组织内部已有 AI 速记产品产出纪要+待办——**纪要→目标提案、待办→承诺提案**两座桥，走 verdict 提案裁决状态机，接缝见 §8）；②**对话登记**（"立个目标：…，我 own，季度末验收" + 确认卡）；③**承诺板 GOALS 入口**（同一动词的看板形态，§7.4）。图表示（零新节点类型）：目标承诺 = 带 `goalRef` 的承诺节点；子承诺 `parentGoalRef` 仍指真身 URI，物化层按 URI 归组解析到目标承诺（无目标承诺的 URI 照旧自由挂——真身外部原则不变）；**聚合是信号不是状态**（子承诺状态计数；父承诺终态永远人工验收——Asana 印证：connected work 仍保留人工 check-in）；状态余生经 `goal/written-back` 写回真身（同一条边两个听众）。
- **流程 = 带模板的复合承诺**：「立为模板」（九年的 checklist.docx 不再每月手拖）/「按模板实例化」（生成子承诺集+父任务-子会话路由：四部门回执路由回父流程）；实例记模板版本（env 类）。
- **回程：回执面三门收拢（v3.12 = v4.20）**——①**话语回执**（既有）：自然语言回复（"分析发了""明天给"）→ `receipt/recorded` 立即生效+公示可纠；捕捉入口=会话语境+对象寻址回复+F-read ambient 观察（完整形态）；②**行为回执（新增：交付推断）**：执行者**只甩工件不说话**（文件甩进某群/DM）→ executor 侧 agent 在**其自己的可见域内**识别疑似交付（查自己名下未终态承诺 = 合法查询，§1.6 不破；语义比对交付物描述 × 文件名/摘要）→ **提议卡**「这像是『X』的交付——挂为交付回执？」投给执行者（单答确认模式，持久化走 proposal 族——"提案确认前不是回执"与"提案确认前不是承诺"同一族语义，零新事件族；**为何先问而非默认生效（v3.12r）**：话语回执可默认生效可纠，因为话已由本人说出、ack 只纠解析；行为回执的回流要**替执行者说一句他没说过的话**——代发言是社交行为不可默认代做，与"agent 不代按一键催办"同一条刀法，实现者不得把此门"优化"成默认挂接；**幂等锚（v3.12r）**：提议卡 idemKey=(承诺, 工件消息锚)——watcher 轮询驱动，无锚必重复出卡【模式补遗⑤同域】；执行者**驳回即该配对入吸收态**永不再提（换新文件=新配对新卡）；同一承诺同时多个候选文件合并一卡供选不连发）→ 确认后以执行者名义**按回程律回流登记场所**（代发"已交付 X"回执消息——确认即签发代发，同拆解代发授权模型；登记的听众看到出生也该看到交付）→ `receipt/recorded` 携工件锚 → **触发验收卡出卡**（§5.2 家族延伸）；与 ack 推断同族零新机制（保守推断/亮出可纠/宁空勿错）；**识别归 F-read ambient 观察线**（scheduler watcher 对轮询到的文件消息做执行者匹配——**§6.2 分诊定序不动**，非分诊旁路）；**P1 降级明标**：寄生单实例期行为回执**仅对操作者本人**可识别（自己甩文件→提议卡走工作台/自聊，零越境零借身）；他人执行者需 executor 侧 agent（每人一 agent/专号阶段解锁）——寄生期他人的行为交付走既有门：话语回执/结构化回执/**owner 对该消息一句话补登**（owner 看得见即合法，同一登记动词）；③**结构化回执**（既有，v4.17）：平台待办 complete = 回执的结构化来源，走 §6.9。**图外交付地板明标**：口头/邮件/外部系统的交付，唯一入口 = 人一句话补登（同登记语法）——**agent 不扫描图外世界比对承诺**（摩擦检验句：那是监工不是跟踪；跟踪的对象是话语与事实，不是人的行为——agent 执行者结构性不静默，此门只为人类执行者存在）。**反模式双拒**：定时自动催办（违社交摩擦三分法）/静默超期自动判失败（违三值状态）。作废/显式合并不变。
- **执行面四通道**（经 relay+platform-api）：人类叶子→云之家待办（generatetodo/action/passUrl 快捷回调）或 cloudwork 任务；审批型节点→cloudflow；进度卡→原生消息卡 edit-in-place。回调中继到位前的降级=登记+轮询式跟催。
- **拒绝清单**（非目标）：甘特/依赖图/资源视图/进度百分比/自动拆解建议/自建 OKR。

### 5.4 记忆（obj-memory）

- **三轴**：场所（群合同域）/实体（客户——销售的复利单位）/组织（组织级事实单一权威副本，场所引用不复制）。
- **蒸馏**：归档触发；**蒸馏定向**裁决"蒸到哪根轴/哪个对象"（裁决卡样式）；来源锚强制（哪个 turn 产出）；**注入边**从 env/snapshot 派生——"口径变更后哪些在跑的任务用过旧口径"是其上投影。
- **卫生**：可检视可纠正（记忆卡+对象面记忆 tab）；返工回滚（tombstone）；错误记忆可反查来源。
- **策略入硬合同**：永不记忆/仅事实类/正常三档，guard 强制；永不记忆场所不产生蒸馏不进任何轴+读取域收敛（3.4）；策略改严时撤销类穿透+回溯清除经显式确认。

### 5.5 实体与外部（obj-entity）

联系人/客户/候选人/外部顾问为实体节点；组织外 = **影子节点**（无触达通道、有身份位：实体轴记忆、承诺归属、上下文归属）。动词：「已代发」（人肉信道发出后登记——图知道在等客户）/「回执回填」（外部回复结构化入口）。出流走**脱敏导出投影**（受众矩阵"组织外"格：不含内部读写清单；每次导出留 crossing 事件）。中期通道：邮件/短信/外部日程邀请（infra）。

### 5.6 事件（obj-event）

日程五边模型（服务/生成/操作/触发/聚合）；**服务边是可选边（v3.12 = v4.19）**——大多数会议无关联任务也不必然挂目标（"未挂是合法状态"的会议版），`sessions[undefined]` 类空引用是实现层红线（渲染前判空非事后修）；**材料就绪度**从关联任务状态免费推导（**工件事实驱动**：等审批=交付未定稿仍 ⏳），**就绪度三态（v4.19）**：**无期待=不显示徽标**（没有期待就没有"缺"——语义空缺不得渲染成负面状态，与"无信号≠没问题"同族纪律）/期待未就绪（⏳ 缺+来源）/就绪（✓）；**「为此会准备」双语义（v4.19）**：有关联任务=**话题内追加**（传送门跳该话题，语境继承——落点是既存工作语境非听众推导）；无关联=**发起准备任务=生成边的诞生时刻**——无天然语境，落点必须**人选**（场所选择条，v4.9 传送门同款语法，CTA 不得断路）；首个准备任务落地后会议转入有关联态、就绪度语义激活（空状态的出生故事闭环）；边也落云之家（材料链接经确认写入事件 description，全参会人可见）；会议=事件锚定的会话，纪要=工件。**摄取形态定稿（v3.9 = v4.16，yapi 事实）**：**每用户一条增量轮询线**（`aisteno/list` 按 updateTime 增量、无 creator 参数范围=登录身份 → FINISHED+enhanced 拉 `detail`+`minutes`；`workSetting/callBackUrl` 为唯一翻案线索入实测②）；**双桥映射定稿**：`minutes.decisions[{content, basis, owner}]`→目标提案**带依据**、`minutes.actionItems[{text, executors[含 openId]}]`→承诺提案**带 openId**，全部经 verdict 提案裁决（人签发铁律；**提取分工：平台 extract 产出并入我方提案队列去重，不替我们干活**）；**发言人三级可信度**：绑定 userId > AI assignee 文本 > 发言人N——未绑定进裁决不自动挂人；**纪要无版本号**→提案内容级 diff 防重复；meetingId↔stenoId 桥待实测③；**摄取听众集合**：纪要携带参会人听众（audience=参会人）、知识库自动上传的 docId ACL 与图听众对齐入实测⑧、**evidence 越境=提案确认即人签发**（机制零新增，成文）。**日程五边字段化**：`workData{msgId,groupId}`=IM 消息→日程的**出生凭证官方字段**（"生成"边真实落点）、`redirectUrl.detail`=官方回链（通知/列表直跳 dsh 会话页）、repeatMeeting 服务端展开 batchId 聚合、**代建授权面板 getAuthorizedAgentList**=on-behalf-of 的平台正式面（B4 落点）；**冲突四策略确认门在我们侧**（detect 给 strategy 建议，shorten/reschedule/delegate 无平台确认直接落库——我方确认卡先行，摩擦再分配实证；entrustJoin 例外自带应答链=半门）；找时段族（participant-availability 带 score/谁没空）；**brief=素材段非晨报本体**（v4.17：晨报主体=图的投影，平台 executive/brief 成文晨报只供今日日程段）。拉现在做，推（会前自动检查/会后行动项）归 F-act。

## 6. 通道与编排（`channel` + `relay` + `scheduler`）

### 6.1 transport 双适配器

- **CLI 适配器**（真人身份，永久保留——平台无消息流订阅，读群语境只能轮询）：子进程通道模式（1.3）+ 轮询（recent+list，锚点游标）；
- **platform-api 适配器**（HTTPS+token 直连，不等 CLI）：对话机器人回调（@ 即秒级触发，HmacSHA1 验签、sessionId、3 秒空响应转异步）、群机器人 webhook 出站、消息卡片收发与更新、待办、cloudflow、组织读取族与九类变更回调、公共号双向 DM。**混合定式：机器人收触发，CLI 读语境。**
- **relay**：公网回调中继（云函数/轻量服务器→本机转发，验签在本机完成）；一切平台回调（机器人/卡片按钮/passUrl/组织/审批/日程）的前置基建。

### 6.2 入站分诊（定序不可改——命令先行是死锁修复）

原始消息 → ① 回声抑制（6.3）→ ② **命令**（前导 `/` 语法识别，旁路通道不入话题队列：`/cancel`=resolve waterfall 为 deny+agent.cancel）→ ③ **卡片动作**（回复∈已投影 msgAnchors 且命中 keywords → 动作总线，`allowedActors` 状态机校验）→ ④ **受话判定（v4.7：受话者含 agent 即触发）**：alias/@（既有）**或 回复任何 agent 消息**（出站预登记+messageTopics 索引判定——"回复某人的消息即向其受话"是 IM 本能，ack「回复本条可继续」由此成立；授权同 @ 触发：allowedSenders 白名单，群成员回复 agent 消息与 @agent 完全同权——v2.5 F13 的"仅操作者可 steering"限定随之作废，因为这不是特权 steering 而是普通受话）→ ⑤ 丢弃。触发词试运行期为 `@next`/`@下一代`（部署分区，附录 A），平价切换后回 `@agent`。

### 6.3 自聊回声协议

出站预登记（clientNonce+内容指纹，发送后回填 msgId，崩溃窗口指纹兜底）+ 自聊白名单分诊（仅命令/对象寻址/leading-alias，其余丢弃）。专号/机器人身份到位后自聊通道退役，协议保留给任何"同 openId 双向"场景。

### 6.4 orchestrator

- **路由铸键与回复定律（v4.7）**：新域标签铸独立 sessionId 空间；DM 默认连续（`direct`+`/new` 分段，**DM 内回复退化为纯指涉**——流即界，落点不变）；generation 从图 topicHandle 读。**回复 = 挂链，受话 agent = 点火**：`replyRootMsgId` 链是数据事实（云之家本就记录），人-人链不建 session；链上任何消息受话 agent 的瞬间 session 锚定链根、`topic/registered`——**此前的人-人闲聊自动成为话题开场上下文**（contextFor 按链根过滤收集，机制既有，v4.7 只是把它正名为"链是话题的胚胎"）；含 @ 时锚定层级同样生效（回复着某消息 @agent = 入其链点火，不自成根）。**「新」是推导不是选择**：新话题 = 主楼落点 + 受话 agent + 未挂链的系统推导（A0③），无"开新话题"用户模式。
- **命令集**：`/new` `/reset` `/cancel` `/done` `/reject` `/link` `/unlink` `/handoff` `/fork` `/status`。**`/unlink` 摘除（v3.14 = v4.22）**：与收养（/link）对称的减法动词——owner 对子图边界的修理（作废杀承诺、移交换 owner，语义都过重时用它）；数据语义 = commitment/updated 追加去除 parentGoalRef（更正即追加，attachedVia 史留痕），行落无归属组；主权谓词 = 该承诺所挂目标的 owner 或承诺 owner。`/handoff <群>`=fork 血缘+脱密背景包（工件链接/验收标准/决议摘要）经确认卡→投递目标群开新话题，私语不迁移，crossing 记录；授权链=解析群 ID 亮示+成员预检+歧义列候选，失败降级拟稿亲发。`/status`=graph_query 预设投影。
- **steering**：turn 间=排队 followup（同话题串行）；step 内 `steer()` 增强位。
- **过程摘要**：终态回帖升格——从图免费投影（lineage 动作清单+approval 记录+产物链接），会话流 report 卡渲染、IM 文本投递；机密场所按合同默认关闭。
- **viewer/env**：per-turn viewer 钉入；env/snapshot 懒写（3.2）。
- **guard**：turn 级授权模式 + `contractFor()`（三层：组织默认→场所→会话快照）+ 租约命中 + oaRequiredCategories 拒绝 + 撤销穿透 + 逃逸封禁 + 身份 pin。

### 6.5 通道健康

连续 N 次轮询失败/回调心跳丢失 → 系统级 waiting 对象 + 桌面高优通知；鉴权失败（10000400/93001）提示重登。**系统对自己的离线不可以失明。**

### 6.6 审批生命周期（确认卡）

TTL 与任务 deadline 对齐（超时 expired+deny+回声）；重启恢复：先判 TTL，非阻塞型无缝恢复可应答，turn 阻塞型转 `interrupted`+"回复 重试"——重试一次性（应答即 superseded 终态，幂等锚=approvalId+'retry'），重试=新 followup 重新执行+guard 重新 ask（旧应答不变预授权——那是租约职权）；部分投影恢复按 card/projected 差额补投；决策者 allowedActors 校验，落败应答留痕。

### 6.7 组织镜像（platform-api）

getallpersons 全量+时间水位增量 + 部门树 + 按角色取人 + 九类变更 webhook（经 relay）→ 本地组织镜像：@对的人/找对审批人/audience 成员解析/汇报链（承诺板管理者维度）的数据地基。只读不写组织。

### 6.8 对接三角色定律（v3.9 = v4.17 对接裁决刀，一切平台 adapter 的总律）

**平台对象在本设计中只能扮演三种角色：投影**（触达面——待办推送/提醒/卡片）、**证据源**（回执签字——confirm/reject/应答链）、**素材段**（brief 日程段/纪要原料）。**图的本体论一寸不移**：承诺/会话/听众的真身永远在图。**采纳轴外挂类（第四种情况，与三角色并列而非例外）**：目标表、OA 审批单、workreport 周报——真身外挂是**采纳轴裁决**（利益相关者住在那里），不是本体论移交；图记发起边与状态回流，外挂真身受真身之变律管辖（消费时点校验/断链显形/人工回填）。词汇卫生条款：平台视角的"真身/正式/转正"等措辞进入本设计语言前必须经三角色转换——v4.17 的三错两缺共同病根就是 subagent 的平台措辞未经转换流入设计。每个 adapter 的 spec 必须首行声明其平台对象扮演哪个角色。

### 6.9 双轨与执行面投影（v3.9 按 §6.8 三角色定律与 yapi 事实定稿）

agent 过程审批=本地卡轨（全栈自有）；OA 流程审批=cloudflow adapter（`track` 字段：代发起/代查/事件回调进图；oaRequiredCategories 命中即引导走 OA；**协作流 `getFlowInfo` 为 v4.3"审批单挂接"基建门的候选钥匙**——等待对象挂审批单、状态可查回填）。

**人类承诺叶子 adapter（v3.9 定稿——角色声明：user-action-item = 投影+证据源，真身在图）**：
- **主从铁律**：代发登记话语为**主**（确立听众集合，幽灵承诺禁令）、待办写入为**副**（执行者侧触达投影）——顺序不可倒；**主失败副暂缓（v3.9r）**：代发失败（「未通知」态）时待办写入不得先行——副先于主 = 触达先于听众确立，幽灵承诺换个通道复活；
- **REJECTED 回流的三层落点（v3.9r）**：责任人拒绝认领（reject+reason）→ `receipt/recorded` 携原因 + **留意层信号 + 就近动词**（作废 / 重新协商=传送门回登记场所）——不是阻塞待答（与逾期同格：需要 owner 留意，不需要 owner 立刻签字；永久无回执与拒绝认领同通 A3 作废出口）；
- 写入：internal upsert（`(sourceId, ownerUserId)` = 平台幂等键，sourceId = 我方承诺 ID）+ `DELETE source/{id}` 级联清理；**sourceType 自定义值待实测⑤**；**速记侧 actionItems 只读铁律**（无 per-item ID、update 全量替换——写回会覆盖人的手工编辑）；
- **证据源映射**：责任人 confirm=CONFIRMED（对方签字→`receipt/recorded`，受领门）、reject+reason（再协商回流→receipt 携原因）；`/complete` 无 body 不押证据→**只是回执的结构化来源**，走既有 `receipt/recorded` 零新机制；完成回流**零 webhook 只能轮询**；
- **催办按摩擦三分法**：事件类声明式提醒用平台原生；**承诺催办=社交摩擦，仍拟稿+传送门+亲发**——agent 不代按平台"一键催办"；
- **最大门槛明标**：internal 写入口**零 gateway 化**（服务间信任）——此 adapter 的新基建门条件；fallback = 日程投影 + IM 登记消息。

**待办中心投影**（公开面路径不变）：审批/承诺可推 generatetodo（passUrl 回调回图）——与 internal 路径二选一按可达性。

### 7.4 承诺板与时间回顾（v3.12 = v4.21 定稿：账本的对账面；v3.4 GOALS 视图并入）

**定性：板 = 账本的对账面**——注意力归收件箱、推送归晨报、作业台归目标枢纽与会话；板上每个元素必须服务「随时可对账」。**合法增量条款（hub 同款自检，板此前缺失即十几版失修的制度原因）**：板的合法增量只有**对账排列 + 一跳指路 + 就近动词**；**板不设决断条/待办聚合区——收件箱是唯一跨会话聚合处**（三层分工：聚合=收件箱/指路=板行/送达=会话决断条；「3 分钟知道哪里不对劲」由**排列**满足不由聚合满足——异常即排序与分节，正常行安静）。**上板判据**：凡登记话语确立的承诺皆上板（含 DM 私下登记）——板 = 查看者可见域并集，**非"公开承诺板"**。

**三个系统透镜（无用户自铸视图）**：①**方向轴三元 chips**：全部（默认——可见域并集意味着第三关系「我旁观的」存在，组织透明是特性非缺陷）/欠我的/我欠的；②**时间透镜两层规则**：话语原文是真身（"下周初"不得强解析——宁空勿错），时间戳 = 解析投影、可空、可纠（`due:{text,ts?}`，§3.2）；透镜只对有戳行生效（今日到期/逾期浮起 = 事实驱动零维护——Asana 把自动晋升拆成用户规则的反面实验），**无戳行沉底不消失**；**账龄折进排序权重与逾期徽标分层**（每层暗示一个升级动作：催→顺延→作废），不做独立结构；③**目标组（GOALS）**：按目标分组——目标承诺行（虚线框=真身在云之家不在图 + 子承诺状态计数信号【非百分比】+「终态：人工验收」药丸 + 产出归集入口【两跳派生】+「评估」入口）+ **「无归属」组**（周会批量补挂：多选 → /link）+ **「立目标」入口** + 目标行「委派」CTA=传送门（**不做板上分配表单**）+ **目标行点击 = 放大为目标页**（第二缩放级别 §7.6，Back 恢复板位）；**组折叠复用侧栏 chevron 语法**（披露列同位同行为——同构复制），**组头计数带异常语义**（"N 承诺 · M 逾期"——折叠组仍可对账）。

**排序与行规格**：**组内信号序成文**：待决 > 逾期 > 无信号/过时 > 运行 > 进行中 > 休眠 > 终态。**行信息层级**：常显 = **四要素**（谁/向谁【查看者本人省略】/交付什么/何时【原话语 text】）+ **三值信号** + 最后信号时间（三值状态首入第一缩放级——无信号/过时不再只在 hub 可见）；**责任锚两槽位**：执行者（人/agent/流程 ex-tag）×验收人（**恒为人**——Linear assign/delegate 同构：an agent cannot be held accountable；验收人=查看者本人时省略、非本人时显示）——两槽正交；挂接来源与出生故事**降两级披露**（hover 一级 + 详情二级，**hover 永非唯一通道**【触屏/a11y】——出生故事的差异化在有据可查不在常显）；颜色预算 = 仅状态/异常拿饱和色，其余灰阶。**行 = 一跳传送门**（链接话题会话/轨迹真身，行内预览=过程摘要——过程日志永不进板）；**行内修理动词就近**（催/顺延/作废/合并/移交/收养/摘除——§7.6 同族，**无归属承诺的修理在板上同样可达**，不再只活在 hub；**渲染按动词主权谓词**【v3.14 = v4.22：仅该承诺 owner 见修理与催——越级不便利】；**「我的切片」= 我执行的 ∪ 我委派的**两册，与方向轴同构）。

**第一档欠账修复清单（v4.21 明标——板停在 v4.12 前旧语义的同类全集补课，开发按此逐项核销，demo 已对齐）**：①**催办统一**：板行复用"agent 拟稿+传送门+owner 亲发"，**废一键借身提醒**（B4 禁令的板上兑现）；留意行从承诺数据推导（顺延/作废后无僵尸）；②**晨报 = 图的投影且每个数字是门**（逾期/信号异常/待验收/今日到期可点定位——逐级兑付定律在晨报的适用，§9）；③**人执行行一跳登记真身 + 修理动词就近**；④**三值状态下板**（含信号过时样本）；⑤**空板出生样本**（登记覆盖率的分母出生地——样本纪律）；⑥**验收断链接通**：验收卡家族延伸适用人类交付回执（§5.2——交付推断确认→登记场所出卡→验收→终态，断头路接通）；⑦侧栏板徽标动态推导。

**板级明拒六条**：无看板拖拽（状态 = 事实驱动，拖 = 对图撒谎）/无进度条百分比/无用户自铸视图（透镜只有系统三个：方向/时间/目标）/无图表 widget/无日规划仪式/**无决断条**（设计线自审推翻自己草案的产物——板级决断条 = 第二收件箱，违三层分工；GitHub Inbox 合法恰因那是他们唯一的收件箱，模式不可误植）。**Viva Goals 验尸句钉墙：板的每次打开必须是"来取，不是来喂"**。

**时间回顾**：「本周产出」一键汇总（lineage+终态的时间投影——周报的 pull 版）。

### 7.5 对象面（右栏）与工件预览三态（v3.6，D13⑥）

三 tab：**当前**（本会话工件/喂入引用留痕/关联日程 deadline）、**记忆**（可检视可纠正）、**资源**（知识库+表格混排一棵树——按容器组织、类型是过滤属性；日程周条+议程）。**反向来处**（工件→承诺/目标血缘读出）；**系列当前指针**（收藏链接永远指向当前有效版；勘误=血缘+分发清单读出物）。

**工件统一（v4.11）**：**文件消息 = 工件的 IM 出生形态**——同事拖进群的 PDF 与 agent 交付的 md 是同一种图居民（工件），血缘不同、**卡与预览语法相同**（一个物不配两套 UI）。工程：IM 文件/图片消息与 `lineage/produced` 工件用同一工件卡组件（标题/预览/下载/云之家打开）；人发文件不强制入图（agent 劳动才写出生边），被引用/喂入时经既有 ref 机制留痕。真身唯一：文件真身在云之家，预览是投影，下载/云之家打开永远可达。

**预览三态（三种意图，与话题"卡→展开→进入"平行的物缩放语法）**：
- **流内卡**：扫一眼（卡带预览/下载动作）；
- **并排 = 默认预览态**：右栏对象面被预览**接管并加宽**、中栏压缩但保持可读可回复——**边看边回是验收/steering 的原生姿势**（claude.ai artifacts/飞书侧边栏同族；拒绝 Slack 式 modal——挡住对话，验收变"看完凭记忆回复"）。不违反 D5 反而兑现它：中栏是流右栏是物，预览=物的放大态；v3.5"右栏不做第二时间线"无恙（单物非流）；
- **沉浸**：深读全屏、Esc 返回（PDF 多页/长文）；移动端（P5）唯一态、天然降级。

**格式策略：能投影则投影**——md 富渲染（presentationMeta 渲染器复用）、pdf 浏览器原生 viewer、**html iframe sandbox 只读禁脚本**（预览不是运行）、图片 lightbox、表格走资源投影（sheet schema+记录窗口）；数据通路 = file-data 代理模式（CLI 下载→magic-bytes 嗅探→data URL，老小窗已验证）；不能投影 → 下载+外开，**不硬造 viewer**。**切会话即收**（与"锚不跨会话残留"同一纪律）。

**宽度（补充裁决）**：可拖分隔线 + 两端护栏（中栏可回复最小宽=**硬底线**拖不破；预览可读最小宽=再窄不如收起）+ **全局记一个值**下次如旧——固定宽度=替用户决定主次（主次是当下意图的属性），纯比例无视内容自然行长（大屏 md 拉破 30-40 字舒适区）；更宽的需求走沉浸态，分隔线不必覆盖全区间。

### 7.6 事件枢纽与对象枢纽

事件枢纽：日程周条→事件详情。**落点 = 右栏对象面接管（v3.14 收编实现线事实）**——板上一场会一行只装三样（几点/叫什么/准备好没有），"差什么"的一屏放右栏、标题即门（与工件预览同一条纪律同一种形状：模块级订阅**不拿快照**——就绪度要随交付自动翻绿，快照会越看越旧）；枢纽四段 = 关联任务（每件带一跳）/材料（会上要用的是东西不是"已完成"三个字）/日程描述（全参会人可见的那一版）/「为此会准备」（传送门不替人派活，双语义见 §5.6）；平台 list 已回字段不另打 event get、空串按"没填"渲染非空白段；**右栏打不开时如实说话**（revealAside 失败不得渲染成"什么都没发生"）。对象枢纽（通用形态）：长期活对象的对象轴记忆、变更史、关联会话、传送门 CTA。

**目标页（目标枢纽，v3.7 定稿 = v4.12）**：**定性 = 目标这个复合承诺的对象枢纽 = 承诺板的第二缩放级别**（缩放语法第四次复用：板→目标放大态；进出即缩放、**Back 恢复板位**、数据同一查询——非新 surface，"分活去哪/看进度看哪"的割裂从根上不存在）。**灵魂一句：三个主权时刻在此落座，其余一切是派生查询**。范围 = 目标子图全量（目标→子承诺→执行会话/轨迹→产物→回执验收→评估→真身回写），呈现用链不用图（依赖图禁令不动）。

**三条结构性法则（实现者不可违）**：①**可见域（v3.14 升级为参与者视角全则，= v4.22）**——**视角 = 关系 × 可见域 × 问题**：一页 N 个查看者 N 种渲染 = "与我有关的边被点亮"（关系从既有边派生非角色字段；清单/计数/决断层/背景全按查看者可见域过滤——不存在全知视角，目标名遵循**标题/正文两层可见域与三态投影**【§5.3】；**磨稿血缘 owner-only**——机密目标一跳即泄密，read-domain 钩子在血缘投影上生效）；**「我的切片」语义成文 = 我执行的 ∪ 我委派的**（两册——方向轴"欠我的/我欠的"在 hub 切片的同构下放），执行者默认置顶来自**切片律非决断层**（逾期对任何视角都不是可应答对象）；**动词主权法则**：修理动词族与 CTA 的渲染谓词 = **该节点的 owner**（目标级归目标 owner、承诺级归承诺 owner——执行者对自己的承诺是再委派的 owner，递归闭包的席位表达；**越级不便利**：目标 owner 对孙辈承诺不渲染催，不禁社交追问）；执行者对自己承诺的动词 = **登记族**（把我的活拆下去）+ **回执族**（交付/求助/顺延请求 = 回复登记消息）；**无主权的动词不渲染**（非灰化——灰按钮是"你不配"的展示；不渲染不禁言：人人可用话语说任何事，系统只是不为无主权者造按钮）；**渲染过滤与编排层执行校验共用同一主权谓词、单一事实源**（allowedActors 同族——防 UI 不渲染而文本通道绕过执行）；**无主权话语到达时不执行也不静默（v3.14r）**：执行者对 agent 说"这目标作废吧"——agent 不执行、不静默忽略（静默是本设计最大罪）、不公开驳斥（社交羞辱），**回应 = 指路 + 可选转达拟稿**（"作废归 owner 张锐——可直接问 ta，或我拟一条转达你亲发"）；②**单一形态**——一个模板贯穿生命周期，变形全由派生信号驱动（评估卡出现=收口形态、全终态只读=回顾形态），**无任何"阶段"字段落图或落真身**（"磨稿中/收口中"是伪状态——防实现者加 status enum 的栏）；③**随时可对账非持续对账**——常驻只放原料（成功标准正文投影×终态计数×工件归集），对账结论只在人发起评估时产出（依据版本入 env 快照——标准改了简报可追）。

**结构**：Header 全零存储推导（名称/owner/时限/真身链接带时间戳/状态徽标/成功标准条=真身正文派生 + **真身之变显形**「真身已于 x 日修改·未对账」+查看差异+以新基准重估【意图史】+ **staleness**「图内 x 天无新轨迹」——事实驱动非填表驱动）；**Zone1「需要你」两层**：决断层 = 收件箱同源可应答对象的**过滤投影**（先答先赢跨投影，绝非复制列表：待裁决提案/待验收/冲突/移交裁决/评估简报），留意层 = 信号+就近动词（逾期不是可应答对象——催/顺延/作废就在旁边）；**空态三义分家**：在跑/停摆（全在等第三方）/空转（无子承诺）——合并三义即谎言；**Zone2 执行清单**（平铺+计数+一跳，永不画树）：**环行** = 每行承诺携带自己的迷你闭环（来源【出生边】/会话一跳+过程摘要/产物 chips/回执验收态【回流边】）+ **三值状态**（有证据/无信号+最后信号时间/信号过时——观察型承诺不画成确定性）+ **行内修理动词族**（目标的中年）：催（agent 拟稿+传送门+owner 亲发——B4 降级明标）/顺延（期限 vs 提醒分立）/作废/合并/移交（/handoff）/**收养**（无归属承诺 /link 进来，attachedVia:'linked'）/**摘除（/unlink，v3.14——与收养对称的减法动词**：owner 对子图边界的修理，作废杀承诺语义过重时用它，行落无归属组，§6.4）；**全族渲染按动词主权谓词过滤**（v4.22 demo 已兑现：板/hub 行修理与催仅渲染给该承诺 owner）；CTA = ＋委派（传送门）+⚡拆解（禁令文字随卡）+✓评估——**三 CTA 同按主权过滤**（非 owner 席位无此三钮；轻问人人有）；**轻问=传送门**（跳私语会话预载目标语境——无页内输入框，轻问是会话 turn）；右栏 = 该目标的对象面（归集+三态预览/背景：磨稿血缘 owner-only、历次简报=非操作者的目标时间线）。

**生命周期补全**：目标终态 = 已验收/**已作废**（无拒收——评估不通过的出口 = 继续或作废）；作废 = 人签发终态 + 回写真身 + **级联子承诺**（工程语义从摩擦刀裁定：子承诺收到"父目标已作废"信号显形 + 批量修理动线【多选作废/收养改挂/独立存续】，**不自动作废**——主权摩擦保留）。**闭环自检表入验收**（环路完整性对页面自我适用）：拆解委派/执行/产物/回执验收/修理/评估/回写七环，每环**既可见又可动**，缺一即割裂债。**违规能力自检条款**：页面的合法增量只有决断落座+一跳导航+就近动词——**凡只能在这一页获得的能力就是违规能力**。竞品三戒：别做目的地 app、别管过程指标（填写率/check-in 率 = theater 制度化）、催人裁决不催人抄数。**席位诱惑明拒五条（v3.14 = v4.22，全文见 §5.3）**：无参与者面板/认领市场、无上级驾驶舱/进度推送、无跨域背景摘要内嵌、无"我的目标工作台"聚合页、无"另有 N 项你看不到"装饰——**五席位皆无新 surface**。hub 其余丰富度（关键时刻流等）与故事线维持押门（终态回顾态可含）。

## 8. 治理与身份

- **场所合同**：同一 agent 逐场所合同；三层（组织默认→场所→会话快照）；**出生规则（v3.11 = v4.18 场所创设三句）**：创设人签发（`yzj_im_group_create` 强确认；agent 只能提议）、合同默认最严（新场所 `served=false` 不在岗不接单须显式开启）、出生血缘携带语境（birth 字段）；**听众集合按场所解析、随成员动态**（audience 存场所引用永不展开成员快照——两端一致检验：云之家看得见历史登记消息⇔承诺板看得见承诺行；**v3.11r 事实前提待核**：动态解析的正当性依赖"云之家群历史对新入群成员可见"——若平台对新成员隐藏入群前历史，则新成员板上见承诺行而云之家见不到登记消息、检验反向失效，动态解析须按加入时间切分——**入实测清单⑨**）；拉人=听众扩张、移人=听众收缩，均走确认门（能力随阶段二平台 API 到位）；**硬合同**（guard 强制、对话不可写）：接单开关/触发者白名单/写权限级/工具面/审批策略与粒度/记忆策略/preset 允许/oaRequiredCategories/**永不记忆**；**软合同**=场所记忆同库可对话修改；**第三格**（口径类）=软存储+硬变更流程（留痕/生效期/审阅门）；快照语义+撤销穿透（3.4）；三入口（群 agent chip/合同面板/组织默认页）。
- **身份阶梯**：真人寄生（自聊审批弱形态）→ **专号**（第二真人账号：DM 推送、归因清晰、移动轻问通道）→ **机器人**（@ 回调收、卡片发）→ **企业应用**（三级 token API 面）。**B2** 显示名任务态（专号命名+消息内任务标注）；**B3** 语态默认与身份阶段耦合；**B4 on-behalf-of**：代理名义一等参数（"财务助理（代郑慧）"随投影展示），**借身期禁跨场所催办**（降级=拟稿+操作者亲发）。
- **听众集合**（§1.6 完整双域）：读取按提问者可见域、输出按在场者交集过滤；越境唯一合法通道=人签发的工件化脱密+审计+血缘；记忆永不越界（不可撤销故入硬合同）。
- 治理表：租约（期限/自动收回/创建强确认/清单可见）、裁决（记录入审计基底/挂起不阻塞）、越境（谁签发/从哪到哪/脱了什么）、记忆策略（guard 级）、审计导出（走确认/含判定链）、on-behalf-of（名义随投影/跨场所催办拒绝）。

## 9. 主动性（域 F）

> 信任门槛是写权限的函数，不是主动性的函数。

- **F-read**（scheduler 供电，只读）：**轻问**（一次性投影，会话 turn 非旁路——落 DM 日志可审计可升格：「以后每天这样」→晨报条目、「转成工件」→落云之家）；**晨报**（cron→query→report 卡→DM；**v3.12 = v4.21：晨报 = 图的投影且每个数字是门**——逾期/信号异常/待验收/今日到期各数字可点定位到对应板位/对象，逐级兑付定律对晨报同样适用：报出"3 项逾期"却不可点 = 幽灵信号）；**盯(节点类型)**参数化 watcher（承诺到期/事件就绪度/运行健康度/临时定时）；`/status`；碎片「引用+入池/登记」低摩擦捕捉；**提醒=可应答对象**（已催/顺延/完成）；**顺延两动词**（顺延承诺期限=公域经确认回写真身；顺延提醒=私事只改计划）。**推力拆半（v3.9 = v4.16 结构修正）**：**对人的推力平台原生齐备——DSH 不自建对人提醒**（声明式提醒/多次提醒/短信/语音电话/snooze/ICS 订阅全在平台，我们声明式登记即可）；**对 agent 的推力仍靠轮询**（queryByDay/pageRecentList 游标为此而备）——scheduler 的职责域相应收窄为 agent 侧唤醒与图 watcher。**应答环不外包（v3.9r，三角色定律对提醒的应用）**：平台提醒只是**投影**（触达面）——提醒对象的真身与可应答面仍在图（已催/顺延/完成），平台提醒的 `redirectUrl` 回链必须指回图上该可应答对象；否则"提醒是可应答对象"被外包肢解，snooze 只在平台侧生效、图不知情、次日重复提醒——操作者变回状态泵。
- **F-act**（最后解锁）：自主写、代发、ambient 回复、自动跟催、会前自动备料——每项独立拨盘入场所合同。

## 10. 完成质量（唯一未设计因子，如实留空）

"agent 真的把事做对"由 gateway+工具面+模型承载，设计层唯一杠杆=**拒收→学习回路**（打回时"为什么不行"蒸馏为负向记忆/合同修正）。本设计只保证**原料从第一天记录**（拒收轮次/理由/工件版本锚）；回路本身由真实拒收样本喂养后设计（H13）。
