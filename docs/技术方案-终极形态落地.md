## 0. 系统一句话与总判据

**一张会话图，任意投影**：云之家是组织基座（身份/消息/文档/日程，经 CLI 与平台 API），deepseek-harness 是宿主与轨迹底座，**会话图是唯一的产品实体**；桌面工作台、云之家原生消息、移动轻应用全部是图的投影。

**摩擦再分配（v4.13，终极价值层）**：本产品是**组织的摩擦再分配机**——把摩擦从搬运处移走（损耗性归零）、安放到决断处（主权性保留并显式设计：签发/裁决/验收的确认流不是待优化的阻力，是承诺的重量本身）、不碰社交处（B4/听众人选/公开私下委派）。**摩擦检验句（对一切"更顺畅"的提案过刀）**：每当让某件事变容易，先问这件事的难度是不是在保护什么——"自动挂接更聪明""一键验收""代发催办""跳过逐条确认"皆须过此刀。frictionless 的尽头是没人签字、承诺无重量的自动化空转。

总判据（全设计域通用）：
1. **一个话题一个窗口**——IM 流与 agent 轨迹是同一个东西的两个侧面；
2. **每次开口知道谁听得见**——听众集合是隔离函数的自变量；
3. **七动词 × 投影完备**（v4.6）——委派/监控/steering/审批/验收/记忆维护/**作为同事说话**在任何投影可达（IM 文本兜底）——委派是对话的特例不是对话的全部，"人和人说话"是母集；
4. **管理者一屏**——部门全部承诺（人+agent）一个取景框；
5. **人只在决断点**——回执/状态/链接的搬运全部是图的回程，人不做泵；
6. **卡片三定律**——卡=图对象投影；消息载句柄不载状态；任一投影动作经授权者做出全局生效。

**吸收态语义（v3.10，幂等锚律的状态机面；v3.16 增第三员、v3.19 增第四员）**：`voided`、`merged`、**`superseded`（v4.23）**、**`transferred`（v4.24+ #59）** 是**吸收态**——唯 `reopened` 能回（**transferred 例外：无 reopen**——移交回来=再签发新边指回，复活旧边会双活），其余转移一律 no-op 留痕（防真实路径：目标作废后旧简报卡按验收把 voided 翻回 closed=僵尸复活）；assessment 同理（已回答不再打开，已结算锚自动换号）；superseded 特有语义：**替代非否决**——被替代卡的未应答项已迁入现行卡（剩余域替代+挂起跨轮），答旧卡=指针跳转不算落败应答；transferred 特有语义：**重新签发非终结**——活着的义务在新边延续，旧边只是这段责任史的封存卷宗（答旧边投影=指针跳转新边，同 superseded 语法）。

### 3.3 服务 API 与 viewer

`append / isRevoked / contractFor / topicHandle / pendingAnswerables / query(viewer, q)` + cordis 事件 `yzj-graph/appended`。

**viewer 铁律**：由 orchestrator 按 turn 的 `user/message.source` 推导并钉入（群 turn=place、私聊=operator），**模型无此参数**。完整双域语义：**读取按提问者可见域**（私语态跨场所检索以提问者本来可见为界）+ **输出按在场者最小交集过滤**（公域回答前过受众过滤器）。**audience×viewer 桥接**：place 查询=audience 等值匹配；operator 查询=其在场语境全量；audience 存 placeKey/openId 不展开成员（成员解析随组织镜像补全）。

### 3.4 读取域与保留（对称保留律）

默认历史永续，收敛靠视图、清理只在派生缓存。**永不记忆场所**：图对象可读域收敛至合同指定、**审计导出不可触及**、保留期与抹除权是硬合同条款——read-domain 过滤钩子从第一天在 query 与一切导出投影的路径上。已知边界：session 日志经 harness 轨迹视图的读取是宿主路径（RFC-3 session 级读取 ACL ask；到位前以工作区隔离近似）。撤销类硬项（永不记忆、租约撤销、authority-revoked）**穿透会话快照**逐调用实时查；配置类随快照（版本入 env/snapshot）。**私账例外区（v3.20 = #60r）**：pgraph 是对称保留律的**第二例外区**（永不记忆场所之后）——审计导出投影的重放过滤器**不挂 pgraph 源**；且方向与场所例外相反：组织与他人不可导出、**本人可整体取走与销毁**（目录自包含无外部索引，数据主权归人——分册 §2 policy 三条；"启用且组织可见"的中间态无配置项可拧）。

**设计原则的工程兑现**：凡向人提出问题的东西——确认、裁决、验收、租约提议、提醒、定向询问、转办、冲突暂停——**都是可应答对象而非文本**；应答即回写、任一投影生效。LLM 直出卡片走具名窄工具（参数即 schema，校验闸口；无 `card_emit` 通用位；自由卡型归 host-runner 试验通道）。

**四条渲染通道**：① harness 会话流（toolview keyed 组件 + 活状态 RPC；耐久=官方 approval 审计事件+图日志，presentationMeta 仅富化已执行写结果）；② 桌面工作台各视图（§7，graph 查询直渲染）；③ 云之家文本（renderText+句柄+关键词应答）；④ **云之家原生消息卡**（模板 templateId+JSON 数据+按钮回调+按人独享状态+updateCardMsg 活更新——未装我们客户端的同事也能点按钮；经 relay 收按钮提交回调）。

**私账对象条款（v3.24 = #64 零新场所）**：私账**没有可应答对象进入本系统家族**——校准回执是裁决卡下方私语道里的一根**私条**（`pledgerStripFor` 组合点渲染，仅操作者桌面），归因四格与「配对错了」在私条上按（走 pledger 自有总线、写 pgraph）；押是私语道出站拦截的动词；换挡是软合同句。**三不入由构造满足**：私账对象不在 `pendingAnswerables` 的存储域里（不靠 filter）、没有第二个会话可进、不产生任何 IM 消息（无邀约卡、无 DM 副本、无自聊出站）、无未读徽标/收件箱/决断条。未答回执**不老化、不可催、不成欠账**（债主是你自己）；默认无到达信号，opt-in 晨报计数行是人签发的显示。**私语道 placeholder 文字**（"……或「押：」一句预期，可选"）是发现路不是邀约——不弹卡、不计数、不重复。全量规格见[分册 v3.0 §4-§5](./技术方案-私账层.md)；#60r–#62 时代的三不入/沉降/入口不垄断条款降为历史。

## 5. 对象族完整规格

### 5.1 审批家族（obj-approval / obj-verdict / obj-lease）

- **确认卡**：guard `ask` → `approval/opened`（待答态即图数据）→ 四通道投影 → 任一侧应答 → resolve waterfall。粒度拨盘：对场所/对人/对事；连环审批批量化+节流（同会话同目标标准写可合并确认）。安全底线：强风险（删除类）永远确认，放宽的只是到达路径与重复疲劳。
- **裁决卡**：面向"agent 发现的事"（对账差异、异常清单）与"agent 提取的承诺提案"（纪要→批量承诺）。逐条证据锚点，条目级 确认/驳回/挂起——挂起不阻塞其余执行、挂到父承诺/验收处亮相绝不静默丢失；**转办**：对某条发现一键立 executor=人 的承诺，自动携证据锚与血缘。
- **授权租约**：对象级+期间级可过期预授权（"本表本期写入免确认，8/1-8/5"）。创建走强确认；发现入口在疲劳现场（确认卡上「设为租约?」，桌面与 DM 同权）；期中可撤销（撤销穿透快照即时生效）；到期自动收回、租约史保留为审计证据；租约清单在场所合同面板。guard 判定序：逃逸封禁 → 身份复验 → 租约命中放行 → 合同写级 → ask。**证据门与私账层的接力（v3.24r = #64r）**：本族的证据门"审批疲劳"由私账「我的判断」组头给出可观测形态（高同意、零推翻、短停留、长等待），**最小租约随 4p′ D4 同批开工**；发现入口从确认卡「设为租约?」扩至私条/组头「不用再问我」（传送门到同一张强确认卡）——组织侧只多一个入口指向既有对象，零新语义。

### 5.2 任务 / 等待 / 冲突 / 拒收（obj-task）

- **终态与验收卡（v3.8：交付即出卡；v3.8r 三条语义收紧）**：任务终态回帖**本身升格为验收卡**（可应答对象，双动词验收/拒收 + 作废，与并排预览联动 = 边看交付边裁决的验收原生姿势；已交付的"验收条"即其雏形，按第六员语义对齐命名与家族注册）。**三条收紧**：①**只有"有交付的完成终态"出验收卡**——失败/超时/空回合走既有自动作废路径（不出卡：让人验收不存在的产出，正是此前修过的僵尸问题）；②**终态回帖 = 过程摘要 = 验收卡是同一条消息、同一个对象的一体三面**（摘要是它的正文、验收动词是它的交互面——不是三条消息，实现者勿双发）；③**验收卡 `allowedActors` = 该任务委派者 ∪ 操作者**（委派者验收自己委派的活是主权本义；P1 单操作者下二者常同一人，群内同事委派的任务其验收权随之——多操作者期随 audience 细化）；验收（自然语言/`/done`/卡上动词）→ 归档 → 蒸馏 → 侧栏退租；**拒收**携返工轮次+新旧交付工件版本锚（diff 视图可重建），返工触发蒸馏回滚（tombstone），**拒收→返工→再验收同一张卡循环**（轮次在卡上可见）；**作废**（对方不认账/永久无回执）。**家族延伸：人类交付回执同样出卡（v3.12 = v4.21 冻结内澄清）**——"交付即出卡"不分执行者类型：人类承诺的交付回执**确认时**（话语/行为/结构化三门任一，§5.3 回程）在**登记场所**生成验收对象，`allowedActors`=委派者∪操作者同规则、返工同卡循环同规则——人执行承诺的终态自此可达（此前板上人执行行是断头路：登记有呼吸、交付无验收落座）。**交付锚**：回执引用工件则锚工件（行为回执=甩的那个文件）、纯话语回执（"发了"无附件）锚回执消息本身——被验收的是交付主张，拒收=不认可主张；**三门的"确认时点"各按其模式**：话语门=receipt/recorded 生效即出卡（执行者亲口主张即确认——该门本属默认生效可纠类，无第二道确认）、行为门=执行者应答提议卡、结构化门=平台 complete 动作本身；**回执被纠正（ack 可纠窗口/更正追加）→ 验收卡级联作废**（墓碑+吸收态防复活——卡随主张生随主张死，不悬空；**v3.12r 边界：级联只及未终态卡**——已验收后纠正到达 = 迟到应答走既有竞态定律【先答先赢+高声回执，已执行不可撤销】，推翻已验收终态只能走人的显式动词，不由纠正自动触发）；**v3.8r ① 边界不动**：失败/作废/永久无回执仍不出卡（验收不存在的产出仍是僵尸禁区）。
- **等待**：对象化（被等待者+已等时长），等第三方一等公民；超时升级（escalated 非终态，喊得更响）；任务取消级联关闭；同因幂等复用。系统级等待：通道离线自动开（通道健康 6.5）。
- **冲突可见**：排队 steering 与进行中工作相反 → `conflict/flagged` + 任务原生场所回帖亮出 + 可应答暂停（确认继续/取消）；DM 来源另发应答入口副本，先答先赢。检测形态：编排层语义比对为终态，模型自觉（prompt+`conflict_flag` 工具）为过渡（H18 观察）。

### 5.4 记忆（obj-memory）

- **三轴**：场所（群合同域）/实体（客户——销售的复利单位）/组织（组织级事实单一权威副本，场所引用不复制）。
- **蒸馏**：归档触发；**蒸馏定向**裁决"蒸到哪根轴/哪个对象"（裁决卡样式）；来源锚强制（哪个 turn 产出）；**注入边**从 env/snapshot 派生——"口径变更后哪些在跑的任务用过旧口径"是其上投影。
- **卫生**：可检视可纠正（记忆卡+对象面记忆 tab）；返工回滚（tombstone）；错误记忆可反查来源。
- **策略入硬合同**：永不记忆/仅事实类/正常三档，guard 强制；永不记忆场所不产生蒸馏不进任何轴+读取域收敛（3.4）；策略改严时撤销类穿透+回溯清除经显式确认。

### 5.5 实体与外部（obj-entity）

联系人/客户/候选人/外部顾问为实体节点；组织外 = **影子节点**（无触达通道、有身份位：实体轴记忆、承诺归属、上下文归属）。动词：「已代发」（人肉信道发出后登记——图知道在等客户）/「回执回填」（外部回复结构化入口）。出流走**脱敏导出投影**（受众矩阵"组织外"格：不含内部读写清单；每次导出留 crossing 事件）。中期通道：邮件/短信/外部日程邀请（infra）。

### 5.6 事件（obj-event）

日程五边模型（服务/生成/操作/触发/聚合）；**服务边是可选边（v3.12 = v4.19）**——大多数会议无关联任务也不必然挂目标（"未挂是合法状态"的会议版），`sessions[undefined]` 类空引用是实现层红线（渲染前判空非事后修）；**材料就绪度**从关联任务状态免费推导（**工件事实驱动**：等审批=交付未定稿仍 ⏳），**就绪度三态（v4.19）**：**无期待=不显示徽标**（没有期待就没有"缺"——语义空缺不得渲染成负面状态，与"无信号≠没问题"同族纪律）/期待未就绪（⏳ 缺+来源）/就绪（✓）；**「为此会准备」双语义（v4.19）**：有关联任务=**话题内追加**（传送门跳该话题，语境继承——落点是既存工作语境非听众推导）；无关联=**发起准备任务=生成边的诞生时刻**——无天然语境，落点必须**人选**（场所选择条，v4.9 传送门同款语法，CTA 不得断路）；首个准备任务落地后会议转入有关联态、就绪度语义激活（空状态的出生故事闭环）；边也落云之家（材料链接经确认写入事件 description，全参会人可见）；会议=事件锚定的会话，纪要=工件。**摄取形态定稿（v3.9 = v4.16，yapi 事实）**：**每用户一条增量轮询线**（`aisteno/list` 按 updateTime 增量、无 creator 参数范围=登录身份 → FINISHED+enhanced 拉 `detail`+`minutes`；`workSetting/callBackUrl` 为唯一翻案线索入实测②）；**双桥映射定稿**：`minutes.decisions[{content, basis, owner}]`→目标提案**带依据**、`minutes.actionItems[{text, executors[含 openId]}]`→承诺提案**带 openId**，全部经 verdict 提案裁决（人签发铁律；**提取分工：平台 extract 产出并入我方提案队列去重，不替我们干活**）；**发言人三级可信度**：绑定 userId > AI assignee 文本 > 发言人N——未绑定进裁决不自动挂人；**纪要无版本号**→提案内容级 diff 防重复；meetingId↔stenoId 桥待实测③；**摄取听众集合（v3.15 修正我方措辞——"audience=参会人"不成立）**：图的听众词汇是 placeKey（场所引用），**表达不了"这几个人"**——拿表达不了的东西当听众用 = 假的隔离承诺（§6.8 词汇卫生），比没有更坏；正解（实现线已按此做，确认成文）：**参会人 = 提案的证据字段，不冒充听众**——提案默认仅操作者可见，**确认那一刻 = 人签发的越境**（纪要内容随代发消息进入新场所的听众，合法因为有人签字）；**听众词汇不扩展人员集合型**（其动态语义无场所合同管辖，是未开的治理面）；知识库自动上传的 docId ACL 与图听众对齐入实测⑧、**evidence 越境=提案确认即人签发**（机制零新增，成文）。**日程五边字段化（v3.15 按实测⑦修正——两字段用法被推翻）**：`workData{msgId,groupId}` 是官方出生凭证字段但**只声明在 create/modify 上、detail 不返回——写得进、读不回**，故"生成"边的**唯一落点是我们的图**，平台字段是它的单向投影（三角色定律自答：那是投影不是证据源）；`redirectUrl` 同为 create 写入字段（我们写给平台、让平台通知跳回 dsh）——**且 CLI calendar 命令不接这两个参数（二进制无此字符串，实测）**，"应答环回链"今天做不了，**降为 ask**（CLI 加参或 tenant_app OAuth 直连，二选一）；repeatMeeting 服务端展开 batchId 聚合、**代建授权面板 getAuthorizedAgentList**=on-behalf-of 的平台正式面（B4 落点）；**冲突四策略确认门在我们侧**（detect 给 strategy 建议，shorten/reschedule/delegate 无平台确认直接落库——我方确认卡先行，摩擦再分配实证；entrustJoin 例外自带应答链=半门）；找时段族（participant-availability 带 score/谁没空）；**brief=素材段非晨报本体**（v4.17：晨报主体=图的投影，平台 executive/brief 成文晨报只供今日日程段）。拉现在做，推（会前自动检查/会后行动项）归 F-act。

## 6. 通道与编排（`channel` + `relay` + `scheduler`）

### 6.1 transport 双适配器

- **CLI 适配器**（真人身份，永久保留——平台无消息流订阅，读群语境只能轮询）：子进程通道模式（1.3）+ 轮询（recent+list，锚点游标）；
- **platform-api 适配器**（HTTPS+token 直连，不等 CLI）：对话机器人回调（@ 即秒级触发，HmacSHA1 验签、sessionId、3 秒空响应转异步）、群机器人 webhook 出站、消息卡片收发与更新、待办、cloudflow、组织读取族与九类变更回调、公共号双向 DM。**混合定式：机器人收触发，CLI 读语境。**
- **relay**：公网回调中继（云函数/轻量服务器→本机转发，验签在本机完成）；一切平台回调（机器人/卡片按钮/passUrl/组织/审批/日程）的前置基建。

### 6.2 入站分诊（定序不可改——命令先行是死锁修复）

原始消息 → ① 回声抑制（6.3）→ ② **命令**（前导 `/` 语法识别，旁路通道不入话题队列：`/cancel`=resolve waterfall 为 deny+agent.cancel）→ ③ **卡片动作**（回复∈已投影 msgAnchors 且命中 keywords → 动作总线，`allowedActors` 状态机校验）→ ④ **受话判定（v4.7：受话者含 agent 即触发）**：alias/@（既有）**或 回复任何 agent 消息**（出站预登记+messageTopics 索引判定——"回复某人的消息即向其受话"是 IM 本能，ack「回复本条可继续」由此成立；授权同 @ 触发：allowedSenders 白名单，群成员回复 agent 消息与 @agent 完全同权——v2.5 F13 的"仅操作者可 steering"限定随之作废，因为这不是特权 steering 而是普通受话；**冻结内澄清（2026-09-03 dsh-2 实测）：显式受话者优先于隐式**——消息显式叫了人（平台标「有人@你」/ @所有人 / 正文 `@某人`）而不含触发词，受话者就是那些人，回复锚指向 agent 消息也不算受话（寄生期 agent 顶着操作者账号说话，同事回复"你账号那条"再 @ 你本人，是在跟人说话；实测助理替人接了单还要人验收）；纯回复不带任何 @ 维持原样，回复 + 触发词照旧触发；桌面出站同律，`acceptAccountMentions:false` 即"@ 我的账号 = 叫的是人"）→ **④′ 受话解析·实例归属（v3.23 = #63，受话成立后、入队前；v3.23r 修订为四级 + 按路分派）**：受话者含 agent 只回答"是不是在叫 agent"，多实例部署下还要回答"**叫的是哪一个**"。**前置**：分诊① 回声抑制扩为**同侪回声**——一切实例出站（含代发登记话语、/handoff 帖、在岗声明、让位帖）恒带署名（§8 B5），**同侪出站永不进入本步**，只作 §7.4 镜像源（否则 Bruce 的代发登记会被张三的在岗实例二次登记——v3.23r 抓到的最重一处）。四级：**级 0 对象归属**（真身唯一律的分诊形态）——话语指向的对象（回复的 agent 消息 / 命令② 引用的任务或承诺 / 卡片动作③ 的锚 / 话题内 steering 所属会话）在谁的图谁处理：在本图 → 本实例；在同侪图（同侪回声识别 / 镜像行 origin）→ 不是叫我，丢弃（镜像行上的动作走 §7.4 文本传送门）——**跨实例永不竞赛**；**级 1 发言者实例**——发言者是有实例的操作者（署名/在岗史可知）→ 由其自己的实例接单（**真身跟说话的人**：委派——他的助理为他干活，账号/合同/归因三重自然；登记他人承诺——owner 从发言者派生，真身归 owner 实例）；他人实例对该触发**延迟一个轮询周期**再看（发言者实例第一优先）；发言者实例对该场所未 served → 视同无实例；**级 2 在岗实例**——发言者无实例或其实例未接：本场所**对群在岗**（scope:'all'）的实例接单；≥2 个对群在岗重叠 → 级 3；**级 3 认领竞赛**（§6.4）。**路型差异**（v3.13 三路先判后解析）：委派 agent 路全四级；登记他人承诺 / 疑问询问路只用级 0-1，在岗仅兜底——登记不是执行、不需要在岗授权（代发登记 ack 本就以 owner 账号发出不问在岗）。DM 与自聊不经此步（对端唯一，无歧义）→ ⑤ 丢弃。触发词试运行期为 `@next`/`@下一代`（部署分区，附录 A），平价切换后回 `@agent`。**桌面出站对称（v3.15③ 同律）**：操作者从桌面向群发出受话 agent 的话语时，出站侧先跑同一解析——本实例非该场所在岗 → **不就地点火**，锚定条明示「本群在岗：云小助（张三）——将由它接单」；在岗 → 就地点火 + ack 如常（同侪实例见 ack 让位）。

### 6.3 自聊回声协议

出站预登记（clientNonce+内容指纹，发送后回填 msgId，崩溃窗口指纹兜底）+ 自聊白名单分诊（仅命令/对象寻址/leading-alias，其余丢弃）。专号/机器人身份到位后自聊通道退役，协议保留给任何"同 openId 双向"场景。

### 6.4 orchestrator

- **路由铸键与回复定律（v4.7）**：新域标签铸独立 sessionId 空间；DM 默认连续（`direct`+`/new` 分段，**DM 内回复退化为纯指涉**——流即界，落点不变）；generation 从图 topicHandle 读。**回复 = 挂链，受话 agent = 点火**：`replyRootMsgId` 链是数据事实（云之家本就记录），人-人链不建 session；链上任何消息受话 agent 的瞬间 session 锚定链根、`topic/registered`——**此前的人-人闲聊自动成为话题开场上下文**（contextFor 按链根过滤收集，机制既有，v4.7 只是把它正名为"链是话题的胚胎"）；含 @ 时锚定层级同样生效（回复着某消息 @agent = 入其链点火，不自成根）。**「新」是推导不是选择**：新话题 = 主楼落点 + 受话 agent + 未挂链的系统推导（A0③），无"开新话题"用户模式。
- **命令集**：`/new` `/reset` `/cancel` `/done` `/reject` `/link` `/unlink` `/handoff` `/fork` `/status`。**`/unlink` 摘除（v3.14 = v4.22）**：与收养（/link）对称的减法动词——owner 对子图边界的修理（作废杀承诺、移交换 owner，语义都过重时用它）；数据语义 = commitment/updated 追加去除 parentGoalRef（更正即追加，attachedVia 史留痕），行落无归属组；主权谓词 = 该承诺所挂目标的 owner 或承诺 owner。`/handoff <群>`=fork 血缘+脱密背景包（工件链接/验收标准/决议摘要）经确认卡→投递目标群开新话题，私语不迁移，crossing 记录；授权链=解析群 ID 亮示+成员预检+歧义列候选，失败降级拟稿亲发；**承诺形态（v3.19 = #59）**：/handoff 对承诺 = 边的重新签发（旧边 transferred+新边出生，§5.3 移交定稿）——agent 任务的 handoff 与承诺的移交是同一动词的两个对象形态，血缘与背景包纪律同源。`/status`=graph_query 预设投影。
- **认领协议（v3.23 = #63——受话唯一律的运行时协议；v3.23r 改为梯队协议）**：**梯队 = 发言者实例（0 延迟）› 对群在岗（1 轮询周期）› 备岗（k 周期，押门）**——每梯队各自跑三段式 **看一眼 → 认领 → 复核**。①**看一眼**：到达本梯队的延迟点后重读该触发所在线程与场所近史——存在高梯队/同梯队的同侪 ack（署名识别）或同侪在岗声明 → **静默让位**（`yielded reason:'speaker-instance'|'presence'`——没开口，无需撤）；②**认领 = 既有 ack**（ack 先于一切工作是既有时序——ack 即 claim，零新消息）；③**复核**：本 ack 经回声协议拿到 msgId 后重读线程——**高梯队的 ack 在窗口内到达** → 本实例输（即便我先 ack——**梯队高于时序**："真身跟说话的人"高于"谁先应"）；**同梯队且 msgId 更早**的同侪 ack → 本实例输；输 → **显式让位帖**「↪ 已由 云小助（张三）接单」（`yielded reason:'ack-order'`，retractAnchor 入账）+ **不开工**；赢 → task/opened 带 `claim{contenders, tier, tiebreak}`。**同梯队平局裁决 = 服务端 msgId 总序**（双方观察同一顺序——前提入实测⑩：`recent/list` 按 msgId 单调一致返回；不成立则退化为 operatorOpenId 字典序，仍确定性）。梯队延迟的代价 = 在岗服务"有助理但未接本群"的同事时多一个轮询周期——损耗侧一次性小额，换取归因永远落在发言者自己的账号上（主权侧）。**让位必须显式**：ack 是对群的承诺，一条不撤的 ack = 幽灵承诺（模式补遗⑦"言之凿凿说做而没做"的实例版）——静默让位合法只因它从未开口。**写前复核**：guard 在任何写工具调用前读本 turn 的 claim 态（`sole|presence|msgId` 胜出）——输了却已进入工作的 turn 在第一个写调用处被截断（撤销穿透同款：claim 是穿透快照的硬项），双写的最后一道机械防线。**同侪回声**：§6.3 回声协议从"识别自己的出站"扩为"识别任何实例的出站"（署名标记 = 互认凭据），是①③两步的数据基础。
- **过程摘要**：终态回帖升格——从图免费投影（lineage 动作清单+approval 记录+产物链接），会话流 report 卡渲染、IM 文本投递；机密场所按合同默认关闭。
- **viewer/env**：per-turn viewer 钉入；env/snapshot 懒写（3.2）。
- **guard**：turn 级授权模式 + `contractFor()`（三层：组织默认→场所→会话快照）+ 租约命中 + oaRequiredCategories 拒绝 + 撤销穿透 + 逃逸封禁 + 身份 pin。

### 6.5 通道健康

连续 N 次轮询失败/回调心跳丢失 → 系统级 waiting 对象 + 桌面高优通知；鉴权失败（10000400/93001）提示重登。**系统对自己的离线不可以失明。**

### 6.6 审批生命周期（确认卡）

TTL 与任务 deadline 对齐（超时 expired+deny+回声）；重启恢复：先判 TTL，非阻塞型无缝恢复可应答，turn 阻塞型转 `interrupted`+"回复 重试"——重试一次性（应答即 superseded 终态，幂等锚=approvalId+'retry'），重试=新 followup 重新执行+guard 重新 ask（旧应答不变预授权——那是租约职权）；部分投影恢复按 card/projected 差额补投；决策者 allowedActors 校验，落败应答留痕。

### 6.7 组织镜像（platform-api）

getallpersons 全量+时间水位增量 + 部门树 + 按角色取人 + 九类变更 webhook（经 relay）→ 本地组织镜像：@对的人/找对审批人/audience 成员解析/汇报链（承诺板管理者维度）的数据地基。只读不写组织。

### 6.8 对接三角色定律（v3.9 = v4.17 对接裁决刀，一切平台 adapter 的总律）

**平台对象在本设计中只能扮演三种角色：投影**（触达面——待办推送/提醒/卡片）、**证据源**（回执签字——confirm/reject/应答链）、**素材段**（brief 日程段/纪要原料）。**图的本体论一寸不移**：承诺/会话/听众的真身永远在图。**采纳轴外挂类（第四种情况，与三角色并列而非例外）**：目标表、OA 审批单、workreport 周报——真身外挂是**采纳轴裁决**（利益相关者住在那里），不是本体论移交；图记发起边与状态回流，外挂真身受真身之变律管辖（消费时点校验/断链显形/人工回填）。词汇卫生条款：平台视角的"真身/正式/转正"等措辞进入本设计语言前必须经三角色转换——v4.17 的三错两缺共同病根就是 subagent 的平台措辞未经转换流入设计。每个 adapter 的 spec 必须首行声明其平台对象扮演哪个角色。

### 6.9 双轨与执行面投影（v3.9 按 §6.8 三角色定律与 yapi 事实定稿）

agent 过程审批=本地卡轨（全栈自有）；OA 流程审批=cloudflow adapter（`track` 字段：代发起/代查/事件回调进图；oaRequiredCategories 命中即引导走 OA；**协作流 `getFlowInfo` 为 v4.3"审批单挂接"基建门的候选钥匙**——等待对象挂审批单、状态可查回填）。

**人类承诺叶子 adapter（v3.9 定稿——角色声明：user-action-item = 投影+证据源，真身在图）**：
- **主从铁律**：代发登记话语为**主**（确立听众集合，幽灵承诺禁令）、待办写入为**副**（执行者侧触达投影）——顺序不可倒；**主失败副暂缓（v3.9r）**：代发失败（「未通知」态）时待办写入不得先行——副先于主 = 触达先于听众确立，幽灵承诺换个通道复活；
- **REJECTED 回流的三层落点（v3.9r）**：责任人拒绝认领（reject+reason）→ `receipt/recorded` 携原因 + **留意层信号 + 就近动词**（作废 / 重新协商=传送门回登记场所）——不是阻塞待答（与逾期同格：需要 owner 留意，不需要 owner 立刻签字；永久无回执与拒绝认领同通 A3 作废出口）；
- 写入：internal upsert（`(sourceId, ownerUserId)` = 平台幂等键，sourceId = 我方承诺 ID）+ `DELETE source/{id}` 级联清理；**sourceType 自定义值待实测⑤**；**速记侧 actionItems 只读铁律**（无 per-item ID、update 全量替换——写回会覆盖人的手工编辑）；
- **证据源映射**：责任人 confirm=CONFIRMED（对方签字→`receipt/recorded`，受领门）、reject+reason（再协商回流→receipt 携原因）；`/complete` 无 body 不押证据→**只是回执的结构化来源**，走既有 `receipt/recorded` 零新机制；完成回流**零 webhook 只能轮询**；
- **催办按摩擦三分法**：事件类声明式提醒用平台原生；**承诺催办=社交摩擦，仍拟稿+传送门+亲发**——agent 不代按平台"一键催办"；
- **最大门槛明标**：internal 写入口**零 gateway 化**（服务间信任）——此 adapter 的新基建门条件；fallback = 日程投影 + IM 登记消息。

**待办中心投影**（公开面路径不变）：审批/承诺可推 generatetodo（passUrl 回调回图）——与 internal 路径二选一按可达性。

**锚定条（v4.7 D13④——A0 锚定层级的 UI 真身）**：一次发送回答四个正交问题——**落点**（哪个边界）/**受话**（说给谁）/**指涉**（引用什么）/**可见域**（公/私语态）——四者共享一个发送键，所以落点必须在按下前**常显**：「发到主楼」「↩ 挂到某消息 → 进入其话题」「发到话题 X」「发给某人 · 连续会话」；点 ↩ 即改锚、点 × 回默认锚；**点火预告**：已挂链状态下输入 @ 的瞬间，锚定条切换为「整条链将收纳为话题」。

**导航（v4.6 D13②）**：进话题 = push 导航栈，「‹ 返回」= pop **恢复离开时的精确滚动位置**（Back）；面包屑群名 = Up 到群顶。主次是当下意图的属性不是场所的属性。

**会话决断条与信号即门（v3.8，D13⑦）**：**逐级兑付定律**（导航不变量）——凡显示"需要你"之处，点击兑付到它所在缩放级的下一级：侧栏组徽标→群、话题卡徽标→话题、**会话决断条→对象**，每跳是门不跳级；**没有不可兑付的信号**（幽灵承诺禁令的 UI 对称版：徽标说"有事等你"却不说在哪 = UI 自己开的幽灵承诺）。**决断条**：会话内存在未应答可应答对象时，时间线顶部常显细条（计数+chip），点击滚动定位+高亮闪烁，**答完即溶**（calm 零 chrome）；**同源条款**：与收件箱是同一批 `pendingAnswerables` 的过滤投影，先答先赢跨投影——绝非会话私有待办；**指针投影非复制落座**：真身留原位、前后语境强制在场（防"批量清账不看上下文"堕化——把卡拔顶钉住 = 复制真身或丢语境，两个都错）；会话头"需要你"chip = 同对象第二门。**空间三规则**：①**本语境直属、绝不上卷**——话题/DM/主楼各自一条，话题内待办经话题卡徽标逐级兑付不上卷主楼（上卷三宗罪：跳级/复制落座/群顶变第二收件箱）；收件箱是唯一跨会话聚合——三层分工：收件箱聚合/卡徽标指路/决断条本级送达；②**一行封顶**——计数+放得下的 chip+折叠 +N（条是指针不是清单，长成横幅吃半屏对话即违背"对话不离场"）；③**条长即治理信号**——健康负载 0-2 项，长期 5+ = 审批疲劳，条尾就地长出「经常在确认这类操作？**设为租约 ›**」（租约发现入口的条上延伸，疼痛门数据采集位）；**v3.24（#64）：两读卡押证据门**——两个出口（租约／负重）保留，载体改为**私条与「我的判断」组头上的就近动词「以后这类事…」**（就地展开三句：先看要求×交付／给我看上次的结果／不用再问我——不跳转，pledger 自有面），条尾入口回到组织侧既有的单出口「设为租约›」；两读卡回归的触发器 = 人自述找不到「以后这类…」出口（分册 v3.0 §1 接缝④撤销）。摩擦边界：**寻路归零、决断保留**——条只送达不代答；决断条不构成第四注意力入口（不产生新去处，只接驳既有入口的落点）。

### 7.4 承诺板与时间回顾（v3.12 = v4.21 定稿：账本的对账面；v3.4 GOALS 视图并入）

**定性：板 = 账本的对账面**——注意力归收件箱、推送归晨报、作业台归目标枢纽与会话；板上每个元素必须服务「随时可对账」。**合法增量条款（hub 同款自检，板此前缺失即十几版失修的制度原因）**：板的合法增量只有**对账排列 + 一跳指路 + 就近动词**；**板不设决断条/待办聚合区——收件箱是唯一跨会话聚合处**（三层分工：聚合=收件箱/指路=板行/送达=会话决断条；「3 分钟知道哪里不对劲」由**排列**满足不由聚合满足——异常即排序与分节，正常行安静）。**上板判据**：凡登记话语确立的承诺皆上板（含 DM 私下登记）——板 = 查看者可见域并集，**非"公开承诺板"**。**镜像行（v3.23 = #63，多实例部署下上板判据的兑现——P1.5）**：同侪实例在本操作者可见场所登记的承诺，其真身在**登记者实例的图**；本实例从群消息流中**带句柄的**登记 ack 物化镜像行（`commitment/opened{origin:'foreign'}`），状态随后续携句柄的终态回声/验收回声更新——真身唯一律原文直接适用：**投影允许滞后、禁止错序、滞后必须可见**（行上「镜像 · 云小助（张三）· 更新于 x」）；修理动词族按动词主权**自然不渲染**（owner 是另一操作者——零新规则）；来源实例消失 → 行入「信号过时」（三值状态既有）；幂等锚 = (operatorOpenId, handle)。**镜像行的动作 = 文本传送门（v3.23r）**：镜像行按动词主权渲染——owner = 本操作者时（我委派给同侪在岗 agent 的活）催/验收/顺延在场，但真身在对方图，**动作形态 = 预填关键词回复到该卡的 msgAnchor（IM 文本通道③）、发送即应答**——卡片三定律③"任一投影动作经授权者全局生效"的跨实例形态：动作经文本投影到达真身实例，**本实例永不本地改写镜像**（改写 = 两本真身）；状态经对方的携句柄回声流回镜像。**回写归属（v3.23r）**：每实例只回写自己持真身的承诺到目标真身，镜像永不回写（否则同一承诺两行台账）。**P1 明标降级**：镜像落地前，多操作者部署下板 = 本实例登记集，管理者检验④在寄生期**只在镜像落地后成立**——如实入账，不假装一屏。**「我裁决的」透镜（v3.24 = #64）**：方向轴第四 chip——点击进入**第三取景框「我的判断」**（session kind `judg`，Back 恢复板位；与承诺板严格同构：组织轴 = 裁决族、组头 = 比值原料 2×2【同意 N（成立／被推翻）｜没同意 N（证明对／错）】+ 每次停留、行 = 我的裁决 × 押/回执/归因、就近动词「以后这类…」长在组头；板级明拒原文适用——无决断条、无排名、无跨人比较；受 D10 整层管辖）。它不是板的第四透镜（不换组织轴、不动本板）而是**跨裁决取景框的入口**——分册 v3.0 §5。

**三个系统透镜（无用户自铸视图）**：①**方向轴三元 chips**：全部（默认——可见域并集意味着第三关系「我旁观的」存在，组织透明是特性非缺陷）/欠我的/我欠的；**排列细则（v3.16 = v4.23+ #56：透镜 = 换组织轴，不是过滤器）**——「我欠的」是**行动清单**（急迫序）、「欠我的」是**应收账簿**（原生问题 = **债务人 × 账龄/信号，横切目标**：催张锐时想的是"张锐那边怎么样"不是"目标第三条怎么样"；会计学应收报表按债务人×账龄组织，从不按项目）；**目标分组是「全部」视图的正确骨架，方向透镜一开即成噪音**——**透镜激活时目标分组退场**（组头/组 CTA/出生线/无归属分节全部收起），**信号序平铺**（待验收>逾期>无信号浮起、正常行安静），**目标降为行内 ◎chip**（一跳回目标组/枢纽——从骨架降为上下文，一跳指路不丢；**chip 点击不得被行跳转吞**——事件分层，demo 已断言；**chip 过三态投影过滤（v3.16r）**——goalRef 一切投影位的既有总则对新投影位自动适用：标题不可见的查看者不渲染此 chip、零暗示）；两册同规则（我欠的同样不顶目标组头）；切回「全部」恢复分组与折叠态；**按人分组押证据门**（催办按人批量是真实工作流，但每人 1-2 条时人头组即组头噪音——等"一人欠我五条以上"的 dogfood 密度再开）；合法性：全在"对账排列+一跳指路+就近动词"条款内，零新机制；②**时间透镜两层规则**：话语原文是真身（"下周初"不得强解析——宁空勿错），时间戳 = 解析投影、可空、可纠（`due:{text,ts?}`，§3.2）；透镜只对有戳行生效（今日到期/逾期浮起 = 事实驱动零维护——Asana 把自动晋升拆成用户规则的反面实验），**无戳行沉底不消失**；**账龄折进排序权重与逾期徽标分层**（每层暗示一个升级动作：催→顺延→作废），不做独立结构；③**目标组（GOALS）**：按目标分组——目标承诺行（虚线框=真身在云之家不在图 + 子承诺状态计数信号【非百分比】+「终态：人工验收」药丸 + 产出归集入口【两跳派生】+「评估」入口）+ **「无归属」组**（周会批量补挂：多选 → /link）+ **「立目标」入口** + 目标行「委派」CTA=传送门（**不做板上分配表单**）+ **目标行点击 = 放大为目标页**（第二缩放级别 §7.6，Back 恢复板位）；**组折叠复用侧栏 chevron 语法**（披露列同位同行为——同构复制），**组头计数带异常语义**（"N 承诺 · M 逾期"——折叠组仍可对账）。

**排序与行规格**：**组内信号序成文**：待决 > 逾期 > 无信号/过时 > 运行 > 进行中 > 休眠 > 终态。**行信息层级**：常显 = **四要素**（谁/向谁【查看者本人省略】/交付什么/何时【原话语 text】）+ **三值信号** + 最后信号时间（三值状态首入第一缩放级——无信号/过时不再只在 hub 可见）；**责任锚两槽位**：执行者（人/agent/流程 ex-tag）×验收人（**恒为人**——Linear assign/delegate 同构：an agent cannot be held accountable；验收人=查看者本人时省略、非本人时显示）——两槽正交；挂接来源与出生故事**降两级披露**（hover 一级 + 详情二级，**hover 永非唯一通道**【触屏/a11y】——出生故事的差异化在有据可查不在常显）；颜色预算 = 仅状态/异常拿饱和色，其余灰阶。**行 = 一跳传送门**（链接话题会话/轨迹真身，行内预览=过程摘要——过程日志永不进板）；**行内修理动词就近**（催/顺延/作废/合并/移交/收养/摘除——§7.6 同族，**无归属承诺的修理在板上同样可达**，不再只活在 hub；**渲染按动词主权谓词**【v3.14 = v4.22：仅该承诺 owner 见修理与催——越级不便利】；**「我的切片」= 我执行的 ∪ 我委派的**两册，与方向轴同构）。**修理动词的可动性与作废确认门（v3.17 = v4.23+ #57）**：⋯ 修理入口必须是**可执行的就地动词条**（板与 hub 同构组件），不得以说明文字/toast 占位——「既可见又可动」对板行自我适用（占位=半环割裂债，无归属行的修理占位即全域不可达）；**作废全入口两段式**（板行/hub 行/留意层/目标级/话语路径皆过门）：UI 侧=就地轻确认（按钮文字切换或确认条列明"终态不可逆·级联·回写"三后果，取消可回无痕、不进决断面、**修理条与确认门不跨会话残留**）、话语侧=agent 确认卡；**摘除/收养按归属互斥渲染**（有 parentGoalRef 显摘除、无则显收养——同一格的加减法）；demo 主诉验证：无归属行在板上走完 收养→摘除→作废 全程。

**第一档欠账修复清单（v4.21 明标——板停在 v4.12 前旧语义的同类全集补课，开发按此逐项核销，demo 已对齐）**：①**催办统一**：板行复用"agent 拟稿+传送门+owner 亲发"，**废一键借身提醒**（B4 禁令的板上兑现）；留意行从承诺数据推导（顺延/作废后无僵尸）；②**晨报 = 图的投影且每个数字是门**（逾期/信号异常/待验收/今日到期可点定位——逐级兑付定律在晨报的适用，§9）；③**人执行行一跳登记真身 + 修理动词就近**；④**三值状态下板**（含信号过时样本）；⑤**空板出生样本**（登记覆盖率的分母出生地——样本纪律）；⑥**验收断链接通**：验收卡家族延伸适用人类交付回执（§5.2——交付推断确认→登记场所出卡→验收→终态，断头路接通）；⑦侧栏板徽标动态推导。

**板级明拒六条**：无看板拖拽（状态 = 事实驱动，拖 = 对图撒谎）/无进度条百分比/无用户自铸视图（透镜只有系统三个：方向/时间/目标）/无图表 widget/无日规划仪式/**无决断条**（设计线自审推翻自己草案的产物——板级决断条 = 第二收件箱，违三层分工；GitHub Inbox 合法恰因那是他们唯一的收件箱，模式不可误植）。**Viva Goals 验尸句钉墙：板的每次打开必须是"来取，不是来喂"**。

**时间回顾**：「本周产出」一键汇总（lineage+终态的时间投影——周报的 pull 版）。

### 7.5 对象面（右栏）与工件预览三态（v3.6，D13⑥）

三 tab：**当前**（本会话工件/喂入引用留痕/关联日程 deadline）、**记忆**（可检视可纠正）、**资源**（知识库+表格混排一棵树——按容器组织、类型是过滤属性；日程周条+议程）。**反向来处**（工件→承诺/目标血缘读出）；**系列当前指针**（收藏链接永远指向当前有效版；勘误=血缘+分发清单读出物）。

**工件统一（v4.11）**：**文件消息 = 工件的 IM 出生形态**——同事拖进群的 PDF 与 agent 交付的 md 是同一种图居民（工件），血缘不同、**卡与预览语法相同**（一个物不配两套 UI）。工程：IM 文件/图片消息与 `lineage/produced` 工件用同一工件卡组件（标题/预览/下载/云之家打开）；人发文件不强制入图（agent 劳动才写出生边），被引用/喂入时经既有 ref 机制留痕。真身唯一：文件真身在云之家，预览是投影，下载/云之家打开永远可达。

**预览三态（三种意图，与话题"卡→展开→进入"平行的物缩放语法）**：
- **流内卡**：扫一眼（卡带预览/下载动作）；
- **并排 = 默认预览态**：右栏对象面被预览**接管并加宽**、中栏压缩但保持可读可回复——**边看边回是验收/steering 的原生姿势**（claude.ai artifacts/飞书侧边栏同族；拒绝 Slack 式 modal——挡住对话，验收变"看完凭记忆回复"）。不违反 D5 反而兑现它：中栏是流右栏是物，预览=物的放大态；v3.5"右栏不做第二时间线"无恙（单物非流）；
- **沉浸**：深读全屏、Esc 返回（PDF 多页/长文）；移动端（P5）唯一态、天然降级。

**格式策略：能投影则投影**——md 富渲染（presentationMeta 渲染器复用）、pdf 浏览器原生 viewer、**html iframe sandbox 只读禁脚本**（预览不是运行）、图片 lightbox、表格走资源投影（sheet schema+记录窗口）；数据通路 = file-data 代理模式（CLI 下载→magic-bytes 嗅探→data URL，老小窗已验证）；不能投影 → 下载+外开，**不硬造 viewer**。**切会话即收**（与"锚不跨会话残留"同一纪律）。

**宽度（补充裁决）**：可拖分隔线 + 两端护栏（中栏可回复最小宽=**硬底线**拖不破；预览可读最小宽=再窄不如收起）+ **全局记一个值**下次如旧——固定宽度=替用户决定主次（主次是当下意图的属性），纯比例无视内容自然行长（大屏 md 拉破 30-40 字舒适区）；更宽的需求走沉浸态，分隔线不必覆盖全区间。

### 7.6 事件枢纽与对象枢纽

事件枢纽：日程周条→事件详情。**落点 = 右栏对象面接管（v3.14 收编实现线事实）**——板上一场会一行只装三样（几点/叫什么/准备好没有），"差什么"的一屏放右栏、标题即门（与工件预览同一条纪律同一种形状：模块级订阅**不拿快照**——就绪度要随交付自动翻绿，快照会越看越旧）；枢纽四段 = 关联任务（每件带一跳）/材料（会上要用的是东西不是"已完成"三个字）/日程描述（全参会人可见的那一版）/「为此会准备」（传送门不替人派活，双语义见 §5.6）；平台 list 已回字段不另打 event get、空串按"没填"渲染非空白段；**右栏打不开时如实说话**（revealAside 失败不得渲染成"什么都没发生"）。对象枢纽（通用形态）：长期活对象的对象轴记忆、变更史、关联会话、传送门 CTA。

**目标页（目标枢纽，v3.7 定稿 = v4.12）**：**定性 = 目标这个复合承诺的对象枢纽 = 承诺板的第二缩放级别**（缩放语法第四次复用：板→目标放大态；进出即缩放、**Back 恢复板位**、数据同一查询——非新 surface，"分活去哪/看进度看哪"的割裂从根上不存在）。**灵魂一句：三个主权时刻在此落座，其余一切是派生查询**。范围 = 目标子图全量（目标→子承诺→执行会话/轨迹→产物→回执验收→评估→真身回写），呈现用链不用图（依赖图禁令不动）。

**三条结构性法则（实现者不可违）**：①**可见域（v3.14 升级为参与者视角全则，= v4.22）**——**视角 = 关系 × 可见域 × 问题**：一页 N 个查看者 N 种渲染 = "与我有关的边被点亮"（关系从既有边派生非角色字段；清单/计数/决断层/背景全按查看者可见域过滤——不存在全知视角，目标名遵循**标题/正文两层可见域与三态投影**【§5.3】；**磨稿血缘 owner-only**——机密目标一跳即泄密，read-domain 钩子在血缘投影上生效）；**「我的切片」语义成文 = 我执行的 ∪ 我委派的**（两册——方向轴"欠我的/我欠的"在 hub 切片的同构下放），执行者默认置顶来自**切片律非决断层**（逾期对任何视角都不是可应答对象）；**动词主权法则**：修理动词族与 CTA 的渲染谓词 = **该节点的 owner**（目标级归目标 owner、承诺级归承诺 owner——执行者对自己的承诺是再委派的 owner，递归闭包的席位表达；**越级不便利**：目标 owner 对孙辈承诺不渲染催，不禁社交追问）；执行者对自己承诺的动词 = **登记族**（把我的活拆下去）+ **回执族**（交付/求助/顺延请求 = 回复登记消息）；**无主权的动词不渲染**（非灰化——灰按钮是"你不配"的展示；不渲染不禁言：人人可用话语说任何事，系统只是不为无主权者造按钮）；**渲染过滤与编排层执行校验共用同一主权谓词、单一事实源**（allowedActors 同族——防 UI 不渲染而文本通道绕过执行）；**无主权话语到达时不执行也不静默（v3.14r）**：执行者对 agent 说"这目标作废吧"——agent 不执行、不静默忽略（静默是本设计最大罪）、不公开驳斥（社交羞辱），**回应 = 指路 + 可选转达拟稿**（"作废归 owner 张锐——可直接问 ta，或我拟一条转达你亲发"）；②**单一形态**——一个模板贯穿生命周期，变形全由派生信号驱动（评估卡出现=收口形态、全终态只读=回顾形态），**无任何"阶段"字段落图或落真身**（"磨稿中/收口中"是伪状态——防实现者加 status enum 的栏）；③**随时可对账非持续对账**——常驻只放原料（成功标准正文投影×终态计数×工件归集），对账结论只在人发起评估时产出（依据版本入 env 快照——标准改了简报可追）。

**结构**：Header 全零存储推导（名称/owner/时限/真身链接带时间戳/状态徽标/成功标准条=真身正文派生 + **真身之变显形**「真身已于 x 日修改·未对账」+查看差异+以新基准重估【意图史】+ **staleness**「图内 x 天无新轨迹」——事实驱动非填表驱动）；**Zone1「需要你」两层**：决断层 = 收件箱同源可应答对象的**过滤投影**（先答先赢跨投影，绝非复制列表：待裁决提案/待验收/冲突/移交裁决/评估简报），留意层 = 信号+就近动词（逾期不是可应答对象——催/顺延/作废就在旁边）；**空态三义分家**：在跑/停摆（全在等第三方）/空转（无子承诺）——合并三义即谎言；**Zone2 执行清单**（平铺+计数+一跳，永不画树）：**环行** = 每行承诺携带自己的迷你闭环（来源【出生边】/会话一跳+过程摘要/产物 chips/回执验收态【回流边】）+ **三值状态**（有证据/无信号+最后信号时间/信号过时——观察型承诺不画成确定性）+ **行内修理动词族**（目标的中年）：催（agent 拟稿+传送门+owner 亲发——B4 降级明标）/顺延（期限 vs 提醒分立）/作废/合并/移交（/handoff）/**收养**（无归属承诺 /link 进来，attachedVia:'linked'）/**摘除（/unlink，v3.14——与收养对称的减法动词**：owner 对子图边界的修理，作废杀承诺语义过重时用它，行落无归属组，§6.4）；**全族渲染按动词主权谓词过滤**（v4.22 demo 已兑现：板/hub 行修理与催仅渲染给该承诺 owner）；CTA = ＋委派（传送门）+⚡拆解（禁令文字随卡）+✓评估——**三 CTA 同按主权过滤**（非 owner 席位无此三钮；轻问人人有）；**轻问=传送门**（跳私语会话预载目标语境——无页内输入框，轻问是会话 turn）；右栏 = 该目标的对象面（归集+三态预览/背景：磨稿血缘 owner-only、历次简报=非操作者的目标时间线）。

**生命周期补全**：目标终态 = 已验收/**已作废**（无拒收——评估不通过的出口 = 继续或作废）；作废 = 人签发终态 + 回写真身 + **级联子承诺**（工程语义从摩擦刀裁定：子承诺收到"父目标已作废"信号显形 + 批量修理动线【多选作废/收养改挂/独立存续】，**不自动作废**——主权摩擦保留）；**目标级作废入口与确认门（v3.17 = #57）**：终态成文已久而无门是割裂债——hub 与板的目标行皆有作废入口，**两段式**（确认条含级联提示：N 条子承诺将显形待处置），承诺级作废同门（全入口两段式总则见 §7.4）。**闭环自检表入验收**（环路完整性对页面自我适用）：拆解委派/执行/产物/回执验收/修理/评估/回写七环，每环**既可见又可动**，缺一即割裂债。**违规能力自检条款**：页面的合法增量只有决断落座+一跳导航+就近动词——**凡只能在这一页获得的能力就是违规能力**。竞品三戒：别做目的地 app、别管过程指标（填写率/check-in 率 = theater 制度化）、催人裁决不催人抄数。**席位诱惑明拒五条（v3.14 = v4.22，全文见 §5.3）**：无参与者面板/认领市场、无上级驾驶舱/进度推送、无跨域背景摘要内嵌、无"我的目标工作台"聚合页、无"另有 N 项你看不到"装饰——**五席位皆无新 surface**。hub 其余丰富度（关键时刻流等）与故事线维持押门（终态回顾态可含）。

## 8. 治理与身份

- **场所合同**：同一 agent 逐场所合同；三层（组织默认→场所→会话快照）；**出生规则（v3.11 = v4.18 场所创设三句）**：创设人签发（`yzj_im_group_create` 强确认；agent 只能提议）、合同默认最严（新场所 `served=false` 不在岗不接单须显式开启）、出生血缘携带语境（birth 字段）；**听众集合按场所解析、随成员动态**（audience 存场所引用永不展开成员快照——两端一致检验：云之家看得见历史登记消息⇔承诺板看得见承诺行；**v3.11r 事实前提待核**：动态解析的正当性依赖"云之家群历史对新入群成员可见"——若平台对新成员隐藏入群前历史，则新成员板上见承诺行而云之家见不到登记消息、检验反向失效，动态解析须按加入时间切分——**入实测清单⑨**）；拉人=听众扩张、移人=听众收缩，均走确认门（能力随阶段二平台 API 到位）；**硬合同**（guard 强制、对话不可写）：接单开关/触发者白名单/写权限级/工具面/审批策略与粒度/记忆策略/preset 允许/oaRequiredCategories/**永不记忆**；**软合同**=场所记忆同库可对话修改；**第三格**（口径类）=软存储+硬变更流程（留痕/生效期/审阅门）；快照语义+撤销穿透（3.4）；三入口（群 agent chip/合同面板/组织默认页）。
- **身份阶梯**：真人寄生（自聊审批弱形态）→ **专号**（第二真人账号：DM 推送、归因清晰、移动轻问通道）→ **机器人**（@ 回调收、卡片发）→ **企业应用**（三级 token API 面）。**B2** 显示名任务态（专号命名+消息内任务标注）；**B3** 语态默认与身份阶段耦合；**B4 on-behalf-of**：代理名义一等参数（"财务助理（代郑慧）"随投影展示），**借身期禁跨场所催办**（降级=拟稿+操作者亲发）。**B5 多实例受话唯一律（v3.23 = #63；v3.23r 精确化）**：**一次受话一个接单者**（不变量是受话唯一，不是"一个场所一个实例"）。①**对群在岗（P1）**：接单开关的触发者范围含他人 = **对群在岗** = 人签发的身份/听众敏感动作（把自己的账号与授权借给这个群），切开即向群发一次**在岗声明帖**「云小助（Bruce）在本群在岗 · 接受全群委派」（`presence/declared{scope:'all'}` 锚入；群即审计面——v3.15⑤"谁把 agent 接进这个群须可审计"由此兑现，三方知情零新机制）；**仅本人合同不声明、不算在岗**（它只服务自己的操作者，与他人天然无冲突——个人工具不需向群公告）；**接单前先读场所近史**：已有同侪**对群**在岗声明 → 警示两出口（请对方退岗【拟稿亲发，社交摩擦不碰】/ 改为仅本人），**≥2 个对群在岗重叠押门**（分工需要名字，名字需要专号）；**发言者实例优先**（§6.2④′ 级 1）：有助理的人由自己的助理接单，对群在岗只服务没有助理的人——归因永远落在说话者自己的账号上；**代发登记话语等一切实例出站恒带署名**（下②），故在岗实例见同侪代发永不二次登记；退岗 = 退岗帖 + `withdrawn`；**在岗移交** = 退岗帖 + 在岗帖（/handoff 同族：背景包含**场所记忆**须人签发的工件化脱密——越境律，私语不迁移）；声明的观测缺口（F13⑨ 新成员看不到历史、后加入、双方同时切开）由 §6.4 认领协议兜底。②**署名 B2 升格为协议**：寄生期 agent 一切公域出站消息恒带「—— 云小助（Bruce）」+ 机器可认标记——对人 = 归因（寄生期没有它，群里没人分得清 Bruce 与 Bruce 的助理——这本就是 B2 的初衷），对同侪实例 = 互认凭据（agent 经人看得见的同一条通道发现彼此，**不需要成员列表**）。③**可用性缺陷明标**：在岗实例离线（电脑合盖）= 全群无人接单且群无从得知（通道健康是实例内事，§6.5 对群失明）——P1 已接受缺陷；**备岗序**（第二梯队延迟 k 个轮询周期后认领，同一竞赛协议）押 dogfood 疼痛门。④**根治 = 身份阶梯本身**：专号让每个 agent 有可 @ 的名字，受话唯一由平台原生 @ 兑现，触发词与竞赛退役；机器人/企业应用 = 服务端托管一个组织级实例，N 图收一图、镜像行退役、可用性不再寄生于个人电脑——**爬阶梯的理由从"更好"变为"多操作者部署的结构性必需"**。**明拒四条**：按操作者分触发词（`@next-bruce`——把身份塞进触发词 = 让全群手打路由，摩擦放错处）；全局锁/协调服务（寄生期无共享后端，且群消息流本就是共享的服务端总序日志——不另造）；都干活让人挑（双写不可逆）；随机/哈希选（李四不知道谁的账号会动手——归因不透明毁信任）。
- **听众集合**（§1.6 完整双域）：读取按提问者可见域、输出按在场者交集过滤；越境唯一合法通道=人签发的工件化脱密+审计+血缘；记忆永不越界（不可撤销故入硬合同）。
- 治理表：租约（期限/自动收回/创建强确认/清单可见）、裁决（记录入审计基底/挂起不阻塞）、越境（谁签发/从哪到哪/脱了什么）、记忆策略（guard 级）、审计导出（走确认/含判定链）、on-behalf-of（名义随投影/跨场所催办拒绝）。

## 9. 主动性（域 F）

> 信任门槛是写权限的函数，不是主动性的函数。

- **F-read**（scheduler 供电，只读）：**轻问**（一次性投影，会话 turn 非旁路——落 DM 日志可审计可升格：「以后每天这样」→晨报条目、「转成工件」→落云之家）；**晨报**（cron→query→report 卡→DM；**v3.12 = v4.21：晨报 = 图的投影且每个数字是门**——逾期/信号异常/待验收/今日到期各数字可点定位到对应板位/对象，逐级兑付定律对晨报同样适用：报出"3 项逾期"却不可点 = 幽灵信号）；**晨报对表行（v3.24 = #64，opt-in）**：仅当操作者软合同含「每天早上告诉我有几条结果等着看」句（`clause/set{key:'morning'}`）时，晨报多一行**只有计数**的「🔒 N 条结果等着看 ›」（N = 未答且未配对错了的校准回执）——人签发的显示、仅桌面私语投影、**不进 IM 副本**、点击进 `judg`、受 D10；默认没有这行（仪式锚是人自己立的）；**盯(节点类型)**参数化 watcher（承诺到期/事件就绪度/运行健康度/临时定时）；`/status`；碎片「引用+入池/登记」低摩擦捕捉；**提醒=可应答对象**（已催/顺延/完成）；**顺延两动词**（顺延承诺期限=公域经确认回写真身；顺延提醒=私事只改计划）。**推力拆半（v3.9 = v4.16 结构修正）**：**对人的推力平台原生齐备——DSH 不自建对人提醒**（声明式提醒/多次提醒/短信/语音电话/snooze/ICS 订阅全在平台，我们声明式登记即可）；**对 agent 的推力仍靠轮询**（queryByDay/pageRecentList 游标为此而备）——scheduler 的职责域相应收窄为 agent 侧唤醒与图 watcher。**应答环不外包（v3.9r，三角色定律对提醒的应用）**：平台提醒只是**投影**（触达面）——提醒对象的真身与可应答面仍在图（已催/顺延/完成），平台提醒的 `redirectUrl` 回链必须指回图上该可应答对象；否则"提醒是可应答对象"被外包肢解，snooze 只在平台侧生效、图不知情、次日重复提醒——操作者变回状态泵。
- **F-act**（最后解锁）：自主写、代发、ambient 回复、自动跟催、会前自动备料——每项独立拨盘入场所合同。
